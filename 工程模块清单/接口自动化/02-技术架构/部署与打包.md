# 部署与打包

## 后端打包

### 构建命令

```bash
# 服务端（pom.xml，artifactId=testin-api-backend）
mvn package                          # surefire 已配置 skipTests=true，默认不跑测试

# 执行端（必须显式指定 runnerPom.xml）
mvn package -f runnerPom.xml

# 跑单个测试（需显式覆盖 skip）
mvn test -DskipTests=false -Dtest=ClassName

# MyBatis Generator（generatorConfig.xml 在 resources 下）
mvn mybatis-generator:generate
```

- JDK 1.8；依赖走阿里云 mirror（pom 里配置的 alimaven），**不依赖公司内网 Artifactory**，离线/外网环境可构建。
- 没有 `mvnw`，用本机 `mvn`。

### 产物布局（重要：`deploy/` 而非 `target/`）

`mvn package` 的输出目录被改成 `${basedir}/deploy/`：

```
deploy/
├── testin-api-backend.jar     # 主 jar（manifest 里 Class-Path: ./lib）
├── lib/                       # maven-dependency-plugin 拷出的全部依赖
│   ├── ApacheJMeter-associate-api-functions.jar  # system scope，按文件名排序优先加载
│   └── ...
├── resources/                 # 配置文件 + jmeter/ 运行时目录 + deb/ + python_dep/
└── bin/                       # 脚本
```

两个关键事实：

1. **资源文件被 maven-jar-plugin 排除在 jar 外**，运行时靠 classpath 上的 `resources/` 目录加载。所以必须保持 `java -cp resources:lib/*:...` 的启动方式，单独拷走 jar 是跑不起来的。
2. **lib 目录按文件名字典序加载**——第三方与 JMeter 冲突的 jar 靠命名靠前获得优先（见 [后端双形态架构](后端双形态架构.md) 的类加载约定）。

`resources/template/` 与 `resources/bin/` 在 copy-configs 阶段被排除，不进 `deploy/resources`。

### 启动脚本（也是容器入口）

`startup.sh`（服务端）/ `startup_runner.sh`（执行端）做三件事再拉起 Java：

```sh
# 1. 用环境变量 OPENAPI_URL 替换所有 yml 里的主平台地址
find resources -name "*yml" -exec sed -i "s#http://openapi.pro.testin.cn#${OPENAPI_URL}#g" {} \;

# 2. 安装系统级依赖（.deb 包）
dpkg -i resources/deb/*.deb

# 3. 解压 python 依赖到系统 python3.8
tar -zxf resources/python_dep/python_dep.tgz -C /usr/local/lib/python3.8/dist-packages/

# 4. 启动（注意 classpath 顺序：resources 在最前）
java -cp ${DEPLOY_PATH}/resources:${DEPLOY_PATH}/*:${DEPLOY_PATH}/lib/*:. ${JAVA_OPTIONS} cn.testin.Application
# 执行端则是：
java -cp ... cn.testin.runner.RunnerApplication ${HTTP_PORT:-6254} ${REDIS_HOST:-redis.pro.testin.cn} \
     ${REDIS_PORT:-6379} ${REDIS_DB:-0} ${TESTINPRO_REDIS_PASSWORD:-EMPTY_PASSWORD}
```

默认 JVM 参数：`-Xmx8192m -Xms2048m`，OOM 时 dump 到 `/home/syy/data/logs/oom-dump-%p.hprof`。

执行端位置参数与默认端口 6254 详见 [执行端Runner详解](../03-实现逻辑/执行端Runner详解.md)。

### Docker 镜像

`Dockerfile` 极简：

```dockerfile
FROM hub-mirror.testin.cn/library/busybox:stable
ADD target /data/target
VOLUME /data/webhome /home
CMD ["sh", "-c", "cp -R /data/target/* /data/webhome/; mkdir -p /home/syy/data/logs/; ..."]
```

注意：**镜像构建不含 mvn 步骤**——CI 里需先 `mvn package` 再把 `deploy/` 归置为 `target/` 供 `ADD target /data/target` 使用。

## 前端打包

```bash
pnpm build   # vitepress build docs && vue-tsc && vite build —— 三步都可能失败
```

- 产物 `dist/`（含 vitepress 文档站点）。
- 文件名按构建时间戳目录输出 `YYYYMMDDHHmm/[name]-[hash].js`（`vite.config.ts` 的 `getNowDate()`），用于 CDN/缓存隔离。
- manualChunks：`element-plus`、`ace-builds` 独立 chunk，其余进 `vendor`。
- CI（`.workflow/*.yml`）用 **node 14** 跑 `npm install && npm run build`。

## 环境拓扑（生产形态）

```
┌─────────────┐   iframe   ┌──────────────────────────────┐
│  主平台      │ ─────────► │ 前端静态资源（nginx/CDN）      │
└─────────────┘            └──────────────────────────────┘
                                     │ /api/v1
                              ┌──────▼───────┐
                              │ 前置网关      │ 剥离 /api/v1 前缀
                              └──────┬───────┘
                              ┌──────▼───────┐      ┌────────┐
                              │ 服务端   │ ───► │ MySQL  │
                              │ (xxl-job内嵌) │      └────────┘
                              └──────┬───────┘
                                     │ lpush/brpop
                              ┌──────▼───────┐      ┌────────────────┐
                              │    Redis     │ ◄──► │ 执行机 N 台     │
                              └──────────────┘      │ (runner ) │
                                                    └────────────────┘
```

- 执行机可水平扩容，部署后由服务端 `TestMachineService` 监听在线状态（见 [测试机管理](../01-产品功能/测试机管理.md)）。
- 数据源、Redis、主平台地址等全部支持环境变量覆盖（profile yml 里 `${VAR:default}` 形式），容器化部署通过环境变量注入即可。

## 配置与环境变量速查

| 配置项 | 位置 | 环境变量 |
|---|---|---|
| MySQL 地址/库名/账号 | `application-test.yml` datasource 段 | `TESTINPRO_DB_HOST` / `TESTINPRO_DB_PORT` / `TESTINPRO_DB_NAME` / `TESTINPRO_DB_USER` / `TESTINPRO_DB_PASSWORD` |
| Redis | 同上 redis 段 | 执行端走启动位置参数 |
| 主平台 OpenAPI 地址 | 各 yml 中 `http://openapi.pro.testin.cn` | 启动脚本用 `OPENAPI_URL` 全局 sed 替换 |
| profile 选择 | `application.yml` `spring.profiles.active` | dev / test / prod 三份 |
| mongodb shell 路径 | profile yml `mongodbshell.path` | v4 默认 `/opt/mongodb-linux-v4/bin` |
