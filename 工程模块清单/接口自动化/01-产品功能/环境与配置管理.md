# 环境与配置管理

## 功能是什么

**环境**是接口自动化执行的"目标上下文"：同一份脚本/用例，换一个环境就换一批域名、请求头、数据库连接和全局变量。测试工程师只需要维护一份用例，通过在执行时选择不同环境（如 SIT、UAT、生产影子），即可让用例跑在不同的目标系统上。

平台把环境相关的配置拆成两层：

- **命名连接（环境配置项）**：项目级别的"连接注册表"，只登记"这个项目中存在一个名为 XX 的 HTTP 连接 / 数据库连接"，**不含实际连接参数**。命名连接在 [协议配置管理](协议配置管理.md) 页或环境定义页里统一登记。
- **环境**：一套环境的完整参数表。每个环境里都会出现项目下所有命名连接的同名条目，由使用者在**各环境里分别填写**实际参数（域名、账号、超时等）。

这种"一次登记、各环境填值"的设计带来一个关键特性：**新建一个命名连接后，项目下所有环境都会自动出现同名空连接**，各环境填各自的值；改名、删除也会同步到全部环境。

环境维度支持的连接类型：HTTP、LDP、OES、ATP、TCP、Dubbo、WebSocket、gRPC、GraphQL、MQTT、FIX、数据库，外加**全局变量**。页面实际展示哪些协议页签，取决于当前项目开通了哪些协议。

## 页面入口与界面分区

入口：左侧菜单 **测试环境**。

页面采用"多页签"布局，默认页签是**环境列表**，新建或点击环境名称会打开独立的**环境定义**页签（可同时打开多个环境对比编辑，页签上有未保存标记，关闭未保存的页签会提示是否保存）。

### 环境列表

| 区域 | 内容 |
|---|---|
| 搜索区 | 按环境名称模糊搜索 |
| 列表列 | 环境名称（点击进编辑）、环境描述、维护人、状态（启用/禁用） |
| 行操作 | 启用 / 禁用、复制、删除 |
| 右上按钮 | 新建环境 |

> 每次进入该页面，平台会自动从私有云主平台同步一次"绑定了本项目且已启用"的环境，同步来的环境会自动出现在列表里（见"核心概念 · 主平台环境同步"）。

### 环境定义页

分上下两区：

1. **基本信息**：环境名称（必填）、环境描述、维护人（必填，下拉选择项目成员）、状态（启用/禁用单选）。右上角**保存**按钮，编辑态支持 `Ctrl+S` 快捷保存。
2. **环境配置**：按协议分页签（HTTP 配置、LDP 配置、OES 配置、ATP 配置、TCP 配置、Dubbo 配置、WebSocket 配置、gRPC 配置、GraphQL 配置、MQTT 配置、FIX 配置、数据库配置、全局变量）。每个协议页签内是该类连接的参数列表；页签区右上角有**新建连接**按钮（等价于在协议配置页登记一个命名连接）。

## 核心概念

### 环境

一行环境 = 名称 + 描述 + 维护人 + 状态 + 一整套连接参数与全局变量。环境是执行入口（调试、测试任务、定时任务、测试计划）的必选项——没有可用环境就无法执行。

### 命名连接与级联同步

命名连接是"名字 + 描述"的占位登记，真正的参数存在每个环境里。级联规则：

- **新增**：所有环境自动出现同名空连接（排在列表最前），各环境分别填值。
- **改名**：所有环境里的同名条目自动跟着改。
- **删除**：平台先检查该连接是否被接口定义或脚本引用，**有引用则拒绝删除**并提示先解除关联；无引用则从所有环境中移除该条目。

### 全局变量

环境级别的变量，在执行时对整份用例生效，两种类型：

| 类型 | 含义 |
|---|---|
| 变量赋值 | 直接写 键 = 值，可附描述 |
| SQL 语句执行 | 执行时先对指定数据源跑一条 SQL，把查询结果赋给变量（常用于动态取数，如取一个可用账号） |

编辑支持"键值模式"（逐行表单）与"批量模式"（按文本格式整段粘贴，每行一组）互相切换。

### 启用与禁用

- **启用**：执行入口的环境下拉框中可选。
- **禁用**：不在执行入口展示，但环境数据完整保留，随时可以重新启用。禁用在列表行操作上完成，需二次确认。

### 主平台环境同步

平台与私有云主平台联动：主平台上"绑定了当前项目且已启用"的环境，会在你每次进入环境页面时自动同步过来（本地不存在的才创建，同名跳过）。若主平台环境带数据库配置，对应的数据库连接也会一并登记好。同步过程失败不会打断页面使用（页面无感知），发现"主平台有、这里没有"时联系管理员检查主平台对接配置。

### 环境的删除与回收站

删除环境会先进 **回收站**（可从回收站还原），确认彻底删除后才不可恢复。详见 [回收站](回收站.md)。

## 如何操作

### 新建并配好一套环境

1. 进入 **测试环境** 页，点击 **新建环境**，打开"新建环境"页签。
2. 填写基本信息：环境名称、描述，选择维护人，状态保持"启用"。
3. 切到下方"环境配置"区：此时各协议页签下已经列出了项目中登记过的全部命名连接（空值状态）。
4. 逐个点 **修改**，填写本环境的实际参数。以 HTTP 连接为例：

   | 字段 | 说明 |
   |---|---|
   | 连接名称 | 命名连接名，**在环境内不可改**（要改名去协议配置页） |
   | 连接地址 | 本环境的目标域名/地址，如 `http://sit.example.com` |
   | 超时时间 | 毫秒，默认 10000 |
   | 请求头 | 键值对，可增删多行，对该连接所有请求生效 |
   | 自动跟踪重定向 / keepAlive | 按被测系统需要勾选 |
   | 是否启用代理服务器 | 勾选后填代理协议（HTTP/HTTPS）、地址、端口、用户名、密码 |

   数据库连接的弹窗多一个 **验证连接** 按钮：填好驱动、地址、账号密码后先点它确认能连通，再保存。
5. 在"全局变量"页签维护本环境的全局变量（键值模式或批量模式）。
6. 点 **保存**（或 `Ctrl+S`）。页签标题变为环境名，列表刷新。

### 新增一个命名连接（环境内入口）

1. 在环境定义页切到目标协议页签，点右上角 **新建连接**。
2. 在弹窗填连接名称与参数，保存。
3. 注意：这只是"在本环境顺手登记 + 填值"——其它环境会同步出现同名空连接，**记得通知相关人员去其它环境补值**，否则用例在别的环境跑会取到空配置。

### 复制环境

列表行点 **复制**，平台生成一个名为"原名_副本_xxxx"的环境，全部配置原样带过来。搭一套参数相近的新环境（如 SIT → SIT2）时最省事。

### 禁用 / 启用 / 删除

- 列表行点 **禁用**（二次确认）→ 该环境从执行入口消失；点 **启用** 恢复。
- 点 **删除**（二次确认）→ 进回收站，误删可在回收站还原。

## 使用场景与最佳实践

1. **一套用例多环境复用**：用例/脚本里只引用"命名连接"，绝不写死域名与账号。换环境执行时平台自动取对应环境的参数——这是环境机制的核心价值。
2. **命名连接先在协议配置页统一登记**：推荐由项目管理员在 [协议配置管理](协议配置管理.md) 页集中维护连接清单与命名规范（如 `订单服务-HTTP`、`核心库-MySQL`），再让各环境负责人分别填值，避免大家在环境里各自起名。
3. **敏感参数按环境隔离**：生产账号只填在生产环境，配合权限控制环境编辑入口，避免泄密到测试环境。
4. **用复制快速扩容环境**：新环境 90% 参数相同，先复制再改差异项（域名、库地址）。
5. **下线环境用"禁用"而不是"删除"**：禁用可逆、历史报告里对环境的引用不受影响；确认长期不用再删。

    C --> D[用例只引用连接名]

## 注意事项

- 环境是**执行的硬前提**：执行/调试时若提示"未发现执行环境"或"请增加配置"，说明所选环境不存在或没配任何连接，回环境页补齐。
- 在环境 A 新建连接后，**其它环境里它是空值**——跨环境执行报错"取不到连接参数"时，先检查目标环境的该连接是否填了值。
- 删除命名连接被"存在关联过的接口/脚本"拦下时，需要先在接口定义/脚本里把引用切走再删；平台暂无"查看谁引用了它"的界面入口，必要时找管理员协助排查。
- 改名命名连接会同步改写项目下所有环境，环境很多时操作会稍慢，属正常现象。
- 主平台同步来的环境默认带空配置（数据库连接除外），同步后仍需人工补值才能用于执行。
- 数据库连接的"验证连接"由服务端发起，若总是失败而数据库本身正常，检查平台服务器到数据库的网络与白名单。
