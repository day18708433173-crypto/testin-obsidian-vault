# 接口管理

## 功能是什么

接口管理是平台的**资源底座**。一条"接口"是对一个被测服务端点的定义：用什么协议、向什么路径、发什么参数、期望什么响应。它本身**不可执行**，真正可执行的是由它派生出的[脚本](脚本管理.md)，脚本再被[用例](用例管理.md)编排成完整业务场景。

它解决的核心问题：

- **统一定义**：把散落在 Swagger 文档、Postman 集合、口头约定里的接口信息，沉淀成团队共享、版本受控的标准定义。
- **一次定义多处复用**：接口是脚本的"模板"，从接口一键生成脚本，避免每个用例重复填写请求参数。
- **变更可管理**：通过状态流转（待评审 → 已启用 → 已废弃）和标签，管理接口的生命周期。

核心能力一览：

- 多协议接口定义：HTTP、TCP、Dubbo、WebSocket、gRPC、GraphQL、MQTT、FIX 以及证券行业协议（LDP、ATP、OES 等）
- 按模块树分目录组织接口，每种协议有独立的模块树
- 从 Swagger / Postman / JMeter / 平台自导出文件批量导入接口，支持导出与跨项目迁移
- 每个接口自动生成 Mock 地址，可配置 Mock 期望（细节见 [Mock服务](../04-复杂功能细节/Mock服务.md)）
- 接口状态流转、标签、项目内自动编号

## 页面入口与界面分区

从主平台菜单进入"接口管理"。页面采用**左树右签**的布局（与脚本、用例页一致）：

- **左侧：模块树**。按目录组织接口，支持拖拽调整目录结构；首次进入会自动生成一个"未规划接口"根目录。树节点支持右键操作。
- **右侧上方：页签区**。固定有一个"接口列表"页签；每打开一个接口会新增一个编辑页签，可同时打开多个接口对照编辑。页签右键有关闭/关闭其他等菜单，内容有未保存修改时页签标题会有提示标记。
- **接口列表页**：顶部搜索区 + 接口表格 + 批量操作。

列表表格默认展示接口名称、描述、协议类型、请求方式、请求路径、接口状态等列，点表格右上角的列设置按钮可自定义显示列（接口编号、创建人、创建时间、更新人、更新时间、标签等默认隐藏，可自行开启）。表格支持按名称、状态、路径等列排序，排序方式会记住，下次进入保持。

接口编辑页从上到下分三块：

1. **基本信息**：接口名称、接口状态、接口协议、接口请求（请求方式 + 关联服务 + 路径）、接口标签、接口描述，右上角是保存按钮。
2. **参数信息**：请求头、Query 参数、Restful 参数、请求体（表单/URL 编码/JSON/XML/原文），以及前置处理器、后置处理器、断言规则页签；不同协议这一块展示的表单不同（例如 Dubbo 是注册中心与方法参数，WebSocket 是连接与收发配置）。
3. **响应内容**：预期响应结构定义（JSON Schema 形式）。

编辑时有几个贴心的交互：内容有未保存修改时页签标题会出现提示标记；Ctrl+S 快捷保存；关闭有改动的页签时会询问是否保存；他人正在编辑时整块表单只读。

## 核心概念

| 概念 | 说明 |
|---|---|
| 模块树 | 左侧的目录树，用于给接口分组。目录最多 8 层，同一目录下接口名称不能重复 |
| 接口编号 | 项目内自动分配的递增编号（从 100001 开始），删除的编号不回填，只做标识用 |
| 接口状态 | 待评审、待设计、设计中、已启用、已废弃五档，仅作流程标记，不影响使用 |
| 接口请求 | 由"请求方式（GET/POST 等）+ 关联服务 + 路径"组成，关联服务来自[环境与配置管理](环境与配置管理.md)里的环境/连接配置 |
| 参数信息 | 请求头、Query 参数、Restful 路径参数、请求体（表单 / JSON / XML / 原文等），以及前后置处理器、断言规则 |
| 响应内容 | 接口预期的响应结构定义（JSON Schema 形式），供下游理解返回格式 |
| Mock 地址 | 保存接口后自动生成的 Mock 访问地址，同项目下同路径同方法只有一个"默认 Mock"接口 |

接口与周边资源的关系：

```mermaid
flowchart LR
    A[接口<br/>定义端点长什么样] -->|一键生成脚本| B[脚本<br/>这次调用具体发什么]
    B -->|被编排为步骤| C[用例<br/>完整业务流程]
    C --> D[测试任务/测试计划]
```

## 支持的协议

平台按协议族组织接口能力，定义接口时下拉选择协议后，参数表单会切换为对应协议的形态：

| 协议族 | 包含协议 | 定义要点 |
|---|---|---|
| 通用 | HTTP | 请求方式 + 路径 + 请求头/参数/请求体，支持 GET/POST/PUT/DELETE/HEAD |
| 传输层 | TCP、WebSocket、MQTT | 面向连接：连接复用、收发报文、发布/订阅主题等配置 |
| RPC | Dubbo、gRPC、GraphQL | 面向方法：Dubbo 可从注册中心实时拉取服务与方法列表；gRPC 上传 proto 文件后自动解析出可调用的服务/方法 |
| 证券/金融 | FIX、LDP、ATP、OES 等 | 依赖[协议配置管理](协议配置管理.md)中维护的协议配置与数据字典；FIX 内置标准数据字典，选消息类型后按字段模板填写 |

不同协议的接口在模块树里分树管理，互不影响。

## 如何操作

### 新建接口

1. 在左侧模块树选中目标目录（不选则默认进"未规划接口"）。
2. 点列表上方"新建接口"按钮（或在模块树上右键选择新建），右侧打开编辑页签。
3. 填写**基本信息**：接口名称（必填）、接口状态（必填）、接口协议（必填）、接口请求（请求方式 + 关联服务 + 路径）、标签、描述。
4. 填写**参数信息**：请求头、Query / Restful 参数、请求体；可按需配置前置处理器（如取变量）、后置处理器（如提取出参）、断言规则（见 [前置后置处理器与断言](../04-复杂功能细节/前置后置处理器与断言.md)）。
5. 维护**响应内容**：定义预期响应结构。
6. 点"保存"（或 Ctrl+S）。保存后接口进入模块树和列表，并获得接口编号与 Mock 地址。

### 编辑接口

- 在列表中点击接口名称，打开编辑页签修改后保存。
- **编辑锁**：同一时间只允许一人编辑。别人正在编辑时，页面会提示"XX 正在编辑，当前页面锁定中"，此时只能查看不能保存（详见 [编辑锁机制](../03-实现逻辑/编辑锁机制.md)）。列表里被锁定的接口名称旁有锁图标。
- 在模块树上右键接口节点，可进行**重命名 / 删除 / 移动到**；右键目录节点可**新建目录 / 重命名 / 删除 / 展开全部下级 / 批量导出**。

### 导入接口

1. 点列表上方"接口导入"，弹出导入窗口。
2. 选择文件（浏览文件上传）、导入格式（Swagger、Postman、JMeter、TestIn 四种）、绑定服务（导入的接口统一关联的服务，TestIn 格式可不选）、导入目录。
3. 选择**覆盖模式**：
   - 覆盖：系统已存在的同一接口内容不一致则覆盖原接口；内容一致则不变更；不存在的则新增。
   - 不覆盖：已存在的不变更，不存在的则新增；TestIn 格式下同名的会改名为"名称_2、名称_3"。
4. 确定导入，完成后提示"新增接口 X 条，更新接口 Y 条，跳过 Z 条"。

注意：**一次导入只保留一种协议的接口**——导入窗口选定协议后，文件里其他协议的接口会被跳过。全系统同一时间只允许一个导入任务，导入中请稍候再试。

### 导出与复制、移动

- **导出**：勾选接口后"批量操作 → 批量导出"，下载平台自描述格式文件，可用于跨项目/跨环境迁移（再配合导入）。
- **复制**：行内"复制"直接在当前目录克隆一份；批量复制可选择目标目录，重名自动加后缀。
- **移动**：勾选后"批量操作 → 批量移动"，选择目标目录。

### 生成脚本

勾选若干接口 →"批量操作 → 创建脚本"→ 选择脚本目标目录，即可批量生成脚本（初始状态为"待设计"）。这是从接口定义过渡到可执行资产的主路径，见 [脚本管理](脚本管理.md)。

### 删除接口

- 行内"删除"或勾选后批量删除。删除后进入[回收站](回收站.md)，可在回收站还原。
- **限制**：已被脚本引用的接口**不能直接删除**，需先到脚本管理中解除或删除相关脚本。
- 删除、批量修改状态、批量移动等操作前系统会检查编辑锁，被他人锁定的接口会被拒绝并提示。

### 搜索接口

- 顶部快捷搜索框支持"名称/描述/路径"模糊搜索。
- 展开更多筛选可按：接口名称、描述、路径、状态、协议、请求方式、更新/创建时间区间、标签组合查询。

## 使用场景与最佳实践

- **先定义后执行**：推荐"接口 → 脚本 → 用例"的资产建设顺序。接口只维护协议、路径、参数骨架；具体取值、断言、数据集留给脚本。
- **用模块树按业务域分目录**：如"账户服务/转账服务/对账服务"，比靠名称前缀更可持续；拖拽即可调整结构。
- **用状态表达就绪度**：评审通过再置"已启用"，下游任务选择脚本时优先使用已启用资产的来源接口。
- **Swagger 定期同步**：后端服务以 Swagger 为准的团队，可把 Swagger 导出文件定期导入，选"覆盖"模式同步变更。
- **多协议分树管理**：每种协议有独立模块树，证券类协议（FIX/LDP/ATP/OES）的接口定义依赖[协议配置管理](协议配置管理.md)中的配置，先配协议再建接口。
- **接口编号做沟通锚点**：评审、缺陷单里引用接口编号比引用名称更精确（编号在列设置里打开显示）。

## 注意事项

- 同一目录下接口名称必须唯一，保存时会校验。
- 接口删除是"进回收站"而非物理删除，但**有关联脚本时会被直接拒绝**，先处理脚本。
- 接口编号删除后不回填，不要指望它连续，也不要拿编号数量当接口总数。
- 导入文件内若混有多种协议，只会导入与当前所选协议一致的部分，其余静默跳过——导入结果提示里的"跳过"数量要留意。
- 同项目下同路径同方法只能有一个"默认 Mock"接口，新建重复定义时 Mock 地址会带额外区分参数，细节见 [Mock服务](../04-复杂功能细节/Mock服务.md)。
- 编辑页打开期间他人无法编辑同一接口；长时间离开请关闭页签释放锁定，避免同事被挡。
- 接口是"定义"，改接口**不会**自动同步到已生成的脚本；接口变更后需要检查派生脚本是否要跟着改。
