# 开放接口总览

> 本文是第三方系统 / CI 流水线对接本平台开放接口（`/open/**`）的入门页：接入方式、鉴权、响应约定、通用错误码。各端点详细文档见文末索引。产品视角的能力介绍见 [开放平台OpenApi](../01-产品功能/开放平台OpenApi.md)，内部实现见 [开放平台OpenApi实现](../03-实现逻辑/开放平台OpenApi实现.md)。

## 接入地址

服务端控制器**没有统一前缀**，路径就是 `/open/**`；生产环境经前置网关时带 `/api/v1` 前缀：

```
直连服务端：  http://<服务端host>/open/env/list
经网关：      https://<网关域名>/api/v1/open/env/list
```

实际接入地址以部署形态为准（私有化部署问运维要网关地址）。

## 鉴权

所有 `/open/**` 端点都需要携带有效的 **`sid`**（主平台会话凭证）。服务端按以下优先级取 sid：

1. 请求头 **`Sid`**（推荐）
2. URL 参数 `?sid=`
3. 请求体 JSON 里的 `sid` 字段

无 sid 或 sid 无效会返回"获取Sid失败"/"无效的Sid"错误。

**重要约定：**

- **不校验功能权限**：任何有效 sid 都能调用全部 `/open/**` 端点（包括创建接口、触发执行）。接入时务必使用**专用账号**，并在主平台控制该账号的可见项目范围。
- **首次调用略慢**：sid 对应的用户在平台本地不存在时，会自动从主平台同步用户与环境信息后放行，属正常现象。
- `projectId` 不从请求头取，各端点在 body 里显式传（`thirdProjectId` 或 `projectId`，注意两个端点字段名不同，见各文档）。

## 响应约定（两套并存，务必注意）

| 包装类 | 用于 | 成功标志 | 结构 |
|---|---|---|---|
| `R` | 除 `/open/api` 外的所有端点 | **`code === 0`** | `{code, msg, data, detailMessage}` |
| `ResponseResult` | 仅 `/open/api` | **`code === 200`** | `{code, msg, data}` |

> ⚠️ 这是对接最容易踩的坑：同一个前缀下两套成功码。通用错误码（R 体系）：`10005` 无效参数、`10016` 执行失败；`/open/api` 体系另有 `1000503`（op 参数无效）、`10300`（任务不存在）等，见 [开放接口-通用调用](开放接口-通用调用.md)。

业务异常通过 HTTP 200 + 非 0 错误码返回（`msg` 为人类可读错误、`detailMessage` 为内部调试明细），少数参数校验异常可能返回 HTTP 500，调用方应同时处理两种情况。

## 通用调用示例

```bash
curl -X POST 'http://<host>/open/env/list' \
  -H 'Content-Type: application/json' \
  -H 'Sid: <主平台会话sid>' \
  -d '{"thirdProjectId": "1"}'
```

成功响应：

```json
{
  "code": 0,
  "msg": "成功",
  "data": [ ... ],
  "detailMessage": null
}
```

## 对接注意事项

1. **所有端点都是 POST + JSON body**（包括纯查询类）。
2. 幂等性各端点不同：`task/create` 每次调用都会真实触发一次执行；`saveTaskCase` 是"先清空再全量插入"的覆盖语义——调用前务必读各文档的注意事项。
3. 设备相关两个端点是**未实现的桩**，不要依赖。
4. 触发类接口（`task/create`、`/open/api` 的 Task.run）是**异步执行**：返回值是报告 ID，需要轮询结果接口（scriptRunInfos / Report.get）直到状态终态。
