# 开放接口-设备查询

> ⚠️ **这两个端点是未实现的桩（stub），不要对接、不要依赖。**

## 现状

| 端点 | 实际行为 |
|---|---|
| POST `/open/device/conditions` | 无参数，永远返回空的成功响应 `{"code": 0, "msg": "成功", "data": null}` |
| POST `/open/device/list` | 无参数，永远返回写死的假数据：一条名为"默认设备"的分页结果（`listObject="默认设备", itemCount=1, pageCount=1`） |

```json
// POST /open/device/list 的实际返回（示例，永远是这个结构）
{"code": 0, "msg": "成功", "data": {"listObject": "默认设备", "itemCount": 1, "pageCount": 1}}
```

## 对接建议

1. **不要对第三方承诺设备查询能力**——这两个端点存在于接口清单是历史遗留，返回内容与真实执行机无关。
2. 真实的执行机信息只在平台界面的"执行机管理"页维护（见 [测试机管理](../01-产品功能/测试机管理.md)），没有对应的开放查询接口。
3. 如果你的场景需要"指定执行机跑任务"，目前开放接口不支持选择执行机（`Task.run` 内部按串行模式由平台分配）；有需求请联系平台团队评估。
