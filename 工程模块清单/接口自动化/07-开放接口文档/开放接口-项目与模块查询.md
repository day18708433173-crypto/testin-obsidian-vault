# 开放接口-项目与模块查询

> 两个"按名称换 ID"的辅助端点，通常在其他端点调用前使用（如 `interface/add` 需要 moduleId）。

## POST /open/project/queryid

按项目名称批量查询项目 ID。

**请求参数**：body 直接是**项目名称的 JSON 数组**（不是对象）：

```bash
curl -X POST 'http://<host>/open/project/queryid' \
  -H 'Content-Type: application/json' -H 'Sid: <sid>' \
  -d '["订单中心", "支付中心"]'
```

**响应（`R` 包装）**：`data` 为匹配到的项目 ID 数组（`["1", "27"]`）。

- 匹配不到的名称**静默跳过**（结果里没有对应项，也不保证与入参顺序一致）。
- 匹配范围是平台本地缓存的项目表（与主平台项目同步），刚建的项目可能略有延迟。

## POST /open/module/queryid

按模块名称批量查询模块 ID。

```bash
curl -X POST 'http://<host>/open/module/queryid' \
  -H 'Content-Type: application/json' -H 'Sid: <sid>' \
  -d '["支付模块", "下单"]'
```

**响应**：`data` 为模块 ID 数组。

**注意事项（重要）：**

1. ⚠️ **不按项目、不按模块类型过滤**：全库同名模块（任何项目、接口/脚本/用例/任务任何类型的目录）都会命中返回。模块名在多项目间很可能重复，**结果可能含别的项目的同名模块 ID**。
2. 因此可靠的用法是：先通过项目内页面确认模块 ID，或把本端点结果与 [开放接口-脚本查询](开放接口-脚本查询.md) 的 `dirList`（按项目过滤、含树形结构）交叉验证后再用。
3. 匹配不到同样静默跳过。

## 推荐替代

如果目的是"拿某项目下的目录结构"，`POST /open/script/dirList`（脚本目录树，见 [开放接口-脚本查询](开放接口-脚本查询.md)）比 `module/queryid` 更可靠——它按项目过滤且返回层级关系。目前平台只开放了脚本目录树查询；接口/用例/任务的目录树没有对应开放接口。
