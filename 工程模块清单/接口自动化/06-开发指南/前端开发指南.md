# 前端开发指南

> 工程：`api-test/testin-api-frontend`（Vue 3.2 + TS + Vite 3 + Element Plus + Pinia）。先读 [前端架构](../02-技术架构/前端架构.md)。

## 新增一个模块的标准流程

1. **API 层**：新建 `src/api/<feature>.ts`，直接 export 函数；**不要手动传 `sid` / `projectId` / `userId`**——`Http.ts` 拦截器自动注入（见 [前端HTTP层与响应约定](../03-实现逻辑/前端HTTP层与响应约定.md)）。
2. **页面**：新建 `src/views/<feature>/`，惯例是 `index.vue` + `components/` + `config.ts`（表格列/搜索项配置）。
3. **路由**：在路由表注册；需要权限控制就配 `meta.authKey`（key 来自 `src/directives/permission/const.ts`，一级路由 authKey 必须是数组）——不配等于不做权限拦截，见 [权限体系](../03-实现逻辑/权限体系.md)。
4. **元素级权限**：按钮/入口用 `v-auth="'api-xxx-xxx'"`（数组任一命中即显示）。
5. **锁**：涉及 rename/copy/delete/save 的 API 函数，先调 `checkLockedByApi(...)`，返回真则拒绝操作（见 [编辑锁机制](../03-实现逻辑/编辑锁机制.md)）。
6. **验证**：`pnpm build`（vue-tsc 会抓类型错误）+ dev 页面自测。

## 列表页标准写法

```vue
<!-- 组合：TreeList + TableSearch + el-table + ApiPagination -->
<el-table-column label="请求路径">
  <template #default="{ row }">{{ row.path }}</template>
</el-table-column>
```

**铁律：`el-table-column` 不要用 `prop` 取值**——element-plus 在低版本浏览器（构建目标 chrome71）有 bug，值不显示。一律 `<template #default="{ row }">`。

弹窗用 `CommonDialog`，执行入口用 `RunDialog`，搜索组件 `TableSearch` 传配置对象（已内置 enter 触发）。这些公共组件在 `src/utils/components/`，**自动注册，直接用，不用 import**。

## 约定清单

### 包管理与构建
- **必须用 pnpm**；依赖全部是精确版本（`save-prefix=''`），升级依赖是慎重操作。
- 不要改构建产物的时间戳目录命名（`YYYYMMDDHHmm/[name]-[hash].js`），那是 CDN 缓存隔离机制。
- `components.d.ts` / `auto-imports.d.ts` 是生成文件，不要手改。
- ace（vue3-ace-editor）、vue-json-viewer、handsontable 已锁定版本，不要升级。

### 兼容性（chrome71 硬约束）
- 新 ES 语法/Web API 先确认在 `vite.config.ts` 的 polyfills 列表或能被转译。
- 遇到"本地 chrome 正常、客户浏览器白屏"先怀疑这条。

### 代码组织
- 别名 `@` → `src`。
- Less 全局自动注入 `src/mixin.less`，组件样式里可直接用其中 mixin/变量。
- 全局业务类型（`Api`、`Mock`、`JsonSchema`、`JSONValue` 等）声明在 `src/global.d.ts` / `src/vite-env.d.ts`，新增领域类型也放这里。
- 改协议相关的请求编辑逻辑，入口是 `src/components/RequestParameters/`（HTTP/Dubbo/TCP/WebSocket 都在这里）与 `src/components/Response/`。

### HTTP 与数据
- 成功码是 **`code === 200`**；`505` / `508` 原样返回由调用方处理；其余已统一弹错并 throw。
- 报告页（`/report/1|2`、`/share/report/1|2`）在新页签打开，store 从 sessionStorage 恢复——改报告页数据结构时注意这条链路。

### 路由
- **hash history**（`createWebHashHistory`），生成链接/跳转时注意 `#/`。
- 全局守卫：无 `sid` 跳 `/unauthorized`；`to.query.skey` 存在时跳过（分享报告免登场景）。

## 调试技巧

| 场景 | 做法 |
|---|---|
| 连测试环境后端 | 默认代理已指向 `http://api-test.pro.testin.cn`，直接 `pnpm dev` |
| 连本地后端 | proxy target 改 `http://127.0.0.1:8526` + 开 `rewrite` 注释行 |
| 看请求注入 | devtools Network 里看 body/params 里的 `sid/projectId/userId` 与 `Sid` 请求头 |
| 权限不对 | 先查 `usePermission` store 里的权限串列表是否含该 authKey（`api-all` 为全权限） |
| 类型错误 | `pnpm build` 里的 vue-tsc 输出最准 |
