# 术语表

> 按拼音/字母排序。每条给"一句话定义 + 深入阅读"。

## B

**批次（Batch）** — 一次测试任务执行的全局单位；服务端 `TestTaskBatchPoller` 每 3s 轮询活跃批次做结果聚合，直到终态。见 [批次结果聚合](../03-实现逻辑/批次结果聚合.md)。

**被测系统（SUT）** — 接口/用例实际请求的 target 系统；执行机向其发起协议请求。

**编辑锁** — 资源级互斥锁：rename/copy/delete/save 前必须通过 `checkLockedByApi` 检查，防止并发覆盖。见 [编辑锁机制](../03-实现逻辑/编辑锁机制.md)。

## C

**补充执行 / 补测（Supplement）** — 任务执行后对失败/遗漏用例的追加执行，历史单独记录（`TestTaskSupplementHistoryService`）。见 [测试任务](../01-产品功能/测试任务.md)。

## D

**数据集（DataSet）** — 参数化数据源，用例按数据行循环驱动执行；前端用 handsontable 编辑。见 [数据集与数据枚举](../01-产品功能/数据集与数据枚举.md)。

**单接口调试** — 编辑页内"立即执行"，不走任务批次，结果即时返回；与批量任务共用执行链路但模式不同（`ApiRunMode`）。见 [任务执行链路](../03-实现逻辑/任务执行链路.md)。

## E

**authKey** — 权限标识串（如 `api-xxx-xxx`），前端路由 `meta.authKey`、元素 `v-auth`、后端 `KeyInterceptor` 三处使用同一套 key。`api-all` 表示全权限。见 [权限体系](../03-实现逻辑/权限体系.md)。

## F

**FIX 协议** — 金融行业信息交换协议，平台基于 QuickFIX/J 支持证券类接口测试。见 [FIX协议支持](../04-复杂功能细节/FIX协议支持.md)。

## H

**环境（Environment）** — 一组执行上下文配置（域名、请求头、数据库连接等）；用例与环境解耦，切环境即换执行目标。见 [环境与配置管理](../01-产品功能/环境与配置管理.md)。

**回收站** — 资源的软删除暂存区，可还原或彻底删除。见 [回收站](../01-产品功能/回收站.md)。

## J

**JMX** — JMeter 测试计划的 XML 描述文件；平台数据结构在服务端转成 JMX、经 Redis 传给执行机执行。见 [JMX生成与解析](../03-实现逻辑/JMX生成与解析.md)。

**machineId** — 执行机唯一标识，执行机启动后由服务端初始化下发；任务队列按 machineId 隔离（每台机器一个 Redis list）。见 [测试机管理](../01-产品功能/测试机管理.md) / [执行端Runner详解](../03-实现逻辑/执行端Runner详解.md)。

**module（模块树）** — 接口/用例等资产的树状分组，各资源类型一套模块树（`TestModuleType`）。

## R

**RunningParam（运行参数）** — 执行时注入的动态参数（环境级/全局级），key 定义见 `commons/constants/RunningParamKeys`。见 [环境与配置管理](../01-产品功能/环境与配置管理.md)。

**runner / 执行机** — 执行端进程（`RunnerApplication`），内嵌 JMeter 5.5，从 Redis 队列领任务执行。见 [执行端Runner详解](../03-实现逻辑/执行端Runner详解.md)。

## S

**skey** — 分享报告的免登访问凭证；URL 带 `skey` 时前端路由守卫跳过 sid 校验。见 [测试报告与分享](../01-产品功能/测试报告与分享.md) / [登录态与主平台集成](../03-实现逻辑/登录态与主平台集成.md)。

**sid** — 主平台会话凭证，本平台登录态的唯一来源（iframe query / postMessage 传入）。见 [登录态与主平台集成](../03-实现逻辑/登录态与主平台集成.md)。

## T

**T2 协议** — 恒生电子的金融中间件协议，平台通过本地 SDK（`extension/t2/`）接入。见 [T2协议支持](../04-复杂功能细节/T2协议支持.md)。

**TestModule / NodeTree** — 模块树的节点结构服务（`NodeTreeService`），各资产类型复用。

## X

**xxl-job** — 分布式任务调度框架；本平台**内嵌其 admin 管理台**于服务端（`/job` 路径），执行器名 `testin-task-job-executor`。见 [定时调度体系](../03-实现逻辑/定时调度体系.md)。

## Y

**用例（TestCase）** — 步骤的有序编排；步骤可引用接口/脚本，支持前后置、断言、变量、控制器。见 [用例管理](../01-产品功能/用例管理.md)。

**运行模式（ApiRunMode）** — 执行模式枚举（单接口调试 / 任务批量等），见 `commons/constants/ApiRunMode.java`。

## Z

**执行器（xxl-job executor）** — 内嵌在服务端的 xxl-job 执行端，接收调度中心触发的 jobhandler 调用。见 [定时调度体系](../03-实现逻辑/定时调度体系.md)。

**主平台** — 私有云门户系统；本平台以 iframe 嵌入其中，账号/项目/权限均来自主平台。见 [登录态与主平台集成](../03-实现逻辑/登录态与主平台集成.md)。
