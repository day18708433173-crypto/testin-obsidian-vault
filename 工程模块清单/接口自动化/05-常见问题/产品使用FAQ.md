# 产品使用FAQ

> 使用平台过程中的高频疑问（非故障类）。故障排查见 [任务执行问题排查](任务执行问题排查.md)、[前端联调FAQ](前端联调FAQ.md)、[构建与部署FAQ](构建与部署FAQ.md)。

## Q1：用例编排添加脚本时，"直接关联"和"另存副本"有什么区别？

**一句话：直接关联是"共享引用"，改脚本处处生效；另存副本是"私有拷贝"，改副本只影响本用例。**

### 对比表

| 维度 | 直接关联 | 另存副本（脚本副本） |
|---|---|---|
| 步骤引用的是什么 | 脚本**本体**（脚本管理里那份） | 拷进用例的**私有拷贝** |
| 步骤表"脚本类型"列显示 | 直接关联 | 脚本副本 |
| 修改步骤的请求内容 | 改的是脚本本体，**所有引用它的用例同步生效** | 只改本用例的拷贝，源脚本和其他用例**不受影响** |
| 源脚本在脚本管理里被修改 | 本步骤跟着变 | 副本**不会**自动跟随源脚本更新 |
| 源脚本能否被删除 | **被用例直接关联时禁止删除**（须先解除关联） | 可以删（副本是独立数据，不受影响） |
| 断言的存储 | 用脚本本体的断言 | 生成副本时**深拷贝**一份断言，之后各自独立 |
| 适用场景 | 登录、鉴权、公共前置等"一处修复、处处生效"的共享脚本 | 需要为用例定制参数/断言、不希望被别处改动影响的场景 |

### 典型场景怎么选

- **登录脚本被 50 个用例引用** → 用**直接关联**：登录逻辑变了改一处，50 个用例全部生效。若用副本，就得改 50 份。
- **同一个下单接口，10 个用例各测不同参数组合** → 用**另存副本**：每个用例改自己的参数/断言，互不干扰。
- **担心别人改脚本影响我的用例** → 用副本做"版本冻结"。

### 常见误解与注意

1. **"改副本会不会同步回源脚本？"** —— 不会。副本一旦生成就与源脚本脱钩（只保留一个"原脚本 ID"的溯源关系）。
2. **"副本的出参/断言改动能同步到其他用例"** —— 这是平台提供的**手动一键同步**能力：同一源脚本的多个副本之间，可以把出参/断言的改动同步过去（在步骤的请求详情抽屉里操作）。同步范围只是出参/断言，不是整个请求体。
3. **"直接关联的脚本删不掉？"** —— 是保护机制：被用例直接关联的脚本禁止删除，需要先解除用例关联或改用副本。删脚本前系统会检查（见 [脚本管理](脚本管理.md)）。
4. **步骤级数据集覆盖对两者都生效**：不管关联还是副本，步骤都可以单独绑定/覆盖数据集（见 [用例管理](../01-产品功能/用例管理.md) 与 [数据集与数据枚举](../01-产品功能/数据集与数据枚举.md)）。
5. **混用没冲突**：一个用例里可以既有直接关联步骤、又有副本步骤，按步骤粒度各自独立。
