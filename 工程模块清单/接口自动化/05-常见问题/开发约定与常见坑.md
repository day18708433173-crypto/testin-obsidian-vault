# 开发约定与常见坑

> 本页收录"不知道就会踩"的约定，按主题分组。各条目的细节请点链接进专题文档。

## 跨系统边界（最容易搞混）

| 约定 | 本平台 api-test | 另一套系统 testin-core / testin-frontend |
|---|---|---|
| 接口前缀 | `/api/v1`（网关剥离） | `/openapi/v3`（sid/apikey 签名） |
| 成功码 | `code === 200` | `code === 0` |
| 前端 UI | Element Plus | Arco Design |
| 强制登出码 | `505` / `508` 原样返回 | `10014` / `1000505` |

**不要把那边的约定带到这边**（父目录 CLAUDE.md 描述的是另一套独立系统）。

## 后端约定

1. **fastjson 安全模式**：`Application.main` 第一行 `ParserConfig.getGlobalInstance().setSafeMode(true)`，不要绕过 autoType 限制；新代码 JSON 一律用 fastjson（org.json、gson 是存量）。
2. **mapper XML 位置**：与接口同目录（`src/main/java/cn/testin/mapper/`），不在 `resources/` 下——新建 `resources/mapper/` 不会被打包。
3. **产物在 `deploy/`** 不在 `target/`；资源在 jar 外，必须 `java -cp resources:lib/*:...` 启动。
4. **lib 按文件名字典序加载**：与 JMeter 冲突的包靠命名靠前优先，新依赖注意类加载顺序。
5. **AuthInterceptor 是假实现**：`@UserAuth` 注解的方法会被塞一个写死的 User 1010——**别在生产逻辑上依赖它**；真正的权限是 `KeyInterceptor`。见 [后端请求处理管线](../03-实现逻辑/后端请求处理管线.md)。
6. **控制器无统一前缀**：`@RequestMapping("/case")` 直接生效，`/api/v1` 只存在于网关层。
7. **定时任务选型**：复杂/需手动触发的挂 xxl-job handler，简单轮询用 `@Scheduled`（见 [定时调度体系](../03-实现逻辑/定时调度体系.md)）。
8. **surefire 默认 skip**：跑测试要 `mvn test -DskipTests=false -Dtest=ClassName`。
9. **Swagger 生产禁用**：别依赖线上 swagger 调试。

## 前端约定

1. **必须 pnpm**；依赖精确版本锁定，升级 ace / handsontable / vue-json-viewer 等锁定组件是禁区。
2. **`el-table-column` 不用 `prop`**：低版本浏览器 bug，一律 `<template #default="{ row }">`。
3. **chrome71 硬约束**：新语法先查 polyfills；构建目标改了会打破客户环境。
4. **不要手改生成文件**：`components.d.ts`、`auto-imports.d.ts`。
5. **不要改构建产物时间戳目录**：那是 CDN 缓存隔离机制。
6. **公共组件不用 import**：`src/utils/components/` 自动注册；Element Plus 也按需自动引入。
7. **HTTP 三字段不要手动传**：`sid` / `projectId` / `userId` 拦截器自动注入。
8. **hash history**：站内链接记得 `#/`。
9. **报告页走新页签 + sessionStorage 恢复**：改报告链路时别忘了写 sessionStorage。
10. **README 目录树已过时**：以 `src/views/` 实际结构为准。

## 跨端协同红线

1. **改传输协议两端同发**：`JmeterRunRequestDTO`、`RedisKeyUtil` 等改动，服务端 + runner 两个产物必须同时重新构建部署（见 [后端双形态架构](../02-技术架构/后端双形态架构.md)）。
2. **权限 key 两端一致**：前端 `const.ts` 的 authKey ↔ 后端 `KeyInterceptor` 的 configKey，命名保持同步（见 [权限体系](../03-实现逻辑/权限体系.md)）。
3. **新资源类型两端一起加锁**：编辑锁的资源类型枚举前后端各有一份（见 [编辑锁机制](../03-实现逻辑/编辑锁机制.md)）。
4. **报告数据结构三方联动**：执行端产出 → Redis 传输 → 服务端聚合 → 前端渲染，改一处查全链。

## 源码走读发现的深层约定

以下是编写本知识库时逐行读代码确认的隐性设计，改相关模块前必读：

1. **接口模块树存在两套实现**：`test_module` 表 vs 遗留的 `test_interface_module` 表（`/interface/module/*`）。改树逻辑前先确认调用方走哪套，见 [接口管理实现](../03-实现逻辑/接口管理实现.md)。
2. **用例步骤的 `scriptId` 是多态外键**：步骤 type=1 指向 `test_script_copy`、type=2 指向 `test_script`、控制器步骤 type 为 null——联表查询必须先判 type，见 [用例管理实现](../03-实现逻辑/用例管理实现.md)。
3. **导入功能共用一把 JVM 级静态锁 `TestImportLock`**：任何新增导入路径漏调 `closeLock()` 会把导入功能永久挂死（直到重启），见 [接口管理实现](../03-实现逻辑/接口管理实现.md)。
4. **复制脚本/生成脚本副本时断言必须深拷贝**：断言存在独立的 `test_script_assertion` 表，漏拷会让两条数据共享一份断言、互相污染，见 [脚本管理实现](../03-实现逻辑/脚本管理实现.md)。
5. **用例历史报告"有记录但打不开"是自愈设计**：报告被清理后，查询逻辑会把 `test_case_rel_report.reportId` 置空并异步回写——不是 bug，见 [用例管理实现](../03-实现逻辑/用例管理实现.md)。
6. **`requestParam` / `request` 是裸 JSON 无 schema**：前端 `getScriptByApi` / `getInterfaceByApi` 里硬编码了七个协议参数块的默认值兜底老数据；新增协议字段必须前端兜底、后端实体、存量数据三处同步考虑。
7. **`AssembleElementsThreadPool` 名不副实**：用例组装实际在 HTTP 请求线程里同步执行（类内线程池未使用），大任务组装会占住请求线程——不要误以为它是异步的。
8. **执行结果回传序列化是 Jackson，任务下发是 fastjson**：`TestinResultBackendListener.convertToXML` 名字带 XML 但产出的其实是 Jackson JSON；两套序列化对字段命名/空值的处理不同，改 DTO 时两端都要验证。

## 安全与权限类隐患（源码确认）

1. **存在两个硬编码超级 sid**：`TestUserFunctionService.java` 写死两个 sid 直接给 `api-all`——调试遗留，生产注意别泄露（见 [权限体系](../03-实现逻辑/权限体系.md)）。
2. **`POST /recycleBin/scheduleDelete` 无 `@ApiConfigKey`**：裸露的管理端点，网关层应限制访问（见 [回收站实现](../03-实现逻辑/回收站实现.md)）。
3. **开放接口不校验功能权限**：任何有效 sid 都能调 `/open/**` 全部端点；接入第三方要用专用账号并控制其可见项目（见 [开放平台OpenApi实现](../03-实现逻辑/开放平台OpenApi实现.md)）。
4. **T2 license 明文落盘**：测试/正式连接都会把 license 写到 `uploadFiles/t2Config/`（SDK 只支持文件路径），注意目录权限与清理（见 [T2协议支持](../04-复杂功能细节/T2协议支持.md)）。
5. **OpenAPI 两套成功码并存**：`/open/**` 多数端点成功码是 0，唯独 `/open/api` 是成功码 200——给第三方的对接文档必须写清。

## 第三方对接注意

1. **`saveTaskCase` 是先清空再全量插入**任务用例关系（`OpenApiService.java`）：第三方增量传参会覆盖界面上的修改；任务不存在时按 名称+项目+目录 反查，**静默返回不报错**。
2. **回收站只能操作本人删除的数据**：管理员也无法替别人还原；用户离职后其删除数据只能等 30 天自动清理（见 [回收站](../01-产品功能/回收站.md)）。
3. **GraphQL 配置字段名前后端大小写不一致**（`graphQLServerConfigList` vs `graphqlServerConfigList`）：只改一端会导致配置丢失（见 [环境与配置管理实现](../03-实现逻辑/环境与配置管理实现.md)）。
