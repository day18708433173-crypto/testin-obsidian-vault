# 上位机长连接

> 本文是 [04-核心链路-上位机长连接](../04-复杂功能细节/核心链路-上位机长连接.md) 的自然语言版（不含代码细节）。

## 功能是什么

- 每一台上位机（机房里的 ucom 主机、树莓派、PC 客户端）都通过一条**常驻的网络长连接**与设备控制中心保持通信。这条连接是设备域一切能力的地基：设备上线、心跳保活、任务下发、管控指令、执行结果回传，全部走这一条通道。
- 连接上的通信分为两个方向：
  - **上位机主动发起**：认证登录、周期心跳（顺带汇报所挂设备的状态、领取待执行任务）。
  - **服务端主动下发**：任务执行、停止，以及设备管控指令（占用、释放、重启、截图等），上位机执行完毕后沿同一连接回执结果。

## 连接的生命周期

### 1. 建立连接与认证

- 上位机接入后必须先完成**账号认证**（账号 + 密码），认证通过后才被视为"在线"，后续请求才会被正常处理。
- **同一账号只允许一条连接在线**：如果同账号的上位机在别处再次登录，旧连接会被踢下线——这保证了"一个上位机身份对应一个在线实例"，避免指令发错对象。

### 2. 心跳保活（稳态）

- 认证通过后，上位机按固定周期（约 30 秒一次）发送心跳，心跳里携带其所挂载的手机、浏览器、PC 客户端等资源的最新状态。
- 心跳有两个作用：
  1. **保活与状态同步**：服务端据此刷新设备的在线状态与忙闲情况；
  2. **任务领取通道**：服务端在处理心跳时，会顺手为空闲设备做任务匹配，把匹配到的任务**随心跳响应一并带回**。也就是说，平台不做"服务端主动推送任务"，而是"上位机每次来报到时顺便领走任务"——这大幅降低了服务端推送的复杂度。
- 心跳响应里除了任务，还会带回上位机需要的配置信息（如 OEM 定制配置）。

### 3. 指令下发与回执

- 服务端可以沿连接主动下发指令，典型的有：任务执行、任务停止、设备占用、设备释放、重启、截图等。
- 每条指令从发出到收到回执都有完整的**状态跟踪**（已发出 → 等待回执 → 已完成），任何一条指令都能查清它最终有没有被上位机执行。
- 如果下发时上位机已经掉线，指令会**立即失败并标记"上位机离线"**，不会无限期挂起。

### 4. 断连

以下任一情况都会让连接被判定为断开：

- 上位机主动断开或网络中断；
- 连接上**超过约 60 秒没有任何读写**，被判定为闲置并回收；
- 同账号在别处登录，旧连接被踢出；
- 上位机发来的单条消息**超过约 15MB 的大小上限**，连接会被直接断开（防止异常大报文拖垮服务）。

断连后，该上位机身份被标记为离线，后续的影响（任务如何处理、设备池如何清理）见 [设备异常恢复](设备异常恢复.md)。

## 用户与上游服务需要知道的约束

| 约束 | 含义 |
|---|---|
| 先认证后通信 | 未认证的连接只能做认证这一件事 |
| 一号一连接 | 重复登录会踢掉旧连接，适合上位机重连场景，但不支持同账号多实例并存 |
| 60 秒无通信即断开 | 上位机必须保持周期心跳，心跳停了连接就保不住 |
| 单条消息最大约 15MB | 超限直接断连，大文件（如结果文件）不走这条连接，而是上传后传 URL |
| 心跳即任务通道 | 上位机不心跳就领不到任务——设备"在线但一直没任务"时，先确认心跳是否正常 |
