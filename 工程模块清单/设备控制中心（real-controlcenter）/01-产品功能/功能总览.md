# 功能总览

> 本页是功能维度的总索引：每个域一句话定位 + 核心能力清单 + 深入阅读链接。接口级清单见 [开放接口模块索引](../07-开放接口文档/00-模块索引.md)（16 个 Spring MVC Controller + 30 个 ApiServlet service + 23 个 MINA TCP handler）。

## 设备管理

设备的登记、状态维护、管控操作与统计分析，覆盖 App 真机 / Web 浏览器 / PC 客户端三类资源。

- **设备台账**：device_info 主档 + device_detail/device_info_extend 扩展 + view_device_info 视图；设备分组 device_group；资产 device_assets_info。
- **状态维护**：心跳刷新 `refresh`（`real-controlcenter/src/main/java/cn/testin/trans/controller/req/script/HeartBeat.java`）、离线检测（refreshtime 超过 DEVICE_TIMEOUT 置 unknown）、状态统计 device_total / device_online_count / view_device_status_total。
- **管控操作**：截图、关机、重启、释放、屏幕模式批量设置等（`/ControlCenter/device` 系列，见 [DeviceController](../07-开放接口文档/设备管理/DeviceController.md)）。
- **配套能力**：iOS 证书 certificate_info/device_certificate、设备签名 device_sign、项目独占 device_project_exclusive、设备公告 device_notice、机柜 cabinet_space_cfg、树莓派 Raspi 管理、串口配置。
- **异常恢复**：设备掉线的三层判定、受影响任务的统一取消（"设备过期"原因码）与设备回归后的自动救活，见 [设备异常恢复](设备异常恢复.md)（自然语言版）。

## 任务下发

把任务指令经长连接送到上位机执行，是本服务最核心的职责。

- **主动下发**：`Task.distributeTask`（`real-controlcenter/src/main/java/cn/testin/service/control/Task.java`）校验设备锁归属与在线状态 → 组装 `Task.execute.v2` 报文 → 落协议表 → 分发线程送上 TCP → **同步等待**上位机响应。
- **心跳捎带下发**：上位机心跳时空闲设备被推进 match 队列，由 DeviceDispatchThread 向任务调度服务请求匹配，匹配到的任务随心跳响应带回（`tasks` 字段），见 [核心链路-设备匹配与下发](../04-复杂功能细节/核心链路-设备匹配与下发.md)。
- **停止/控制**：`Task.stop` / `TaskGroup.stop` / TaskControl 等长连接命令字。
- 代码级链路见 [任务下发与结果回传实现](../03-实现逻辑/任务下发与结果回传实现.md)。
- 自然语言版：[上位机长连接](上位机长连接.md)（认证、一号一连接、心跳即任务通道、60 秒闲置断开、15MB 报文上限）、[设备匹配与下发](设备匹配与下发.md)（三类资源的匹配规则、空闲/防重/并发保护）。

## 结果回传

上位机执行完任务后的两级回报（`/UcomDeivce/task`）：

- **precomplete（预完成）**：脚本执行结束即上报，携带运行信息、输入/输出参数；本服务转发任务侧后清理设备池中的子子任务（sstask）标记（`real-controlcenter/src/main/java/cn/testin/business/impl/TaskInfoServiceImpl.java`）。
- **reportResult（结果回报）**：结果文件就绪后上报 resultUrl，转发任务侧落库（`TaskInfoServiceImpl.java`）。
- 分流规则：taskid 以 `tt/wt/pt` 开头 → 任务调度服务 `TaskApi`（doPress RealScheduling）；否则 → 任务管理服务 `TaskV3Api`（REST v3 remotePost，prefix=RealTask）。
- 另有过程回报、视频回报、日志上报（`/UcomDeivce/log`）、抓包任务（Task-pcap）。

## 预约

设备预约（device_appointment / device_appointment_config）：用户预约某台设备某时段的使用权。

- `AppointmentConfigInitThread` 每 10 分钟加载预约配置，`AppointmentWorkerThread` 每 5 分钟处理预约逻辑（`real-controlcenter/src/main/java/cn/testin/config/StartRunner.java`）。
- 心跳线程维护设备当前预约者（`maintainApplicant`）并逐条处理预约（`real-controlcenter/src/main/java/cn/testin/schedule/device/DeviceWorkerThread.java`）。
- PC 客户端还有"当前时间段是否可用"校验 `currentTimeSlotValidForDevice`（`Task.java`）。

## 客户端升级

- **升级日志**：device_upgrade_log 记录 ROM/客户端升级过程；心跳中根据池内 `romUpdateStatus`（0 未升级/1 下载中/…/5 完成/101-103 失败）回写升级结果（`HeartBeat.java`）。
- **源码配置**：SourcecodeConfig（ApiServlet + `/UcomDeivce/sourcecodeConfig`）向客户端下发源码加载配置。
- **命令下发**：Command（action=control）通用命令通道。

## 定时任务

全部后台线程在 `StartRunner.run`（`real-controlcenter/src/main/java/cn/testin/config/StartRunner.java`）中启动，明细见 [定时任务总览](../07-开放接口文档/定时任务/00-定时任务总览.md)。关键的几个：

| 线程 | 周期 | 职责 |
|---|---|---|
| ServiceInitThread | 1h | 重新加载系统配置 |
| ProtocolWorkerThread | 30s | 清理过期协议（下发后未响应的指令） |
| DeviceDispatchThread ×2 | 长驻 | match/extract 两个设备匹配队列的消费 |
| ProtocolDispatchThread ×2 | 长驻 | activity/passivity 两类协议的分发 |
| DisconnectAppThread | 5s | 远程调试 App（adb 远程访问）心跳检测与断连清理 |
| DeviceDataThread 等 | 长驻 | 过期设备/PC/客户端数据清理（refreshtime 超 DEVICE_TIMEOUT） |
| AppointmentWorkerThread | 5min | 预约处理 |
| DeviceCountThread | 1h | 设备趋势统计落 device_online_count |

## 数据模型要点

四个业务库（`dynamic-datasource`，主库为 db_device_monitor，`real-controlcenter/src/main/resources/application.yml`），详见 [存储总览](../02-技术架构/00-存储总览.md)：

| 库 | 规模 | 要点 |
|---|---|---|
| db_device | 40+ 表 | 设备域核心：device_info 主档、**device_lock_pool 设备锁**、device_process 占用、device_appointment 预约、分组/资产/证书/统计 |
| db_pc | 5 表 | Web 浏览器侧：pc_info 主档（以 ucomid 为键）、browser_process 浏览器占用、pc_browser_info 浏览器清单 |
| db_client | 6 表 | PC 客户端侧：client_info 主档、client_process 占用、pc_device_action_log |
| db_device_monitor | 3 表 | 监控告警：device_monitor_info、alarm_log、parameter_config_code |

需要特别记住的三点：

1. **device_lock_pool 是跨服务共享的互斥原语**：任务管理服务经 `/ControlCenter/device/lock_device_by_taskid` 加锁、`unlock_device_by_taskid` 解锁；残留锁会让后续 `distributeTask` 永远报"this device is locking by task!"，是运维高危点，见 [设备锁与心跳实现](../03-实现逻辑/设备锁与心跳实现.md)。
2. **内存池是读路径主力**：DevicePoolUtil / PcInfoPoolUtil / ClientInfoPoolUtil 三个 CachePool 缓存设备运行态（含 DeviceTaskInfo 任务标记），DB 是持久层，二者由心跳线程和 Data/Worker 线程双向同步。
3. **状态字段语义跨库复用**：`DeviceConfig.DeviceStatus`（free/runScript/unknown…）同时用于 device_info、pc_info、client_info 三表（`real-controlcenter/src/main/java/cn/testin/pojo/device/DeviceConfig.java`）。
