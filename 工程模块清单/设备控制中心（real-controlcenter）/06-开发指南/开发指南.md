# 开发指南

> 工程：real 仓 `real-controlcenter/` 子模块（Spring Boot 1.5.20 parent，模块版本 6.0.0，Java 8，约 780 个 Java 文件）。分支基准：`syy.release.z7.8.1.0`。先读 [产品概述](../01-产品功能/产品概述.md) 建立业务认识。

```
real-controlcenter/
```

## 三入口模型

本服务有**三个并存的请求入口**，改代码前先确认改的是哪个入口：

| 入口 | 端口/路径 | 分发方式 | 典型消费者 |
|---|---|---|---|
| ApiServlet（V1 老协议） | 8080 `/*` | `{action, op}` 反射到 `service/<action>/` 下的类方法 | 任务管理服务、任务调度服务等内部服务 |
| Spring MVC（V3） | 8080 `/v3/*`（`Boot.java` 把 DispatcherServlet 映射到 /v3） | `@RequestMapping` | 上位机回报（/UcomDeivce）、管控台（/ControlCenter）、其他服务 v3 调用 |
| MINA TCP | 8000（`devicecenter.port`） | 4 字节头+JSON 体，按 `{mkey, op}` 反射到 `trans/controller/req/` | 上位机长连接 |

两个 Servlet 的注册都在 `Boot.java`：ApiServlet 接 `/*`，DispatcherServlet 接 `/v3/*`。注意 URL 里 `/UcomDeivce` 的拼写是历史遗留，**不要"修正"它**，上位机固件按这个拼写写死。

## 启动过程

1. `Boot.main`（`real-controlcenter/src/main/java/cn/testin/startup/Boot.java`）：先 `DbConfigUtil.loadConfig()` 加载 DB 配置，再校验 `Config.MODULE_NODE_ID`（读自 config.properties 的 `module.node.id`）——两者任一失败**直接退出，不起 Spring**；
2. Spring 容器起来后 `StartRunner.run`（`real-controlcenter/src/main/java/cn/testin/config/StartRunner.java`）依次拉起：Redis MQ 订阅、配置加载线程、协议清理/分发线程、设备匹配队列线程、**MINA TCP 服务**、断连检测、预约、统计等约 15 个后台线程（明细见 [定时任务总览](../07-开放接口文档/定时任务/00-定时任务总览.md)）。

## 分层约定

- **controller 层**：V3 入口在 `mvc/controller/`，返回 `ResponseResult`；V1 入口在 `service/<action>/`，继承 `GenericBaseService`，返回 JSON 字符串。
- **business 层**：`business/interfaces` + `business/impl`，领域逻辑（TaskInfoService、DeviceProcessService 等）。
- **dao 层**：MyBatis-Plus，`@MapperScan("cn.testin.dao")`；XML 在 `resources/mapper/<库名>/` 下（与接口自动化模块的"XML 与接口同目录"约定不同）。
- **跨服务调用**：`api/` 包封装对其他服务的 HTTP 调用（TaskApi→任务调度服务、TaskV3Api→任务管理服务、UserApi→平台基础功能服务等）。
- **内存池**：`util/cachepool/` 三个 CachePool 是设备运行态的读路径主力，改设备状态相关逻辑时先想清楚改池还是改库。
- **历史风格**：大量代码不走 Spring 注入，用 `SpringHelper.getBean("BeanName")` 按名取（如 `Task.java`）；新代码建议走注入，但不要顺手"重构"老代码。

## 本地构建运行

```bash
# 在 real 仓根
mvn -pl real-controlcenter -am clean package -DskipTests
```

- 产物：`real-controlcenter/target/real-controlcenter/`，依赖由 maven-dependency-plugin 拷到 `lib/` 子目录（pom.xml），启动脚本见 `resources/bin/`。
- 运行前置：本机/网络可达 MySQL 与 Redis；`config.properties` 里 `module.node.id` 必须是平台分配的合法节点号（默认 1020001），`devicecenter.port=8000` 不能被占用。
- 测试：junit 已依赖，surefire 默认 skip，`-DskipTests=false -Dtest=ClassName` 单跑。

## 配置要点

| 配置 | 位置 | 说明 |
|---|---|---|
| `module.node.id` | config.properties | 模块节点号，协议表按它隔离多实例；缺失则拒绝启动（Boot.java） |
| `devicecenter.port` | config.properties | MINA 监听端口，默认 8000（Config.java） |
| `device.timeout` | config.properties | 设备心跳超时，默认 120000ms（Config.java） |
| `device.connectUrl` / `device.delDeviceUrl` | config.properties | 上位机连接/移除的回调地址 |
| 数据源 | application.yml `spring.datasource.dynamic` | 5 个库：db_device_monitor（**primary**）/db_device/db_client/db_pc/db_realcfg，Druid 连接池，密码 baomidou ENC 加密，地址走 `${TESTINPRO_MYSQL_HOST:...}` 环境变量注入 |
| Redis | application.yml `spring.redis` | jedis 池，既做缓存也做 Redis MQ（订阅在 StartRunner 开头） |
| Undertow | application.yml `server.undertow` | 8080；io-threads 16 / worker-threads 256——distributeTask 是同步等响应的**阻塞调用**，worker 线程数就是并发下发上限 |

## 跨端修改红线

| 修改对象 | 影响方 | 要求 |
|---|---|---|
| 长连接报文结构（mkey/op/data 字段、codec 4 字节头） | 上位机固件 | 上位机发版节奏远慢于服务端，必须向后兼容 |
| `Task.distributeTask` 入参/出参 | 任务管理服务 DeviceServiceApi | 两端同改同发 |
| precomplete/reportResult 转发 DTO（TaskPreCompleteRequestDTO 等） | 任务调度服务 / 任务管理服务 | 三端字段对齐 |
| device_lock_pool 表结构 | 任务管理服务（加解锁调用方） | 先评估残留锁清理脚本 |
| `sysnProtocolPro` 轮询语义 | 所有经 ApiServlet 下发的指令 | 加超时必须同步评估 ProtocolWorkerThread 的清理周期 |
