# 任务状态机

> 本文是 [04-任务状态机](../04-复杂功能细节/横切-任务状态机.md) 的自然语言版（不含代码细节）。

## 功能是什么

测试计划执行记录中的每个任务节点，从创建到结束都沿着一套固定的状态流转。理解这套状态，就能看懂执行记录页上每个任务"现在到哪一步了、接下来会发生什么、还能做什么操作"。

## 用户可见的状态

| 状态 | 含义 |
|---|---|
| 等待执行 | 任务已生成，还没开始跑 |
| 执行中 | 任务已下发到执行服务，正在执行 |
| 已完成 | 任务全部脚本/用例执行完毕 |
| 取消中 | 已发起停止/取消，正在等执行服务确认 |
| 已取消 | 取消完成，任务终止 |

> 平台内部还存在两个过渡性子状态——"预提测完成待执行"与"取消已下发待确认"。**界面上不单独展示它们**，分别归入"等待执行"和"取消中"显示，因此用户看到的状态集合就是上表五种。

## 状态如何流转

```
创建任务
   │
   ▼
等待执行 ──预提测成功──▶ (内部过渡) ──下发到执行服务──▶ 执行中 ──全部跑完──▶ 已完成
   │                                                    │
   │                              用户停止 / 终止执行记录 │ 用户停止
   ▼                                                    ▼
   └──────────────────▶ 取消中 ──执行服务确认取消──▶ 已取消
```

- **等待执行 → 执行中**：后台先把任务预先提交（预提测）到执行服务，再到点正式下发；执行服务开始回传进度后，任务进入"执行中"。预提测失败不会卡住任务——失败原因被记录，后台自动重试（见[后台自动机制](后台自动机制.md)）。
- **执行中 → 已完成**：任务下所有脚本/用例都回传了结果，任务标记完成，并逐级向上汇总；整份执行记录的全部任务完成时，执行记录也闭环（触发邮件等，见[回调与通知](回调与通知.md)）。
- **任意未终态 → 取消中**：用户停止单个任务，或终止整份执行记录时，所有未完成任务一起进入"取消中"，平台向执行服务下发取消指令。
- **取消中 → 已取消**：执行服务确认取消后落定。若执行服务迟迟没有确认，后台兜底机制会在超时后直接把任务判定为已取消，不会无限挂在"取消中"。
- **已完成/已取消 → 等待执行**：仅发生在[重测](测试计划.md#重测)场景——发起重测会把原已完成节点回退为等待执行，开始新一轮。

## 状态分组视角

平台内部按状态分组来做判断，对应到用户可感知的规则：

| 分组 | 包含状态 | 影响 |
|---|---|---|
| 未完成 | 等待执行、执行中、取消中 | 有这些状态的任务时，执行记录视为"还没跑完"，会被后台持续调度 |
| 可被停止 | 等待执行、执行中 | 只有这些状态的任务能点"停止" |
| 终态 | 已完成、已取消 | 到达后状态不再自发变化（除非重测）；**终态任务才可以重测**，取消中/执行中禁止重测 |

## 并发与一致性保证

- 状态推进遵循"只有当前状态符合预期才允许变更"的原则：两个操作同时改一个任务时，只有一个生效，不会出现状态错乱（例如停止与完成回传同时到达时，任务只会落定到一个确定终态）。
- 取消、完成等关键推进都有后台兜底检查，即使执行服务的回传丢失，任务状态最终也会收敛到正确的终态（兜底节奏见[后台自动机制](后台自动机制.md)）。
