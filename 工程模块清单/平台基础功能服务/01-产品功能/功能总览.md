# 功能总览

> 本页是功能维度的总索引：每个模块一句话定位 + 数据模型要点 + 操作约束。接口级明细见 [开放接口文档索引](../07-开放接口文档/00-模块索引.md)，代码级链路见 03-实现逻辑 各篇。

## 用户与认证（db_user / db_admin）

> 界面入口：[登录页](用户登录.md) + [管理中心](企业管理.md) `/platform/admin/overview`（企业/成员/角色/权限）。

用户、企业、项目、角色、登录态的全量管理，是全平台基础数据的唯一来源。

- **数据模型要点**：`DbUserInfo`（用户）、`DbEnterpriseInfo`/`DbEnterpriseUserRelation`（企业与成员）、`DbProjectInfo`/`DbUserProjectRoleInfo`（项目与用户-项目-角色三元组）、`DbRoleInfo`/`DbUserRoleInfo`（角色）、`DbSSOConfig`（SSO 配置）、`DbUserOnline`（在线状态）、`DBUserLoginLog`（登录日志）。
- **认证方式**：密码 / LDAP / SSO 三种（LDAP 连接配置在 `src/main/resources/config.properties` 的 `ldap.*`）。
- **操作约束**：权限按"用户-项目-角色"判定，切项目即切数据视图；登录链路见 [核心链路-用户登录](../04-复杂功能细节/核心链路-用户登录.md)，功能规则的自然语言版见 [用户登录](用户登录.md)（邮箱/手机号登录、密码/LDAP/SSO 三种认证、锁定拦截与 LDAP 自动建档）。
- **接口文档**：[UserController](../07-开放接口文档/用户与认证/UserController.md)、[ProjectController](../07-开放接口文档/用户与认证/ProjectController.md)、[EnterpriseController](../07-开放接口文档/用户与认证/EnterpriseController.md)、[service-Login](../07-开放接口文档/用户与认证/service-Login.md)、[service-Role](../07-开放接口文档/用户与认证/service-Role.md)、[service-SystemCfg](../07-开放接口文档/用户与认证/service-SystemCfg.md)。

## 用例管理（db_case）

> 界面入口：[测试用例页](测试用例.md) `/platform/case`。

测试用例资产的 CRUD 与组织：目录树、步骤、标签、评论、版本、统计，并跟踪用例与 real 侧脚本的同步状态。

- **数据模型要点**：`CaseInfo`（用例主表）、`CaseStep`（步骤）、`CaseDir`（目录树）、`CaseTag`（标签）、`CaseComment`（评论）、`CaseRevision`（版本）、`CaseActionLog`（操作日志）、`CaseScriptNoSync`（脚本不同步追踪）、`CaseStatistic`（统计）。
- **操作约束**：用例挂到计划时要求关联任务模板状态有效——执行计划前 `checkCaseStatus` 会校验，存在无效模板直接拒绝执行（`src/main/java/cn/testin/business/impl/plan/PlanInfoServiceImpl.java`）；脚本同步状态由 `ComputeCaseScriptNoSyncStatusThread`（2 分钟轮询）维护。
- **接口文档**：[CaseInfoController](../07-开放接口文档/测试用例/CaseInfoController.md)、[CaseStepController](../07-开放接口文档/测试用例/CaseStepController.md)、[CaseDirController](../07-开放接口文档/测试用例/CaseDirController.md)、[CaseCommentController](../07-开放接口文档/测试用例/CaseCommentController.md)、[CaseStatisticController](../07-开放接口文档/测试用例/CaseStatisticController.md)。

## 测试计划（db_plan）—— 本服务核心

> 界面入口：[测试计划页](测试计划.md) `/platform/test-plan/plan-list`。

把任务模板按子计划组织成可执行计划：编排、触发、提测、跟踪、汇总、通知全生命周期。

- **数据模型要点**：
  - 模板侧：`DbPlanInfo`（计划，含 `type`=planInfoType、`planDeviceStatus` 是否启用计划级设备）→ `DbSubPlanInfo`（子计划，树状 root）→ `DbPlanTask`（关联任务模板）+ `DbPlanTaskCase/Script/Device`（明细）+ `DbPlanTaskStrategy`（策略）+ `DbPlanInfoConfig`（配置）+ `DBPlanDevice`（计划级设备）+ `DbPlanInfoExecutePeriod`（执行周期）+ `DbPlanInfoScheduled`（定时配置）。
  - 执行侧（执行时深拷贝快照）：`DbExecuteRecord` → `DbExecuteRecordTask`（记录树节点）→ `DbExecuteRecordTaskCase/Script/Device/Config`。
- **操作约束**：
  - 同一计划存在执行中的记录时禁止再次执行（`existExecutePlanInfo`）；`START_EXECUTE_PLAN_INFO` 内存集合防重复提交（`PlanInfoServiceImpl.java`）。
  - 执行名称不能超过 100 字符；`checkDevice=1` 时先校验设备有效性。
  - 计划类型决定分流出口（CASE→任务管理服务、APP→app处理服务、Web/桌面→web/pc处理服务），建计划后类型不可混用。
  - 支持前置/后置任务（`RelationTaskTypeEnum`），前置任务失败可按策略（`AfterFailOperateTypeEnum`）取消后续任务。
- **触发方式**：手动 `POST /v3/test_plan/test_plans/execute/{plan_info_id}`（`src/main/java/cn/testin/controller/plan/PlanInfoController.java`）或 Quartz Cron（`QuartzPlanInfoExecuteJob`）。
- **功能说明**：执行生命周期（快照冻结、企业限流、前置任务级联取消）、定时触发（一计划一策略、与执行时段叠加）、计划复制（深拷贝、模板重建/复用）的规则细节均已并入 [测试计划](测试计划.md) 相应章节；任务状态含义与流转见 [任务状态机](任务状态机.md)。
- **接口文档**：[PlanInfoController](../07-开放接口文档/测试计划/PlanInfoController.md)、[SubPlanInfoController](../07-开放接口文档/测试计划/SubPlanInfoController.md)、[PlanTaskController](../07-开放接口文档/测试计划/PlanTaskController.md)、[PlanTaskStrategyController](../07-开放接口文档/测试计划/PlanTaskStrategyController.md)、[PlanDeviceController](../07-开放接口文档/测试计划/PlanDeviceController.md)、[PlanInfoScheduledController](../07-开放接口文档/测试计划/PlanInfoScheduledController.md)、[PlanInfoExecutePeriodController](../07-开放接口文档/测试计划/PlanInfoExecutePeriodController.md)。

## 执行记录（db_plan）

> 界面入口：[测试计划页](测试计划.md) `/platform/test-plan/plan-list` 内的执行记录。

一次计划执行的进度与结果视图：记录树查询、停止/取消、重测、分享、报告明细。

- **数据模型要点**：树节点 `recordTaskType`：SUB_PLAN(1) 子计划 / TASK_PLAN(2) 任务 / RESET_TASK_PLAN(3) 重测 / TASK_PLAN_AND_RESET_TASK_PLAN(4) 聚合节点（`RecordTaskTypeEnum`）；状态机见 `PlanExecuteStatusEnum`：WAIT_EXECUTE(1)/WAIT_EXECUTE_PRE_TEST(11)/EXECUTE(2)/EXECUTE_WAITE_CALL_BACK(12)/FINISH(3)/CANCEL_ING(4)/CANCEL_SEND_TASK_MANAGE(14)/CANCEL(5)，11/14 是内部子状态、对前端仍显示为 1/4。
- **操作约束**：
  - 取消中/执行中的任务禁止重测（`ExecuteRecordServiceImpl.resetTask`，`src/main/java/cn/testin/business/impl/plan/ExecuteRecordServiceImpl.java`）。
  - 重测不覆盖首测结果：新增 RESET_TASK_PLAN 节点 + 聚合节点累计统计；`onlyRetest=1` + `retestTaskReportCaseIds` 可只跑失败用例；`retestUpdateDevice=1` 可换设备。
  - 停止走两路：CASE 走 HTTP `/v3/real_task/cancel` 到任务管理服务，APP/Web 走 V1 `Task.cancel`（`src/main/java/cn/testin/schedule/plan/CancelTaskThread.java`）。
- **功能说明**：重测规则（保留首测、按轮次累计、前后置任务共享、定时任务时间顺延）的自然语言版见 [测试计划-重测](测试计划.md#重测)；五种可见状态的含义与可停止/可重测约束见 [任务状态机](任务状态机.md)。
- **接口文档**：[ExecuteRecordController](../07-开放接口文档/测试计划/ExecuteRecordController.md)、[ExecuteRecordTaskController](../07-开放接口文档/测试计划/ExecuteRecordTaskController.md)、[EmailNoticeController](../07-开放接口文档/测试计划/EmailNoticeController.md)、[ScriptStatisticController](../07-开放接口文档/测试计划/ScriptStatisticController.md)。

## 通知（db_notice）

> 界面入口：[通知设置页](通知设置.md) `/platform/notice-manage`。

9 渠道通知中枢：渠道配置、事件订阅、发送记录，以及独立的运维告警。

- **数据模型要点**：渠道配置、事件配置、发送记录三类表 + 邮件模板（`DbPlanEmailNotice` 在 db_plan，计划级邮件通知配置）；渠道含邮件/SMS/HTTP/钉钉/飞书/企业微信/Teams/JoyChat/FAW，Dispatcher+Worker 线程模型在 `SpringStartRunner` 启动。
- **操作约束**：计划执行完成时由 `updateRootRecordTaskFinishStatus` 触发邮件（`planEmailNoticeService.sendEmail`）与 WebHook（执行记录上配了 `callBackUrl` 才发），均异步线程池 + 睡 0.5s 等事务提交（`src/main/java/cn/testin/business/impl/plan/ExecuteRecordTaskServiceImpl.java`）。
- **详见** [横切-通知系统](../04-复杂功能细节/横切-通知系统.md)（代码级）；自然语言版见 [回调与通知](回调与通知.md)（执行进度七类回传的业务含义、人工修正结果的统计重算、9 渠道通知与运维告警规则）。接口文档：[NoticeChannelCfgController](../07-开放接口文档/通知与消息/NoticeChannelCfgController.md)、[NoticeEventController](../07-开放接口文档/通知与消息/NoticeEventController.md)、[NoticeLogController](../07-开放接口文档/通知与消息/NoticeLogController.md)、[OpsNoticeEventController](../07-开放接口文档/通知与消息/OpsNoticeEventController.md)。

## 任务管理（db_portal）

> 界面入口：无独立页面，供旧门户/外部调用方经 `POST /v3/task/tasks` 提交，详见 [任务提交与结果回传](任务提交与结果回传.md)。

跨服务的任务提交入口（Portal 任务），主要服务旧门户/外部调用方。

- **数据模型要点**：`DbPortalTask`（portal_task）；执行结果回写 portal_task 并同步 ES `esportalsummarys`。
- **操作约束**：`POST /v3/task/tasks` 按 taskType 分流——taskType=1 发 app处理服务，其他发 web/pc处理服务（详见 [核心链路-任务提交](../04-复杂功能细节/核心链路-任务提交.md)，自然语言版见 [任务提交与结果回传](任务提交与结果回传.md)）。
- **接口文档**：[TaskController](../07-开放接口文档/任务管理/TaskController.md)、[portal-Task](../07-开放接口文档/任务管理/portal-Task.md)。

## 基础设施与统计（db_common / db_bi / db_cross）

> 界面入口：[日志管理页](日志管理.md) `/platform/log-manage`、[管理中心](企业管理.md) `/platform/admin/overview` 等。

- **目录管理**：通用目录树（DirInfo），各业务复用。→ [DirInfoController](../07-开放接口文档/基础设施与统计/DirInfoController.md)
- **Quartz 管理**：计划定时执行的 Job 登记与目录-模板关联。→ [QuartzController](../07-开放接口文档/基础设施与统计/QuartzController.md)、[DirQuartzJobController](../07-开放接口文档/基础设施与统计/DirQuartzJobController.md)
- **磁盘监控**：每日 3:00 采集挂载点数据。→ [DiskMonitorController](../07-开放接口文档/基础设施与统计/DiskMonitorController.md)
- **操作日志 / 活动日志**：`CaseActionLog`、通用 ActionLog。→ [OperateLogController](../07-开放接口文档/基础设施与统计/OperateLogController.md)
- **BI 统计**：用户/项目维度脚本执行统计打点。→ [BiStatisticController](../07-开放接口文档/基础设施与统计/BiStatisticController.md)
- **健康检查**：Redis + MySQL 连通性。→ [HeartBeatController](../07-开放接口文档/基础设施与统计/HeartBeatController.md)
- **后台自动机制**：待执行任务提交（30s）、预提测/取消重试与兜底（5min）、同步状态刷新（2min）、磁盘清理等自动机制的节奏与生效延迟预期。→ [后台自动机制](后台自动机制.md)
