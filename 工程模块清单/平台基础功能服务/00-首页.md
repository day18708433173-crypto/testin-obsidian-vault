# 平台基础功能服务 总览

> 平台基础服务：用户、项目、用例、日志等基础模块 + 测试计划编排引擎。本页为分支无关的通用介绍，分支强相关内容见下方分支索引。

## 定位

平台基础功能服务 是测试平台的"大脑"，负责编排与决策：

| 职责                               | 平台基础功能服务 | app处理服务 | 任务调度服务 |
| -------------------------------- | ----------- | --------- | --------------- |
| 测试计划编排 / 用例管理 / 任务模板             | **核心**      | —         | —               |
| 执行记录跟踪 / 通知发送 / 用户项目 / 定时调度 / BI | **核心**      | 部分        | 部分              |
| 任务创建与执行                          | 提交请求        | **核心**    | —               |
| 设备匹配与分发                          | —           | —         | **核心**          |

## 双入口架构

| 入口 | 路径 | 技术 | 路由方式 |
|------|------|------|----------|
| ApiServlet | `/*`（兜底） | 原生 Servlet + 反射 | `action=包名` → 包路径, `op=类.方法` → 反射调用 |
| DispatcherServlet | `/v3/*` | Spring MVC | `@RequestMapping` 注解路由 |

- `/*` → `ApiServlet`：action/op 参数决定 `cn.testin.service.{action}.{Action}` 类的反射调用
- `/v3/*` → `DispatcherServlet`：`@RestController` 注解，`/v3` 前缀由 DispatcherServlet 剥离后交给 Spring MVC 路由

详见 [横切-双入口路由机制](横切-双入口路由机制.md)。

## 核心业务域

### 1. 测试计划（db_plan）

测试计划编排的核心。涉及表：`plan_info` → `sub_plan_info` → `plan_task` → `plan_task_script`/`plan_task_case`/`plan_task_device`。

关键流程：创建/编辑计划模板 → 手动执行或 Cron 定时触发 → `executePlanInfo()` 快照建树（`execute_record` + `execute_record_task`）→ `ExecuteTaskThread` 30s 轮询提测 → app处理服务 执行 → callback 7 种类型回收结果 → `taskFinishAfterDeal` 父节点汇总 → 邮件/回调通知。

详见：[核心链路-测试计划执行](04-复杂功能细节/核心链路-测试计划执行.md)、[核心链路-定时执行](04-复杂功能细节/核心链路-定时执行.md)、[核心链路-回调处理](核心链路-回调处理.md)

### 2. 测试用例（db_case）

用例的 CRUD、目录管理、步骤管理、评论、标签、操作日志、版本管理、统计。支持脚本关联和脚本同步状态追踪。

### 3. 用户与认证（db_user）

用户注册/登录（LDAP/SSO/密码三种认证）、企业/项目管理、角色权限、用户活动记录。

详见：[核心链路-用户登录](04-复杂功能细节/核心链路-用户登录.md)

### 4. 通知系统

9 渠道 Dispatcher+Worker 模式：邮件/SMS/HTTP/钉钉/飞书/企业微信/Teams/JoyChat/FAW。所有线程在 `SpringStartRunner` 启动。

详见：[横切-通知系统](横切-通知系统.md)

### 5. 任务管理（db_portal）

Portal 任务提交：`POST /v3/task/tasks` → taskType=1 发 app处理服务，其他发 web/pc处理服务。执行结果通过 `Task.report` 回传写入 `portal_task` + ES `esportalsummarys`。

详见：[核心链路-任务提交](04-复杂功能细节/核心链路-任务提交.md)

## 后台线程全景

- `SpringStartRunner` 启动：Email/SMS/HTTP 分发线程、MQ 线程、6 个 WebHook 渠道线程、OEM/SSO 配置线程
- `@Scheduled` 定时任务：ExecuteTaskThread(30s)、CancelTaskCheckThread(5min)、PreTestTaskRestartThread(5min)、ComputeTaskTemplateSyncStatusThread(2min)、ComputeCaseScriptNoSyncStatusThread(2min)、DiskMonitorScheduled(每日3:00)、CaseStatisticSchedule(每周一3:00)、OpsAlarmScheduledTask(15min)
- 13 个 AsyncConfig 线程池（按 CPU 核数 × 2 设置 corePoolSize）

详见：[横切-后台线程全景](横切-后台线程全景.md)
