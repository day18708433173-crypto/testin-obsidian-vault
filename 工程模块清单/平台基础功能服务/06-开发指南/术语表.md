# 术语表

> 平台基础功能服务（testin-core）特有术语。按拼音/字母排序，每条"一句话定义 + 深入阅读"。通用跨服务术语见 [跨模块链路索引](../../跨模块链路/00-索引.md)。

## A

**action / op** — ApiServlet（`/*` 入口）的路由参数：`action=包名` 定位 `cn.testin.service.{action}` 包，`op=类.方法` 反射调用。见 [横切-双入口路由机制](../04-复杂功能细节/横切-双入口路由机制.md)。

**ApiServlet** — 本服务的历史入口 Servlet（`/*` 兜底），与 `/v3/*` 的 Spring MVC DispatcherServlet 并存。见 [开发指南](开发指南.md)。

## B

**补测** — 执行侧对漏跑/失败脚本的补充执行，由下游执行服务发起；**不是**本服务的重测概念。见 [端到端-补测](../../跨模块链路/端到端-补测.md)。

## C

**重测（reset/retest）** — 编排层对已完成任务的完整重跑：在执行记录树上新增 `RESET_TASK_PLAN` 节点，不覆盖首测结果。入口 `resetTask` / `batchReset`。见 [提测调度与重测实现](../03-实现逻辑/提测调度与重测实现.md)。

**callback（回调）** — 下游执行服务向本服务回传进度/结果的 HTTP 调用，统一入口 `POST /v3/test_plan/execute_record_tasks/callback`，7 种 `callbackType` 策略化消费。见 [核心链路-回调处理](../04-复杂功能细节/核心链路-回调处理.md)。

**caseNum** — 用例在任务/计划内的位置编号，回调结果对位落库的锚点之一。

## E

**eid** — 企业 ID（enterpriseId），基础数据接口的通用租户参数，默认值见 `Constants.EID_DEFAULT`。

**executePeriod（执行周期）** — 计划执行允许的时间段 JSON（`[{startTime:"HH:mm",endTime:"HH:mm"}]`），ExecuteTaskThread 触发前过 `checkCurTimeNeedExecuteTask`；非 CASE 出口下发前去冒号转 Long。

**executeCount** — 节点被执行次数（首测=1，每重测一次 +1），`executeCount>1` 时重测子计划全部并行。

## H

**回调 URL（callBackUrl）** — 执行记录上配置的 WebHook 地址，根节点完成后由 `callBackUrlExecutor` 异步推送结果。

**后置任务 / 前置任务（postTask / preTask）** — 计划任务节点的前后挂载任务（`RelationTaskTypeEnum`）；前置任务失败按 `afterFailOperate` 策略取消后续任务（含/不含后置）。

## J

**计划级设备（planDeviceStatus）** — `plan_info.plan_device_status`：VALID 时提测设备取 `plan_device` 表（计划统一设备），否则用任务模板自带设备；重测 `retestUpdateDevice=1` 时不套用。

**聚合节点** — `execute_record_task` 中 `recordTaskType=TASK_PLAN_AND_RESET_TASK_PLAN(4)` 的节点，汇总同一任务首测+全部重测的累计统计。见 [提测调度与重测实现](../03-实现逻辑/提测调度与重测实现.md)。

## P

**planInfoType** — 计划类型字段（`plan_info.type` / `execute_record.plan_info_type`），**三出口分流的依据**：APP(1)/WEB_OLD(2)/WEB(3)/DESKTOP(5)/CASE(1000)，枚举 `TaskTypeEnum`。见 [测试计划执行链路实现](../03-实现逻辑/测试计划执行链路实现.md)。

**Portal 任务** — db_portal 的跨服务任务（`POST /v3/task/tasks`），taskType=1 发 app处理服务、其他发 web/pc处理服务。见 [核心链路-任务提交](../04-复杂功能细节/核心链路-任务提交.md)。

## R

**recordTaskType** — 执行记录树节点类型：SUB_PLAN(1) 子计划 / TASK_PLAN(2) 任务 / RESET_TASK_PLAN(3) 重测 / TASK_PLAN_AND_RESET_TASK_PLAN(4) 聚合节点，枚举 `RecordTaskTypeEnum`。

**relationTaskContent** — `execute_record_task` 上保存的任务原始请求快照（JSON），提测时原样取出再叠加计划级参数（设备、时间段、离线配置）后下发。

**任务模板（taskTemplate）** — real 侧的任务定义，计划的 `plan_task.relation_task_id` 关联之；执行时其内容深拷贝进执行记录树。

## S

**三出口分流** — 提测按 planInfoType 分三个下游：CASE→任务管理服务（`RealTaskV3Api`）、APP→app处理服务（`RealTestV3Api` 或 V1 taskAdd）、Web/桌面→web/pc处理服务（V1 taskCreate）。分流点 `ExecuteRecordTaskServiceImpl.java` / 。

**执行记录（executeRecord）** — 一次计划执行的快照根（`execute_record`），下挂 `execute_record_task` 树；名称可随意改，多数冗余字段为查询提速。

**执行记录树** — `execute_record_task` 的 parentId 树：根子计划(SUB_PLAN, orderNum=0) → 子计划 → 任务/重测节点；回调汇总沿 parentId 自底向上。

## T

**提测** — 本服务向下游执行服务创建任务/触发执行的总称；CASE 提测即执行，APP/Web 分预提测+触发两段。

**taskFailMsg** — `execute_record_task.task_fail_msg`：提测/执行失败原因记录，排查"计划卡住"的第一现场。

## Y

**预提测（preTest）** — APP/Web/桌面计划的建任务阶段：`PreTestTaskThread` 调 `preTestSingleTask` 向下游建任务拿 taskId，节点状态 WAIT_EXECUTE→WAIT_EXECUTE_PRE_TEST(11)。见 [提测调度与重测实现](../03-实现逻辑/提测调度与重测实现.md)。

**预提测标记（preTestTask）** — `execute_record.pre_test_task`：NO_PRE_TEST_TASK(未预提测)/PRE_TEST_TASK(已预提测)，`PreTestTaskRestartThread` 每 5 分钟按此标记扫漏。

## Z

**执行记录子状态** — `PlanExecuteStatusEnum` 中 11(WAIT_EXECUTE_PRE_TEST)/12(EXECUTE_WAITE_CALL_BACK)/14(CANCEL_SEND_TASK_MANAGE) 三个内部状态，对前端分别显示为 1/2/4，用于减少线程扫描范围。

**执行周期校验** — `checkCurTimeNeedExecuteTask`：判断当前时刻是否落在 executePeriod 任一时间段内，不在则本轮跳过（取消中任务除外）。

**状态乐观更新** — `updateSelectiveByIdAndOldStatus(id, oldStatus, update)`：`WHERE id=? AND execute_status IN (oldStatus)` 的条件更新，是全服务防并发冲突的主要手段（提测去重、重测回退、取消竞态都靠它）。
