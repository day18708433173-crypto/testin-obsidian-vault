# 平台基础功能服务 部署文档

> 工程：`D:\programfile\major\java\testin\workspace\testin-core`（Java 8 / Spring Boot 2.3.7，Maven 单模块，artifactId=testin-core）。本文基于 Dockerfile 的构建/启动命令整理；镜像由 CI 产出供 k3s 使用，本地打包可复用同一套 mvn 与 java 启动命令。本地启动 pom.xml 修改见文末内部 wiki 链接。

## Docker 镜像构建（两阶段）

| 阶段 | 基础镜像 | 作用 |
|---|---|---|
| BUILD | `registry.testin.cn/deploy/mevan:8u341` | 带 JDK8 + Maven，编译打包 |
| RUN | `hub-mirror.testin.cn/library/busybox:stable` | 只承载 jar/config，启动时解包到挂载卷 |

### 打包命令（BUILD 阶段）

```bash
/var/maven/bin/mvn install -P test -Dmaven.test.skip=true
```

- 激活 `test` profile，跳过单元测试。

### 启动命令（startup.sh）

```bash
/var/java/bin/java -Xms1024m -Xmx2048m -XX:PermSize=128M -XX:MaxNewSize=256m -XX:MaxPermSize=256m -jar testin-core.jar
```

- 初始堆 1024m、最大堆 2048m；`-XX:MaxNewSize` 限年轻代；PermGen 参数为老式写法。

### 运行阶段（busybox）

- 挂载卷：`VOLUME /data/webhome /home`
- CMD：`cp -R /data/target/* /data/webhome/` 解包 + 创建目录 `/home/syy/data/tempfiles/tmplog`、`/home/syy/data/logparse`、`/home/syy/data/logs/testin-core`

## 镜像构建与推送（.gitlab-ci.yml）

| 触发 | 命令 | 镜像 tag |
|---|---|---|
| 打 tag | `docker buildx build -f Dockerfile --platform linux/arm64,linux/amd64 -t $CI_REGISTRY_IMAGE:$CI_COMMIT_TAG . --push` | `$CI_REGISTRY_IMAGE:$CI_COMMIT_TAG` |
| `syy.release.*` 分支 | `docker build --pull` + 两次 `docker push` | `$CI_REGISTRY_IMAGE:$CI_COMMIT_REF_SLUG-<短SHA>` 与 `...:$CI_COMMIT_REF_SLUG` |

构建前 `docker login` 到 `$CI_REGISTRY`；DOCKER_HOST 指向 `tcp://registry.testin.cn-public-docker:2375`；buildx 驱动镜像 `hub-mirror.testin.cn/dockerpracticesig/buildkit:master`。

## 部署到 k3s

镜像推送后，k3s 工作负载引用镜像 tag；容器启动时 busybox CMD 先把 `/data/target` 解包到 `/data/webhome`，再由 startup.sh 的 java 命令拉起进程（`/var/java/bin/java` 为节点/镜像层固定路径）。

## 本地打包与启动

```bash
/var/maven/bin/mvn install -P test -Dmaven.test.skip=true   # 打包（或用本机 mvn install -P test）
/var/java/bin/java -Xms1024m -Xmx2048m -XX:PermSize=128M -XX:MaxNewSize=256m -XX:MaxPermSize=256m -jar testin-core.jar
```

- 产物：`target/testin-core/testin-core.jar`（pom `finalName=${project.artifactId}`）。
- 本地开发也可直接跑 `cn.testin.startup.Boot.main`，见 [开发指南](开发指南.md)。

## 本地启动 pom.xml 修改

本地启动（IDE 或直接 `java -jar`）时，pom 把 `src/main/resources` 外置到了 `target/testin-core/config`（`<build><resources>` 里带 `<targetPath>${project.build.directory}/${project.artifactId}/config</targetPath>` 的 resource 块），本地跑起来配置不在 classpath 上、会起不来。需**注释掉该 resource 块**，让配置回到默认 classpath（打进 jar）。

> **注意：此修改仅用于本地启动；Docker 部署不需要** —— 镜像构建保持配置外置，由 startup.sh 从 `config/` 目录加载。
