# 并发控制

> 任务调度是多线程 + 多节点环境，同一子任务可能同时被"心跳匹配、异常扫描、结果回收"撞上。本服务靠 **LockUtil 本地锁 + Redis 防重 + 处理中 map + task_exec_relation 唯一锚点**四层机制保证状态变更幂等、不重复下发、不覆盖结果。

## 四层机制

### 1. LockUtil 本地锁（JVM 内）

`LockUtil.getLock(KEY)` 返回同一 key 的共享锁对象，代码里 `synchronized(lock)` 串行化。锁 key 用 `TaskConfigEnum.TaskLockKeys`（`real-scheduling/src/main/java/cn/testin/pojo/task/TaskConfigEnum.java`），前缀统一带 `MODULE_ID`：

| 锁 key | 用途 |
|---|---|
| taskAction | 任务动作/结果收尾：`handleAbnormalTask`（key=subtaskid）、`handleSkipTask`（key=subsubtaskid）、跨端 `execute`（key=subtaskid） |
| taskMatch | 任务匹配相关 |
| taskInit | 任务初始化 |
| simulationTaskPrematch | 模拟网络任务预匹配（按上位机/全局） |

### 2. Redis 防重（跨节点）

- **init 防重**：`checkReqIdTaskIdStatus`（`TaskServiceImpl.java`）用 Redis key `reqId + "_" + taskId` 记状态（0 执行中/1 成功/2 失败），`NX` 写 1 小时；执行中先 sleep 30s 再查一次，仍执行中抛 `execFailed`——防止同 reqId 并发初始化。
- **设备-任务关系缓存**：`addByDevice` 写设备-任务关系（2 分钟），`receive` 读它领任务。

### 3. 处理中 map（去重队列消费）

各 dispatch 线程用 `ConcurrentHashMap<String, Long> processmap`（key=设备/子任务 id，value=处理中过期时间，30 分钟）避免同一对象被线程池重复处理：

- `DeviceDispatchThread` / `AbnormalDeviceDispatchThread` / `EsTaskDispatchThread` 都是"捞 pending → 查 processmap → 塞 map → 交 handler 线程池 → handler finally 清理 map"。

### 4. task_exec_relation 唯一锚点（DB 层）

预匹配时 `checkMatchTaskInfos` 先确认 `task_exec_relation` 无该 subtaskid 记录再 INSERT——即使锁外并发，DB 层也能挡住重复预匹配。

## 结果幂等

`ResultServiceImpl.handle`（`ResultServiceImpl.java`）对已 PARSED 的结果直接返回；并用 `HANDLING_MAP.putIfAbsent(subSubtaskid, now)` 做幂等：同一 subsubtaskid 5 分钟内重复投递直接跳过（超 5 分钟认为上次处理异常，允许重试）。`handleAbnormalTask` / `handleSkipTask` 写入前也查 `itaskresultdao.getBySubSubTaskId > 0` 防止覆盖已完成结果。

## 线程池配置

`StartRunner`（`real-scheduling/src/main/java/cn/testin/config/StartRunner.java`）启动的后台线程与线程池：

| 线程 | 线程池(core/max/queue) | 节奏 |
|---|---|---|
| MessageDispatchThread | 5/50/500 | 死循环取 BlockingPool |
| DeviceDispatchThread | 5/50/500 | 死循环消费设备匹配队列 |
| BrowserDispatchThread / ClientDispatchThread | — | Web/PC 匹配队列 |
| AbnormalDeviceDispatchThread | 1/10/500 | 10s 轮询 + 30s 空转 |
| ResultDispatchThread | — | 结果解析队列 |
| TaskDispatchThread | — | 异常扫描（空闲 5s） |
| EsTaskDispatchThread | 5/50/500 | ES 同步队列 |
| NoticeDispatchThread | — | 通知队列分发（`new NoticeDispatchThread(..., 100, 10, 100)`） |
| MqNoticeDataThread | — | 200ms 加载通知 |
| DeviceTaskCountThread | — | 60s 统计设备任务数 |
| AbnormalDeviceLoadThread | — | 30s 加载异常设备 |

## 多节点隔离

- 匹配队列 key、异常扫描 SQL、通知加载都按 `module.node.id`（vhost）过滤（`Config.MODULE_NODE_ID`），多节点各扫各的，避免跨节点重复处理；
- 但 **LockUtil 是 JVM 内锁**：同一子任务只会落在同一节点（按 vhost 归属），跨节点不共享锁，因此多节点部署必须保证 vhost 隔离正确。
