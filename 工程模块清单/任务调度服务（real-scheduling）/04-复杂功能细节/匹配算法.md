# 匹配算法

> 设备心跳触发两段式匹配：先 `receive` 领取已预匹配任务，领不到再 `match` 进队列等后台 `prematch` 做 ES 检索匹配。本文聚焦"匹配到谁、按什么规则、为什么是两段式"。

## 为什么是两段式

设备心跳是高频、低延迟的请求，而 ES 检索 + 写预匹配关系 + 领账号是耗时操作。任务调度服务把匹配拆成"同步领取 + 异步预匹配"两段，保证心跳接口即时返回：

1. **receive**（同步）：查 Redis 设备-任务关系缓存（2 分钟有效），命中直接返回任务 JSON；
2. **match**（同步）：只把设备 JSON 推进 Redis 匹配队列就返回空；
3. **prematch**（异步）：`DeviceDispatchThread` 消费队列 → `DeviceHandlerThread` 做 ES 检索 + 写 `task_exec_relation`（2 分钟有效）；
4. 设备**下一次心跳** `receive` 命中关系，领走任务。

因此设备至少两次心跳才能拿到任务；心跳间隔异常拉长会导致"匹配了但领不到"。

## 匹配类型路由（TaskMatchFactory）

`TaskMatchFactory.match`（`real-scheduling/src/main/java/cn/testin/business/util/TaskMatchFactory.java`）只实现 **APP** 分支（Web/PC 分支为空，走 MySQL 预匹配 `prewebMatch/preClientMatch`），按 `TaskMatchTypeEnum` 路由到 4 个 Spring bean：

| 匹配类型 | 枚举值 | Bean | 说明 |
|---|---|---|---|
| 全部设备 | ALL(5) | AppTaskMatchByAllServiceImpl | 不限定设备 |
| 指定设备 | DeviceID(1) | AppTaskMatchByDeviceServiceImpl | 按 deviceid |
| 机型 | ModelID(2) | AppTaskMatchByModelServiceImpl | 按机型 model |
| 操作系统 | OS(4) | AppTaskMatchByOsServiceImpl | 按系统 |

> `TaskMatchTypeEnum.ModelIDAndVersion(3)`（机型+版本）在 `TaskMatchFactory` 中**未注册 bean**，属已定义未实现。

## ES 检索公共条件

`AbstractTaskMatchServiceImpl` / 各 `AppTaskMatchBy*ServiceImpl`（`real-scheduling/src/main/java/cn/testin/business/impl/`）构造 ES 查询的公共条件：

- `execNum < TASK_MAX_EXEC_NUM(10)`：匹配次数未耗尽；
- `publishtime < now`：发布时间已到（轮次任务递推发布）；
- `execStatus`：`IDLE(0)`，或 `ING(1) 且 execDevice == 当前设备`（断点续跑）；
- 排序：`level`（优先级）升序，再 `createtime` 升序。

## 匹配前置过滤

`TaskServiceImpl.prematch`（`real-scheduling/src/main/java/cn/testin/business/impl/TaskServiceImpl.java`）在 ES 检索前做：

1. **脚本设备聚焦**：数据驱动下同一脚本需分配同设备，查"聚焦排除列表"（`task_script_device_focus`），命中则跳过；
2. **项目组过滤**：`parseProjectGroupList / excludeProjects`（`AbstractTaskMatchServiceImpl.java`）调用平台配置 `ProjectGroup.list`（本服务唯一一次调 real-cfg，`action=cfg`）解析项目组包含/排除；
3. **下发时间段过滤**：`task_release_time_periods` 控制任务只在指定时间段可下发，匹配时按时间段排除/包含；
4. **设备断点优先**：`device_last_task_info` 记录设备上一任务，data 策略下优先续跑。

## 预匹配与执行的衔接

- **预匹配**：`checkMatchTaskInfos`（`TaskServiceImpl.java`）对 subtaskid 加锁，确认 `task_exec_relation` 无记录后 INSERT，`expiretime = now + 2 分钟`——先占住关系；
- **执行**：`exec`（`TaskServiceImpl.java`）校验 `publishtime` 未到删关系、`execNum >= 10` 推迟 10 分钟等扫描、模拟网络超限删关系；通过后 relation 置 ING、`task_info` 置 ING、`exec_num+1`、同步 ES、发 MATCH 通知、写设备-任务缓存。

## Web / PC 匹配

Web/PC 不依赖 ES：`Task.webMatch`（PcInfo）/ `Task.clientMatch`（ClientInfoPojo）→ `IWebTaskService.prematch/exec` / `IClientTaskService.prematch/exec`，直接查 MySQL `task_info` 按 ucomid + 浏览器类型/版本（Web）或 pcId（PC）匹配。
