# 开发指南

> 工程：real 仓 `real-scheduling/` 子模块（Java 1.8 / Spring Boot 2.0.9）。先读 [产品概述](../01-产品功能/产品概述.md) 建立定位认识；本服务的公共背景（real 仓总览、MQ 体系、ApiServlet 协议）见 [real 云真机（公共）](../../app处理服务（real-test）/04-复杂功能细节/公共-real仓总览.md)。

## 分层约定

### 双 HTTP 入口（改代码前先确认走哪个）

1. **ApiServlet（`/*`）**：`Boot.openapiServlet` 注册（`real-scheduling/src/main/java/cn/testin/startup/Boot.java`），real 仓传统的 `action + op` 协议——`action=scheduling` 路由到 `service/scheduling/Task`，`op=init` 反射调 `init(ApiRequest)` 方法。service 类继承 `GenericBaseService`（`real-scheduling/src/main/java/cn/testin/service/GenericBaseService.java`），通过 `SpringHelper.getBean` 拿业务 bean（非 @Autowired）。
2. **Spring MVC（`/v3/*`）**：`Boot.dispatcherMvcServlet`（`Boot.java`），`@RequestMapping("/v3/RealScheduling/...")` 风格的新接口（Task/DeviceTask/HeartBeat）。

**新增 op 还是新增 REST 端点？** 旧链路内部调用（app处理服务 / 设备控制中心 调本服务）走 ApiServlet op；门户/管理后台新功能走 `/v3` MVC。两套并存是历史演进结果，不要混用。

### 数据层双体系

- **老体系（主体）**：`dao/interfaces` + `dao/impl`，JdbcTemplate 手写 SQL + RowMapper（如 `TaskInfoDAOImpl`），表 DO 在 `pojo/task/`。改 SQL 直接在 impl 里拼，注意 `Config.TASK_MAX_EXEC_NUM` 等常量的引用。
- **新体系（补充）**：mybatis-plus + dynamic-datasource（`application.properties`：`spring.datasource.dynamic.primary=db_task`），mapper XML 在 `resources/mapper/`。新表（如 task_release_time_periods）用这套。
- **ES**：`dao/impl/es/EsTaskInfoDAOImpl`，ES 5.6.8 transport client + spring-data-elasticsearch，承载 APP 任务匹配索引。

### 后台线程启动

全部在 `StartRunner.run`（`real-scheduling/src/main/java/cn/testin/config/StartRunner.java`）显式 new + start：9 个 Dispatch 线程（消息/设备/浏览器/PC/异常设备/结果/任务清理/ES 任务/ES 同步）+ NoticeDispatchThread + 3 个定时任务（MqNoticeDataThread 200ms、DeviceTaskCountThread 60s、AbnormalDeviceLoadThread 30s）。新增后台线程在这里登记；线程模型统一是 Dispatch（拉队列/扫表 → 投线程池）+ Handler（处理单条）。

### 通知（MQ）

用 real-common 的 mq_info_notice 表可靠通知：生产 `INoticeService.add(notice)`，消费在 `NoticeServiceImpl.handle`（`real-scheduling/src/main/java/cn/testin/business/impl/NoticeServiceImpl.java`）按 type 分发。新增通知类型：① `TaskConfigEnum.NoticeType` 加枚举（type/level/delay/有效期）；② StartRunner 的 `noticetypes` 数组登记（`StartRunner.java`）；③ handle 加分发分支。

## 本地构建与运行

```bash
# 构建（在 real-scheduling 目录）
mvn clean package -DskipTests
# 产物布局：target/real-scheduling/
#   real-scheduling.jar   （manifest: mainClass=cn.testin.startup.Boot, Class-Path=config/ lib）
#   lib/                  # 全部依赖 jar（maven-dependency-plugin copy-dependencies）
#   config/               # resources 原样拷贝
# 运行（产物目录下，与 bin/startup.sh 一致）
java -Xms1024m -Xmx1024m -jar real-scheduling.jar
```

- 依赖私有仓库 `https://repository.testin.cn/repository/testin`（pom.xml），关键依赖：`cn.testin:real-common:7.8.1.0`（ApiServlet/MQ/工具基座）、ES transport 5.6.8、jedis 2.9.0、mybatis-plus 3.2.0、druid + dynamic-datasource。
- surefire 默认 skip；单跑测试：`mvn test -DskipTests=false -Dtest=ClassName`。
- 运行期依赖：MySQL（db_task）、Redis、ES 三存储齐全才能正常工作；`/v3/RealScheduling/heartBeat` 可做三存储探活。

## 配置要点

| 配置 | 位置 | 说明 |
|---|---|---|
| `module.id` / `module.node.id` | config.properties | 104 / 1040001。**module.node.id 即 vhost**，任务扫描、Redis 队列 key、通知路由都按它隔离；多节点必须各配不同 node id（且以 module.id 开头，`Config.java` 有校验） |
| `task.max.exec.num` | config.properties | 匹配次数上限，默认 10（`Config.java`） |
| `task.max.precomplete.time` | config.properties | 预完成最大超时 600000ms |
| `simulation.task.exec.max` / `ucom.simulation.task.exec.max` | config.properties | 模拟网络任务全局/单上位机并发上限（默认 6） |
| `globalparameter.rule` | config.properties | 全局参数策略（启动时强制非空，`Boot.java`） |
| 数据源 | application.properties | `${TESTINPRO_MYSQL_HOST:...}` 环境变量注入；密码 `ENC(...)` 加密 |
| 下游地址 | service.api.properties | RealTest/RealCfg/ControlCenter/Script/File/DataSource 等 base URL |

## 跨模块修改红线

| 修改对象 | 影响方 | 要求 |
|---|---|---|
| `DeviceInfo` / `PcInfo` / `ClientInfoPojo`（api/bean/realcontrolcenter） | 设备控制中心 心跳调用协议 | 两端同改同发版 |
| `Task.init` 的 taskdetailJson 字段 | app处理服务 / web/pc处理服务 提测侧 | 先查 `NoticeServiceImpl` 等上游组装点，兼容旧字段 |
| task_info 状态机（TaskConfigEnum.TaskExecStatus） | 上游状态展示、TaskDispatchThread 扫描 SQL、real-test 侧查询 | 全仓 grep exec_status 相关判断 |
| mq_info_notice 通知 type/content 格式 | app处理服务（TASK_CREATE/ADAPT_COMPLETE 等互为生产消费） | 生产消费两端同改 |
| ES task_info 索引结构 | EsTaskInfoDAOImpl + AppTaskMatchBy* 查询条件 | 索引需重建或兼容双写 |

## 常见坑

1. **TaskServiceImpl 约 7000 行**：init/match/receive/exec/cancel/recover 全在里面，改之前先按本文与 [任务匹配调度实现](../03-实现逻辑/任务匹配调度实现.md) 定位方法行号。
2. **bean 获取方式混杂**：`SpringHelper.getBean`（老）、`SpringUtil.getBean`（hutool，新）、`SpringBootContext.getContext().getBean`（service 层）三种并存，新增代码跟随所在类的既有方式。
3. **日志双门面的日志级别**：大量 `Logit.debugLog(msg, "ERROR")` 把 ERROR 当标记位用，搜日志时按字符串过滤而不是按级别。
4. **match 的返回值没用**：`Task.match` 里 `boolean matchresult = ...` 赋值后不使用（`Task.java`），调用方靠"返回体无 RES_OBJECT"判断未匹配。
5. **TMP 任务无自愈**：改动 init 链路时务必保证"入库 → INIT 通知"的原子性兜底（失败按 reqId 删数据，`TaskServiceImpl.java`），否则会制造需要手工修复的 TMP 残留。
