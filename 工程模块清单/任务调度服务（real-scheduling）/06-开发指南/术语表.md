# 术语表

> 按拼音/字母排序。每条给"一句话定义 + 深入阅读"。

## A

**action / op** — real 仓 ApiServlet 协议的两级路由：`action=scheduling` 定位 service 类（如 `cn.testin.service.scheduling.Task`），`op=init` 反射调方法。见 [开发指南](开发指南.md)。

**ApiServlet** — real-common 提供的统一入口 Servlet（`/*`），与 Spring MVC（`/v3/*`）并存的旧协议入口。

## B

**梆梆回调（callCreate）** — 任务匹配成功后回调梆梆加固的创建接口（`ITaskService.callCreate`，`TaskServiceImpl.java`）。见 [任务匹配调度实现](../03-实现逻辑/任务匹配调度实现.md)。

**补测（retest / scriptRetest）** — 任务类型 taskType=2/脚本补测：init 时复用已有 subtaskid、合并 recoverScriptInfos，而非删旧重插。

## D

**待调度（PENDING_SCHEDULING, -2）** — task_info 状态：`needPendingScheduling=1` 的任务 init 后停在此状态，等 `Task.execute` 激活。见 [功能总览](../01-产品功能/功能总览.md)。

**多端任务（cross task）** — 一次提测跨 APP/Web/PC 执行的任务组，crossTaskid 关联，入口 `action=cross`。

## E

**ES 匹配索引** — APP 任务的匹配候选池（EsTaskInfo，ES 5.6.8）：init 激活后 `pushByEsQueue` 写入，prematch 时按 execNum<10、项目组、时间段等条件查询。

**exec_num** — 子任务被匹配下发的次数；上限 `TASK_MAX_EXEC_NUM=10`，超限由 TaskDispatchThread 扫描生成异常结果收尾。

**expiretime** — 任务过期时间戳 = publishtime + 提测传入的过期时长（0=永不过期，业务通常 7 天）；过期任务由扫描线程补 `result_code=999999 任务过期`。

## M

**match / 匹配** — 设备心跳触发的任务匹配总称；入口 `Task.match` 内部是"先 receive 领取、领不到再 match 排队"的两段式。

**MqInfoNotice** — real 仓基于 mq_info_notice 表的可靠通知模型（type/level/publishtime/expiretime/content）；本服务消费 8 类通知（StartRunner.java）。

## P

**prematch / 预匹配** — 设备入队列后由后台线程执行的 ES 查询 + 写 task_exec_relation（2 分钟有效）；设备下次心跳才能真正领取。

**publishtime** — 子任务可下发时间：轮次任务按 `(轮次-1)×roundPeriod` 递推，未到时间的任务不参与领取。

## R

**receive / 领取** — `ITaskService.receive`：心跳时查 Redis 设备-任务关系（2 分钟内有效）+ task_info（ING 且 publishtime 已到），命中即把任务 JSON 下发给设备。

**reqId** — 任务初始化请求唯一 ID：Redis 防重锁 + task_info.req_id 幂等检查的依据，init 失败按它删数据。

## S

**subtaskid / subsubtaskid** — 子任务（task_info 主键，调度最小单位）/ 子子任务（task_sub_info 主键，脚本执行单元）的 ID。

## T

**task_info / task_sub_info / task_info_extra** — 任务三链：子任务（状态机主体）、子子任务（脚本明细）、任务扩展（参数/依赖/过期配置）。

**task_exec_relation** — 设备-任务预匹配关系表：防重复匹配的唯一锚点，预匹配记录 2 分钟过期。

**TMP（-1）** — "任务入库临时数据"状态：init 入库后、INIT 上报成功前的中间态；**无兜底扫描，残留需手工修复**（见 [异常修复 runbook](../../跨模块链路/横切-服务异常影响与数据修复.md)）。

**taskdetailJson** — `Task.init` 的任务详情 JSON：设备列表、脚本列表、过期时长、优先级、网络配置等全在里面。

## V

**vhost** — 模块节点编号（`module.node.id`，如 1040001）：任务扫描、Redis 队列、通知路由的隔离维度，多节点部署必须各异。

## X

**心跳匹配** — 旧链路的调度范式：设备控制中心 在设备心跳时回调 `Task.match/webMatch/clientMatch`，任务"拉"到设备上；区别于 任务管理服务 新链路的"服务端主动锁设备直推"。

## Y

**预完成（precomplete）** — 设备执行完单个脚本的上报：子子任务置 PRE_FINISH(2)，记录输入/输出变量并释放账号。

## Z

**执行策略（execStandard）** — 任务执行方式枚举：fast（快速）/normal/simple/monkey/script/data（数据驱动）/replace（可更换设备）/retention（始终保持）；影响 init 拆分方式与匹配行为。

**子任务状态机（TaskExecStatus）** — task_info.exec_status：-2 待调度 / -1 TMP / 0 待执行(IDLE) / 1 执行中(ING) / 2 预完成 / 3 完成 / 4 取消 / 5 跳过。枚举见 `real-scheduling/src/main/java/cn/testin/pojo/task/TaskConfigEnum.java`。
