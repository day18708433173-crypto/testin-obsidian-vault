# 任务调度服务 部署文档

> 工程：`D:\programfile\major\java\testin\workspace\real\real-scheduling`（real 仓多模块子模块之一，Spring Boot 2.7.18 / Java 8，artifactId=real-scheduling）。**四个 real 子模块（real-cfg / real-controlcenter / real-scheduling / real-test）共用同一个 `real/Dockerfile`，通过 `MODE` 环境变量选中本服务**。本文基于该 Dockerfile 的构建/启动命令整理；镜像由 CI 产出供 k3s 使用。

## Docker 镜像构建（两阶段，多模块单镜像）

| 阶段 | 基础镜像 | 作用 |
|---|---|---|
| BUILD | `reg-noc.testin.cn/pub/mevan:8u341` | 带 JDK8 + Maven，编译 real 仓全部子模块 |
| RUN | `hub-mirror.testin.cn/library/busybox:stable` | 承载 4 个子模块产物，启动时按 MODE 选一个解包 |

real 仓 pom `modules`：`real-cfg`、`real-test`、`real-controlcenter`、`real-scheduling`（`real-portal` 已注释）。

### 打包命令（BUILD 阶段）

```bash
sed -i 's#http://10.10.32.40:8000/maven2/#http://10.10.32.40:8000/artifactory/repo/#g' /var/maven/conf/settings.xml
/var/maven/bin/mvn clean
/var/maven/bin/mvn install -P privateCloud -Dmaven.test.skip=true
mkdir target && \
  cp -r real-cfg/target/real-cfg target/ && \
  cp -r real-controlcenter/target/real-controlcenter target/ && \
  cp -r real-scheduling/target/real-scheduling target/ && \
  cp -r real-test/target/real-test target/
```

- 先把 maven settings.xml 私服地址从 `maven2` 切到 `artifactory/repo`；再 `clean` + `install`（激活 `privateCloud`，跳过测试）；最后把 4 个子模块 target 归集到根 `target/`。

### 启动命令（startup.sh，MODE=scheduling 选中本服务）

```bash
cd real-scheduling && cp ../config/service.api.properties ./config/service.api.properties && \
/var/java/bin/java -Xms1024m -Xmx2048m -XX:PermSize=256M -XX:MaxNewSize=512m -XX:MaxPermSize=512m -jar real-scheduling.jar
```

- 生成脚本里的通用形式是 `cd *${MODE}* ... -jar *${MODE}*.jar`，本服务 `MODE=scheduling` → 目录 `real-scheduling`、jar `real-scheduling.jar`。
- 启动前把根目录 `../config/service.api.properties` 拷进子模块 `config/` 覆盖环境配置。
- JVM：初始堆 1024m、最大堆 2048m，年轻代上限 512m。

### 运行阶段（busybox）

- 环境变量：`ENV MODE=cfg`（默认值，部署本服务需显式覆盖为 `scheduling`）
- 暴露端口：`EXPOSE 8080 8000`
- 挂载卷：`VOLUME /data/webhome /home`
- CMD：`cp -R /data/target/* /data/webhome/` 解包 + 创建日志目录（含 `/home/syy/data/logs/real-scheduling` 等）

## 部署到 k3s

同一 real 镜像可部署 4 个服务，靠 `MODE` 区分：本服务用 `MODE=scheduling`。k3s 工作负载设置 `MODE=scheduling` 后，busybox CMD 先解包 `/data/target`，再执行 startup.sh 拉起 `real-scheduling.jar`。

## 本地打包与启动

```bash
# 在 real 仓根目录
mvn clean install -P privateCloud -Dmaven.test.skip=true   # 全量构建（或用 mvn -pl real-scheduling -am package 只构建本模块）
cd real-scheduling && java -Xms1024m -Xmx2048m -XX:PermSize=256M -XX:MaxNewSize=512m -XX:MaxPermSize=512m -jar target/real-scheduling.jar
```

- 产物：`real-scheduling/target/real-scheduling.jar`。
- 本地 maven 需指向内网 Artifactory（对应 Dockerfile 里的 `settings.xml` sed 修正）。

## 本地启动 pom.xml 修改

本地启动（IDE 或直接 `java -jar`）时，pom 把 `src/main/resources` 外置到了 `target/real-scheduling/config`（`<targetPath>${project.build.directory}/${project.artifactId}/config</targetPath>` 块），本地跑配置不在 classpath。需**注释掉该 resource 块**，让配置回到默认 classpath（打进 jar）。

> **注意：此修改仅用于本地启动；Docker 部署不需要** —— 镜像构建保持外置，由 startup.sh 从 `config/` 目录加载。

另：本地只启动单模块时，real 仓根 pom 的 `<modules>` 可只保留需要的子模块（其余注释掉），减少构建范围。
