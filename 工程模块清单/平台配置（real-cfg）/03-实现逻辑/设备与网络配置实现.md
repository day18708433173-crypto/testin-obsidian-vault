# 设备与网络配置实现

## 概述

设备/网络/项目侧的配置全部走**老栈（ApiServlet action=cfg/group + JDBC DAO 直读直写）**，业务层在 `cn.testin.business.impl` 下，service 类在 `cn.testin.service.cfg`（`action=cfg`）与 `cn.testin.service.group`（`action=group`）。本域的核心难点不在 CRUD，而在**主云/子云的层级关系**与**设备-云绑定数组列的并发修改**。

## 设备云（DeviceSource / DeviceSourceServiceImpl）

入口 `DeviceSource`（action=cfg）op：`add / remove / maintain / get / list`。

- **新增 `add`**（`DeviceSourceServiceImpl.add`）判定主云还是子云，核心是「企业项目组是否已配设备云」：
  - 已配企业主云（`eid + projectid=0` 有记录）且本次 `projectid > 0` → 作为**子云**：`parentName` 置为企业主云的 `devicegroupid`，并新建 `realcfg_project_group` 记录（子云 expiretime 继承企业主云）。
  - 已配企业主云且本次 `projectid` 为 0/空 → 报 `duplicateKey`（企业云已配置）。
  - 未配企业主云且本次 `projectid > 0` → 报错（企业云未配置不能加子云）。
  - 未配企业主云且 `projectid` 为 0 → 作为**企业主云**，新建 `projectid=0, type=0` 的项目组记录，expiretime 取接口传入（且必须晚于当前时间）。
  - 同云名去重：`getBycloudName(icloudName, parentName)` 已存在则复用其 name，否则 `irealcfgdevicesourcedao.add`。
- **删除 `delete`**（`DeviceSourceServiceImpl.delete`）：先查 `realcfg_project_group` 是否引用（在引用则 `deviceSourceInuse` 报错）；主云（parentName 空）再查 `realcfg_pc_cfg` 是否有上位机绑定；通过后发 `cleanDeviceCfg` 通知（异步解绑设备）→ **同步** `irealcfgdevicesourcedao.delete` 删记录。
- **查询 `get`**：`subsource=1` 时若目标为主云，额外查 `parentName = name` 的子云填充 `subsources`；`enterpriseConfig=1` 时按 `devicegroupid` 反查 `realcfg_project_group` 填 eid/projectid/type。

## 项目组（ProjectGroup / ProjectGroupServiceImpl）

入口 `ProjectGroup`（action=cfg），维护 `realcfg_project_group`（企业/项目 → 设备云 映射）。

- `add`：**只接受 projectid=0**（`projectid > 0` 直接报错并强制置 0、`type` 强制 0，即 web/app/接口共用同一主云）；校验 eid、devicegroupid 指向**主云**（`deviceSource.parentName` 必须为空，否则无效）、expiretime 晚于当前。**项目级子云映射不在这里建**，而是 `DeviceSourceServiceImpl.add` 加子云时内部 `irealcfgprojectgroupdao.add` 写入。
- `remove`：查 `eid(+projectid/type)` 的映射列表，倒序删除；对 `projectid>0` 的每条先发 `cleanSource` 通知（异步删子云记录）再删 `realcfg_project_group`。
- `get`：`checkValid == STATUS_ON` 时加 `checkValid` 条件过滤过期项。

## 设备-云绑定（DeviceCfg / DeviceCfgServiceImpl）

入口 `DeviceCfg`（action=cfg），维护 `realcfg_device_cfg`（`clouds` / `subclouds` 两个 JSON 数组列）。**所有写操作按 `deviceid` 用 `LockUtil` 加锁**（`new KEY("IDeviceCfgService.RealcfgDeviceCfg.deviceid", deviceid)`），临界区内改数组，云与子云全空则删行。

- `maintainSource(ucomid, deviceid, clouds)`：设置设备主云。校验 clouds 必须是主云（`parentName` 空）；`clouds` 为空时回退用上位机 `realcfg_pc_cfg.clouds`；若提交的 clouds 与上位机配置完全一致，则把待存 clouds 置空（表示"继承上位机"）；重算该设备还挂着的子云（子云父云必须仍在 deviceSources 里），全空则删行。
- `maintainSubsource(oprtype, eid, projectid, type, ucomid, deviceid)`：增删设备子云。先按 `eid+projectid+type` 查 `realcfg_project_group` 得到 `cloud`（子云名），校验它是子云（parentName 非空）；add 时校验设备主云包含该子云的 parentName（无权限则报错）；在 `subclouds` 数组上追加/移除；全空删行。
- `cleanSource(deviceid, cloud)` / `cleanSubsource(deviceid, subcloud)`：供 `NoticeServiceImpl.handleCleanDeviceCfg` 异步调用，从 `clouds`/`subclouds` 数组移除指定云，全空删行。
- `get(ucomid, deviceid)` / `list`：直接 DAO 透传，无业务逻辑。

## 弱网模拟（NetworkCfg / NetworkSimulationServiceImpl / NetworkController）

双入口：`NetworkCfg`（action=cfg，`list/maintain/delete`）+ `NetworkController`（`/v3/realcfg/network`，只读 list）。

- 数据模型：`realcfg_network_simulation` 一张表按 `name + eid` 存一条，五种规则 `rate`(限速)/`delay`(时延)/`loss`(丢包)/`corruption`(损坏)/`reorder`(乱序) 各以 `downlink,uplink` 逗号串存列（如 `rate`、`delay` 列）。`NetworkCfg.changeToUpDownLink` 把单记录拆成 5 条返回，`changeTypes` 把 5 条规则合并回单记录入库。
- `maintain`：`maintainflag=1` 新增 / `0` 更新；校验 `networkArray` 每项 name、ruleName、uplink/downlink；`validateRule` 按规则类型限幅（loss/corruption/reorder 0-100，delay 0-60000，rate 0-100000）。保留名 `wifi/sim/unlimited/4G/3G/2G` 不允许作为自定义弱网名。
- `delete`：`deleteByName(name, eid)`。

## 超时配置（Timeout / RealCfgTimeoutConfigServiceImpl）

入口 `Timeout`（action=cfg）op：`add / update / get`。

- `get`（`RealCfgTimeoutConfigServiceImpl.get`）是**读时回填默认值**：按 `projectId + businessType` 查 `realcfg_timeout_config`，查不到则用 `Config.TIME_OUT` 造一条 `status=1` 的记录先 `add` 再查——即首次读取会落一条默认超时配置，后续读取命中。
- `add/update`：直接 DAO 透传（service 层只校验必填 `projectId/businessType`）。

## 环境配置（EnvCfg / RealCfgEnvConfigServiceImpl / EnvController）

双入口：`EnvCfg`（action=cfg，写 + 老查询）+ `EnvController`（`/v3/env/envs`，新栈分页查询）。

- `add(envConfig, projectInfo, extras)`：环境名查重（`contains`）后写 `realcfg_env_config`，批量写 `realcfg_env_config_extra`（附加参数），再 `addToRelation` 写环境-项目关系。
- `maintain`：环境名查重（排除自身）；更新主表后，对比新旧 `projectInfo` 计算增删项目关系（`remove`/`addToRelation`）；`extras` 非空则**先 `deleteExtra` 全删再重插**。
- 查询：`EnvController.getEnvList` → `EnvService.getEnvListByCondition` → `EnvMapper.getEnvListByCondition`（MyBatis + PageHelper），按 project_id/status/env_name 条件分页。

## 项目高级配置（ProjectAdvancedConfigController / ProjectAdvancedConfigService）

入口 `ProjectAdvancedConfigController`（`/v3/realcfg/project`）op：`getAdvancedConfig` / `updateAdvancedConfig` / `flush_config`。

- 配置类型 `ProjectAdvancedConfigType`：`EXECUTE`（执行超时 + 加速开关，含 app/web/pc 三端，各端 `ConfigDetail` 有超时毫秒 + android/harmony/ios 全局控制加速开关）、`VAR_RULES`（变量规则，web/pc 的 varScope=local/global + varType）、`TIMEOUT`（历史遗留类型）。
- `getConfigByProjectIdAndType`：查不到时**生成默认配置落库**（`EXECUTE` 默认 30000ms 超时 + 加速关闭；`VAR_RULES` 默认局部变量字符串类型）再返回。
- `flushAdvancedConfig`（`POST /realcfg/project/flush_config`）：**一次性数据迁移**——分页 100 条扫所有 `TIMEOUT` 类型配置，把 `TimeoutConfigDTO` 转成 `EXECUTE` 的 `ExecuteConfigDTO`（加速开关补默认关闭），改 `configType` 后 `updateByPrimaryKeyWithBLOBs`。用于把老超时配置升级为带加速开关的执行配置。

## 上位机幂等开通（UcomIdController / UcomIdService）

入口 `UcomIdController`（`GET /v3/realcfg/ucomid`）。

- `UcomIdService.addUcomId(ip, password)`：ucomId = `ip + "@testin.cn"`；`realcfg_pc_account` 已存在则直接返回其密码（幂等），否则用默认密码 `Test!n_2024#`（或传入密码）`ipcaccountservice.add` 建上位机账号。
- `checkRealCfgPcCfg`：确保上位机配置 `realcfg_pc_cfg` 存在且已挂设备云——clouds 为空时，`getRealCfgPcCfg` 用默认配置（wififlag=0/minicapflag=1/ssid 空等）并调 `realCfgProjectGroupMapper.selectByEidAndProjectId(1, 0, 1)` 取企业默认设备云挂上。

## 涉及表

| 表 | 说明 |
|---|---|
| `realcfg_device_source` | 设备云（主云 parentName 空 / 子云 parentName 非空） |
| `realcfg_project_group` | 企业/项目 → 设备云映射（含 expiretime） |
| `realcfg_device_cfg` | 设备-云绑定（clouds/subclouds 数组列） |
| `realcfg_pc_cfg` / `realcfg_pc_account` | 上位机配置 / 账号 |
| `realcfg_network_simulation` | 弱网模拟（5 种规则逗号串） |
| `realcfg_timeout_config` | 超时配置 |
| `realcfg_env_config` / `realcfg_env_enterprise` / `realcfg_env_extra_enterprise` | 环境配置与关系 |
| `realcfg_project_advanced_config` | 项目高级配置（EXECUTE/VAR_RULES/TIMEOUT） |
