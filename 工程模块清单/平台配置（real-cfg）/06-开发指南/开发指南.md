# 开发指南

> 工程：real 仓子模块 `real-cfg`（`D:\programfile\major\java\testin\workspace\real\real-cfg`）。Java 1.8 / Spring Boot 1.5.20.RELEASE（`real-cfg/pom.xml`），产物版本 6.0.0。公共能力（ApiServlet、MQ、DAO 基类、工具）来自私有仓库依赖 `cn.testin:real-common:7.8.1.0`（`pom.xml`，仓库 `https://repository.testin.cn/repository/testin`），**real-common 的源码不在本仓**。

## 工程结构与分层


## 两条开发栈（改代码前先选栈）

| | 老栈 | 新栈 |
|---|---|---|
| 入口 | ApiServlet service 类（`cn.testin.service.*`，继承 `GenericBaseService`） | `@RestController`（`cn.testin.controller`，挂 `/v3/*`） |
| 业务层 | `business/interfaces` + `business/impl`，在 `cfg/spring/Spring-Service.xml` 注册 bean（id=接口名，如 `IDeviceCfgService`，`Spring-Service.xml`） | `business/service` 的 `@Service` + `@Resource` 注入 |
| 数据层 | `dao/impl` 手写 SQL，`IGenericJdbcDAO` 执行，在 `Spring-DAO.xml` 注册（如 `IRealcfgDeviceCfgDAO`，`Spring-DAO.xml`） | `mapper/` MyBatis 接口 + 同目录 XML，按库进对应 `@MapperScan` 包 |
| 分页 | 手写 limit 或 BaseList | PageHelper |
| JSON | org.json + gson | Jackson（Spring 默认） |

数据源绑定：Mapper 放错包会绑错库——`cn.testin.mapper.realcfg|group` → dsRealcfg（`RealCfgMybatisConfig.java`）、`mcfg` → dsMcfg（`McfgMybatisConfig.java`）、`servicecfg` → dsService（`ServiceMybatisConfig.java`）。`db_user` 没有独立 Mapper，靠 SQL 里写 `db_user.role_info` 跨库 join。

## 本地构建与运行

```bash
# 构建（依赖私有仓库 repository.testin.cn，需内网/凭证）
cd real/real-cfg
mvn clean install
# 产物布局（maven-dependency-plugin + resources-plugin 组装，pom.xml）：
#   target/real-cfg/real-cfg.jar     主 jar（manifest: mainClass=cn.testin.startup.Boot, Class-Path=config）
#   target/real-cfg/lib/             全部依赖
#   target/real-cfg/config/          *.properties/xml/so + cfg/db、cfg/mysql、cfg/redis
#   target/real-cfg/startup.sh       java -Xms1024m -Xmx1024m -jar real-cfg-6.0.0.jar
```

运行前置条件：

1. `config.properties`：`module.id=101`，`module.node.id` 必须以 101 开头（`Config.java`），否则 `Boot.main` 直接退出（`Boot.java`）；
2. `cfg/db/config.json` 里的 MySQL/Redis 可达——`DbConfigUtil.loadConfig()` 失败拒绝启动（`Boot.java`）；密码是 base64 密文（`secretPwd` 字段）；
3. 默认端口 8080；健康检查 `GET /v3/realcfg/heartbeat/check`（`HeartBeatController.java`，会探 MySQL）。

## 启动流程（Boot.main）

1. 设 log4j2 异步日志上下文（`Boot.java`）；
2. `DbConfigUtil.loadConfig()` 加载数据源 → 校验 `MODULE_NODE_ID`；
3. 起 `LicenseInitThread` 线程（；`ResourceInitThread` 已注释停用）；
4. 起通知线程对：`NoticeDispatchThread`（channel=`realcfg`）+ `MqNoticeDataThread` 200ms 轮询，机制见 [配置读取与缓存实现](../03-实现逻辑/配置读取与缓存实现.md)；
5. `SpringApplication.run`：Undertow 起两个 Servlet——`/v3/*` DispatcherServlet、`/*` ApiServlet。

## 新增功能的标准流程

**新功能一律走新栈**（老栈只维护）：

1. DTO 放 `dto/`，枚举放 `enums/`，DO 放 `dao/Do/`；
2. Mapper 接口 + XML 放 `mapper/<库名>/`（注意库包归属）；
3. `@Service` 放 `business/service/`；涉及错误归因类写操作时参考 `ErrorCauseTypeController` 加 `@OperateLog`（`aop/OperateLogAspect` + `business/strategy/log/`）；
4. `@RestController` 挂 `@RequestMapping("/realcfg/xxx")`（实际路径 `/v3/realcfg/xxx`），返回体用 real-common 的 `ResponseResult`；
5. 配置变更若需通知下游刷新，调 `NoticeUtil.sendNotice(action, target, keys...)`，并在 `CfgConfigEnum.NoticeType` 评估是否需要新通知类型。

老栈维护要点：service 类方法签名固定 `public String op(ApiRequest)`，参数从 `reqjson` 逐字段取，错误抛 `GeneralException(CommonCode.xxx)`；业务 bean 注册进 `Spring-Service.xml` 并在 `GenericBaseService` 加字段；DAO 注册进 `Spring-DAO.xml`。

## 约定与坑

1. **测试默认跳过**：surefire `<skip>true</skip>`（`pom.xml`），`src/test` 下有 DAO 测试基类（`BaseJunit`/`AbstractTest`），需 `-DskipTests=false` 手动跑。
2. **git-commit-id 的 `.git` 路径**：`dotGitDirectory` 写死 `${project.basedir}/.git`（`pom.xml`），而 `.git` 在 real 仓根——把 real-cfg 单独拷出构建会拿不到 git 信息甚至失败，需在整仓检出中构建。
3. **javadoc 插件 charset=UTF16**（`pom.xml`），生成文档乱码先看这里。
4. **JSON 三库并存**：org.json（接口协议）、gson（DTO 互转，`Config.gson`）、Jackson（MVC）；老接口协议层不要换 Jackson（数字/空值语义不同）。
5. **配置类是 static 加载**：`Config`/`ResourceConfig`/`WAFConfig` 都是静态块读 properties（`Config.java`），改配置必须重启进程。
6. **log4j-core 被 real-common exclusion 后重引 2.18.0**（`pom.xml`），升级日志框架注意传递依赖冲突。
7. **`libdecode.so` / JNA**：`OpenAPIFromJNA` 依赖本地库（resources 根目录 `libdecode.so`，jna 3.0.9），Windows 本地起服务相关路径会失败，注意避开或 mock。
8. **通知 channel 固定 `realcfg`**（`Boot.java`），多节点部署靠 `module.node.id` 区分消费范围。
