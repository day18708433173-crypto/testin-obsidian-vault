# 功能开关

## 主题定位

功能开关（`realcfg_function_switch`）按企业 eid 维度存一份开关配置，控制平台功能的全局/企业级启停。入口 `FunctionSwitch`（ApiServlet action=cfg），业务实现 `FunctionSwitchServiceImpl`。

## 数据与维度

- 表 `realcfg_function_switch`，POJO `RealcfgFunctionSwitch`。
- 维度字段 `eid`：**eid=0 是全局默认开关**；查询某企业开关时若命中不到，`getSwitchList` 会用 `eidList=[0]` 兜底再查一次全局项。

## 方法

| op | 方法 | 说明 |
|---|---|---|
| add | `addSwitch` | 校验 `eid >= 1` 且 `config` 非空后 `insert` |
| modify | `modifySwitch` | 校验 `eid >= 1` 后 `update` |
| get | `getSwitch(eid)` | 单条查开关；见下方私有云分支 |
| list | `getSwitchList(conditionMap, page, pageSize)` | 分页查；空结果时 `eidList=[0]` 兜底再查全局 |

## 私有云分支（`getSwitch`）

`FunctionSwitchServiceImpl.getSwitch` 里有 `Config.DEPLOY_TARGET == "PRIVATE CLOUDS"` 分支：私有云部署时本应从加密狗（`securityapi.getSWConfig()`）读开关并解析 `ConfigDetail`，**但该段代码整体被注释**，私有云分支当前直接返回 `null`。非私有云走 `irealcfgfunctionswitchdao.get(eid)` 直读库。

## 与菜单"功能点开关"的区别

注意区分两个"开关"：

- 本文的 `realcfg_function_switch` 是**业务功能开关**（按 eid，config 为 JSON 内容）；
- 权限体系里的 `service_function.config_key` 是**菜单/按钮权限点**，`openCloseFunction` 按 `config_key` 前缀启停功能点（见 [权限体系实现](../03-实现逻辑/权限体系实现.md)）。

两者表、入口、语义都不同，勿混。

## 要点

- 无变更广播：改功能开关后不发刷新通知，消费方读取时实时查库（或依赖自身缓存 TTL）。
- `addSwitch` 只校验 `eid >= 1`，意味着**全局开关（eid=0）不能通过 add 直接新增**（需运维侧预置或走其它途径）；但 `getSwitchList` 兜底逻辑又把 eid=0 当全局项查询。
