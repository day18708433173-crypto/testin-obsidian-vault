# 功能总览

> 本页是功能维度的总索引：每个功能域一句话定位 + 核心能力 + 接口/表链接。接口细节见 [07-接口文档索引](../07-开放接口文档/00-模块索引.md)，表结构见 [02-存储总览](../02-技术架构/00-存储总览.md)。

| 能力 | 入口 | 主要表 |
|---|---|---|
| 项目组管理 | [ProjectGroup](../07-开放接口文档/项目与平台配置/ProjectGroup.md) | `realcfg_project_group` |
| 项目高级配置 | [ProjectAdvancedConfigController](../07-开放接口文档/项目与平台配置/ProjectAdvancedConfigController.md) | `realcfg_project_advanced_config` |
| 品牌 / 机型档案 | [Brand](../07-开放接口文档/项目与平台配置/Brand.md) / [Model](../07-开放接口文档/项目与平台配置/Model.md) | `realcfg_brand` / `realcfg_model`、`view_model_brand` |

## 错误原因规则（错误归因）

测试失败归因的规则库：错误类型（按企业/项目）、错误原因日志、匹配规则、操作日志。app处理服务在报告侧读取类型与规则做失败分类。

- 入口：[ErrorCauseTypeController](../07-开放接口文档/基础设施与问题管理/ErrorCauseTypeController.md)（`/v3/realcfg/error_cause_type`）、[ErrorCauseLogController](../07-开放接口文档/基础设施与问题管理/ErrorCauseLogController.md)（`/v3/realcfg/error_cause_log`）、[ErrorCauseOperateLogController](../07-开放接口文档/基础设施与问题管理/ErrorCauseOperateLogController.md)
- 表：`error_cause_type`、`error_cause_log`、`error_cause_match_rule`、`error_cause_operate_log`
- 附带版本升级用的数据迁移接口 `POST /v3/realcfg/error_cause_type/sync`（`ErrorCauseTypeController.java`，为存量错误日志批量补建"未设置问题类型"）

## 数据模型要点

1. **配置即表**：绝大多数功能 = 一张 `realcfg_*` 配置表 + 一套 CRUD 接口，业务层很薄，直接 DAO 读写（如 `DeviceCfgServiceImpl.get/list` 直接透传，`DeviceCfgServiceImpl.java`）。
2. **设备-云绑定是数组列**：`realcfg_device_cfg` 的 `clouds`/`subclouds` 是 JSON 数组列，增删按 `deviceid` 加锁（`LockUtil`）后在临界区内改数组，全空则删行（`DeviceCfgServiceImpl.java`）。
3. **权限两库三表**：菜单功能点在 `db_service.service_function`（树形，`config_key` 标识），角色绑定在 `db_service.service_role_function`，角色主档在 `db_user.role_info`——查询时跨库 join（`RoleFunctionDAOImpl.java`）。
4. **OpenAPI 权限独立一套**：`db_mcfg` 的 `mcfg_role`/`mcfg_api`/`mcfg_role_api`，并有视图 `view_role_api`。
5. **配置变更靠消息最终一致**：关键配置（如角色-接口）变更后经 redismq 广播刷新各节点缓存，失败落 `mq_info_notice` 重发，见 [配置读取与缓存实现](../03-实现逻辑/配置读取与缓存实现.md)。
6. **错误归因按项目隔离**：`error_cause_*` 均以 `eid + project_id` 为维度，`error_cause_match_rule` 存放错误日志 → 类型的匹配规则。
