# 产品概述

> **Git 仓库**：`git@git.testin.cn:stock/backend/real.git`（子模块 `real-cfg/`）　**分支**：`syy.release.z7.8.1.0`

## 这是什么

平台配置（real-cfg）是 Testin 云真机平台的**配置中心**，real 仓的子模块（`real-cfg/`，Spring Boot 1.5.20 + Undertow 独立部署，模块编号 `module.id=101`，见 `real-cfg/src/main/resources/config.properties`）。它不承载测试执行主流程，而是把全平台共享的"配置与规则"集中管理，供其他服务通过接口读取：

1. **设备与网络配置**：设备云（主云/子云）分组、设备-云绑定、机型档案与品牌、树莓派、弱网模拟。
2. **项目与平台配置**：项目组（项目→设备云的映射）、项目高级配置、环境配置、平台系统参数。
3. **用户与权限**：上位机（ucom）账号与配置、平台菜单功能点权限（角色-功能）、OpenAPI 角色（角色-接口）。
4. **业务规则与界面**：功能开关、业务编码、超时配置、编辑视图、Portal 菜单。
5. **数据源与代码配置**：数据库连接配置（含 RSA 密钥）、CAN/DAQ 采集、源码/编码配置。
6. **错误归因规则**：错误类型、错误原因日志、匹配规则（`error_cause_*` 系列表）。

## 上下游关系

**下游（读它配置的服务）**——通过 HTTP JSON 接口调用，前缀 `RealCfg` 映射到 `http://realcfg.api.pro.testin.cn:8080`（`real-cfg/src/main/resources/service.api.properties`）：

| 调用方 | 读取内容 | 代码依据 |
|---|---|---|
| app处理服务（real-test） | 环境配置 `EnvCfg.get`、超时 `Timeout.get`、数据库配置 `DbCfg.listByEnvId`、上位机配置 `PcCfg.get`、错误类型 | `real-test/src/main/java/cn/testin/api/realcfg/cfg/EnvConfigApi.java`、`TimeoutApi.java`、`DBConfigApi.java`、`PcCfgApi.java` |
| 设备控制中心（real-controlcenter） | 数据库配置 `DbCfg.get` | `real-controlcenter/src/main/java/cn/testin/api/real/cfg/DbConfigApi.java` |
| 任务调度服务（real-scheduling） | 持有 `realCfgPrefixName = "RealCfg"` 调用前缀 | `real-scheduling/src/main/java/cn/testin/api/AbstractApi.java` |
| 前端 Portal / 各服务 | 菜单与功能点权限 `ServiceCfg.*`、角色接口权限 `RoleCfg.*` | `real-cfg/src/main/java/cn/testin/service/scfg/ServiceCfg.java`、`service/mcfg/RoleCfg.java` |

**上游（它依赖的服务）**——real-cfg 也反向调用其他服务（`real-cfg/src/main/java/cn/testin/api/`）：

- `UserApi`（user/UserApi.java）→ 平台基础功能服务：按 userid/email/sid 查用户信息；
- `OemApi`（core/OemApi.java）→ 平台基础功能服务（core）：读 OEM 系统参数（如权限菜单的 OEM 裁剪，`ScfgServiceImpl.java`）；
- `UcomApi`（contorlcenter/UcomApi.java）→ 设备控制中心：上位机相关操作；
- `ReportApi`（report/ReportApi.java）→ 上报/分享：按 skey 取分享内容（错误类型分享查询用）。

## 核心概念

| 概念 | 一句话 |
|---|---|
| 设备云（主云/子云） | 设备的调度分组；主云是企业级设备池，子云挂在主云下；设备与云的绑定存在 `realcfg_device_cfg` |
| 上位机（ucom） | 连接真机的宿主机，`realcfg_pc_cfg` / `realcfg_pc_account` 维护其配置与账号 |
| 项目组（ProjectGroup） | 企业项目 → 设备子云的映射，决定一个项目能用哪些设备（`realcfg_project_group`） |
| action / op | 老接口协议：HTTP body 里 `action` 选服务包（cfg/mcfg/scfg/group/portal），`op` 选 `类.方法` |
| 功能点（service_function） | 平台菜单/按钮权限点，按 `config_key` 树形组织；角色绑定在 `service_role_function` |
| 配置变更通知 | 配置改动经 redismq 广播 `{action,target,content}`，失败落库重发（见 [配置读取与缓存实现](../03-实现逻辑/配置读取与缓存实现.md)） |

## 双入口形态

一个进程、两套 HTTP 入口（`real-cfg/src/main/java/cn/testin/startup/Boot.java`）：

- **ApiServlet**（`/*`）：来自依赖包 real-common 的反射分发 Servlet，承载 32 个 service 类（`cn.testin.service` 下 cfg/mcfg/scfg/group/portal 五个包）；
- **Spring MVC**（`/v3/*`）：8 个 `@RestController`（错误归因、环境、网络、项目高级配置、健康检查等）。

## 存储

四个 MySQL 库 + Redis，详见 [02-存储总览](../02-技术架构/00-存储总览.md)：`db_realcfg`（业务配置主体）、`db_mcfg`（OpenAPI 角色）、`db_service`（菜单功能点权限）、`db_user`（角色信息，跨库 join）。
