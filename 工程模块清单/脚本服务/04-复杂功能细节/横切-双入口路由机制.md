# 双入口路由机制

脚本服务 用两个 Servlet 承接两类流量：`ApiServlet`（`/*`，V1 反射调用）与 Spring MVC `DispatcherServlet`（`/v3/*`，注解路由）。两者都在 `cn.testin.startup.Boot` 注册。

## Boot 注册（cn.testin.startup.Boot）

- `@SpringBootApplication` + `@ComponentScan("cn.testin")` + `@MapperScan("cn.testin.file.mapping")` + `@EnableTransactionManagement` + `@EnableScheduling`；
- `dispatcherMvcServlet`：把 Spring Boot 自动装配的 DispatcherServlet 的 URL 映射设为 `/v3/*`；
- `dispatcherApiServlet`：`new ServletRegistrationBean(new ApiServlet(), "/*")`；
- `fixedThreadPool`（18 daemon 线程）与 `initExportScript`（2 daemon 线程）启动后台任务（见 [横切-后台线程全景](横切-后台线程全景.md)）。

> 注意：入口类是 `cn.testin.startup.Boot`，**不是** `cn.testin.file.Boot`。

## V1 ApiServlet（/*）

`cn.testin.common.service.ApiServlet`（real-common 工程）接收 POST，读 `UPLOAD-JSON` 头或 body 解析 `ApiRequest{action, op, sid, data}`，交给 `ApiDispatch.doPress`：

1. `op` 按 `[\.,]+` 拆成 `[类名, 方法名]`（如 `op=Script.batchCopyScript` → `Script` + `batchCopyScript`）；
2. 拼类全名：`{servicePath}.{action}.{类名}`，默认 `servicePath = cn.testin.service`（可由 `service.path` 覆盖）——如 `action=script op=Script.check` → `cn.testin.service.script.Script.check`；
3. 若带 `servicePrefix` 且命中 `servicePathMap`（来自 `service.path.{prefix}` 配置，如 `pc → cn.testin.pc.service`），则把 servicePath 换成目标服务路径，实现**跨服务反射调用**；
4. `Class.forName(...).newInstance()` 后 `getMethod(方法名, 参数类型)` + `method.invoke`，参数为 `[ApiRequest]` 或 `[HttpServletRequest, ApiRequest]`。

### 跨服务前缀映射（service.api.properties / service.path.*）

`ApiUtil.doPress(prefixName, ...)` 的 `prefixName`（`UserManager` / `FileUpload` / `DataSource` / `xmlrpcservice`）经 `servicePathMap` 路由到对应服务，详见 [模块间通信](横切-模块间通信.md)。

## V3 DispatcherServlet（/v3/*）

标准 Spring MVC `@RestController` + `@RequestMapping`，由 `GlobalExceptionHandler`（`@RestControllerAdvice`）统一兜底。

### Controller 清单（cn.testin.mvc.controller）

| Controller | 类级路径 | 说明 |
|------------|----------|------|
| `ScriptController` | `/script` | 脚本 CRUD/批量/导入导出/复制/回收站 |
| `ScriptDirController` | `/script` | 目录 |
| `ScriptGroupController` | `/script` | 脚本组 |
| `TestCaseController` | `/script/test_case` | 脚本转用例三件套 |
| `SuiteController` | `/suite` | 套件 |
| `ScriptRecordController` | — | 脚本记录 |
| `ScriptUpgradeController` | — | 版本升级修复工具 |
| `ResourcesMarkController` | — | AI 资源标注 |
| `pythonController` | — | Python 脚本 |
| `HeartBeatController` | — | 健康检查 |

> 多个 Controller 共用 `/script` 前缀，靠方法级 `@RequestMapping` 的完整子路径区分（如 `/scripts/list`、`/dirs/...`、`/groups/...`）。

## 两种路由对比

| 特性 | ApiServlet（/*） | DispatcherServlet（/v3/*） |
|------|------------------|---------------------------|
| 路由方式 | `action` + `op` 反射 | `@RequestMapping` 注解 |
| 参数绑定 | `ApiRequest.reqjson` 手动取 | Spring `@RequestBody`/`@PathVariable` |
| 异常处理 | `ApiDispatch` 内部 catch + `GeneralException` | `GlobalExceptionHandler` |
| 主要使用方 | 平台内部服务 RPC（app处理/任务管理等） | V3 管理台前端、平台基础功能服务 |
