# 模块间通信

脚本服务（filesystem）对外调用下游服务，统一走 `cn.testin.api` 包下的客户端封装。底层协议分四类：**V1 Action/Op（ApiUtil.doPress）**、**V3 REST（RestTemplate）**、**XML-RPC（Python 引擎）**、**HTTP 直连（fileupload 文件上传/校验）**。Redis 只用于 ActionLog 投递，不参与服务间 RPC。

## 服务地址（service.api.properties）

| 前缀 | 地址 | 用途 |
|------|------|------|
| `UserManager` | `usermanager.api.pro.testin.cn:8080` | 用户/项目/在线/系统参数/OEM |
| `FileUpload` | `fileupload.pro.testin.cn` | 文件存储/App 解析/脚本校验重检 |
| `DataSource` | `datasource.api.pro.testin.cn:8080/openapi` | 数据源/参数数据源 |
| `xmlrpcservice` | `xmlrpcservice.api.pro.testin.cn:8080` | Python 脚本引擎（XML-RPC） |

## V1 Action/Op（ApiUtil.doPress）

客户端封装与对应前缀：

| 客户端 | 前缀 | 典型调用 |
|--------|------|----------|
| `UserApi` / `ProjectApi` / `OnlineApi` / `SystemParamApi` | `UserManager` | 查用户、项目、在线、系统参数 |
| `OemSystemApi` | `UserManager` | OEM 配置 |
| `TestinScriptApi.checkIfExistProject` | `UserManager` | 跨项目复制时解析目标项目 |
| `AppParse`（`api.file`） | `FileUpload` | `App.parseAppInfo` 解析 App 包 |
| `DataSourceApi` | `DataSource` | 数据源树/基本信息/批量复制/导入 |

通用封装 `ServiceRemoteV1Api.remoteApi(action, op, prefixName, data, clazz)`：构造 `ApiRequestDTO{data, action, op}` 后 `ApiUtil.doPress(prefixName, uri, json)`，再按 `result`/`jsonObjInfo`/`jsonList` 反序列化；`remoteApiPageList` 处理分页。

## V3 REST（ServiceRemoteV3Api）

`cn.testin.api.ServiceRemoteV3Api` 用 `RestTemplate` 发 `remotePost` / `remoteGet` / `remoteDelete`，响应统一包 `ApiV3ResponseDTO<T>`（code != 0 抛 `GeneralException`）。用于调用下游服务的 V3 端点（如平台基础功能服务、app处理服务等，地址在配置里按服务名解析）。

## XML-RPC（PythonScriptApi）

`cn.testin.api.PythonScriptApi`（继承 `AbstractXMLRpcApi`）指向 `xmlrpcservice`，底层 `xmlRpcClient.execute("doPress", params)` 调 Python 脚本引擎做解析/执行/函数发现。

## HTTP 直连 fileupload

- **文件上传**：`TestinScriptApi.upload` / `uploadScriptFile` / `uploadImage` / `multipartUpload` / `merge` 直接 `HttpUtils.fsUpload` 到 `{Config.UPLOAD_HOST}/openapi`，请求头 `UPLOAD-JSON` 带 `{op: File.upload, action: fs, data:{suffix, fileType}}`，返回文件 URL。
- **脚本校验重检**：`cn.testin.api.script.CheckApi.checkScript(scriptId)` GET `{Config.UPLOAD_HOST}/api/checkScript?key={fileupload.auth.key}&scriptId=...`，code=200 才视为触发成功（校验引擎在 fileupload 异步消费）。

## Redis

`RedisService.lPush(REDIS_QUEUE_KEY_ACTION, json)` 把 ActionLog 投递给平台基础功能服务落 `script_action_log`，是唯一跨服务消息；不是任务队列（任务队列都是 JVM 内存结构，见 [横切-脚本导入导出异步队列](横切-脚本导入导出异步队列.md)）。

## 调用方向速查（易写反点）

- **本服务 → 下游**：UserManager（用户/项目）、DataSource（数据源）、fileupload（文件上传/App 解析/校验重检）、xmlrpcservice（Python 引擎）。
- **下游 → 本服务**：app处理服务/任务管理服务（V1 `action=script/app` 取脚本 ZIP、取 App 包）；文件管理服务（`op=FileApi.cleanCacheByFileId` 清文件缓存）；平台基础功能服务（V3 转用例三件套）。
