# 核心链路：脚本解析与导入

脚本导入分两代：V1 走 `Script.parse` / `Script.importScript(Url)` → `TestinScriptManageService`（旧层），V3 走 `ScriptController` → `ScriptImportService`（新层）。两代都依赖**文件解析**（`TestinScriptApi.parseScript`）与**上传后按 URL 异步解析**（`ParseJobTaskThread` / `ImportJobTaskThread`）。

## 一、V3 导入（新链路）

入口 `POST /v3/script/scripts/import_script`（`ScriptController`），`ThreadPoolUtils.execute(() -> scriptImportService.importScript(dto))` 异步执行，`finally` 调 `scriptImportService.deleteImportTempFile(requestId)` 删临时文件。

### 预检（ScriptImportService.preImportScript）

`POST /v3/script/scripts/pre_import_script`：下载 zip 解压 → `checkImportFile`（校验 script_dir / script_dir_child / testCase.xml / step.json 是否存在，缺则"文件损坏"）→ `checkScriptSystemMsg`（读 system_msg 版本，`isVersionHigher` 判低版本，**禁止低版本向高版本导入**）→ 按 `scriptUUID` 匹配已存在脚本（排除已删除/硬删）得 `existUUID` → 解析标签、目录树、数据源名称 → 返回 `ScriptPreImportResponseDTO`（脚本清单 + 冲突标记 + dirMap + 数据源名）。

### 正式导入（ScriptImportService.importScript）

顺序固定（每个 `importModify*` 都是独立小步）：

1. 下载 zip 解压，读 `script_file.json`（无则返回活动记录失败）；
2. 校验脚本类型一致（`oldScriptFiles[0].scripttype` == 请求 `scriptType`）；
3. `importModifyScriptFileAndCommonFile`：按 `scriptImportFlag`（SKIP / COVER / CREATE_NEW）与 `scriptUUID` 存在性决定跳过/覆盖/新建；新脚本 `generateScriptNo` 生成 scriptNo、必要时 `generateScriptUUid`、`build` 重置/递增；`modifyTestCase` 重写 testCase.xml 引用（scriptNo 重映射、图片 URL 重传）→ 压缩 → `TestinScriptApi.uploadScriptFile` 上传 → 先批量插 `common_file` 再批量插 `script_file`；
4. `importModifyScriptRelation`：重映射 `script_relation` 的 parentScriptNo/parentScriptId；
5. `importScriptRecoverInfo`：重映射 `script_recover_info`（自愈脚本）；
6. `importScriptAtLast`：插 `script_at_last`；
7. `importScriptCheck`：为每个新脚本插 `script_check`（**checkStatus=1，直接置有效**）；
8. `importScriptDirAndScriptDirChild`：有目录则重建目录树（`insertDirTree`）+ `script_dir_child` 挂载；未分配目录则挂到请求 `dirId`；
9. `importSuiteScript`：APP 脚本插 `suite_script`（用户选的 suiteId）；
10. `importScriptTag`：插 `script_tag`；
11. `saveScriptStepSearchRelation`：按 stepFileId 拉步骤 JSON，拼 `actionShow + stepname + stepdesc` 生成 `script_step_fast_search`；
12. `importDataSource`：`DataSourceApi.importDataSourceInfo` 跨服务导入数据源 Excel；
13. `updateSuccessImportActionLog`：统计 skip/new/cover/失败数写活动记录。

## 二、V1 导入（旧链路）

- `Script.parse`（`op=Script.parse`）：入参 `url` + `again`；`again==1` 先 `clear(url)`；`scriptManageService.parse(url)` 解析出主脚本 + 依赖脚本地址，返回 details 供下一步拼装。
- `Script.importScript`（`op=Script.importScript`）：入参 `url` + `details[]`（`scriptDes/flag/operate/filePath/scriptNo/projectId/scriptDirId/caseVersion`）+ `dirs[]`；校验 scriptNo 不重复、details ≤ 2000；`scriptManageService.importScript(...)`。
- `Script.importScriptUrl`（`op=Script.importScriptUrl`，新版）：入参 `url` + `scriptImportFlag`；`TestinScriptManageService.findScriptInfoInQueue(url)` 查解析队列状态（`ScriptParseFlowEnum.FINISH` 且主脚本 ≤ 2000）；`scriptManageService.importScript(...)` 返回 `requestId`。
- `Script.importScriptToDir`：`HttpServletRequest` 流式上传到临时目录 → `CompletableFuture` 异步 `scriptParse` → `modifyScriptInfoInQueue(absolutePath, FINISH, result, depends)` → `scriptUpload`。

## 三、解析与后台线程

- 解析入口 `TestinScriptApi.parseScript`（filePath），产出 `ScriptParseObServer`（主脚本/依赖脚本元数据 + 上传 URL）。
- 解析结果放进**解析队列**：`TestinScriptManageService.modifyScriptInfoInQueue` / `findScriptInfoInQueue`，由 `Boot.fixedThreadPool` 启动的 `ParseJobTaskThread` / `ImportJobTaskThread`（`TestinScriptManageService.getParseJobTaskThread/getImportJobTaskThread`）消费。

## 涉及表（V3 导入）

`common_file`（脚本文件重传）→ `script_file` → `script_relation` → `script_recover_info` → `script_at_last` → `script_check` → `script_dir`/`script_dir_child` → `suite_script` → `script_tag` → `script_step_fast_search`；数据源写入外部数据源服务。

## 注意事项

1. **导入顺序有依赖**：必须先插 `common_file` 再插 `script_file`（script_file.fileid 指向新 commonFile）；先建 `scriptNoMap` 再重映射 relation/recover/dir_child。
2. **checkStatus 直接置 1**：V3 导入把新脚本标为有效，不触发校验引擎；需要重检另走 `CheckApi.checkScript`。
3. **版本校验禁止低版本导入**：`preImportScript` 读 system_msg 里的 `testinProSystemVersion`，低于当前版本直接抛错。
4. **2000 主脚本上限**：V1 与 V3 都限制一次性导入主脚本数量。
5. **图片/依赖关系按需**：`getImportRelationFlag` / `getImportImageFlag` 依据 zip 里是否存在 `script_relation.json` / 图片目录决定是否重写引用。
