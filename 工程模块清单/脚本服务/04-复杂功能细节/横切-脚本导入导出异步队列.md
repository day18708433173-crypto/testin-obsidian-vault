# 脚本导入导出异步机制

脚本服务 的导入/导出/复制**不是**"Redis 队列 + 轮询"，而是三种**JVM 内**异步手段的混用。Redis 只承担 **ActionLog 活动记录**的投递。本文以代码为准纠正常见误解。

## 机制总览（以代码为准）

| 场景 | 异步载体 | 提交方式 | 结果获取 |
|------|----------|----------|----------|
| V1 脚本导出 | `ScriptExportDispatchThread.waitTaskMap`（ConcurrentMap） | `waitTaskMap.put` + `notify()` | `getResult` 读 `resultMap`（15s 后清理） |
| V3 脚本导出 | `ThreadPoolUtils.execute` | Controller 拿 requestId 后异步执行 | 前端按 requestId 轮询活动记录 |
| V3 脚本导入 | `ThreadPoolUtils.execute` | Controller `finally` 删临时文件 | 同上 |
| V3 脚本批量复制 | `ThreadPoolUtils.execute` | `checkScriptCopyParamAndGetRequestId` 生成 requestId | 同上 |
| AI 标注资源导入导出 | `ResourceUtils.getExportQueue/getImportQueue`（`LinkedBlockingQueue`） | `ExportDispatchThread` / `ImportDispatchThread` 消费 | 读 `exportMap` / `importMap` |
| 活动记录 ActionLog | Redis `REDIS_QUEUE_KEY_ACTION` LPUSH | 各导出/复制流程显式调用 | 平台基础功能服务消费落 `script_action_log` |

## 后台线程（Boot.fixedThreadPool + initExportScript）

启动入口 `cn.testin.startup.Boot`：

- `fixedThreadPool()`：`newFixedThreadPool(18)`，daemon 线程名 `script.jobTaskThread`，启动 5 个任务：
  - `TestinScriptManageService.getParseJobTaskThread()`（脚本解析）
  - `TestinScriptManageService.getImportJobTaskThread()`（脚本导入）
  - `ScriptService.getBatchRfJob()`（批量 RF）
  - `ExportDispatchThread(ResourceUtils.getExportQueue())`（AI 资源导出）
  - `ImportDispatchThread(ResourceUtils.getImportQueue())`（AI 资源导入）
- `initExportScript()`：`newFixedThreadPool(2)`，daemon 线程名 `exportScript-->`，启动 `ScriptExportDispatchThread` + `CleanScriptExportFileThread`。

## V1 脚本导出：waitTaskMap + notify/wait

`ScriptExportDispatchThread` 的 `process()` 死循环：`waitTaskMap` 空则 `wait()`，被 `ExportScript.asyncExportScript` 的 `notify()` 唤醒后，遍历 map 提交 `ScriptExportWorkThread` 到 5 线程池，任务移入 `disposeTaskMap`（防同 key 重复提交）。

**要点**：这是进程内对象锁/通知，无持久化、无跨实例。

## V3 脚本导入/导出/复制：ThreadPoolUtils.execute

Controller 只做同步校验、生成 requestId 并立即返回，真正的重活丢给 `ThreadPoolUtils.execute` 的线程池：

- 导出：`ScriptExportService.exportScript`（打包上传）——见 [核心链路-脚本导出](核心链路-脚本导出.md)
- 导入：`ScriptImportService.importScript`——见 [核心链路-脚本解析与导入](核心链路-脚本解析与导入.md)
- 复制：`file.service.ScriptService.copyScripts`——见 [核心链路-脚本复制](核心链路-脚本复制.md)

## AI 资源导入导出：LinkedBlockingQueue

`cn.testin.schedule.resources.export.utils.ResourceUtils` 用静态 `LinkedBlockingQueue`（容量 Integer.MAX_VALUE）做队列，`ExportDispatchThread`/`ImportDispatchThread` 消费；结果/进度存 `exportMap`/`importMap`（ConcurrentHashMap）。同样是**进程内队列**，非 Redis。

## Redis 的唯一用途：ActionLog

`RedisService.lPush(REDIS_QUEUE_KEY_ACTION, actionLogJson)` 把活动记录推给平台基础功能服务落 `script_action_log`（导出/复制/导入的进度与结果）。参见 [AOP与操作日志](横切-AOP与操作日志.md) 中"两套日志机制"的对照。

## 关键设计要点（修正版）

1. **进程内、无持久化**：所有"队列"都是 JVM 内存结构，服务重启即丢；这就是 V1 导出结果 15 秒即清理、V3 靠 requestId + 活动记录而非队列结果的原因。
2. **防重复提交**：V1 导出用 `disposeTaskMap` 记录处理中 key；V3 用 requestId 幂等。
3. **清理靠独立线程**：`CleanScriptExportFileThread` 每 10 秒清 V1 导出临时目录与 result/schedule/dispose 标记。
4. **Redis 只解耦活动记录**：`REDIS_QUEUE_KEY_ACTION` 是唯一跨服务投递，且是 fire-and-forget 的 LPUSH。
