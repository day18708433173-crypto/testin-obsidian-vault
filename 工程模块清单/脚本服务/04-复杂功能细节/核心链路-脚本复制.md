# 核心链路：脚本复制

脚本复制分 V1 / V3 两条入口，最终都落到 `cn.testin.file.service.ScriptService`（旧层）的复制逻辑上，本质是"**按 scriptNo 建新版本 + 重建多表关联**"的深拷贝。

## 复制策略枚举

| 枚举 | 取值 | 含义 |
|------|------|------|
| `CopyWithDependenciesEnum.COPY` | 0 | 连子脚本/调用关系一起复制 |
| `CopyWithDependenciesEnum.NOCOPY` | 1 | 只复制选中脚本本身 |
| `CopyWithDependenciesEnum.ASYNC_COPY` | 2 | 跨项目场景，异步复制全部子脚本 |

`copyType`（V3 专属，决定是否连数据源一起复制）：`ScriptCopyConstant.COPY_SCRIPT`（仅脚本）/ `COPY_SCRIPT_AND_INSTANCE_DATA`（+实例表）/ `COPY_SCRIPT_AND_DATA_SOURCE`（+数据源）。

## V3 复制链路

入口 `POST /v3/script/scripts/batch_copy`（`ScriptController`）：

1. `mvc.service.ScriptService.checkScriptCopyParamAndGetRequestId` 同步校验并生成 requestId：
   - 校验 `targetDirId`、`targetProjectId`、`scriptNos` 或 `condition.dirId`、`copyType`、`copyWithDependencies`、`userId`、`userName`；
   - `ProjectApi.get(targetProjectId)` 查目标项目名、`oldScriptDirService.selectByPrimaryKey(targetDirId)` 查目标目录、可选 `targetSuiteId` 校验；
   - `getAllScriptNosForBatchCopyScript` 按条件解析出待复制 scriptNo 列表；单脚本且传了 `newScriptName` 时记录 `customNameScriptNo`；
   - 生成 UUID requestId 返回。
2. Controller 拿 requestId 后 `ThreadPoolUtils.execute(() -> oldScriptService.copyScripts(dto))` 异步执行。

### file.service.ScriptService.copyScripts

`copyScripts(ScriptCopyDTO)` 主体：

1. `UserApi.get(userId)` 取用户；`targetProjectId` 为空则回退 `projectId`；
2. `copyWithDependencies == COPY/ASYNC_COPY` 时 `scriptRelationService.getChildScriptNosAndCommentedChildScriptNos` 展开子脚本；
3. `scriptRecoverInfoMapper.getByScriptNos` 取自愈脚本，复制依赖时一并补入；
4. `checkScript(oldScriptNos)` 过滤无效脚本（checkStatus != 有效）；
5. `getScriptFileListByScriptNoListOrScriptUUIDList` 查脚本；`actionLogService.buildScriptCopyActionLog` + `recordScriptCopyActionLog` 记录活动；
6. 单脚本走 `modifyScriptFileAndCheckName`，多脚本走 `modifyScriptFile`（内部按 copyWithDependencies 决定是否同步/异步 `modifyCommonFile`，生成新 scriptNo、新 scriptUUID、`build` 版本号）；
7. 依次维护：
   - `ScriptDirService.batchCopyScriptModifyScriptDirAndScriptDirChild`（目录层级 + 脚本目录挂载）
   - `scriptAtLastService.modifyScriptAtLast`（`script_at_last`）
   - `scriptRelationService.modifyScriptRelations`（`script_relation`）
   - `checkService.modifyScriptCheck`（`script_check`）
   - `scriptSuitService.modifySuiteScript`（`suite_script`，目标套件）
   - `scriptRecordService.modifyScriptRecoverInfo`（`script_recover_info`）
8. `copyType != COPY_SCRIPT` 时 `DataSourceApi.batchCopyDataSources`（跨服务复制数据源/实例表）；
9. `handleScriptStepSearchRelation`（`script_step_fast_search` 搜索表）；
10. `finally` 里 `actionLogService.updateScriptCopyActionLog(actionLog, errorScriptMap)` 收尾活动记录。

## V1 复制链路（Script.batchCopyScript）

`cn.testin.service.script.Script.batchCopyScript`，路由 `action=script op=Script.batchCopyScript`：

1. 校验 `projectid`、`userid`（`UserApi.get`）；若传 `newHundsunProjectId + newVId` 则 `TestinScriptApi.checkIfExistProject` 解析目标项目；
2. 跨项目时 `copyWithDependencies = ASYNC_COPY`，展开子脚本 + 自愈脚本；
3. `scriptService.getScriptFileListByScriptNoListOrScriptUUIDList` 查脚本；`scriptCheckService.selectByScriptNos` 取校验状态，仅保留 `checkStatus == 1`（有效）的脚本；
4. `scriptService.modifyScriptFile`（生成新脚本版本 + `scriptNoMap` 新旧编号映射）→ `modifyScriptAtLast` → `modifyScriptRelations` → `scriptRecordService.modifyScriptRecoverInfo` → `scriptCheckService.modifyScriptCheck`；
5. 返回 `scriptNoMap`（老 scriptNo → 新 scriptNo）。

> 注意：V1 `batchCopyScript` 只做脚本本体 + at_last + relation + recover_info + check，**不复制目录/套件/数据源**；目录/套件复制在 V3 `copyScripts` 与 `Script.dirCopy`（目录复制，走 `ScriptDirCopyUtils` 任务队列容器）里。

## 涉及表

`script_file`（新版本行）、`script_at_last`、`script_relation`、`script_check`、`script_recover_info`、`script_dir`/`script_dir_child`、`suite_script`、`script_tag`、`script_step_fast_search`、`common_file`（脚本文件重传，跨项目时）。

## 注意事项

1. **复制是"深拷贝 + 重编号"**：新脚本拿新的 `scriptNo`（`generateScriptNo`）与新的 `scriptUUID`，`build` 版本号重置/递增；不是简单 `INSERT SELECT`。
2. **只复制"有效"脚本**：V1/V3 都会按 `script_check.checkStatus` 过滤掉无效脚本，全无效时返回"请选择有效的脚本"。
3. **子脚本展开含"被注释的调用关系"**：`getChildScriptNosAndCommentedChildScriptNos` 同时取注释掉的依赖，跨项目 `ASYNC_COPY` 才触发完整展开。
4. **跨项目才异步复制依赖**：同项目 `COPY` 同步处理 commonFile；`ASYNC_COPY` 在 `modifyScriptFile` 内 `ThreadPoolUtils.execute` 异步重传脚本文件。
5. **V1 与 V3 复制范围不对称**：V1 只复制脚本关联核心表，目录/套件/数据源要靠 V3 或 `Script.dirCopy`。
