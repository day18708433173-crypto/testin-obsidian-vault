# 核心链路：脚本导出

脚本服务 有**两套导出链路**，机制不同：V1 走 `ExportScript`（JVM 内 `waitTaskMap` + notify/wait），V3 走 `ScriptController` + `ScriptExportService`（`ThreadPoolUtils.execute` 异步 + requestId）。**两者都不走 Redis 队列**；Redis 只用于 ActionLog 活动记录（`REDIS_QUEUE_KEY_ACTION` LPUSH）。

## 一、V1 导出（ExportScript）

### 提交（ExportScript.export）

`cn.testin.service.script.ExportScript.export`，路由 `action=script op=ExportScript.export`：

1. 校验 `key`、`sid`、`scriptArray`（`{scriptNo, scriptId, exportDepend}` 数组）；
2. `verifyScript` 校验：scriptId 能查到脚本、脚本 projectid 与当前登录用户 projectid 一致、scriptNo 不重复；
3. `asyncExportScript`：`synchronized (ScriptExportDispatchThread.waitTaskMap)` 下，若 `disposeTaskMap` 无该 key，则构建 `ScriptExportTask` 放入 `waitTaskMap` 并 `notify()`。

### 分发（ScriptExportDispatchThread）

`cn.testin.schedule.script.export.ScriptExportDispatchThread`（随 `Boot.initExportScript` 启动）：

- 线程池 `ThreadPoolExecutor(5, 5, ArrayBlockingQueue(1000))`；
- `process()` 死循环：`waitTaskMap` 为空则 `wait()`；否则遍历 entry，按 key.hashCode % 5 取模，`threadPoolExecutor.execute(new ScriptExportWorkThread(task))`，同时移入 `disposeTaskMap`（防重复提交）并从 `waitTaskMap` 移除。

### 执行（ScriptExportWorkThread）

`ScriptExportWorkThread.run`：

1. `ScriptExportUtils.createScriptZip(jsonArray, fileSavePath, key, projectId, sourceIdList)` 生成 zip；
2. `ScriptFileUtils.uploadZipByForm(resultMap, task)` 上传 zip，得 `ResponseBean`（含 URL）；
3. `ScriptExportDispatchThread.resultMap.put(key, result)`；
4. 向 `CleanScriptExportFileThread.cleanInfoTaskMap` 写入 3 个 15 秒后清理的标记：`{key}_dispose`、`{key}_result`、`{key}_schedule`，并 `scheduleMap.put(key, 100)`；
5. 若 `recordActionLogFlag` 为 true，`redisService.lPush(REDIS_QUEUE_KEY_ACTION, actionLog)` 更新活动记录（成功/失败、失败脚本明细）。

### 结果轮询（ExportScript.getResult / getScriptPath）

- `getResult`：从 `ScriptExportDispatchThread.resultMap.get(key)` 取 `ResponseBean`；为 null 时看 `scheduleMap` 是否含 key（返回"正在导出"），否则"导出请求不存在"；拿到结果后 `AdminApi.insertToDel(res)` 登记清理。
- `getScriptPath`：内部先 `export` 再循环最多 200 次、每次 sleep 200ms 调 `getResult` 轮询下载路径。

### 清理（CleanScriptExportFileThread）

`cn.testin.schedule.script.export.CleanScriptExportFileThread` 每 10 秒扫 `cleanInfoTaskMap`，对到期的 `dispose`/`result`/`schedule` 标记分别清 `disposeTaskMap`/`resultMap`/`scheduleMap`，`dispose` 到期还会删除本地临时目录。

## 二、V3 导出（ScriptController + ScriptExportService）

入口 `POST /v3/script/scripts/datasources/export`（`ScriptController`）：

1. `ScriptExportService.scriptExport`（同步，`@Transactional`）生成 UUID requestId，解析条件：直接传 `scriptNos` 则 `oldScriptService.checkScript` 过滤有效脚本；传 `condition` 则递归目录、拼 `ScriptConditionDTO`（`checkStatus=VALID`）查 `scriptResponseList` 得 scriptNos。返回 requestId。
2. Controller 拿 key 后 `ThreadPoolUtils.execute(() -> scriptExportService.exportScript(dto))` 异步执行，前端按 requestId 轮询活动记录。

`ScriptExportService.exportScript` 主体：

- 建 ActionLog（`redisService.lPush` 初始化）；
- `exportDepend == EXPORT_DEPEND` 时 `scriptRelationService.getChildScriptNosAndCommentedChildScriptNos` 展开子脚本 + `scriptRecoverInfoMapper.getByScriptNos` 补自愈脚本；
- `oldScriptService.checkScript(scriptNos)` 过滤无效脚本；
- 逐脚本下载 `testCase.xml`（解压 `fileid` 对应 zip 取 testCase）、`STEP_JSON_FILE`、校验图（UI_ASSIGN_AI/UI_CHECK_AI 的 models.imageUrl）与预期截图（smallImg/stepimage/thumbImg）；
- 导出 `script_file` 列表 JSON、`script_relation`、`script_recover_info`、`script_dir`、`script_dir_child`、`script_tag`、数据源 Excel（`DataSourceApi.getDataSourceTreeNode`）、系统版本信息 `system_msg`；
- `IOTools.toZip` 打包 → `FileUtils.uploadZip` 上传 → 更新活动记录（`updateSuccessActionLog`）；`finally` 删临时目录和本地 zip。

## 导出包结构（V3）

导出 zip 内含：`script_file.json`、`script_relation.json`、`script_recover_info.json`、`script_dir.json`、`script_dir_child.json`、`script_tag.json`、`system_msg.json`、`script/{scriptUUID}/testCase.xml + step.json + 图片`、`datasource/`（Excel 数据源）。

## 涉及表

V1 只读 `script_file`（scriptId 校验）+ 写活动记录（经 Redis 队列到平台基础功能服务）；V3 读 `script_file`、`script_relation`、`script_recover_info`、`script_dir`、`script_dir_child`、`script_tag`、`common_file`（文件 URL）。

## 注意事项

1. **导出队列是 JVM 内 Map，不是 Redis**：`waitTaskMap`/`resultMap`/`scheduleMap` 都是 `ConcurrentMap`/`LinkedHashMap`，服务重启即丢；跨实例/重启后 `getResult` 会返回"导出请求不存在"。
2. **V1 结果 15 秒后即被清理**：`resultMap` 只有约 15 秒窗口，`getScriptPath` 用 200ms×200 次轮询赶在清理前拿结果；`getResult` 拿到结果后还会 `AdminApi.insertToDel` 登记额外清理。
3. **V1 与 V3 的 `exportDepend`/`exportDependEnum` 含义**：V1 用 `scriptArray[].exportDepend`，V3 用 `ExportDependEnum`（EXPORT_DEPEND / NO_EXPORT_DEPEND）。
4. **V3 导出只出"有效脚本"**：条件查询强制 `checkStatus=VALID`，直接传 scriptNos 也会 `checkScript` 过滤。
