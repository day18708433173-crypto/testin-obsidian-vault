# 脚本管理

> 来源：http://test.pro.testin.cn/docs/base/script_management/

自动化脚本用于记录UI的操作步骤和验证等，即自动化用例，是自动化测试的核心测试资产。通过脚本管理功能，可以让项目组成员都参与脚本建设、维护和共享脚本资源进行测试。

## 脚本列表
管理脚本文件，用于App、Web或桌面软件的自动化测试。

### 录制脚本
可以记录用户鼠标点击、键盘输入、屏幕截图等操作，将其转换为可自动化执行的脚本文件，以便在其他App、Web或PC的软件上重复执行相同的操作，录制完成后，可在任务管理模块进行任务提测，获得脚本执行报告。

### 文件目录管理
可以实现脚本文件的分类管理，通过文件目录管理，可以方便地查找、定位和访问所需的文件。

复制到：选中某一目录文件复制到其他目录里，复制成功后选中文件的目录结构保持不变。

删除：删除目录文件后，会删除该目录中的所有文件，已删除的文件可在回收站中操作彻底删除或恢复（恢复后将回到删除前的目录结构）。

### 批量操作
支持对多个脚本进行处理，无需逐一进行重复的手动操作，如：批量复制、批量移动、批量导出、批量导入、批量删除、批量修改标签。脚本列表页的「更多操作」下拉菜单提供移动到、批量复制、批量导出、批量导入、批量删除、批量恢复等批量能力；每行脚本的行内操作为复制、重命名、移动、删除。

#### 批量复制
支持把一批脚本**完整复制**到另一个项目（或本项目的另一个目录）：不只是脚本本身，还包括全部步骤、所在目录结构，以及脚本之间的调用关系。复制是"深拷贝"——复制出来的新脚本与原脚本互不影响。（本节规则细节来自 04 专题，见 [核心链路-脚本复制](../04-复杂功能细节/核心链路-脚本复制.md)）

复制时可以选怎么处理"脚本引用了别的脚本"的情况：

| 策略 | 行为 | 适用场景 |
|---|---|---|
| 连同依赖一起复制 | 被引用的脚本（含间接引用，逐层递归）全部一并复制，引用关系在新脚本间完整重建 | 完整迁移一套业务到新项目 |
| 只复制脚本本身 | 不复制依赖；如果选中的几个脚本互相引用，内部引用会重建，指向范围外的引用不处理 | 复用独立脚本 |
| 只复制选中的 | 严格只复制勾选的脚本，不做任何依赖扩展 | 精确指定迁移范围 |

规则与限制：

- **权限要求**：需要对源脚本有读权限、对目标项目有写权限；目标项目无权限时整个复制任务中止，不会只复制一部分。
- **名称冲突**：目标位置已有同名脚本时，自动追加 `_copy` 类后缀避让，不会覆盖已有脚本；名称带 `_copy` 后缀的脚本建议及时改成规范名称。
- **目标目录不存在**：自动放到目标项目根目录，不报错。
- **源脚本不存在**：跳过该脚本并在结果中记录，不影响其他脚本。
- **部分失败不拖垮整体**：单个脚本复制失败会跳过并记录，其余脚本继续；完成后返回成功清单和失败清单。
- 复制是**异步执行**的：提交后先返回一个任务标识，大批量复制需要等后台跑完再看结果；复制完成的新脚本会自动纳入脚本校验。

#### 批量导出
支持同时导出脚本和数据源数据，导出后保留脚本与数据源实例表的对应关系，再次导入后可直接使用数据源内的数据进行任务提测。如：客户要求对某一段时间内的脚本及数据源数据资产进行备份归档，可同时将脚本和数据源导出进行归档，若后期需要可再次导入平台进行自动化测试。

注：导出数据压缩包文件仅保留7天，请尽快下载。

导出为**异步任务**：提交后立即返回任务标识，平台在后台收集脚本、打包、生成下载地址，用任务标识轮询查询，状态为"完成"时拿到下载地址，状态为"失败"时能看到失败原因。（本段规则细节来自 04 专题，见 [核心链路-脚本导出](../04-复杂功能细节/核心链路-脚本导出.md)、[横切-脚本导入导出异步队列](../04-复杂功能细节/横切-脚本导入导出异步队列.md)）

- **导出方式**：可选"完整导出"（选中脚本 + 全部依赖脚本，逐层递归、自动去重，并保持原始目录结构）或"仅脚本自身"（只打包选中的脚本，不带依赖）。
- **导出包内容**：ZIP 包保持脚本在平台上的原始目录层级，内含一份清单（导出时间、脚本数量、每个脚本的名称/类型/依赖/目录路径）和每个脚本的完整数据（步骤、参数等）。
- 导出前做权限校验，没有对应项目和脚本权限无法提交；实现侧导出任务结果约 24 小时后会被平台清理，过期只能重新导出，拿到文件后请尽快转存到正式备份位置。

#### 批量导入
可批量导入脚本及脚本对应使用的数据源。

支持的文件格式：ZIP 工程包（按约定结构解压解析，可含多个脚本）、JSON 脚本文件（单个脚本的 JSON 描述）、Python 脚本（额外提取脚本中定义的函数及参数签名，供步骤编排时选用）。（本段规则细节来自 04 专题，见 [核心链路-脚本解析与导入](../04-复杂功能细节/核心链路-脚本解析与导入.md)）

导入过程：先解析出脚本名称、步骤列表（含每步的类型和参数）、依赖声明、数据源引用；然后创建脚本及全部步骤，在**目标项目内**查找依赖声明对应的脚本并建立调用关联，恢复脚本与数据源的关联，新脚本自动纳入校验。批量导入同样走异步任务，提交后用任务标识轮询结果。

异常时的表现：

| 场景 | 用户可见表现 |
|---|---|
| 文件解析失败 | 返回具体解析错误原因，不导入任何内容 |
| 脚本名称重复 | 提示名称冲突，需更名后重新导入 |
| 依赖的脚本在目标项目找不到 | 脚本照常导入，但结果中带"依赖缺失"警告，后续补齐同名依赖脚本即可，否则执行会失败 |
| 个别步骤参数格式错误 | 该步骤跳过并记录错误详情，其余步骤正常导入 |
| Python 函数提取超时 | 不阻断导入，只少了函数签名信息，脚本本体正常 |

迁移场景建议使用"完整导出 + 导入"组合：依赖自动带出，避免导入后一堆"依赖缺失"警告。
