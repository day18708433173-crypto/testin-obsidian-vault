# 开发指南

> 工程：`filemanagement`（Maven 制品 `cn.testin:filesystem:1.2.0`，`pom.xml`；JDK 1.8 / Spring Boot 1.5.20 + Spring 5.0.4 / Undertow）。先读 [横切-双入口路由机制](../04-复杂功能细节/横切-双入口路由机制.md) 建立"双形态"认识，接口清单见 [07-开放接口文档索引](../07-开放接口文档/00-模块索引.md)。

## 双形态工程结构

本服务一个进程里跑两套 HTTP 入口，由 `cn.testin.startup.Boot` 注册（Boot.java）：

| 形态 | Servlet 映射 | 代码位置 | 路由方式 | 面向 |
|---|---|---|---|---|
| V1 ApiServlet | `/*` | `cn.testin.service.{action}.{Class}` | `action`+`op` 反射 | 内部服务 RPC |
| V3 REST | `/v3/*` | `cn.testin.mvc.controller` | Spring MVC 注解 | V3 管理台/新调用方 |

**新增功能选型的默认规则**：管理台新功能一律写 V3 Controller；只有给老内部调用方补 RPC 时才动 V1（V1 方法签名固定为 `String xxx(ApiRequest)`，继承 `GenericBaseService`）。

## 约定清单

### 数据访问（最易踩坑）

- **数据源不走 Spring 自动装配**：`Boot` 上 `exclude={DataSourceAutoConfiguration.class}`（Boot.java）。旧层 `cn.testin.file.service.*` 手动 `SessionFactoryUtil.getSqlSession(Constants.FILE_DB)` 开/关 SqlSession，**`@Transactional` 对它无效**；新层 `mvc.service` 走 `MybatisConfig` + `@MapperScan("cn.testin.file.mapping")`（Boot.java），可以 `@Transactional`。同一个业务跨两层时，事务边界只在 Spring 侧成立。
- Mapper XML 与接口**同目录**放在 `cn/testin/file/mapping/` 下（构建时靠 `pom.xml` 把 `src/main/java` 下的 xml/properties 打进包），不要建 `resources/mapper/`。
- 分页：新层用 PageHelper（`application.properties`）；旧层用 `BaseList` + 手工 limit。

### 响应与序列化

- V3 统一返回 `cn.testin.common.ResponseResult`；V1 统一 `ApiUtil.getJSONobj` + `ApiResponse.RES_*` 键（`GenericBaseService` 已封装 `respWithSingleObject / respWithMultiObject(AndPager)`）。
- JSON 三套并存：org.json（V1 请求/响应体）、Gson（V1 序列化模型）、fastjson。V1 新代码沿用 org.json+Gson；V3 交给 Spring（Jackson）。

### 异步与后台线程

- 请求内异步：统一 `cn.testin.util.ThreadPoolUtils.execute`（复制/导入/导出，参考 `ScriptController.java`），返回 requestId 给前端轮询。
- 长驻线程：`Boot.fixedThreadPool`（18 线程，Boot.java）挂脚本解析/导入/批量回收/资源导入导出分发；`initExportScript`挂脚本导出分发 + 导出文件清理；`main` 里还有 `OemStartThread`（5min）与 `ParseAppStartThread`（30s）。详见 [横切-后台线程全景](../04-复杂功能细节/横切-后台线程全景.md)。
- 队列语义在 Redis（队列清单见 [Redis 总览](../../数据库管理/脚本服务-redis/00-Redis总览.md)）。

### 操作日志

- V3 方法上加 `@OperateLog(OperateLogEnum.XXX)`（切面在 `mvc/aspect` + `mvc/strategy`），日志经 Redis 队列 `queue:action_log` 异步落 `script_action_log`（本仓无该表 Mapper）。见 [横切-AOP与操作日志](../04-复杂功能细节/横切-AOP与操作日志.md)。

### 缓存

- `common_file` / `common_app` 的 Guava 缓存与失效规则见 [AppPackage包查询实现](../03-实现逻辑/AppPackage包查询实现.md)：改 `common_file` 后必须触发 `FileApi.cleanCacheByFileId`；`common_app` 没有失效入口，改动方要么走直查要么接受 2 分钟 TTL。

### 跨服务调用

- 出站长地址集中 `src/main/resources/service.api.properties`（UserManager / FileUpload / DataSource / xmlrpcservice）；文件存储与 admin 地址在 `config.properties`（`fileupload.url` / `admin.url`，含 `fileupload.auth.key`）。
- 调 V1 服务用 `ServiceRemoteV1Api`（action/op 封装），调 V3 服务用 `ServiceRemoteV3Api`；示例：脚本重检调文件管理服务（`mvc/service/ScriptService.java`）。

## 本地构建与运行

```bash
# 构建（产物布局：target/filesystem/{filesystem.jar, lib/, config/, *.sh}）
mvn clean install

# 运行（主类由 manifest 指定）
java -jar target/filesystem/filesystem.jar
# 或本地直接跑 cn.testin.startup.Boot
```

- 依赖私有仓库 `https://repository.testin.cn/repository/testin`（`pom.xml`），含 itestin/com.testin.script 等私有 jar，版本随分支锁定（`pom.xml`，Z7810-20260226）。
- 打包布局由 maven-jar-plugin + maven-dependency-plugin 定制：依赖拷到 `lib/`，classpath 前缀 `lib/` + `config/`（`pom.xml`），resources 输出到 `config/`（`pom.xml`）；启动脚本 `src/main/resources/bin/*.sh`。
- 端口 8080（`application.properties`）；临时目录 `temp.directory=/home/syy/data/tempfiles/filesystem`（本地 Windows 运行需改）。
- 日志：log4j2 异步（`Boot.main` 第一行设 `Log4jContextSelector`，Boot.java；配置 `src/main/resources/log4j2.xml`）。

## 跨层修改红线

| 修改对象 | 影响 | 要求 |
|---|---|---|
| V1 方法签名/op 名 | 所有内部 RPC 调用方（app处理服务、任务管理服务、数据源、文件管理服务） | 只能加 op，不能改老 op 语义；新旧灰度期双写 |
| `script_file`/`common_file`/`common_app` 等共享表结构 | 文件管理服务 同库同表 | 两服务同步改同步发 |
| `FileApi.cleanCacheByFileId` 行为 | 跨服务缓存一致性 | 与文件管理服务上传链路一起评估 |
| Redis 队列名/消息结构 | 后台线程与消费者（部分消费者在别的服务） | 全链路排查生产者/消费者 |
| `PackageExt` 等 ICE 遗留 bean | 旧调用文档对齐 | 仅兼容扩展 |
