## 双入口架构

| 入口 | 路径 | 技术 | 路由方式 |
|------|------|------|----------|
| ApiServlet | `/*`（兜底） | 原生 Servlet + 反射 | `action=包名` → 包路径, `op=类.方法` → 反射调用 |
| DispatcherServlet | `/v3/*` | Spring MVC | `@RequestMapping` 注解路由 |

- `/*` → `ApiServlet`：action/op 参数决定 `cn.testin.service.{action}.{ClassName}` 类的反射调用。action 可以是 `script`、`app`、`suite`、`ai`、`voice`、`form`、`file`、`result`、`tab`、`thirdparty`
- `/v3/*` → `DispatcherServlet`：`@RestController` 注解，`/v3` 前缀由 DispatcherServlet 剥离后交给 Spring MVC 路由

## 数据库

单数据库 `db_file`，MySQL 实例 `mysql.pro.testin.cn:3306`。约 36 张业务表。

Druid 连接池，`SessionFactoryUtil` 手动管理 SqlSession，非 Spring 自动装配数据源（`exclude={DataSourceAutoConfiguration.class}`）。

## 核心业务域

### 1. 脚本管理（script_file + 关联表）

脚本全生命周期管理。核心流程：脚本创建/解析 → 步骤编辑 → 参数/数据源关联 → 校验 → 导入导出/批量操作。

涉及表：`script_file` → `script_step` → `script_relation`（父子脚本依赖）→ `script_param`（参数）→ `script_check`（校验状态）→ `script_tag`（标签）

关键流程：上传脚本 zip/json → 解析生成步骤 → 编辑步骤/参数 → 脚本校验 → 导出/复制到其他项目。

### 2. 目录管理（script_dir + script_dir_child）

树形目录结构管理脚本归属。支持懒加载和全量加载、环形引用检测、目录排序、脚本-目录关系维护。

### 3. 测试套件（suite_info + suite_script + suite_app）

应用级别的测试套件管理，一个套件可关联多个 App、多个脚本。

### 4. 导入导出

异步队列模式：DispatchThread 轮询 Redis 队列 → WorkThread 处理 → 结果回写 Redis。支持脚本导入导出和数据源导入导出两套系统。

### 5. Python 脚本引擎

通过 XML-RPC 远程调用 Python 执行环境，支持执行、调试、函数发现、参数解析。

## 后台线程全景

- `Boot.main()` 启动：
  - `OemStartThread`：每 5 分钟加载 OEM 系统配置
  - `ParseAppStartThread`：每 30 秒解析应用信息队列
  - `fixedThreadPool(18)`：
    - `TestinScriptManageService.getParseJobTaskThread()`：脚本解析任务
    - `TestinScriptManageService.getImportJobTaskThread()`：脚本导入任务
    - `ScriptService.getBatchRfJob()`：批量回收站任务
    - `ExportDispatchThread`：资源导出分发
    - `ImportDispatchThread`：资源导入分发
  - `initExportScript()`：
    - `ScriptExportDispatchThread`：脚本导出分发（轮询 Redis 队列）
    - `CleanScriptExportFileThread`：清理过期导出文件（每小时）

- 外部线程（通过 `ThreadPoolUtils` 提交）：
  - 脚本导出/导入 Worker 线程
  - 脚本复制异步任务
  - 文件下载 Worker 线程

- `DeleteTempFileThread`：定时清理临时文件
