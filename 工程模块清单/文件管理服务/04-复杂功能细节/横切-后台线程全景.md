# 横切-后台线程全景

> 文件管理服务 模块中所有后台线程（守护线程、定时任务、Redis 消费者）的完整清单。按启动方式分为三类：Servlet init 时启动、Spring Bean 初始化启动（@PostConstruct / ApplicationContextAware）、EventBus 事件启动。

## 一、OemInitServlet.init() 启动的线程

### 1. OemStartThread

- **触发**: `Servlet.init()` → `ScheduledExecutorService.scheduleAtFixedRate`
- **周期**: 每 300 秒（5 分钟）
- **职责**: 定时刷新 OEM 配置（`Config.loadConfig()`），从配置中心/数据库拉取最新系统配置
- **读表**: 配置表
- **外部调用**: 配置中心（如 Redis/DB）
- **线程**: `ScheduledExecutorService` 单线程

### 2. FileMergeThread

- **触发**: `Servlet.init()` → `ThreadPoolExecutor.execute()`
- **周期**: 持续运行（阻塞队列消费者）
- **职责**: 消费文件分片合并队列 `FileMergeUtils.getFileMergeQueue()`
- **线程池**: core=1, max=5, 无界队列 `LinkedBlockingQueue`
- **命名**: `FileMerge-thread-%d`
- **外部调用**: 文件存储（FastDFS/MinIO）

### 3. SyncScriptNoStatusThread

- **触发**: `Servlet.init()` → `ThreadPoolExecutor.execute()`
- **周期**: 持续运行
- **职责**: 同步脚本号（scriptNo）状态到用例服务
- **线程池**: core=1, max=5, 无界队列 `LinkedBlockingQueue`
- **命名**: `SyncScriptNoStatus-thread-%d`
- **外部调用**: Case 服务 HTTP 调用

## 二、Spring Bean 初始化为后台线程

### 4. MqNoticeDataThread

- **触发**: `StartupListener.setApplicationContext()` → `ScheduledExecutorService.scheduleAtFixedRate`
- **周期**: 每 200 毫秒
- **职责**: 从 `db_mq.mq_info` 表扫描 PENDING 状态通知，推入内存队列
- **操作**:
  1. `cleanByCompleted(vhost, types)` -- 清理已完成/过期通知
  2. `listByPending(vhost, types, 0, 100)` -- 查询待处理通知（上限 100 条）
  3. `pushJobqueue(channel, notice)` -- 推入内存队列
- **读表**: `mq_info` (db_mq)
- **写表**: `mq_info` (db_mq) -- 通过 cleanByCompleted

### 5. NoticeDispatchThread

- **触发**: `StartupListener.setApplicationContext()` → `new Thread().start()`
- **周期**: 持续运行（内存队列消费者）
- **职责**: 从内存 `jobqueue` 中取通知并 dispatch 到 `NoticeServiceImpl.handle()`
- **参数**: batchSize=100, delay=10ms, period=100ms
- **外部调用**: RealTest 服务、FileApi、文件存储

### 6. CleanResultScheduleWorker

- **触发**: `CleanResultStartupListener.setApplicationContext()` → `ScheduledExecutorService.scheduleAtFixedRate`
- **周期**: 每 1 分钟
- **职责**: 扫描 `script_result` 表，将过期的测试结果文件从 FastDFS 删除
- **读表**: `script_result`
- **写表**: `script_result` (update isClean=2 / delete)
- **外部调用**: FastDFS (deleteRemoteFile)、HTTP (getRemoteFileContent)

### 7. CheckScriptStartupListener

- **触发**: `CheckScriptStartupListener.setApplicationContext()` → `ScheduledExecutorService`
- **周期**: 单次调度（代码中 `CleanResultScheduleWorker` 的调用已被注释）
- **职责**: (历史) 脚本检测结果清理
- **状态**: 当前版本中清理逻辑已注释，保留空壳

## 三、@PostConstruct 启动的定时任务

### 8. CleanLocalTrashFileWorker

- **触发**: `@PostConstruct init()` → `ScheduledExecutorService.scheduleAtFixedRate`
- **周期**: 每天 1 次
- **职责**: 清理临时目录 `Config.TEMP_DIR_PATH` 中超过 `fastDFSService.getCleanTempSeconds()` 秒的过期临时文件
- **操作**: 执行 `ls -all --time-style --sort=time -r` 列出文件 → 按时间排序 → 删除过期文件
- **读写**: 本地磁盘 `FileUtils.forceDelete()`
- **外部调用**: 无（纯本地文件操作）

### 9. DeleteRemoteFileByExpireTimeWorker

- **触发**: `@PostConstruct init()` → `ScheduledExecutorService.scheduleAtFixedRate`
- **周期**: 每 30 分钟（首次延迟 5 分钟）
- **职责**: 查询 `common_file` 表中 `expiretime < now` 的超期文件，从 FastDFS 删除远程文件后标记已删除
- **读表**: `common_file` (selectExpiredFileList)
- **写表**: `common_file` (updateToDeleted)
- **外部调用**: FastDFS (deleteRemoteFile)
- **状态**: 代码注释标注"TODO MINIO上线后正式移除这个逻辑"

### 10. DeleteRemoteFileExecutorWorker

- **触发**: `@PostConstruct init()` → `ScheduledExecutorService.scheduleAtFixedRate`
- **周期**: 每 5 分钟
- **职责**: 从 Redis SET `Task_SET_DELETE_REMOTE_FILE_URLS` 中取待删除的文件 URL，调用 FastDFS 删除，成功后从 Redis 中移除
- **读 Redis**: `Task_SET_DELETE_REMOTE_FILE_URLS` (SMEMBERS)
- **写 Redis**: `Task_SET_DELETE_REMOTE_FILE_URLS` (SREM)
- **外部调用**: FastDFS (deleteRemoteFile)

### 11. ScheduledDeleteCommonFileRecord

- **触发**: `@PostConstruct init()` → `ScheduledExecutorService.scheduleAtFixedRate`
- **周期**: 每 3 秒
- **职责**: 从 Redis SET `Task_SET_DELETE_COMMONFILE_RECORDS` 中取待删除的 `common_file` 记录 ID，执行物理删除
- **读 Redis**: `Task_SET_DELETE_COMMONFILE_RECORDS` (SMEMBERS)
- **写表**: `common_file` (deleteByPrimaryKey)
- **写 Redis**: `Task_SET_DELETE_COMMONFILE_RECORDS` (SREM)

### 12. ScheduledDeleteScriptResultRecord

- **触发**: `@PostConstruct init()` → `ScheduledExecutorService.scheduleAtFixedRate`
- **周期**: 每 10 秒
- **职责**: 从 Redis SET `Task_SET_DELETE_SCRIPT_RESULT_RECORDS` 中取待删除的 `script_result` 记录 ID，执行物理删除
- **读 Redis**: `Task_SET_DELETE_SCRIPT_RESULT_RECORDS` (SMEMBERS)
- **写表**: `script_result` (deleteByPrimaryKey)
- **写 Redis**: `Task_SET_DELETE_SCRIPT_RESULT_RECORDS` (SREM)

## 四、Redis 消费者线程（ScriptDispatchThread）

### 13. ScriptDispatchThread (普通队列)

- **触发**: Spring Bean 初始化（通过 `IScriptService` 的 `@PostConstruct` 或外部启动类构建多个实例）
- **周期**: 持续运行（`while(true)` BLPOP 循环）
- **职责**: 阻塞消费 Redis 队列中的 `ScriptCheckTask`，提交到线程池执行 `SyncValidatorWorker`
- **读 Redis**: `iqueuedao.pop(queueName)` (BLPOP)
- **线程池**: core=5, max=50, queue=1, keepAlive=5min
- **外部调用**: `SyncCheckScriptServiceImpl.check()` → 文件存储 (HTTP HEAD) / DB 读写

### 14. ScriptDispatchThread (延迟队列)

- **周期**: 同上，但消费的是延迟队列
- **职责**: 处理重试任务，`task.getHandleTime()` 非空时 sleep 到指定时间再执行
- **外部调用**: 同普通队列

## 五、EventBus 事件启动的线程

### 15. SyncValidatorWorker (线程池)

- **触发**: `ScriptDispatchThread` 提交 → `ListenableTaskMgr` Guava ListeningExecutorService
- **周期**: 按需，任务驱动
- **职责**: 封装 `SyncCheckScriptServiceImpl.check(task)` 的调用
- **外部调用**: 文件存储 (HTTP HEAD) / DB (script_check, script_check_status_sync) / Case 服务

### 16. CleanResultWorker

- **触发**: `CleanResultScheduleWorker` 提交到线程池
- **周期**: 按需，任务驱动
- **职责**: 逐个处理过期的 `script_result` 记录，删除关联 FastDFS 文件
- **外部调用**: FastDFS (deleteRemoteFile)、HTTP (getRemoteFileContent)

### 17. TestFileWorker

- **触发**: `TestFileParseTask.handleTargetWithUpload()` → `PoolFactory.submit()`
- **周期**: 按需，任务驱动
- **职责**: 并发上传测试结果中的子文件（截图、日志等）
- **外部调用**: 文件存储 (uploadService)
