# 横切-上传鉴权体系

> 文件管理服务的鉴权按调用方分成三类，彼此独立：面向平台用户/页面的 **sid 登录态鉴权**、面向第三方业务服务的 **token 开放上传鉴权**、面向内部运维的 **硬编码口令鉴权**。跨服务调用方向一律以代码里的 `ApiUtil.doPress(prefix, op)` 为准。

## 一、sid 登录态鉴权

核心是 `AuthApi.getUserOnline(sid)`，它向平台基础功能服务发起 `action=user, op=Online.getUserOnline`（前缀 `UserManager`），返回 `UserOnline{userid, eid, ...}`：

```
AuthApi.getUserOnline(sid) → ApiUtil.doPress("UserManager", {action:user, op:Online.getUserOnline, data:{sid}})
```

使用点（均为同步 HTTP 换取登录态，注入 uid/eid/uname 后继续上传）：

| 入口 | 鉴权方式 |
|---|---|
| `FileUploadController.uploadApp`（`/file/upload-app`） | `public_access_auth` 默认 true 时校验 sid；false 时跳过（内部调用） |
| `AppV3Controller.uploadApp`（`/file_system/app/upload`） | 强制 `getUserOnline(sId)`，失败返回 "sid is invalid" |
| `AppUploadController.checkAuth`（分片上传） | sid + `AuthApi.myProjects(eid, userid)` 校验项目组归属 + suiteId 有效性 |
| `RebuildController.scriptStep` | `getUserOnline(sid)` 认证失败即返回 "sid认证失败" |
| `OpenUpload`（原始 Servlet） | `parseHttpRequest(request, true, false)` 只验 sid 不验 token |
| `UrlController.checkAuth` | 当前 `checkAuth(request, false)` 传入 auth=false，**不强制鉴权** |

`AuthApi.myProjects` 走 `op=Project.getUserProjectList`（前缀 `UserManager`），分页拉取用户项目组列表，返回 status>0 的 projectid 集合，供分片上传校验项目组归属。

## 二、token 开放上传鉴权

给第三方业务服务（自动打包流水线等）用的服务级凭证，签发与校验两端：

**签发**（`TokenController`）：

- `GET /token/get`：参数 `serivceId` + `publicKey`；`publicKey` 必须等于 `MD5(serivceId + privateKey)`；通过后生成 UUID token 写入 Redis `fileUpload_{serivceId}`，TTL 7200 秒。
- `POST /token/registerService`：参数 `serviceName`；生成 `privateKey = Base64(timestamp).substring(1,10)` 写入 `upload_service_auth` 表并返回。

**校验**（`UploadFileRequest.parseHttpRequest(request, needSid, needAccessToken)`，`needAccessToken=true` 时）：

1. UPLOAD-JSON 取 `serviceId` + `accessToken`，缺一即失败；
2. `UploadAuthService.get` 查 `upload_service_auth` 确认 serviceId 已注册；
3. Redis `fileUpload_{serviceId}` 不存在 → token 过期；`accessToken` 不等于 Redis 值 → token 无效。

**当前状态**：`parseHttpRequestWithToken`（`needAccessToken=true`）在本分支无任何调用方，`HttpStreamUpload`/`OpenUpload` 均未启用 token 校验。token 机制是"定义完备、未接线"，勿据此认为第三方上传已受 token 保护。

## 三、内部硬编码口令鉴权

脚本校验相关内部接口共用同一硬编码 key `fa568093e6354882a534dbce946c9d53`：

| 入口 | 位置 |
|---|---|
| `ApiController.checkScript` / `checkScriptAgain` / `getScriptCheckResult` | `cn.testin.filecloud.web.controller.ApiController` |
| `cn.testin.service.fs.Script.checkScript`（V1 `Script.checkScript`） | `cn.testin.service.fs.Script` |

该 key 是内部约定口令，不应出现在公开文档/前端；`fs.Script.checkScript` 额外要求 `key` 与 `scriptid` 均有效。

## 四、跨服务调用方向（以代码为准）

| 客户端类 | 目标 prefix | action/op | 方向 |
|---|---|---|---|
| `AuthApi.getUserOnline / myProjects / getUser` | `UserManager` | `Online.getUserOnline` / `Project.getUserProjectList` / `User.getUser` | → 平台基础功能服务 |
| `ProjectApi.get`（`cn.testin.api.user.ProjectApi`） | `UserManager` | `Project.get` | → 平台基础功能服务 |
| `FileApi.cleanCacheByFileId / getLastestScriptWithNoApp`（`cn.testin.api.file.FileApi`） | `Script`（`BaseApi.fileManagement="Script"`） | `FileApi.cleanCacheByFileId` / `Script.getLastestScriptWithNoApp` | → 脚本服务 filesystem |
| `SuiteApi.bind`（`cn.testin.api.suite.SuiteApi`） | `Script`（复用 `fileManagement`） | `Suite.bind` | → 脚本服务 filesystem |
| `RealTestApi.taskComplete` | `RealTest` | `Task.complete` | → app处理服务 real-test |
| `BladeApi.saveScript`（恒生） | 直连 HTTP `bladeUrl` | — | → 恒生 Blade 平台（不走 doPress） |

> 注意：本仓库内 `BaseApi.fileManagement` 的实际值是 `"Script"`，不是 `"File"`；`FileApi`/`SuiteApi` 是 fileupload 调 filesystem 的客户端，不是服务端。
