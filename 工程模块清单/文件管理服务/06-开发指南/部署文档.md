# 文件管理服务 部署文档

> 工程：`D:\programfile\major\java\testin\workspace\fileupload`（JDK 1.8 / Spring 4.2.6，**WAR 包**，artifactId=fileupload-web）。本文基于 Dockerfile 的构建/启动命令整理；镜像由 CI 产出供 k3s 使用。本地启动 pom.xml 修改见文末内部 wiki 链接。

## Docker 镜像构建（两阶段）

| 阶段 | 基础镜像 | 作用 |
|---|---|---|
| BUILD | `reg-noc.testin.cn/pub/mevan:8u341` | 带 JDK8 + Maven，编译打 WAR 并解压 |
| RUN | `hub-mirror.testin.cn/library/busybox:stable` | 只承载解压后的 WAR 目录，启动时解包到挂载卷 |

### 打包命令（BUILD 阶段）

```bash
/var/maven/bin/mvn clean install -P privateCloud -Dmaven.test.skip=true
mkdir -p /data/webhome/autodeploy && cd /data/webhome/autodeploy && /var/java/bin/jar xvf /data/webhome/target/fileupload-web.war
```

- 激活 `privateCloud` profile（私有云），跳过测试。
- 打包后把 `fileupload-web.war` 解压（`jar xvf`）到 `autodeploy/`，作为 **exploded WAR** 交付。

### 启动方式（WAR 部署，非 fat jar）

- 无独立 `java -jar` 启动命令；镜像里不含 JVM 启动参数。
- 解压产物部署到 Tomcat 容器的 `webapps/ROOT`（`COPY --from=BUILD .../autodeploy /ROOT`），由外部 Tomcat 8+ 提供 Servlet 容器与 Java 运行时。

### 运行阶段（busybox）

- 挂载卷：`VOLUME /data/webhome /home`
- CMD：`cp -R /ROOT/* /data/webhome/` 解包 + 创建目录 `/home/syy/data/logs/fileupload`、`/home/syy/data/tempfiles/fileupload`

## 镜像构建与推送（.gitlab-ci.yml）

| 触发 | 命令 | 镜像 tag |
|---|---|---|
| 打 tag | `docker buildx build -f Dockerfile --platform linux/arm64,linux/amd64 -t $CI_REGISTRY_IMAGE:$CI_COMMIT_TAG . --push` | `$CI_REGISTRY_IMAGE:$CI_COMMIT_TAG` |
| `syy.release.*` 分支 | `docker build --pull` + 两次 `docker push` | `$CI_REGISTRY_IMAGE:$CI_COMMIT_REF_SLUG-<短SHA>` 与 `...:$CI_COMMIT_REF_SLUG` |

构建前 `docker login` 到 `$CI_REGISTRY`；DOCKER_HOST 指向 `tcp://registry.testin.cn-public-docker:2375`。

## 部署到 k3s

镜像推送后，k3s 工作负载引用镜像 tag；busybox CMD 把解压后的 WAR 目录（`/ROOT`）拷到 `/data/webhome`，由外部 Tomcat 容器加载。运行时前置依赖 MySQL（db_file + db_mq）、Redis、FastDFS/MinIO 之一，详见 [开发指南](开发指南.md)。

## 本地打包与启动

```bash
/var/maven/bin/mvn clean install -P privateCloud -Dmaven.test.skip=true   # 打包（或用本机 mvn clean package -DskipTests）
```

- 产物：`target/fileupload-web.war`（WAR 包）。
- 本地运行：Tomcat 8+ 传统 WAR 部署（`mvn tomcat7:run` 或丢进本地 Tomcat webapps），详见 [开发指南](开发指南.md) 的「本地构建与运行」。

## 本地启动 pom.xml 修改

fileupload 的 `<resources>` 直接 `include **/*.properties|xml`，无 config 外置，**本地启动无需此 pom 修改**；Docker 侧也保持 WAR 解压形态。
