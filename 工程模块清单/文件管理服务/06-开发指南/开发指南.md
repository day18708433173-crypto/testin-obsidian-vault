## 分层约定

- **三套路由并存**：`/openapi/v3/*` → DispatcherServlet 注解 Controller；`/*` → ApiServlet 按 `action=fs&op=类.方法` 反射调 `cn.testin.service.fs.*`；`/HttpPostUpload` 等 → web.xml 直接映射的原始 Servlet。新功能优先加在注解 Controller，不要新增 ApiServlet 入口。
- **Controller 继承 `GenericFileProcess`**：上传类 Controller 复用 `processsFacade` 门面（参数→临时文件→责任链→删临时文件），业务差异通过新的 `FileUploadProcessor` 实现类 + `@ProcessorOrder` 扩展，不要在 Controller 里堆逻辑。
- **存储只走 `UploadService` / `FileUploadServiceFactory.fileUploadService`**：业务代码禁止直接注入 `FastDFSService` 或 `MinioService`。
- **mapper XML 与接口同目录**（`filecloud/dao/mapper` + `filecloud/dao/mapping`），表模型在 `filecloud/model`。
- **常量/枚举**：`filecloud/common/constants|enums`（BizCode、FileTypeConstants、FileSource 等）。

## 本地构建与运行

```bash
# 打包（跳过测试）
mvn clean package -DskipTests

# 产物
target/fileupload-web-1.2.0.war
```

- 部署形态：Tomcat 8+ 传统 WAR 部署（非内嵌容器），本地可用 `mvn tomcat7:run` 或手动丢进本地 Tomcat webapps。
- 运行前置依赖：MySQL（db_file + db_mq）、Redis、FastDFS 或 MinIO 之一、平台基础功能服务（用户鉴权 AuthApi）。
- profile 通过 `resources/profiles/*.profile` 选择（dev/test/pre/production/privateCloud/taibaoPrivateCloud/wjxPrivateCloud/zhonghangPrivateCloud），占位符如 `${traker_site}`、`${uploadserver_temp_directory}` 在打包/启动时注入。
- 启动初始化在 `OemInitServlet`：拉起 OEM 配置刷新、分片合并、脚本状态同步等后台线程（详见 [横切-后台线程全景](../04-复杂功能细节/横切-后台线程全景.md)）。

## 存储配置要点（FastDFS / MinIO）

**后端是部署期二选一，不是运行时主备兜底**：

1. 开关：`Config.MINIO_USABLE`（`src/main/java/cn/testin/utils/Config.java`）。读取顺序：环境变量 `MINIO_USABLE` → `config.properties` 的 `minio.usable`（`Config.java`）。
2. 选择逻辑：`FileUploadServiceFactory.getInstance` 按开关取 Spring bean `minioUploadService` 或 `fastDFSFileUploadService`，缓存为静态字段，进程内不变（`src/main/java/cn/testin/filecloud/core/FileUploadServiceFactory.java`）。
3. 对外 URL 前缀：`Config.getPublicFileBaseUrl()`（`Config.java`）——MinIO 用 `MINIO_BASE_URL`，FastDFS 用 `TRACKER_SERVICE_PATH`（来自 OEM 初始化，`db_user.system_param` 的 `oem_upload_file_url`）。**该值为空时所有上传直接失败**（`UploadService.java`，报"oem初始化未完成"），本地起服务先确认 OEM 初始化完成。
4. FastDFS：tracker 地址在 `fdfs_client.conf` 的 `tracker_server=${traker_server}`；>10M 文件服务端内部走断点续传（`FastDFSService.java`）；上传失败重试上限 `filecloud.fdfs-max-retry-times=3`（filecloud.properties）。
5. MinIO：连接参数全走环境变量注入（`minio.properties`：`MINIO_SERVICE_HOST/PORT/ROOT_USER/ROOT_PASSWORD/BUCKET_NAME`），桶配额默认关闭（`MINIO_QUOTA_ENABLE:false`）。
6. 临时目录：`config.properties` 的 `temp.dir.path`，缺省 `/home/syy/data/tempfiles/fileupload`（`Config.java`）。本地 Windows 开发必须显式配置，否则写临时文件直接失败。

## 新增一个上传类功能的标准流程

1. 明确 bizCode / 文件类型：在 `filecloud/common/enums/BizCode`、`constants/FileTypeConstants` 登记（尽量复用现有值）。
2. 写处理器：继承 `AbstractFileProcessor`（App 类可参考 `AppFileProcessor` 的模板方法），实现 `care()` 匹配条件 + `process()` 业务，类上标 `@ProcessorOrder` 定序，注册为 Spring bean。
3. 存储一律走 `UploadService.handle`；入库先写 `common_file` 再写业务表。
4. 入口：新功能加注解 Controller（路径风格 `/资源/动作`），需要兼容旧客户端才考虑 ApiServlet。
5. 需要异步/通知：校验类参考 [脚本校验引擎实现](../03-实现逻辑/脚本校验引擎实现.md) 的 Redis 队列模式；通知参考 [横切-通知系统](../04-复杂功能细节/横切-通知系统.md)。

## 跨端修改红线

| 修改对象 | 影响 | 要求 |
|---|---|---|
| `ScriptCheckTask` 字段 | 校验队列 gson 序列化协议 | 生产者/消费者同版本发版；灰度期新旧任务共存 |
| Redis 队列名 `:fileupload:script.check` | 校验生产/消费寻址 | 代码内常量，两端同改同发 |
| db_file 表结构 | 脚本服务共享该库 | 与脚本服务（filesystem）同步评估、同步上线 |
| 对外 URL 拼接格式（`?filename=` 后缀） | 全链路下载方 | 上位机/任务管理服务都按此格式解析 |
| `/openapi/v3/*` 出入参 | 任务管理服务 FileUploadServiceApi/FileDownloadApi | 按开放接口契约走评审，见 [07-开放接口文档](../07-开放接口文档/00-模块索引.md) |
