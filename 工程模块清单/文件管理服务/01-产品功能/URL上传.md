# URL 上传

> 本文是 [04-核心链路-URL上传](../04-复杂功能细节/核心链路-URL上传.md) 的自然语言版（不含代码细节）。

## 功能是什么

不直接传文件，而是**给平台一个 App 包的下载地址**，由平台在后台自己去下载、解析、登记。适合包已经在某个文件服务器上、调用方不想先下载再上传的场景（典型的是自动化流水线：构建完把包地址直接推给平台提测）。

## 工作方式

这是一条**异步链路**，调用方要有"提交 ≠ 完成"的预期：

1. 调用方提交下载地址、平台类型、任务标识等信息；
2. 平台收下任务后**立即返回成功**——此时只是"任务已受理"，包还没有下载解析；
3. 平台后台去远程地址下载安装包，按平台类型走与表单上传相同的解析登记流程（见 [APP 上传与解析](APP上传与解析.md)）；
4. 解析完成后，平台**主动通知下游的真实测试服务**：任务可以继续走了。结果信息（包信息、下载地址等）随通知一并下发。

## 需要提供的参数

| 参数 | 说明 |
|---|---|
| 包下载地址 | 可通过 HTTP/HTTPS 直接下载的地址 |
| 平台类型 | Android / iOS / 鸿蒙 / 鸿蒙 NEXT，决定按哪种格式解析 |
| 任务标识 | 用于把解析结果关联回发起方的任务 |

## 约束与异常表现

- **任务有有效期**：受理的任务约 5 小时内有效，超时未处理完会自动失效，需要重新提交。
- **下载失败会重试**：远程地址暂时不通、下载中断等情况，平台会自动重试；重试多次仍失败的，放弃处理并**通知下游任务失败**——发起方能明确感知失败，而不是任务无声消失。
- **地址必须可直连**：下载地址如果返回非成功响应（如 404、需要鉴权跳转），按下载失败处理，进入上述重试/失败通知流程。
- **解析结果与表单上传一致**：同一个包无论从文件上传还是从 URL 下载，解析、查重、登记的规则完全相同。

## 使用建议

- 流水线集成时，**以下游的完成/失败通知为准**驱动后续流程，不要在提交后立刻假设包已可用。
- 下载地址尽量用稳定、长期有效的地址；临时签名地址要确保证有效期覆盖平台的下载与重试窗口。
