# APP 上传与解析

> 本文是 [04-核心链路-APP上传与解析](../04-复杂功能细节/核心链路-APP上传与解析.md) 的自然语言版（不含代码细节），其中"哪些文件类型走哪条解析"的规则合并自 [04-横切-文件上传责任链](../04-复杂功能细节/横切-文件上传责任链.md)。

## 功能是什么

把 App 安装包（APK / IPA / HAP）上传到平台，平台自动**解析出包名、应用名、版本号、图标、文件指纹等信息**并登记入库，之后提测选包、脚本录制、任务执行都基于这份登记信息使用。上传成功后返回下载地址和解析出的应用信息。

## 能做什么

- **三平台安装包解析**：
  - Android（.apk）：解析包名、版本、图标，并额外提取 RSA 签名信息；
  - iOS（.ipa）：解析包名、版本、图标；
  - 鸿蒙（.hap，含鸿蒙 NEXT）：解析包名、版本、图标。
- **重复上传去重**：平台按文件指纹（MD5）识别"这个包以前传过"。重复上传同一个包**不会重复占用存储**，直接返回已有的登记信息和下载地址，秒级完成。
- **应用登记与绑定**：首次上传的包会登记为新应用（按"包名 + 平台"识别同一个应用的不同版本），并把包绑定到指定应用下，供提测时按应用选版本。
- **解析失败可见**：包损坏或格式不对时，解析结果中会带失败原因，上传方能看到具体错误。

## 约束与限制

- **只接受三种扩展名**：apk、ipa、hap。其他格式的文件走这个入口会被直接拒绝，提示"该接口只接受 App 格式的文件"。
- **需要登录鉴权**：上传时校验用户身份，并记录上传人。
- 大文件建议走 [分片上传](分片上传.md)，不便于表单直传的场景可走 [URL 上传](URL上传.md)。

## 文件类型的自动识别

平台接收文件后会**根据文件类型自动选择对应的处理方式**，调用方不用关心内部路由：

| 文件类型 | 走向 |
|---|---|
| .apk / .ipa / .hap | App 解析链路：解析包信息、登记应用、绑定 |
| 脚本 ZIP 包 | 脚本处理链路：登记脚本、解析步骤、触发脚本校验 |
| 视频文件 | 视频处理链路 |
| 其他未识别的文件 | 通用文件上传：只登记文件信息和下载地址，不做解析 |

处理完成后，上传产生的临时文件会被自动清理；处理过程出错时已写入的数据会回滚，不会留下"半个应用"的脏数据。

## 异常时的表现

| 场景 | 用户可见表现 |
|---|---|
| 传了非 apk/ipa/hap 文件 | 直接报错"该接口只接受 App 格式的文件" |
| 包已上传过 | 正常返回，内容为首次上传时的登记信息（不重复处理） |
| 包损坏/解析失败 | 返回解析失败原因 |
| 未登录或身份无效 | 鉴权失败，上传被拒绝 |
