# 脚本录制上传

> 本文是 [04-核心链路-脚本录制上传](../04-复杂功能细节/核心链路-脚本录制上传.md) 的自然语言版（不含代码细节）。

## 功能是什么

录制工具（Web 录制器、PC 录制器等）把录好的脚本提交到平台的入口。提交的内容包括脚本步骤、声明的变量、用到的控件、环境配置、脚本包下载地址等。平台接收后登记脚本、保存步骤、维护版本，并**自动触发脚本校验**——一次提交，脚本立刻进入平台的脚本管理体系。

## 提交后平台做了什么

1. **校验提交内容**：检查必备字段是否齐全、取值是否合法（规则见下）。
2. **登记脚本版本**：同一脚本编号每次提交生成一个新版本（版本号自动递增），历史版本保留，可随时回溯。
3. **保存步骤**：录制的步骤列表整体保存为步骤文件并关联到脚本，步骤里引用子脚本的（调用子脚本、区域监控等类型）会被自动识别并关联到平台已有的子脚本。
4. **维护"最新版本"索引与应用绑定**：脚本管理页面看到的始终是最近一次提交的版本；需要绑定应用的脚本会完成与应用的关联。
5. **投递异步校验**：提交成功后脚本自动进入 [脚本校验](脚本校验.md) 流程，校验结果随后可查。

## 校验规则（提交时）

| 规则 | 不满足时的表现 |
|---|---|
| 脚本编号必须是数字 | 直接报错，拒绝提交 |
| 步骤列表不能为空 | 直接报错，拒绝提交 |
| 脚本包下载地址不能为空 | 直接报错，拒绝提交 |
| 上传元数据（企业、项目、用户、应用、文件指纹等）必须齐全 | 直接报错，拒绝提交 |
| 指定了应用时，应用必须真实存在且与项目匹配 | 提示应用与项目不匹配，拒绝提交 |
| **同一脚本编号不能跨项目使用**：编号已有脚本且属于别的项目时 | 提示脚本关联的项目无效，拒绝提交——防止多人共用账号时脚本串项目 |

## 业务规则

- **版本递增**：同一编号重复提交不会覆盖旧版本，而是生成新版本；脚本的唯一标识（UUID）在各版本间保持不变，引用关系不受换版影响。
- **脚本类型自动识别**：根据提交内容自动判定是 Web 脚本、PC 脚本还是 App 脚本，无需调用方显式指定。
- **第三方回调（可选）**：提交时可要求平台把脚本信息回调给合作的第三方平台（如恒生）；回调失败**不影响**脚本提交本身，脚本照常保存。
- **步骤保存失败会回滚**：步骤处理出错时，本次已写入的脚本记录会被删除，不会留下没有步骤的"空壳脚本"。
