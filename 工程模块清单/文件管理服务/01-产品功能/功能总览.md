# 功能总览

> 本页是功能维度的总索引：每个功能一句话定位 + 端点/入口清单 + 深入阅读链接。代码级细节见 [03-App包上传与解析实现](../03-实现逻辑/App包上传与解析实现.md)、[03-脚本校验引擎实现](../03-实现逻辑/脚本校验引擎实现.md) 与 [04-专题索引](../04-复杂功能细节/专题-索引.md)。

## 功能清单

### 1. App 包上传与解析

接收 APK / IPA / HAP 安装包，解析包名/版本/图标/MD5/RSA 签名，登记 common_file + common_app + package_file，产出 appUrl。代码级链路见 [App包上传与解析实现](../03-实现逻辑/App包上传与解析实现.md)。

| 端点 | 入口 | 说明 |
|---|---|---|
| `POST /file/upload-app` | `FileUploadController.uploadApp`（`src/main/java/cn/testin/filecloud/web/controller/FileUploadController.java`） | 页面/接口直传，multipart 单文件，仅接受 apk/ipa/hap |
| `POST /app/checkChunk` `/app/upload` `/app/mergeChunk` | `AppUploadController`（`src/main/java/cn/testin/filecloud/web/controller/AppUploadController.java/160/206`） | 大文件分片上传：查已有分片 → 逐片上传 → 合并 |
| `POST /app/uploadByUrl` | `UrlController`（`src/main/java/cn/testin/filecloud/web/controller/UrlController.java`） | 给 URL 由服务端异步下载并走同一解析链路 |
| `POST /file_system/app/upload` | `AppV3Controller`（`src/main/java/cn/testin/filecloud/web/controller/v3/AppV3Controller.java`） | V3 新接口（/openapi/v3 体系） |

深入阅读：[核心链路-APP上传与解析](../04-复杂功能细节/核心链路-APP上传与解析.md)、[核心链路-分片上传](../04-复杂功能细节/核心链路-分片上传.md)、[核心链路-URL上传](../04-复杂功能细节/核心链路-URL上传.md)

自然语言版：[APP上传与解析](APP上传与解析.md)（三种扩展名限制、MD5 查重不重复占存储、文件类型自动路由）、[分片上传](分片上传.md)（逐片询问、合并校验、服务重启进度丢失需重传）、[URL上传](URL上传.md)（提交即返回、约 5 小时任务有效期、失败自动重试并通知下游）

### 2. 脚本上传

Web 录制脚本与 ZIP 脚本包的接收存储；维护 script_file / script_step / script_relation；上传后自动触发异步校验。

| 端点 | 入口 | 说明 |
|---|---|---|
| `POST /script/upload` | `ScriptController`（`src/main/java/cn/testin/filecloud/web/controller/ScriptController.java`） | 脚本上传主入口（录制保存/ZIP） |
| `POST /script/copy` `/script/update` `/script/delete` | `ScriptController` | 脚本拷贝、更新、删除 |
| `POST /file_system/files/upload` | `FileUploadV3Controller`（`src/main/java/cn/testin/filecloud/web/controller/v3/FileUploadV3Controller.java`） | V3 通用文件上传 |
| `POST /script/status/sync` | `ScriptV3Controller`（`src/main/java/cn/testin/filecloud/web/controller/v3/ScriptV3Controller.java`） | 脚本状态同步 |
| ApiServlet `Script.*` / `File.*` | `cn.testin.service.fs.*` | `action=fs&op=类.方法` 反射入口，兼容旧调用方 |

深入阅读：[核心链路-脚本录制上传](../04-复杂功能细节/核心链路-脚本录制上传.md)；自然语言版：[脚本录制上传](脚本录制上传.md)（字段校验规则、版本递增、脚本编号禁止跨项目、自动触发校验）

|---|---|---|
| `GET /api/checkScript` | `ApiController.checkScript`（`src/main/java/cn/testin/filecloud/web/controller/ApiController.java`） | 触发校验（可全量或指定 scriptId），硬编码 key 鉴权 |

| ApiServlet `Script.checkScript` | `cn.testin.service.fs.Script.checkScript`（`src/main/java/cn/testin/service/fs/Script.java`） | 旧体系校验触发 |

## 数据模型要点

数据库 `db_file`，与脚本服务共享。完整 ER 图见 [表关系总览](../02-技术架构/表关系总览.md)。

```
common_file（文件注册中心，所有文件元数据 + URL + MD5）
 ├── package_file（App 版本包）── common_app（应用注册：包名+平台+RSA签名）
 │     └── suite_app（App 与应用的绑定）
 ├── script_file（脚本，版本化存储）
 │     ├── script_step（步骤明细，复合主键）
 │     ├── script_check（校验结果 JSON + 状态）
 │     ├── script_check_status_sync（校验状态跨服务同步队列）
 │     ├── script_relation（脚本父子调用关系，校验引擎依赖检测用）
 │     ├── script_at_last（最新版本冗余）
 │     └── suite_script（脚本与应用的绑定）
 └── script_result（测试结果文件）
upload_service_auth（开放上传服务鉴权私钥）
```

三个设计要点：

1. **一切文件先登记 common_file**：package_file / script_file / script_result 都以 `fileid` 挂到 common_file，URL 只存在 common_file 一处。
2. **MD5 是存储层唯一键**：重复上传同一文件不重复占用存储，直接复用已有 fileid 与 URL。
3. **脚本版本化**：script_file 按版本多行存储，script_at_last 冗余最新版本加速查询；校验状态经 script_check_status_sync 由后台线程同步给用例侧。
