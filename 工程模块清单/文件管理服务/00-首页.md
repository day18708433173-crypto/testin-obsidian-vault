# 文件管理服务 总览

> 平台文件管理服务：APP上传/解析、脚本上传/校验/存储、文件管理、分片上传。本页为分支无关的通用介绍，分支强相关内容见下方分支索引。

## 定位

文件管理服务 是测试平台的"文件中心"，负责文件接收、存储、解析与校验：

| 职责 | 文件管理服务 | 平台基础功能服务 | app处理服务 |
|---|---|---|---|
| APP 文件上传/解析（APK/IPA/HAP） | **核心** | — | — |
| 脚本文件上传（ZIP/Web录制） | **核心** | — | — |
| 脚本校验（步骤合法性/URL可达性） | **核心** | — | — |
| 分片上传与断点续传 | **核心** | — | — |
| 文件存储（FastDFS/MinIO） | **核心** | — | — |
| 通知分发（MQ→各渠道） | **核心** | 辅助 | — |

## 双入口架构

| 入口 | 路径 | 技术 | 路由方式 |
|---|---|---|---|
| BaseServlet (Spring DispatcherServlet) | `/`, `/openapi/v3/*` | Spring MVC | `@RequestMapping` 注解路由 |
| ApiServlet | `/*`（兜底） | 原生 Servlet + 反射 | `action=fs` + `op=类.方法` → 反射调用 |
| 原始 Servlet | `/HttpPostUpload`, `/OpenUpload`, `/uploadService` | 原生 HttpServlet | web.xml servlet-mapping |

- `/v3/*` → DispatcherServlet → `@Controller`/`@RestController` 注解路由
- `/*` → ApiServlet → `action/op` 参数反射调用（例如 `{"op": "Script.checkScript", "action": "fs"}`）
- 原始 Servlet 兼容旧版客户端流式上传

## 技术栈

| 组件 | 版本/说明 |
|---|---|
| Spring Framework | 4.x（传统 XML 配置，非 Spring Boot） |
| Servlet API | 3.1.0 |
| JDK | 1.8 |
| ORM | MyBatis + MyBatis Generator（Mapper XML） |
| 数据源 | Druid 连接池 + 双数据源（业务 db_file + MQ db_mq） |
| 缓存/MQ | Redis（Jedis 直连）+ 自建 Redis 队列 |
| 文件存储 | FastDFS（主）+ MinIO（新）双后端，通过 FileUploadServiceFactory 切换 |
| Web 容器 | Tomcat 8+（传统 WAR 部署） |
| 依赖注入 | Spring XML + @Resource/@Autowired 注解 |
| 日志 | Log4j + 自定义 Logit 封装 |
| 构建 | Maven（pom.xml） |

## 核心业务域

### 1. APP 文件上传与解析

支持 APK（Android）、IPA（iOS）、HAP（鸿蒙）三种原生应用格式的上传与自动解析。上传方式包括：表单直传、分片上传（chunked upload）、URL 远程下载上传。责任链模式处理不同文件类型。

解析流程：`GenericFileProcess.processsFacade()` → `FileProcessFactory` 责任链 → `ApkFileProcessor`/`IpaFileProcessor`/`HapFileProcessor` → 提取包名/版本/图标 → `PersistenceAppPackageService` 持久化。

### 2. 脚本文件上传与校验

Web 录制脚本上传、ZIP 脚本包上传。上传后异步校验：步骤合法性（`CheckScriptStepTask`）、URL 可达性（`CheckScriptUrlTask`）。校验通过 Redis 队列分发到 Worker 线程池。

脚本校验链路：`ScriptFileProcessorV3` → `ScriptProcessorHelper` → `SyncCheckScriptService.asyncCheck()` → Redis 队列 → `ScriptDispatchThread` 消费 → `CheckTaskSupport` 执行 → 回调通知。

### 3. 文件存储

双后端支持：FastDFS（传统分布式文件系统）和 MinIO（S3 兼容对象存储）。通过 `FileUploadServiceFactory` 根据配置切换。所有文件统一记录在 `common_file` 表。

### 4. 分片上传

大文件分片：前端切分 → `/app/checkChunk` 检查已有分片 → `/app/upload` 逐个上传分片 → `/app/mergeChunk` 合并分片 → 正常上传流程。

### 5. 通知系统

上传完成/校验完成/解析失败 → `NoticeServiceImpl.add()` → `MqNoticeDataThread` 取出 → `NoticeStrategy` 策略路由（Success/Fail/Invalid/Retry）→ 写入通知 DB（通过外部 NoticeManager 服务）。

## 后台线程全景

- **OemInitServlet.init()** 启动：`OemStartThread`(5min)、`FileMergeThread`、`SyncScriptNoStatusThread`
- **Spring 配置启动**：`MqNoticeDataThread`（MQ 通知消费）
- **@Scheduled 定时任务**：`CleanLocalTrashFileWorker`（本地临时文件清理）、`DeleteRemoteFileByExpireTimeWorker`（过期远程文件删除）、`DeleteRemoteFileExecutorWorker`、`ScheduledDeleteCommonFileRecord`、`ScheduledDeleteScriptResultRecord`
- **EventBus**：`CheckScriptStartupListener` → `SyncValidatorWorker` 线程池启动
- **Redis 消费者**：`ScriptDispatchThread`（脚本校验任务）、`CleanResultWorker`（结果清理）

| 存储 | 用途 |
|---|---|
| MySQL（db_file） | 文件记录、APP 信息、脚本数据、套件信息（14 表） |
| MySQL（db_mq） | MQ 消息持久化 |
| Redis（db index 7） | 脚本校验队列、Token 缓存、通知去重 |
| FastDFS / MinIO | 文件实体存储（上传下载） |
