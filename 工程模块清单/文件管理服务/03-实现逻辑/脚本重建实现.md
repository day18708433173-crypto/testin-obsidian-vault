# 脚本重建实现

> 本文描述脚本步骤重建链路：`RebuildController.scriptStep` 接收重建条件 → `ScriptServiceImpl.rebuildScriptStepByCondition` 按脚本 ZIP 内容补齐/修正 `script_step`。用于修复"程序造成的脚本步骤不完整、历史属性不满足最新需求"的场景。自然语言版见 [内部工具与脚本重建](../01-产品功能/内部工具与脚本重建.md)。

## 入口

`RebuildController.scriptStep`（`POST /rebuild/scriptStep`）：

1. 必填参数 `projectId`、`sid`、`start`、`end`（13 位时间戳）；可选 `ignoreScriptList`（忽略脚本 id 列表）、`process_cycle`（默认 30）；
2. 校验起止跨度：`end - start` 超过 `1000*60*60*24*process_cycle` 即返回"重建资源周期不能超过1周"——注意代码文案写"1周"，但 `process_cycle` 默认 30，实际默认允许 30 天跨度（文案与实际默认值不一致）；
3. `AuthApi.getUserOnline(sid)` 换 `UserOnline`（sid 认证失败返回失败）；
4. 调 `ScriptService.rebuildScriptStepByCondition(uo, projectId, start, end, ignore)`。

## 主流程 rebuildScriptStepByCondition

`cn.testin.filecloud.service.impl.ScriptServiceImpl.rebuildScriptStepByCondition`：

1. `scriptFileMapper.queryProjectScriptListByCreateTimeRange` 按 projectId + 起止时间（+ 忽略列表）查出待重建脚本列表；
2. 逐个脚本：`FileUtil.saveToFileByUrl(url, TEMP_DIR/rebuild-script-step/{scriptId}.zip)` 下载脚本 ZIP（下载失败跳过该脚本）；
3. `UnzipFileUtil.uncompress` 解压；`StepUtils.getSingleTestCaseFromZipFile` 从 ZIP 取 `TestCase`（格式错误/无步骤则跳过）；
4. 对照 `scriptStepMapper.selectByScriptId` 查到的库表步骤，按三种情况处理：

| 情况 | 判断 | 处理 |
|---|---|---|
| 无步骤记录 | `databaseScriptSteps` 为空 | `rebuildStepRecord` 全量插入步骤 |
| 步骤不完整 | 库表步骤数 < `TestCase.actions` 条数 | 逐条补：缺失步骤 insert、补步骤图片（`uploadFileReturnFileId` 上传期望图片）、补 `childScriptNo/childScriptId`（call 类型引用子脚本）、补 `ext/stepname/stepdesc/steptype/remark` |
| 步骤齐全但缺 ext | 库表步骤数 == actions 条数 | 只逐条补 `ext` 字段（`JSON.toJSONString(testAction)`） |

5. 返回 `{all: 命中脚本数, processed: 成功处理数}`。

关键点：

- **只补不改，不清理**：注释明确"不清理所有的脚本步骤，只处理缺失属性的和脚本步骤不全的记录"；
- **步骤图片上传**：期望图片存在时 `uploadFileReturnFileId` 上传到文件存储，失败间隔 5 秒重试一次，再失败抛 `IllegalArgumentException`；
- **子脚本引用回填**：`testAction.getActionType() == ActionType.call` 且 `childScriptNo` 为空时，解析 calledScriptName（数字）回填 `childScriptNo`，并按 projectId 查最新脚本回填 `childScriptId`。
