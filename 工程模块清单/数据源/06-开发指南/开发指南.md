# 开发指南

> 工程：`datasource-manage`（Java 1.8 / Spring Boot 2.3.7.RELEASE / Undertow / MyBatis-Plus）。先读 [00-首页](../00-首页.md) 建立整体认识（双入口、多数据源、包结构）。

## 分层约定

### 双入口（最重要的认知）

| 入口 | 路径 | 类位置 | 写法 |
|---|---|---|---|
| ApiServlet | `/openapi/*` | `service/source/*Ctrl` | 继承 `GenericBaseService`，方法签名 `String xxx(ApiRequest)`，**手工** objectMapper 反序列化 `reqjson`，返回 JSON 字符串 |
| DispatcherServlet | `/openapi/v3/*` | `controller/` | 标准 `@RestController` + DTO + `ResponseResult` 包装 |

注册在 `Boot`（`src/main/java/cn/testin/startup/Boot.java`）：DispatcherServlet 绑 `/openapi/v3/*`，`ApiServlet` 绑 `/openapi/*`。新增接口**优先走 MVC**；ApiServlet 体系以维护为主。细节见 [横切-双入口路由机制](../04-复杂功能细节/横切-双入口路由机制.md)。

### ApiServlet Ctrl 的特殊点

- 基类 `GenericBaseService`（`src/main/java/cn/testin/service/GenericBaseService.java`）的 service 字段是 `SpringContextUtils.getBean(XxxService.class)` **静态取 bean**，不是 @Autowired——Ctrl 由 ApiServlet 反射实例化，不在 Spring 容器里。
- 返回统一用 `ApiUtil.getResult(apiRequest, code, msg)` / `packageResult(apiRequest, data)`。
- 异常自行 try/catch + `Logit.errorLog`，靠 `e.getMessage()` 关键字（如 `unique_scriptno`）区分业务错误。

### 数据访问

- MyBatis-Plus：`@DS` 切库（dynamic-datasource），默认 `db_source`；`strict: false`，写错数据源名不会报错而是落到默认库（`application.yml`）——**@DS 值写错是静默故障**。
- Mapper XML 放 `src/main/resources/mapper/`（含 `ext/` 子目录），`mapper-locations: mapper/**/*.xml`（`application.yml`）——与 api-test 工程"XML 与接口同目录"的约定**不同**，别放错。
- `map-underscore-to-camel-case: true`；逻辑删除全局生效：`status` 0=删 1=有效（`application.yml`）。
- 分页：PageHelper（`pagehelper-spring-boot-starter` 1.2.13）；MVC 侧列表返回 `PageInfoList` / `ResponseListDTO`。

### 实体与 DTO

- 表实体放 `pojo/`（继承 `BaseModel`，`@TableName`），DO 与传输对象分离：传输放 `dto/`，出参视图放 `vo/`。
- MVC Controller 入参用 `@Valid` + jakarta validation；GET 接口参数用 `@UnderlineToCamel` 支持下划线转驼峰（`QueryMethodArgumentResolver`）。
- JSON 序列化：MVC 侧 Jackson（`default-property-inclusion: non_null`）；ApiServlet 侧 fastjson/org.json/gson 混用，新代码沿用 Ctrl 内已有的 objectMapper。

## 本地构建运行

```bash
# 依赖内网仓库 repository.testin.cn（real-common 7.8.1.0 等），需 VPN/内网
mvn -U clean package -DskipTests
java -jar target/datasource-manage-1.0.jar
# 或直接跑 cn.testin.startup.Boot main，默认端口 8080
```

- 启动类 `Boot.main`（`src/main/java/cn/testin/startup/Boot.java`）：设置 log4j2 全异步（`AsyncLoggerContextSelector`）+ 关闭 ES netty 处理器探测。
- 心跳自检：启动后可访问 `GET /openapi/v3/datasource/heartbeat/check`（`HeartBeatController.java`）。
- API 文档：集成了 swagger-bootstrap-ui / knife4j，本地 `/doc.html` 调试。

## 配置要点

### application.yml（唯一 profile，环境差异用 `${ENV_VAR:default}`）

| 配置 | 说明 | 环境变量 |
|---|---|---|
| `spring.datasource.dynamic.datasource.db_source/db_file/db_user` | 三库 Druid 连接池，主库 db_source | `TESTINPRO_MYSQL_HOST/PORT/USER/BAOMIDOU_SECRETPWD` |
| 密码 `ENC(...)` | jasypt 加密 | 密钥随部署注入 |
| `spring.redis` | Jedis 连接池（操作日志队列、标签缓存） | `TESTINPRO_REDIS_HOST/PORT/PASSWORD` |
| `testin.controller.enabled: false` | 自定义开关：关闭部分 controller（`application.yml`） | — |
| `spring.data.elasticsearch.*` | **残留配置，ES 已废弃**，启动不排除 ES 自动装配会连不上 | 保持现状即可 |
| `spring.autoconfigure.exclude` | 排除 DruidDataSourceAutoConfigure（交给 dynamic-datasource） | — |

### config.properties / service.api.properties

- `config.properties`：`module.id=103`、`module.node.id`、临时目录 `file.tmp.path`（导入下载文件用，**Windows 本地调试用 D:/tmp，Linux 部署用 /home/syy/data/datasource-manage**）、各报告页 URL。
- `service.api.properties`：外部服务前缀名 → 地址映射（`RealTest`/`Script`/`UserManager`/`FileUpload` 等），`AbstractApi` 按前缀名寻址，`ApiUtil.doPress(prefixName, reqJson)` 发起 MD5 签名调用。

## 新增一个功能的标准流程

1. **定入口**：对外/新功能 → `controller/`（MVC）；维护 legacy 树操作 → `service/source/`（ApiServlet Ctrl）。
2. **DTO/VO**：放 `dto/request`、`dto/response`、`vo/`；表实体放 `pojo/`。
3. **Mapper**：接口放 `mapper/`（按库分子包 normal/ testCase/ project），XML 放 `resources/mapper/`；跨库查询在对应方法加 `@DS("db_file")` 等。
4. **业务层**：接口放 `business/interfaces/`，实现放 `business/impl/`；树/数据源主域逻辑多半落在 `SourceConfigServiceImpl`（注意它已 3359 行，能拆则拆）。
5. **操作日志**：管理侧写操作接 `OperateLogService`（同步 LPUSH `queue:operate_log`），见 [横切-操作日志与异步任务](../04-复杂功能细节/横切-操作日志与异步任务.md)。
6. **导入类型扩展**：新节点类型需同步改 `SourceTypeEnum`、`DataSourceTypeStrategyEnum`、`InitDataSourceImportStrategy` 三处。
7. **接口文档**：本知识库 07 目录按 Controller/Ctrl 一个文件维护，同步更新。

## 跨端修改红线

| 修改对象 | 影响 | 要求 |
|---|---|---|
| `ScriptParamSourceData` / `DataSourceResponseBaseDTO` 等出参结构 | app处理服务、平台基础功能服务 反序列化 | 调用方同改同发；字段只增不删 |
| `getScriptParamDataNew` 的 skip/isGlobal 语义 | 执行侧参数注入逻辑 | 见 [脚本变量填充实现](../03-实现逻辑/脚本变量填充实现.md) 注意事项 |
| `source_config` 唯一索引 / status 逻辑删除 | 全部查询 SQL | 手写 SQL 必须带 status；删改先考虑 unique_scriptno 冲突 |
| ApiServlet Ctrl 方法签名/返回 JSON 结构 | 前端与旧调用方 | 保持 `ApiRequest/ApiResponse` 包装与 success 码体系 |
| `service.api.properties` 前缀名 | `api/` 包全部远程调用 | 与部署配置同步 |
