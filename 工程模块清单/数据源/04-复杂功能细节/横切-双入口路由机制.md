# 横切-双入口路由机制

> 数据源 的双 Servlet 注册与路由分发机制。

## 架构

数据源 在 `Boot.java` 中注册了两个 Servlet：

```java
// /openapi/v3/* → Spring DispatcherServlet（标准 MVC）
new ServletRegistrationBean<>(dispatcherServlet, "/openapi/v3/*");

// /openapi/* → ApiServlet（legacy action/op 反射调用）
new ServletRegistrationBean(new ApiServlet(), "/openapi/*");
```

## 路由分发

### 入口 A：DispatcherServlet（/openapi/v3/*）

- 标准 Spring MVC 路由
- `@RestController` + `@RequestMapping` 注解
- 完整 URL = `/openapi/v3` + 类级 `@RequestMapping` + 方法级路径
- 参数绑定：`@RequestBody @Valid`（JSON Body）、`@RequestParam`（Query String）、`@PathVariable`
- `@UnderlineToCamel` 注解自动将下划线 query 参数转驼峰（通过 `QueryMethodArgumentResolver`）
- 统一响应：`ResponseResult<T>`
- 全局异常处理：`GlobalExceptionHandler`（`@RestControllerAdvice`）

### 入口 B：ApiServlet（/openapi/*）

- legacy 风格，来自 `real-common` JAR 包
- servlet 映射 `/openapi/*`，将 `/openapi` 之后的部分交给 Spring MVC 路由到 `service/source/` 下的 `@RestController` 类
- 完整 URL = `/openapi` + `@RequestMapping` 路径
- 方法签名：`String methodName(ApiRequest apiRequest)`，返回 JSON 字符串
- `ApiRequest` 包含字段：`apikey, mkey, action, op, timestamp, sid, sig, data, reqjson, originalJson`
- 方法内通过 `reqjson` 提取参数，通过 `ApiUtil.getJSONobj()` 构造响应
- 无全局异常处理，需方法内 try-catch

## 接口分类

| 入口 | Controller 位置 | 数量 |
| --- | --- | --- |
| `/openapi/v3/*` | `controller/` 包 | 6 Controller，~75 端点 |
| `/openapi/*` | `service/source/` 包 | 7 Ctrl 类，~47 方法 |

## 参数转换

`QueryMethodArgumentResolver` 实现了 `HandlerMethodArgumentResolver`，对标注 `@UnderlineToCamel` 的参数自动将下划线 query 参数转换为驼峰命名的 DTO 字段。

## 与 平台基础功能服务 的区别

| 特性 | 数据源 | 平台基础功能服务 |
| --- | --- | --- |
| MVC 路径前缀 | `/openapi/v3` | `/v3` |
| ApiServlet 路径 | `/openapi/*` | `/*`（兜底） |
| ApiServlet 反射 | 不使用反射，走 Spring MVC 路由 | action=包名 → 反射实例化 + op=类.方法 → 反射调用 |
| ApiServlet 返回 | `@RestController` 返回 JSON String | 反射调用返回 JSON String |
