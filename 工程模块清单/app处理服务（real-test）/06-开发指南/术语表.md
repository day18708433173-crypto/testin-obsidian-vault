# 术语表

> 按拼音/字母排序。每条给"一句话定义 + 深入阅读"。显示名对照：app处理服务=real-test、任务调度服务=real-scheduling、设备控制中心=real-controlcenter、平台配置=real-cfg。

## A

**adaptDetail（适配详情）** — MongoDB `pmreal_adapt_detail` 文档：一次提测的脚本/设备/执行策略/参数/账号全集，任务初始化的主要输入。见 [APP任务执行链路实现](../03-实现逻辑/APP任务执行链路实现.md)。

**ApiServlet** — real-common 提供的兜底 Servlet（`/*`），按请求参数 `action/op` 反射调用 `cn.testin.service.<action>.<类>.<op>`，是老入口形态。见 [基础设施-双入口路由](../04-复杂功能细节/基础设施-双入口路由.md)。

## B

**补测 / 复测（retest）** — 任务完成后对失败设备/脚本的追加执行，三形态：设备补测 retest、脚本补测 scriptRetest、批量补测 repeatTest，均为增量入库不新建任务。见 [补测复测实现](../03-实现逻辑/补测复测实现.md)。

## D

**db_real / db_task** — 两个 MySQL 库：db_real 存任务主记录/扩展/定时/分享（本服务主写），db_task 存调度三表与结果（任务调度服务主写，本服务补测时读写）。见 [存储总览](../02-技术架构/00-存储总览.md)。

**task 通道 / realtest 通道** — 本服务的两条通知 MQ 通道：task 通道跑任务初始化类 6 种通知（30 线程），realtest 通道跑其余 30+ 种（100 线程），在 `StartRunner` 注册。见 [基础设施-后台线程全景](../04-复杂功能细节/基础设施-后台线程全景.md)。

## E

**execStandard（执行策略）** — 任务执行模式枚举（fast/normal/simple/monkey/script/data 等），由业务配置 `db_realcfg_biz_config` 的 config.execStandards 定义，决定脚本分发与设备分配策略。

**exec_status** — `task_info`/`task_sub_info` 的执行状态：-2 PENDING_SCHEDULING（待激活）→ 0 IDLE → 1 ING → 2 PRE_FINISH → 3 FINISH；补测子任务同样走该流转。见 [核心链路-任务状态机](../04-复杂功能细节/核心链路-任务状态机.md)。

## H

**恢复脚本信息（recoverScriptInfos）** — 自愈脚本映射（scriptNo → 恢复脚本信息），存 `task_info_extra`；补测模式 init 时与原值**合并**而非重建。见 [补测复测实现](../03-实现逻辑/补测复测实现.md)。

## M

**mq_info_notice** — 通知表，本服务异步骨架：业务代码 INSERT 通知（type/level/publishtime/expiretime/noticemark=taskid），`MqNoticeDataThread` 200ms 轮询 → `NoticeDispatchThread` → `NoticeServiceImpl.handle` 分发到 41+ 种 handler。见 [通知系统-总览](../04-复杂功能细节/通知系统-总览.md)。

**MODULE_NODE_ID** — 模块节点标识（config.properties `module.node.id`，默认 1030001），作为通知/任务的 vhost 路由键，多节点部署必须唯一。

## P

**pmreal_\*** — MongoDB pmreal_db 的集合族：adapt_detail（任务明细）、report_detail（报告步骤）、task_summary / script_summary / device_detail（各维度汇总）、retest_summary（补测摘要）等。见 [real-test-mongo-redis-es](../../数据库管理/app处理服务-mongo-redis-es.md)。

**preal_user_adapt** — 任务主表（db_real）：taskid、execStatus（waiting/testing/…）、cancelled、checkApp 等；`preal_adapt_expand` 存图标/启动路径等扩展信息。

## R

**retestMark** — 补测标记位：补测时给被重测的 reportDetail/runInfo 打 `retestMark=1`，报告据此区分原执行与补测批次；常量 `ReportDetailConstant.RE_TEST_MARK`。见 [补测复测实现](../03-实现逻辑/补测复测实现.md)。

**任务三表（调度三表）** — `task_info_extra`（扩展）+ `task_info`（子任务=设备粒度）+ `task_sub_info`（子子任务=脚本粒度），由任务调度服务 `Task.init` 写入 db_task。

## S

**skey** — 报告免登分享凭证，`Task.share` 生成并写 `real_report_share`。见 [功能总览](功能总览.md)。

**上位机** — 连接真机的 PC 客户端，与设备控制中心保持 MINA TCP 长连接，接收脚本下发并回传结果。

## T

**TASK_CREATE / TASKINIT / scriptExecute** — 创建链路三类关键通知：TASK_CREATE 上报门户卡片（`handleTaskCreate`→`PortalApi.report`）；TASKINIT 触发 `handleNormalTask` 调调度 init；调度侧 `scriptExecute` 通知激活任务（exec_status -2→0）。另有 `TASK_INIT_NOTICE`（realtest 通道 115）只同步测试计划模块，不参与激活，二者勿混淆。见 [APP任务执行链路实现](../03-实现逻辑/APP任务执行链路实现.md)。

**taskid** — 任务唯一标识，APP 任务以 `tt` 开头；贯穿 MySQL/MongoDB/ES/Redis 全部存储与通知 noticemark 字段。

**提测** — 创建一次测试任务的业务动作（选包 + 选脚本 + 选设备 + 执行策略）。

**taskType** — 调度 init 的模式标记：1=正常创建（DELETE+INSERT extra），2=补测（合并 recoverScriptInfos、仅增量 INSERT）。

## X

**scriptExecute** — 任务调度服务侧的激活动作：把 `task_info.exec_status` 从 -2 置 0（IDLE），任务才进入调度池可被设备心跳匹配。

## Z

**执行记录 / 测试计划重测** — `executeRecordTaskId` 场景：平台侧发起的重测请求，addNew 内提前分流走 `testPlanResetTask`，不进正常创建链路。

**子任务 / 子子任务（subtask / subsubtask）** — 任务按设备拆分为子任务（task_info）、按脚本拆分为子子任务（task_sub_info）；补测 API 的 subtaskid/subsubtaskid 即指这两层。
