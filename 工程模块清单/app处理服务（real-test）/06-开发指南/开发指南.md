## 启动模型（改代码前必须知道）

`Boot.main`（`real-test/src/main/java/cn/testin/startup/Boot.java`）做三件事：

1. 设置 log4j2 异步日志工厂；
2. `DbConfigUtil.loadConfig()` 加载数据库配置（失败直接退出）；
3. 起 Spring 上下文并挂到 `AppContext` 父上下文。

**双 Servlet 注册**（Boot.java）：

| Servlet | 映射 | 用途 |
|---|---|---|
| `DispatcherServlet` | `/v3/*` | Spring MVC，即 `mvc/controller` + `controller` 下的 `@RestController` |
| `ApiServlet`（real-common） | `/*` | 按 `action/op` 反射调 `cn.testin.service.*`，如 `action=app, op=Task.add` → `cn.testin.service.app.Task.add` |

**启动后拉起全部后台线程**：`StartRunner.run`（`real-test/src/main/java/cn/testin/config/StartRunner.java`）——Redis MQ 订阅线程、RealcfgDataThread、QuartzListenerThread、两条 NoticeDispatchThread（realtest 100 线程 / task 30 线程）、两条 MqNoticeDataThread（200ms 轮询 `mq_info_notice`）、PDFThread、OemStartThread（5 分钟刷 OEM 配置）。全景见专题 [基础设施-后台线程全景](../04-复杂功能细节/基础设施-后台线程全景.md)。

## 分层约定

| 层 | 位置 | 约定 |
|---|---|---|
| ApiServlet 入口 | `service/<action>/<Op>.java` | 类继承 `GenericBaseService`，方法签名 `public String <op>(ApiRequest)`，返回 `ApiUtil.getResult(...)` JSON |
| MVC 入口 | `mvc/controller/` | `@RestController` + DTO 入参，统一返回 `ResponseResult`；service 在 `mvc/service/` |
| 业务层 | `business/interfaces` + `business/impl` | 接口 `I*Service`，实现 `*ServiceImpl`；老代码常 `SpringHelper.getBean("BeanName")` 取 bean |
| DAO 层 | `dao/interfaces` + `dao/impl` | 按存储分子包：`preal`（db_real MySQL）、`pmreal`（MongoDB）、`redis`、`elasticsearch`、`real`、`free`、`trueAgent`（第二 Mongo） |
| 出站调用 | `api/<域>/` | 每域一个 Api 类，底层 `ApiUtil.doPress(<服务名>, reqJson)`（如 `scheduling.TaskApi`、`UserApi` 走 `UserManager`）；bean 名形如 `scheduling.TaskApi` |
| 通知 | `business/impl/NoticeServiceImpl` | 新异步流程 = 新 `NoticeConfig.InfoNoticeType` 枚举值 + `handle()` 分发分支 + handler 方法 + 在 `StartRunner` 的通知类型数组注册通道 |

## 新增一个功能的标准流程

1. **入口选型**：老 op 风格加 `service/<action>/` 下方法（同时在 07 接口文档登记）；新功能优先 `/v3` MVC（`mvc/controller` + `mvc/dto` + `mvc/service`）。
2. **业务逻辑**：放 `business/impl`；需要异步/重试语义的走 `mq_info_notice` 通知而不是本地线程池——可重试、可排障（status/execNum 在库里）。
3. **存储**：MySQL 表走 `dao/impl/preal` + mapper XML 放 `resources/mybatis/mapper/`；执行明细/统计放 MongoDB `pmreal_*`（`dao/impl/pmreal`）；实时状态放 Redis `dao/impl/redis`。
4. **定时**：周期触发任务的用 Quartz 体系（`quartz/`，模板落 `quartz_job_info`）；简单常驻轮询线程放 `schedule/` 并在 `StartRunner` 注册。
5. **跨模块**：调任务调度服务用 `cn.testin.api.scheduling.TaskApi`；不要直接 HTTP 拼 URL。

## 本地构建与运行

- **构建**：real 仓根 `mvn -pl real-test -am package`（或直接在 real-test 目录 `mvn package`）；产物 `target/real-test.jar`，mainClass `cn.testin.startup.Boot`（pom.xml）。
- **运行**：`java -jar target/real-test.jar` 或 IDE 直接跑 `Boot.main`；端口 8080（`application.properties`）。
- **依赖环境**：MySQL（db_real/db_task 等）、MongoDB（pmreal_db + true_agent 双实例，`spring.data.mongodb.primary/secondary.uri`）、Redis（多逻辑库，`RedisConfig.DbConfig`）、Elasticsearch（report_summary 索引）、以及可连通的 real-common 配置中心/外部服务地址（`service.api.properties`）。
- **健康检查**：`GET /realtest/heartbeat/check`（`real-test/src/main/java/cn/testin/controller/HeartBeatController.java`，查 MySQL/Mongo/Redis/ES）。
- **模块标识**：`module.id=103`、`module.node.id=1030001`（config.properties）——`Config.MODULE_NODE_ID` 决定本节点消费哪些 `mq_info_notice`（vhost 字段），多节点部署必须各不相同。

## 配置要点

| 配置 | 位置 | 说明 |
|---|---|---|
| 端口 | application.properties `server.port=8080` | 内嵌容器（undertow 参数已注释备选） |
| Mongo 双实例 | `spring.data.mongodb.primary/secondary.uri` | primary=pmreal_db（业务数据），secondary=true_agent；连接串支持 `${ENV:default}` 注入 |
| ES 拼音分析器 | `es.analyzer.use/type` | report_summary 检索增强 |
| 模块标识 | config.properties `module.id/module.node.id` | MQ 通知按 vhost=MODULE_NODE_ID 路由到节点 |
| 报告 URL / 邮件模板 | config.properties `report.url` / `email.*.templetid` | 邮件里的在线报告链接、各通知邮件模板 |
| 临时目录 | config.properties `file.tmp.path` | Excel/PDF 生成暂存 |
| 外部服务地址 | service.api.properties | notice-manager / UserManager / file-service 等 |
| 日志 | resources/log4j2.xml | 异步 logger，工厂在 Boot.main 首行设置 |

## 跨模块修改红线

| 修改对象 | 影响 | 要求 |
|---|---|---|
| `NoticeConfig.InfoNoticeType` 枚举值 | 两端 mq_info_notice 类型协议 | 新增只能追加；改值要同步任务调度服务/设备控制中心并考虑历史数据 |
| `scheduling.TaskApi` init 的 contentJson 字段 | app处理服务↔任务调度服务 RPC 契约 | 两端同改同发版；补测的 retestMark/recoverScriptInfos 字段尤其敏感 |
| `TestResult.report` / `TestProcess.report` 入参 | 任务调度服务→本服务的结果回传契约 | 与 real-scheduling 同步改 |
| `mq_info_notice` 表结构 | 全模块通知骨架 | 四模块共用模式，勿单模块改 |
| taskid 生成规则（tt 前缀） | 全链路识别 APP 任务 | 勿动 |
