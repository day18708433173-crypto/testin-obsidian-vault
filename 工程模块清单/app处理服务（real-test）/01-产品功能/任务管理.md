# 任务管理

> 来源：http://test.pro.testin.cn/docs/base/task/

任务是自动化用例的执行集合，可根据业务场景或测试计划将用例放入一个任务中执行，附带任务的测试应用、执行时间、测试进度与测试结果，测试报告等信息，了解用例执行的整体表现。

## 任务执行记录列表
通过任务执行记录列表可快速了解任务执行的执行进度、执行结果、执行时长等。

任务执行记录分为创建任务提测后立即执行的记录和由任务模版定时触发执行的记录，定时执行记录，在任务名称会显示时钟的图标。

查看已完成任务执行结果，测试结果状态定义如下：通过：任务中执行通过的脚本数量。取消：人工手动操作取消执行的脚本数量。超时：任务下发后，请求超时的脚本 。未通过：由于脚本错误（脚本错误、AI识别错误）、应用奔溃、启动失败、应用无响应、安装失败等原因导致执行失败的脚本数量。

### 筛选和显示
可自定义任务筛选条件和自定义显示字段，以及进行任务排序。

列表默认按照创建时间倒序显示，支持按应用名称、任务描述、创建人、创建时间等排序。

点击表头空白位置可清空字段排序，恢复按照创建时间倒序显示。

### 任务状态
任务存在3种执行状态，已完成、已取消、执行中，状态定义如下：

**已完成：**任务中所有脚本都执行完成，可查看测试结果。

**执行中：**任务中存在脚本正在执行中，任务执行中若存在无效设备，任务列表提示**执行中**，鼠标悬停图标时，可查看失效设备ID，需人工检查并恢复设备。

**已取消：**手动终止的任务。

#### 状态细节（内部流转与异常标记）

（本小节规则细节来自 04 专题，见 [04-任务状态机](../04-复杂功能细节/核心链路-任务状态机.md)。）

列表页展示的 3 种状态背后，每个任务（及其按设备、脚本拆出的执行单元）在内部有更细的生命周期状态：

| 状态 | 含义 | 用户能看到什么 |
|---|---|---|
| 待调度 | 任务已建档，但执行计划尚未就绪，还没有进入调度池 | 创建后短暂的中间状态，很快自动流转 |
| 待执行 | 任务已激活，正在等待满足条件的空闲设备接单 | 任务排队中，门户显示等待匹配 |
| 执行中 | 设备已接单，正在真机上跑脚本 | 门户实时刷新执行进度 |
| 预完成 | 脚本已跑完，结果已上报但还在解析、汇总中 | 设备已释放，报告尚未出齐 |
| 已完成 | 结果解析完毕，报告已生成 | 可查看完整报告，收到完成通知 |
| 已取消 | 用户主动取消，或系统因欠费、设备异常等原因取消 | 任务终止，取消原因可追溯 |
| 已跳过 | 因条件不满足未执行 | 报告中记录跳过原因，不计入正常完成统计 |

正常流转路径是：**待调度 → 待执行 → 执行中 → 预完成 → 已完成**。非正常出口：

- **取消**：待调度、待执行、执行中、预完成状态下都可以取消（已完成、已取消、已跳过是终态，不可再取消）。执行中取消时，平台会同时通知设备端停止执行，并释放设备与账号占用。
- **跳过**：待执行期间长时间匹配不到设备会超时跳过；脚本或测试数据缺失时，任务在待调度阶段就会直接跳过。跳过会记录原因（无匹配设备 / 数据不存在）。

取消会区分原因，这决定了任务后续会不会"活过来"：

| 取消原因 | 触发场景 | 能否自动恢复 |
|---|---|---|
| 用户主动取消 | 用户手动点取消、批量取消 | 否，永久终止 |
| 欠费取消 | 账户欠费触发 | 否 |
| 设备异常取消 | 设备离线导致被动取消 | 是，设备重新上线后自动恢复为待执行 |

即使任务到达"已完成"，单个执行单元的结果也可能带有异常标记，报告中可见：**结果丢失**（设备端没有成功回传结果文件）、**解析失败**（结果文件多次解析仍不成功）、**设备异常**（执行过程中设备离线导致中断）。

### 任务操作
可对任务进行终止、重测、删除的操作。

**重测**：重测时默认使用上一次提测时的任务配置信息，可修改，提交成功后将自动新增一条任务执行记录。

可根据测试结果选择想要重测的脚本。

#### 补测复测（增量重跑的内部规则）

（本小节规则细节来自 04 专题，见 [04-补测复测](../04-复杂功能细节/核心链路-补测复测.md)。）

一轮测试跑完后，往往需要"只重跑一部分"——换几台设备再验证、只重跑失败的脚本、或两者组合。补测复测提供三种增量重跑模式：不新建任务、不动已有结果，只把需要重跑的部分追加进原任务，重跑完成后报告自动合并更新。

| 模式 | 适用场景 | 补测粒度 |
|---|---|---|
| 设备补测 | 某台设备结果可疑，想换设备重跑 | 重新选设备，原脚本全部重跑 |
| 脚本补测 | 只有个别脚本失败，设备不变 | 指定到单条脚本的执行单元重跑 |
| 批量补测 | 既要换设备又要挑脚本 | 设备 + 脚本任意组合，一次提交 |

一句话概括：**设备补测是"换设备不换脚本"，脚本补测是"换脚本不换设备"，批量补测两者都支持**。

补测时平台依次完成：校验（要补测的子任务都已到达终态，未执行完的任务不能补测）→ 数据准备（已有运行数据打上补测标记；换设备时同步切换脚本参数里的设备指向与参数分配策略；批量补测还支持同时更换被测应用安装包）→ 增量建档（只为补测范围内的"新设备 × 脚本"组合新增执行单元，原有执行单元和已完成结果保持不动）→ 激活执行（走与正常任务完全相同的匹配、下发、回收流程）→ 报告刷新（脚本维度统计重新计算，门户状态同步更新，用户看到的始终是最新合并后的结果）。

业务规则与约束：

- **只增量、不破坏**：补测不会删除或覆盖原任务的任何数据，只追加新执行单元；补测前后的数据都保留。
- **原任务必须已完成**：存在未完成执行单元的任务不能发起补测。
- **换设备必须换参数指向**：如果脚本使用了参数来源（数据驱动），换设备重跑时参数分配会自动重映射到新设备，保证参数正确下发。
- **执行顺序保持**：补测脚本会按原有顺序并入执行计划，与原脚本的先后关系不乱。
- **统计去重**：已统计过的子任务不会因补测重复计入汇总。
- **并发安全**：同一任务的批量补测会被串行化，避免两次补测互相干扰。
- **复用正常链路**：补测与正常创建共用同一套初始化、激活、调度机制，状态流转与异常恢复规则（设备离线自动取消/恢复，见 [任务取消与异常恢复](任务取消与异常恢复.md)）与正常任务一致。
- **异常表现**：补测校验不通过（如原任务还在执行中）会直接提示，不产生任何数据变更。

**查看报告**：查看任务执行详情，可了解脚本测试概况（执行概况、问题统计、设备性能）、脚本执行报告（每条脚本的执行详情、执行状态）、设备执行报告（每个设备的执行详情）、截图对比（每条语句执行前后的截图对比）任务报告。

**删除**：所有状态（已完成、执行中、已取消）的任务都可操作删除，操作删除后，正在执行的脚本会继续执行完毕，没开始执行的脚本将取消执行，任务删除后不可恢复请谨慎操作。

注：任务执行记录已关联测试计划执行记录后，无法操作删除任务执行记录。

**提交缺陷**：和第三方缺陷管理平台对接后，可提交缺陷至第三方管理平台，当前已支持对接 TAPD、Jira、云测测管的平台。

**批量操作**：支持选择任务进行批量终止、删除的操作。

**暂停：**任务触发执行后，未下发至设备执行的脚本可操作暂停，暂停后已下发至设备的脚本将继续执行直至完成，未下发的脚本将不再下发执行，暂仅支持数据驱动方式提测的任务。

**继续执行：**已暂停任务可操作继续执行，暂仅支持数据驱动方式提测的任务。

**有效执行耗时：**统计至少一个脚本在执行的时间段，以评估有效执行的总耗时。

**任务执行耗时：**任务结束时间-任务创建时间。

## 任务模版
配置定时触发执行任务的策略，用于生产巡检场景，例如：每月、每周、每天、某个时刻固定时间点需要开始执行的自动化用例，可放在定时任务中进行执行。

### 启用状态
定时模版存在3种启用状态，进行中、暂停中、已完成，如下：

**进行中：**满足定时配置条件时会自动触发执行任务并生成测试报告。

**暂停中：**不再按照定时规则触发执行任务，可操作恢复继续定时触发任务的执行。

**已完成：**按照定时规则执行完毕后，后续不再触发任务执行。

### 操作
可进行任务定时配置修改、暂停和删除操作，可手动触发立即执行以及查看任务执行记录。

#### 编辑
可修改任务模版的配置信息，如：定时规则、任务描述、执行选项等内容。

如：可将平台历史定时任务模版修改为非定时任务模版，通过测试计划关联非定时任务模版进行回归测试。

注：已关联至测试计划的非定时任务模版不可切换执行时间。

#### 立即执行
手动触发定时任务立即执行 ，执行后可在定时任务配置列表查看任务的执行记录或全部任务列表页查看执行记录。

#### 删除定时任务
仅删除定时任务的配置信息，保留任务执行记录和测试报告，可在全部任务列表查看执行记录。

#### 删除所有执行记录
删除定时任务配置信息，同时删除该任务的所有执行记录以及测试报告数据。

#### 批量操作
支持选择任务批量执行、暂停、恢复、删除等操作。

### 执行记录
查看某一个定时任务配置下的所有任务执行记录以及测试报告，可对任务进行重测、删除的操作。

批量暂停：进行中的任务批量暂停执行。批量恢复：已暂停的任务可批量操作恢复执行。批量立即执行：所有任务可批量操作立即执行。批量删除：可将选中任务批量操作删除。
