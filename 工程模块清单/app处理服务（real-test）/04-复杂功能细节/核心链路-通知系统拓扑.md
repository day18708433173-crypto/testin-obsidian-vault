# 核心链路-通知系统拓扑

> 通知来源（3 通道 ~43 种） → Redis MQ → 线程处理链（NoticeDispatchThread → MqNoticeDataThread → NoticeHandlerThread） → 5 类通知目标（邮件/企微/钉钉/HTTP回调/ES同步）的完整拓扑。

## 通知系统拓扑图

```mermaid
flowchart LR
    subgraph Sources["通知来源（各模块触发点）"]
        Realtest["realtest 通道 (34种)<br/>ADAPT_COMPLETE<br/>TASK_CREATE<br/>REPORT_SUMMARY<br/>FINISH_EMAIL ..."]
        Task["task 通道 (6种)<br/>TASKINIT<br/>RETEST_INIT<br/>SCRIPT_RETEST_INIT<br/>TASK_BIND ..."]
        Scheduling["scheduling 通道 (8种)<br/>cancelTask<br/>revokeTask<br/>actionReport<br/>scriptExecute ..."]
    end

    subgraph MQChain["Redis MQ + 线程处理链"]
        RedisQueue["Redis 通知队列<br/>LPUSH / BLPOP BlockingPool"]
        NDT["NoticeDispatchThread<br/>realtest: 100/10/100 线程池<br/>scheduling: 100/10/100 线程池"]
        MNDT["MqNoticeDataThread 每200ms<br/>SELECT 批量加载通知<br/>realtest 批量50条<br/>scheduling 批量100条"]
        NHT["NoticeHandlerThread<br/>回调 NoticeServiceImpl.handle()<br/>按类型分发到具体 handler"]
        DB[(MySQL<br/>mq_info_notice 表)]
    end

    subgraph Targets["通知目标"]
        Email["邮件通知<br/>FINISH_EMAIL<br/>ADD_TASK_EMAIL"]
        Wecom["企业微信/钉钉<br/>FINISH_NOTICE<br/>SEND_WECHAT"]
        Webhook["HTTP Callback<br/>TASK_CALLBACK<br/>ADD_TASK_CALLBACK"]
        ActionReport["actionReport<br/>跨模块状态回调"]

    end

    %% 来源 → Redis
    Realtest -->|"LPUSH"| RedisQueue
    Task -->|"LPUSH"| RedisQueue
    Scheduling -->|"LPUSH"| RedisQueue

    %% Redis → 线程链
    RedisQueue -->|"BLPOP"| NDT
    NDT --> MNDT
    MNDT -->|"SELECT"| DB
    MNDT --> NHT

    %% 线程 → 目标
    NHT --> Email
    NHT --> Wecom
    NHT --> Webhook
    NHT --> ActionReport
    NHT --> EsSync
```

## 三线程处理链

```mermaid
sequenceDiagram
    participant Module as 业务模块
    participant DB as MySQL(mq_info_notice)
    participant Redis as Redis Queue
    participant NDT as NoticeDispatchThread
    participant MNDT as MqNoticeDataThread
    participant NHT as NoticeHandlerThread
    participant Target as 通知目标

    Module->>DB: INSERT mq_info_notice (type, status=PENDING)
    Module->>Redis: LPUSH notice queue

    loop 每 200ms
        MNDT->>DB: SELECT * FROM mq_info_notice<br/>WHERE status=PENDING AND delaytime<now<br/>LIMIT 50(realtest) / 100(scheduling)
        MNDT->>NDT: submit 到线程池
        NDT->>NHT: 提交处理
        NHT->>NHT: NoticeServiceImpl.handle()<br/>按 type 分发到具体 handler
        NHT->>Target: 邮件/企微/HTTP回调/ES同步
        NHT->>DB: UPDATE mq_info_notice SET status=FINISH
    end
```

## 通知类型详细

| 通道 | 通知类型 | 触发点 | 消费者 | 目标 |
|------|----------|--------|--------|------|
| realtest | ADAPT_COMPLETE | 适配完成后 | NoticeServiceImpl | 门户同步 |
| realtest | TASK_CREATE | 任务创建后 | NoticeServiceImpl | 门户上报 |
| realtest | TASK_SUMMARY | 每条结果写入后 | TaskSummaryServiceImpl | 任务汇总 |
| realtest | REPORT_SUMMARY | 汇总完成后 | NoticeServiceImpl | Portal 推送 |
| realtest | FINISH_EMAIL | 任务全部完成 | NoticeServiceImpl | 邮件发送 |
| realtest | REPORT_GENERATE | 需要生成报告 | GenerateReportServiceImpl | Excel/PDF |
| realtest | SEND_WECHAT | 企微通知 | NoticeServiceImpl | 企业微信 |
| task | TASKINIT | scheduling init完成 | NoticeHandlerThread | app处理服务 收尾 |
| task | RETEST_INIT | 复测初始化 | NoticeHandlerThread | app处理服务 处理 |
| task | TASK_BIND | 定时任务触发后 | NoticeHandlerThread | 绑定 job-task 关系 |
| scheduling | cancelTask | 任务取消 | NoticeServiceImpl | 跨模块同步 |
| scheduling | revokeTask | 设备离线撤销 | AbnormalDeviceService | 异常处理 |
| scheduling | actionReport | 结果解析完成 | TestProcessServiceImpl | app处理服务 回调 |
| scheduling | scriptExecute | 脚本执行授权 | TaskServiceImpl | 激活任务(-2→0) |

## 失败重试策略

| 条件 | 策略 |
|------|------|
| execNum < 3 | 立即重试 |
| 3 ≤ execNum ≤ 10 | 延迟 10 秒重试 |
| execNum > 10 且 > 1小时 | 标记为 INVALID |
| 通知有效期 | 5 小时（超时自动失效） |
| 延迟投递 | delaytime 字段控制 |
| 优先级 | level 字段控制线程池优先级（0=最高） |
