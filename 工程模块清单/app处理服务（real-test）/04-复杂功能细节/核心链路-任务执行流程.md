# 核心链路-任务执行流程

> 端到端泳道图：从 Web 客户端提交任务 → app处理服务 接收 → scheduling 初始化与匹配 → controlcenter 下发 → 上位机执行 → 结果回收 → app处理服务 报告汇总，共 9 个阶段。

## 端到端泳道图

```mermaid
sequenceDiagram
    participant Client as Web客户端
    participant Test as real-test
    participant Sched as real-scheduling
    participant CC as real-controlcenter
    participant Device as 上位机/设备
    participant MySQL as MySQL
    participant ES as Elasticsearch
    participant MQ as Redis MQ

    Note over Client,MQ: ====== Step1-2: 任务创建与初始化 ======

    Client->>Test: Step1 创建任务 (双入口: ApiServlet / MVC)
    Test->>MySQL: 三表入库 pmreal_adapt_detail/expand/user_adapt
    Test->>MQ: INSERT ADAPT_COMPLETE + TASK_CREATE
    MQ->>Test: Step2 通知链: handleAdaptCompleteNew→插 TASKINIT→handleNormalTask
    Test->>Sched: taskapi.init RPC (ApiUtil.doPress RealScheduling)
    Sched->>Sched: 拆分设备子任务 (device_count × script_count)
    Sched->>MySQL: INSERT task_info (exec_status=-2 PENDING_SCHEDULING)
    Sched->>MySQL: INSERT task_sub_info
    Sched->>MySQL: INSERT task_info_extra
    Sched->>ES: async INSERT EsTaskInfo
    Sched-->>Test: return success

    Note over Client,MQ: ====== Step3: 激活任务进入调度 ======

    Test->>MQ: INSERT scriptExecute 通知
    MQ->>Sched: Step3 激活任务 exec_status: -2 → 0(IDLE)

    Note over Client,MQ: ====== Step4-6: 设备心跳与匹配 ======

    Device->>CC: Step4 设备心跳 HeartBeat.keepalive (deviceInfo)
    CC->>CC: ProtocolHandlerThread 处理
    CC->>Sched: Step5 触发匹配 RPC Task.match
    Sched->>Redis: 检查设备状态 (是否被占用)
    Sched->>MySQL: SELECT task_info WHERE exec_status=0 (IDLE)
    Sched->>Sched: Step6 策略匹配 TaskMatchFactory
    Sched->>MySQL: INSERT task_exec_relation (防重)
    Sched->>MySQL: UPDATE task_info SET exec_status=1(ING)
    Sched-->>CC: return taskGroup

    Note over Client,MQ: ====== Step7: 任务下发与执行 ======

    CC->>CC: DeviceHandlerThread 组装下发命令
    CC->>Device: Step7 TASK_EXEC 下发 (taskId + scriptList)

    Note over Client,MQ: ====== Step8-9: 结果回收与报告 ======

    Device->>CC: preComplete (脚本完成)
    CC->>Sched: precomplete 上报
    Sched->>MySQL: UPDATE task_sub_info exec_status=2(PRE_FINISH)

    Device->>CC: reportResult (结果文件URL)
    CC->>Sched: reportResult 上报
    Sched->>MySQL: INSERT task_result (status=UNPARSE)
    Sched->>Sched: Step8 ResultHandlerThread 解析
    Sched->>MySQL: UPDATE task_info exec_status=3(FINISH)

    Sched->>MQ: INSERT actionReport (action=complete)
    MQ->>Test: Step9 报告汇总
    Test->>Test: TaskSummaryServiceImpl 汇总统计
    Test->>Test: 生成 Excel/PDF 报告
    Test->>Test: 发送邮件/企微通知
```

## 9 阶段速查

| 阶段 | 模块 | 关键操作 | 状态变更 |
|------|------|----------|----------|
| Step1 创建任务 | app处理服务 | TaskController.taskAdd() 三表入库+插通知 | — |
| Step2 任务初始化 | 任务调度服务 | 通知链异步触发 Task.init() 拆分入库 | exec_status=-2 (PENDING_SCHEDULING) |
| Step3 激活任务 | 任务调度服务 | scriptExecute 通知 | -2 → 0 (IDLE) |
| Step4 设备心跳 | 设备控制中心 | HeartBeat.keepalive | 设备池更新 |
| Step5 触发匹配 | 设备控制中心 | DeviceDispatchThread | — |
| Step6 策略匹配 | 任务调度服务 | TaskMatchFactory.match() | 0 → 1 (ING) |
| Step7 任务下发 | 设备控制中心 | DeviceHandlerThread → TCP | — |
| Step8 结果解析 | 任务调度服务 | ResultHandlerThread | 1 → 2 → 3 (FINISH) |
| Step9 报告汇总 | app处理服务 | TaskSummaryServiceImpl | 通知 → 邮件 |

| 阶段 | 文件 | 方法 |

| Step9 | `real-test/.../business/impl/TaskSummaryServiceImpl.java` | `stat()` |
