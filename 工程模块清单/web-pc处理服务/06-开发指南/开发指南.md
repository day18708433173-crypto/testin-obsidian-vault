# 开发指南

> 工程：`real-web`（web/pc处理服务，Java 1.8 / Spring Boot 2.7.18 / Undertow）。先读 [00-首页](../00-首页.md) 建立整体认识，路由细节见 [横切-双入口路由机制](../04-复杂功能细节/横切-双入口路由机制.md)。

## 工程结构与分层约定

```
src/main/java/cn/testin/realweb
├── RealWebApplication.java   启动类：注册 ApiServlet(/*)+DispatcherServlet(/v3/*)，
│                             @MapperScan(dao.mapper+business)，@ComponentScan("cn.testin")
├── service/                  ApiServlet 入口层：按包名对应 action 参数
│   └── task/Task.java            action=task, op=Task.create → 反射调用
├── api/                      远程服务调用层（~60 类）：V1 RPC（ApiUtil.doPress）+
│                             V3 REST（RestTemplate，ServiceRemoteV3Api）
├── business/                 业务逻辑层
│   ├── impl/                     实现（TaskServiceImpl/NoticeServiceImpl/ReportServiceImpl 等）
│   ├── interfaces/               业务接口（18 个）
│   ├── redis/                    RedisService（锁/队列/去重）
│   └── strategy/                 定时模板更新策略、操作日志策略
├── mvc/                      Spring MVC 层（/v3/*）
│   ├── controller/               7 个 Controller
│   ├── service/                  MVC 辅助 Service
│   └── dto/                      MVC DTO
├── dao/
│   ├── mapper/                   MyBatis Plus Mapper（db_common 4 表）
│   ├── impl/mongo/               Mongo DAO（6 类集合各一个，继承 AbstractMongoDaoImpl）
│   └── interfaces/               DAO 接口
├── quartz/                   Quartz 调度：SchedulerManager/QuartzHelper/job/listener
├── config/                   Spring 配置（Mongo 双数据源/Jedis/MyBatis/Async/StartRunner）
├── pojo/                     实体：mongo/ dbCommon/ pmreal/ other（NoticeConfig/LockKeyword）
├── aop/                      @OperateLog 切面（异步操作日志）
└── common/                   常量与枚举
```

分层红线：

- **service/（ApiServlet 入口）只做参数解析与转调**，业务逻辑进 business/impl；
- **api/ 只允许出站的远程调用**，不允许被同工程其他包以外的逻辑反向依赖；
- Mongo 访问一律走 dao/impl/mongo 的 DAO，集合名用 POJO 的 `table(taskid)` 计算，不要手拼分片名；
- MySQL 只存 db_common 4 张表（quartz_job/quartz_job_log/app_info/job_task_relation），任务域数据一律进 Mongo。

## 新增一个功能的标准流程

1. **DTO/实体**：Mongo 文档放 `pojo/mongo/`，MySQL 实体放 `pojo/dbCommon/`。
2. **DAO**：Mongo 继承 `AbstractMongoDaoImpl`（模板选择由 `real.common.properties` 的 `abstractmongodao.*` 配置驱动）；MySQL 在 `dao/mapper/` 加接口 + `src/main/resources/mapper/` 加 XML（mybatis-plus `mapper-locations: classpath:/mapper/**/*.xml`）。
3. **业务层**：接口进 `business/interfaces/`，实现进 `business/impl/`；异步/耗时操作**不要同步做**，落 `mq_info_notice` 通知（类型加进 `NoticeConfig.InfoNoticeType`，处理器挂进 `NoticeServiceImpl` 的分发链，见 [横切-通知系统](../04-复杂功能细节/横切-通知系统.md)）。
4. **入口**：旧风格走 `service/{action}/{Class}.java` + `public String xxx(ApiRequest)`（op=类.方法 自动反射）；新接口优先走 `mvc/controller/`（/v3/*）。
5. **并发**：taskid 维度的互斥用 `LockKeyword` + `LockUtil` 枚举化登记（参考 `TaskRepeatTest`，`src/main/java/cn/testin/realweb/pojo/other/LockKeyword.java`）。
6. **跨端修改**：下发报文（handleWebtaskInit/initTask 组装的 contentJson）是 real-web ↔ 任务调度服务 的协议，改字段要两侧同改同发版；通知 content JSON 同理（生产者/消费者都在 NoticeServiceImpl 附近，但要考虑 MQ 里积压的旧格式消息）。

## 本地构建与运行

```bash
# 构建（私服 repository.testin.cn 需可达，pom.xml）
mvn clean package -DskipTests

# 运行
java -jar target/real-web-0.0.1.jar
```

- 启动入口 `RealWebApplication.main`（`src/main/java/cn/testin/realweb/RealWebApplication.java`）：第一行 `DbConfigUtil.loadConfig()`（cn.testin.common）加载 DB 配置，失败直接退出——本地起不来先查这个。
- 启动后 `StartRunner`（`src/main/java/cn/testin/realweb/config/StartRunner.java`）拉起后台线程：PDFThread、NoticeDispatchThread（MQ channel "realweb"）、MqNoticeDataThread（1000ms 轮询）、QuartzListenerThread（恢复定时任务）。全景见 [横切-后台线程全景](../04-复杂功能细节/横切-后台线程全景.md)。
- 默认端口 8080（`application.yml`）。

## 配置要点

| 配置 | 位置 | 说明 |
|---|---|---|
| `application.yml` | src/main/resources | 端口、Mongo 双库（pmweb_db/pmpc_db）、MySQL db_common（Druid，密码 RSA 加密+publickey 解密）、Redis 连接池；全部支持 `${ENV:default}` 环境变量注入 |
| `config.properties` | src/main/resources | `module.id=110` / `module.node.id=1100001`（节点标识，MQ vhost 与锁 key 前缀）、`file.tmp.path`（Excel 临时目录）、邮件模板 id |
| `real.common.properties` | src/main/resources | `service.path=cn.testin.realweb.service`（ApiServlet 反射扫描根包）、`abstractmongodao.*`（Mongo 模板路由） |
| `service.api.properties` | src/main/resources | 各外部服务的地址前缀（realSchedulingPrefixName 等） |
| `log4j2.xml` | src/main/resources | 统一 log4j2，业务日志用 `Logit`（cn.testin.common） |
| `web.job.interval` / `pc.job.interval` | application.yml | Web/PC 定时任务扫描间隔（秒） |

环境变量注入示例：`TESTINPRO_MONGO_HOST` / `TESTINPRO_MYSQL_HOST` / `TESTINPRO_REDIS_HOST` 等，容器部署靠它们切换环境。

## 约定清单

### 序列化与工具
- JSON 三套并存（org.json 的 JSONObject 为主、Gson 用于 MQ content 反序列化、fastjson 少量）；**MQ content 反序列化惯例是 Gson + TypeToken**（参考 `handleRepeatTest`，`NoticeServiceImpl.java`），新旧格式兼容靠 `opt*` 容错读取。
- HTTP 出站：V1 RPC 用 `ApiUtil.doPress`（OkHttp，action/op 协议）；V3 用 `ServiceRemoteV3Api`（RestTemplate + ResponseResult 解包）。

### 日志与异常
- 日志统一 `Logit.debugLog/errorLog`（log4j2）；业务异常抛 `GeneralException`（code + msg），错误码枚举进各自的 Code 类（如 `TaskConfig.RetestCode`、`AddTaskCode`）。
- Assert 校验（org.springframework.util.Assert）在入口层大量使用，断言信息会原样返回给调用方。

### 多数据源
- Mongo 双模板：`RealWebMongoConfig`（pmweb_db，@Primary）/ `RealPcMongoConfig`（pmpc_db），DAO 内 `getMongoTemplate(taskid)` 按 `pt` 前缀自动路由——**新增任务域数据时别忘了 PC 分支**。
- MySQL：Druid 单数据源 db_common，分页用 MybatisConfig 的拦截器。

### 测试
- `src/test/java` 下有基于 JSON 请求样例的 service 层测试（如 `TaskTest.repeatTest` 读 `Task.repeatTest.json`），改接口出入参时同步维护 `src/test/resources` 下的样例 JSON。

## 常见坑

1. **双 Servlet 路由冲突**：`/*` 被 ApiServlet 兜底，新 Spring MVC 端点必须挂在 `/v3/*` 下，否则会被 ApiServlet 截胡（报"action 不存在"类错误）。
2. **module.id 写死 110**：锁 key、MQ vhost、Excel 去重都含此前缀；多节点部署靠 `module.node.id` 区分，本地多实例并行调试会互相抢 MQ。
3. **taskid 前缀分叉**：`wt`/`pt` 决定走 Web 库还是 PC 库、走 browsers 还是 pcs——复制 Web 逻辑改 PC 时要全文检查 `startsWith("wt")` 分支。
4. **MQ 是最终一致性瓶颈**：所有异步步骤都过 `mq_info_notice` + 1000ms 轮询，链路上"慢 1~2 秒"是常态，不要在同步接口里等异步结果。
5. **Excel 临时目录**：`file.tmp.path`（默认 `/home/syy/data/realwebtmp`）在 Windows 本地需自行改成存在的目录，否则报告生成失败。
