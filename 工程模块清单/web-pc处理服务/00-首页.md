# web/pc处理服务 总览

> Web/PC 任务执行与调度服务。本页为分支无关的通用介绍，分支强相关内容见下方分支索引。

## 定位

web/pc处理服务 是 Web 端和 PC 端测试任务的执行入口与调度中心：

| 职责 | web/pc处理服务 | 平台基础功能服务 | app处理服务 |
|------|----------|-------------|-----------|
| Web/PC 任务创建与执行 | **核心** | — | — |
| 任务模板/定时调度（Quartz） | **核心** | 编排层 | App 端 |
| 报告生成与问题分析 | **核心** | — | App 端 |
| 执行结果回收与状态机 | **核心** | 编排层 | App 端 |
| 通知发送（邮件/短信/钉钉/飞书） | **核心** | 编排层 | App 端 |
| 脚本/设备/参数数据管理 | 部分 | 部分（用例） | 部分 |

**与 app处理服务 的关系**：web/pc处理服务 是 app处理服务 的 Web/PC 对等实现，核心业务逻辑高度相似（任务创建→调度→回收→报告→通知），区别在于：
- app处理服务 面向 App/移动端测试（device → 手机设备）
- web/pc处理服务 面向 Web/PC 测试（browser → 浏览器，pc → PC 客户端）

## 双入口架构

| 入口 | 路径 | 技术 | 路由方式 |
|------|------|------|----------|
| ApiServlet | `/*`（兜底） | 原生 Servlet + 反射 | `action=包名` → 包路径, `op=类.方法` → 反射调用 |
| DispatcherServlet | `/v3/*` | Spring MVC | `@RequestMapping` 注解路由 |

- `/*` → `ApiServlet`：action/op 参数决定 `cn.testin.realweb.api.{action}.{Class}` 的反射调用
- `/v3/*` → `DispatcherServlet`（注册于 `RealWebApplication.java`）：`cn.testin.realweb.mvc.controller.*` 处理

## 多数据源

| 数据源 | 数据库 | 业务域 |
|--------|--------|--------|
| MySQL `db_common`（Druid） | `db_common` | 定时任务模板（`quartz_job`）、执行日志（`quartz_job_log`）、app 信息（`app_info`）、任务关系（`job_task_relation`） |
| MongoDB `pmweb_db` | `pmweb_db` | Web 任务详情、报告、脚本运行记录、设备运行记录（6 类集合 × 100 分片） |
| MongoDB `pmpc_db` | `pmpc_db` | PC 任务详情、报告、脚本运行记录、设备运行记录（6 类集合 × 100 分片） |
| Redis（legacy pool） | `realtestcenter` DB | 操作日志队列、Excel 导出、心跳检测 |
| Redis（springBoot pool） | DB 0 | 通用队列/锁（`RedisService`） |
| MySQL `db_mq`（legacy） | `db_mq` | MQ 通知持久化（`IMqInfoNoticeDAO`，来自 cn.testin.common） |

MongoDB 分片规则：按 taskId 末 2 位数字 → 100 个物理集合（如 `pmwebTaskDetail_00` ~ `pmwebTaskDetail_99`）。taskId 以 `pt` 开头走 PC DB，否则走 Web DB。

## 核心业务域

### 1. 任务模板与定时调度（db_common）

Web/PC 端的定时测试模板管理。涉及表：`quartz_job`（模板主表）→ `job_task_relation`（任务关联）→ `quartz_job_log`（执行日志）。

关键流程：创建/编辑模板（`TestTemplateController.saveTemplate`/`updateTemplateContent`）→ 定时调度注册（`QuartzJobServiceImpl.addScheduler`）→ Quartz 触发 → `WebQuartz`/`McPcQuartz`/`AppQuartz` 执行 → 创建任务（`RealWebApi.add`/`McPcTaskApi.add`）→ 任务下发 → 结果回收。

详见：[核心链路-定时任务执行](04-复杂功能细节/核心链路-定时任务执行.md)

### 2. 任务执行与状态机（MongoDB）

任务生命周期状态机（`TaskProcessServiceImpl.report`）：

```
INIT → MATCH → RUNNING → COMPLETE
               → RECOVER  → RUNNING
```

- `INIT`：持久化 deviceRunInfos + scriptRunInfos，设置 execStatus=ing，通知 test plan + portal
- `MATCH`：标记设备/脚本运行状态 + startTime
- `RUNNING`：标记脚本运行中
- `RECOVER`：设备恢复等待
- `COMPLETE`：汇总结果（analysisCategory/analysisTaskResult），发送跨端通知/邮件/短信/HTTP回调

### 3. 通知系统

`NoticeServiceImpl`（6460行）为核心通知分发器，`MqNoticeDataThread` 每 1000ms 轮询 `MqInfoNotice`。支持 19 种通知类型：

- `TASK_ASSEMBLY` — 任务装配（数据驱动参数分配）
- `WEB_TASK_INIT` — Web 任务初始化（设备/脚本分发）
- `REPORT_STAT` — 报告统计汇总
- `FINISH_EMAIL` — 任务完成邮件
- `SEND_MSG` — 钉钉/飞书消息
- `FINISH_NOTICE` — 机器人通知
- `TASK_CALLBACK` — HTTP 回调
- `SCRIPT_FAIL_SEND_ALL_NOTICE` — 脚本失败通知
- `REPORT_GENERATE` / `REPORT_GENERATE_PLAN` — Excel报告生成

详见：[横切-通知系统](04-复杂功能细节/横切-通知系统.md)

## 后台线程全景

- `StartRunner` 启动：PDFThread、NoticeDispatchThread（MQ channel "realweb"）、MqNoticeDataThread（1000ms 轮询）、QuartzListenerThread（恢复定时任务）
- `@Async` 线程池：`operateLogExecutor`（corePoolSize = cpu×2，maxPoolSize = cpu×2+1，queueCapacity = 1000）
- Quartz：通过 `SchedulerManager` 单例管理，`WebQuartzJob`/`McPcQuartzJob`/`AppQuartzJob` 三种 Job 实现
