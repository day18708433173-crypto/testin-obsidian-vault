# 任务完成通知

> 本文是 [04-横切-通知系统](../04-复杂功能细节/横切-通知系统.md) 的自然语言版（不含代码细节）。

## 功能是什么

任务执行期间和结束后，平台按用户在任务上配置的通知策略，把进度、结果和报告推送到各渠道。通知是异步发送的，发送失败会自动重试。

## 支持的通知渠道

- 邮件
- 钉钉群消息
- 飞书群消息
- 短信
- 用户自定义 HTTP 回调
- 机器人通知
- 门户进度推送（平台内消息）
- 测试计划通知（任务挂接测试计划时）

## 通知时机

| 时机 | 通知内容 |
|---|---|
| 任务创建 | 门户出现新任务与初始进度 |
| 任务开始执行 | 门户进度更新；挂接测试计划时计划侧收到启动通知 |
| 单个脚本失败 | 实时单条失败通知（可选）；也可配置为汇总全部失败后统一发一次 |
| 单个脚本出结果 | 单脚本结果通知（可选） |
| 终端匹配 / 恢复 | 设备匹配状态变化通知 |
| 任务完成 | 完成邮件（含分享链接）、群消息、机器人通知、HTTP 回调、计划完成通知、门户推送 |
| 报告生成 | Excel / 计划报告异步生成完成 |
| 任务取消 | 跨端取消同步 |

## 防重复规则

- 同一任务的完成邮件、脚本失败通知在约 60 秒内不会重复发送。
- 渠道侧自动重试时使用独立标识，避免被渠道去重机制吞掉。

## 可靠性规则

- 通知发送失败会自动重试：每次失败 execNum 加 1，并把发布时间推迟 10 秒（代码中 `if (execNum >= 3) ;` 末尾多写了一个分号，导致该 10 秒推迟对每次失败都无条件生效，并非仅超过 3 次后）；超过约 10 次且创建时间超过 1 小时则放弃该条通知（置非法）。
- 完成类通知依赖任务汇总数据；汇总略有滞后时会自动等待重查（每 5 秒一次、最多 6 次），仍拿不到才放弃。
