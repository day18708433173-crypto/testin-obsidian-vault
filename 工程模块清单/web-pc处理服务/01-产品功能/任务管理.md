# 任务管理

> 来源：http://test.pro.testin.cn/docs/base/task/

任务是自动化用例的执行集合，可根据业务场景或测试计划将用例放入一个任务中执行，附带任务的测试应用、执行时间、测试进度与测试结果，测试报告等信息，了解用例执行的整体表现。

## 任务执行记录列表
通过任务执行记录列表可快速了解任务执行的执行进度、执行结果、执行时长等。

任务执行记录分为创建任务提测后立即执行的记录和由任务模版定时触发执行的记录，定时执行记录，在任务名称会显示时钟的图标。

查看已完成任务执行结果，测试结果状态定义如下：通过：任务中执行通过的脚本数量。取消：人工手动操作取消执行的脚本数量。超时：任务下发后，请求超时的脚本 。未通过：由于脚本错误（脚本错误、AI识别错误）、应用奔溃、启动失败、应用无响应、安装失败等原因导致执行失败的脚本数量。

### 筛选和显示
可自定义任务筛选条件和自定义显示字段，以及进行任务排序。

列表默认按照创建时间倒序显示，支持按应用名称、任务描述、创建人、创建时间等排序。
点击表头空白位置可清空字段排序，恢复按照创建时间倒序显示。

### 任务状态
任务存在3种执行状态，已完成、已取消、执行中，状态定义如下：

**已完成：**任务中所有脚本都执行完成，可查看测试结果。

**执行中：**任务中存在脚本正在执行中，任务执行中若存在无效设备，任务列表提示**执行中**，鼠标悬停图标时，可查看失效设备ID，需人工检查并恢复设备。

**已取消：**手动终止的任务。

#### 执行过程的阶段（内部状态）

（本节规则细节来自 04 专题，见 [04-横切-任务状态机](../04-复杂功能细节/横切-任务状态机.md)。）

上面 3 种执行状态是用户可见的汇总状态；在平台内部，任务从下发到结束会经历五个阶段，由执行端上报的过程事件推进：

| 阶段 | 含义 | 用户可见的变化 |
|---|---|---|
| 初始化 | 任务首次到达执行侧，终端与脚本的运行记录建立 | 任务状态从"等待"变为"执行中"；门户出现进度；若挂接测试计划会收到启动通知 |
| 匹配 | 终端与脚本配对成功 | 记录终端开始执行时间；精准测试的覆盖率标记被清除 |
| 运行中 | 脚本正在终端上执行 | 脚本逐条标记运行状态 |
| 恢复 | 脚本异常中断后，终端回到等待池 | 该终端等待重新匹配，任务继续，不需要人工干预 |
| 完成 | 所有脚本 / 终端执行完毕 | 计算任务总结论并批量发出完成通知 |

完成阶段平台会：按设备维度汇总执行结果并计算任务总结论（**全部通过为 PASS，否则 FAIL**）；向跨端模块同步任务状态；发出全部完成通知（短信 / 群消息、完成邮件、机器人通知、用户 HTTP 回调、测试计划完成通知、门户推送，详见 [任务完成通知](任务完成通知.md)）；若开启精准测试，生成并保存覆盖率数据。

状态保护规则：已完成的任务**不会**被迟到的中间状态事件覆盖回"执行中"；终端的开始执行时间一旦记录，不会被更早的时间覆盖。这两条保证任务列表和报告页看到的状态始终单调推进、可信任。

### 任务操作
可对任务进行终止、重测、删除的操作。

**重测** ：重测时默认使用上一次提测时的任务配置信息，可修改，提交成功后将自动新增一条任务执行记录。

可根据测试结果选择想要重测的脚本。

**查看报告**：查看任务执行详情，可了解脚本测试概况（执行概况、问题统计、设备性能）、脚本执行报告（每条脚本的执行详情、执行状态）、设备执行报告（每个设备的执行详情）、截图对比（每条语句执行前后的截图对比）任务报告。

**删除**：所有状态（已完成、执行中、已取消）的任务都可操作删除，操作删除后，正在执行的脚本会继续执行完毕，没开始执行的脚本将取消执行，任务删除后不可恢复请谨慎操作。

注：任务执行记录已关联测试计划执行记录后，无法操作删除任务执行记录。

**提交缺陷**：和第三方缺陷管理平台对接后，可提交缺陷至第三方管理平台，当前已支持对接 TAPD、Jira、云测测管的平台。

**批量操作**：支持选择任务进行批量终止、删除的操作。

**暂停：**任务触发执行后，未下发至设备执行的脚本可操作暂停，暂停后已下发至设备的脚本将继续执行直至完成，未下发的脚本将不再下发执行，暂仅支持数据驱动方式提测的任务。

**继续执行：**已暂停任务可操作继续执行，暂仅支持数据驱动方式提测的任务。

**有效执行耗时：**统计至少一个脚本在执行的时间段，以评估有效执行的总耗时。

**任务执行耗时：**任务结束时间-任务创建时间。

任务操作的底层规则（细节来自 04 专题，见 [04-核心链路-Web任务执行](../04-复杂功能细节/核心链路-Web任务执行.md)）：取消随时可发起，尚未下发完成的任务走快速取消通道；继续执行（`execute`）仅对测试计划渠道的任务重新发起装配与下发，普通任务只翻转暂停/继续状态；补测 / 重测按失败状态过滤脚本后重新封装下发，只重跑需要重测的部分。

## 任务提交校验与执行配置

（本节规则细节来自 04 专题，见 [04-核心链路-Web任务执行](../04-复杂功能细节/核心链路-Web任务执行.md)；Web 与 PC 任务走同一条链路，区别只在终端类型。）

### 提交时的校验

提交任务时平台会做一系列校验，任何一项不通过都会直接拒绝并提示原因：

| 校验项 | 不通过的表现 |
|---|---|
| 业务配置是否存在 | 提示业务配置无效 |
| 用户信息是否有效 | 提示用户信息无效 |
| 通知用的手机号、邮箱格式 | 提示参数非法 |
| 录屏策略取值是否合法 | 提示参数非法 |
| 所选浏览器 / PC 终端是否存在且可用 | 提示设备不存在或不可用 |
| 所选环境配置是否存在 | 校验后才能继续 |

### 任务级执行策略

除 [Web-任务提测](../../其他功能基础介绍/其他功能汇总.md#Web-任务提测) / [PC-任务提测](../../其他功能基础介绍/其他功能汇总.md#PC-任务提测) 中页面可见的执行选项外，提测时还可以携带一组影响整个任务运行方式的策略：

- **出错后继续**：某个脚本失败是否中断后续脚本。
- **录屏**：是否录制执行过程视频。
- **脚本分组**：脚本之间的分组执行方式。
- **完成前回调**：任务收尾前是否先回调用户系统。
- **全局超时**：任务最长执行时间，超时被强制结束；不配置则取平台默认值。
- **失败重试上限**：结果处理异常时的自动重试次数，填负数按 0 处理。

### 数据源装配规则

任务支持两种参数来源：随脚本携带的参数，以及独立的数据源。装配阶段会把数据源按行分配给各个脚本；当执行标准声明为数据驱动模式时，每条数据行会提前绑定到对应脚本，并保证同一脚本的同一条数据在同一台终端上执行。

### 异常时用户可见的表现

| 场景 | 表现 |
|---|---|
| 装配反复失败 | 自动重试；失败超过约 10 次且耗时超过 1 小时，任务被置为非法状态 |
| 脚本展开异常 | 重试超过约 10 次后直接置非法 |
| 结果重复上报 | 只计一次，不会产生重复数据 |
| 任务超时 | 到达全局超时后由调度侧强制结束 |
| 已完成任务 | 状态有保护，不会被后续迟到的中间状态覆盖 |

## 结果回收与报告生成

（本节规则细节来自 04 专题，见 [04-核心链路-报告生成](../04-复杂功能细节/核心链路-报告生成.md)。）

### 结果回收与错误归因

每条脚本结果回收时，平台区分正常结果与异常结果分别解析；异常信息会按项目配置的**错误原因规则**自动匹配（错误文本优先，其次 OCR 识别文本），命中后归类为标准错误原因，方便报告聚合。结果关联到对应脚本与数据行写入报告明细，并触发脚本维度与任务维度的统计汇总，按设备、脚本、结果分类聚合成任务级汇总数据，供报告页、邮件、Excel 共同使用。重复上报同一份结果不会重复计数（幂等处理）；任务已不存在时直接忽略，不影响调度侧重试。

用户人工订正（修改结果分类、修改错误原因）后，汇总会自动重新统计，保证报告页数据与订正结果一致。

### Excel 报告导出

- 导出是**异步生成**：请求后进入"生成中"，生成完成后返回下载地址。
- 如果已有生成时间晚于任务结束时间的报告，直接复用旧地址，不重复生成。
- 任务结果还在统计中时导出会被拦截，提示"任务正在统计中"。
- 重复点击导出不会产生多个生成任务，只返回"等待"。
- 生成内容包含三个部分：任务基本信息、设备维度明细、链接页；补测和历史数据不纳入。
- 生成反复失败（约 20 次）后放弃，报告状态落为失败，前端可见失败态。
- 测试计划也支持导出 Excel：按计划下多次执行记录聚合生成，生成过程会记录操作日志（开始 / 成功 / 失败），导出页可轮询进度。

### PDF 报告

PDF 采用"请求 → 后台异步转换 → 前端轮询"的方式：首次请求进入转换队列，前端轮询同一入口，状态为等待 / 成功 / 失败三种；终态返回后转换记录被清理。

### 完成邮件

任务结束时自动发送完成邮件：

- 收件人取任务上配置的自定义邮箱列表；未配置则静默跳过。
- 项目配置了自定义邮件主题时，用自定义主题替换默认主题。
- 邮件内含**免登分享链接**，点开即可查看报告。
- 同一份完成邮件在短时间内不会重复发送（约 60 秒防重窗口）；通道侧重试时使用独立标识避免被去重吞掉。
- 汇总数据略有滞后时，发送前会自动等待并重查（每 5 秒一次、最多 6 次）；仍拿不到则放弃本次发送。

同阶段还会发出钉钉 / 飞书群消息、机器人通知、用户 HTTP 回调、测试计划完成通知和门户推送，详见 [任务完成通知](任务完成通知.md)。

## 任务模版
配置定时触发执行任务的策略，用于生产巡检场景，例如：每月、每周、每天、某个时刻固定时间点需要开始执行的自动化用例，可放在定时任务中进行执行。

### 启用状态
定时模版存在3种启用状态，进行中、暂停中、已完成，如下：

**进行中：**满足定时配置条件时会自动触发执行任务并生成测试报告。

**暂停中：**不再按照定时规则触发执行任务，可操作恢复继续定时触发任务的执行。

**已完成：**按照定时规则执行完毕后，后续不再触发任务执行。

### 定时调度规则

（本节规则细节来自 04 专题，见 [04-核心链路-定时任务执行](../04-复杂功能细节/核心链路-定时任务执行.md)。Web、PC、App 三类任务共用同一套定时能力。）

#### 两种调度方式

| 方式 | 规则 | 错过触发时 |
|---|---|---|
| 普通 cron | 指定时间 / 定点 / cron 表达式 | 直接丢弃，不补跑 |
| 高级设置 | 在"每天 / 每周 / 每月"的限定时段内周期执行 | 顺延到下一次 |

高级设置下可以额外限制：

- **结束时间**：超过后自动停止并完结该定时任务。
- **总次数上限**：达到上限后自动停删调度、完结任务。
- **当日时段次数上限**：当天额度用尽则跳过，等下一天。
- **上次未结束**：上一次生成的任务还在等待或执行中时，本次触发跳过，稍后再试。

手动触发（立即执行一次）不受上述次数与过期限制。

#### 触发时的业务规则

- 模板已删除或已过期：不再生成任务。
- PC 任务会校验所选终端的禁用状态：全部禁用则报错"设备全部禁用"，部分禁用则提示部分设备不可用。
- 每次触发生成的实时任务**强制使用脚本的最新版本**（不沿用保存模板时的旧版本）。
- 定时生成的任务在门户列表中带有"定时"标记（即执行记录列表中任务名称上的时钟图标），可与手动任务区分。
- 每次触发都会留下一条执行流水（记录了对应生成的任务和请求内容），可在执行日志中查询；高级设置的任务还会记录模板与任务的关联关系。
- 定时触发生成的任务与手动提交的任务走完全相同的装配、下发、执行、回收链路，产出完全一致的执行记录和报告。

#### 保存模板时的约束

- cron 表达式必须合法且未过期，否则保存失败并提示"调度已过期"。
- 同名调度会先删旧再建新，保证一份模板只有一个生效中的调度。
- 调度注册失败时（非修改场景）模板记录会被回滚删除，避免留下"有模板但永远不会触发"的脏数据。

#### 服务重启与删除

- 服务重启后会自动重建所有"执行中 / 暂停中"的定时调度：已过期的 cron 不删除模板，只标记为"已完成"；暂停中的模板重建后保持暂停。
- 删除模板时：若被测试计划占用会阻止删除；否则停止调度并做逻辑删除，可选是否级联删除门户上的执行记录（即上方"删除定时任务 / 删除所有执行记录"两种操作）。

### 操作
可进行任务定时配置修改、暂停和删除操作，可手动触发立即执行以及查看任务执行记录。

#### 编辑
可修改任务模版的配置信息，如：定时规则、任务描述、执行选项等内容。

如：可将平台历史定时任务模版修改为非定时任务模版，通过测试计划关联非定时任务模版进行回归测试。

注：已关联至测试计划的非定时任务模版不可切换执行时间。

#### 立即执行
手动触发定时任务立即执行 ，执行后可在定时任务配置列表查看任务的执行记录或全部任务列表页查看执行记录。

#### 删除定时任务
仅删除定时任务的配置信息，保留任务执行记录和测试报告，可在全部任务列表查看执行记录。

#### 删除所有执行记录
删除定时任务配置信息，同时删除该任务的所有执行记录以及测试报告数据。

#### 批量操作
支持选择任务批量执行、暂停、恢复、删除等操作。

### 执行记录
查看某一个定时任务配置下的所有任务执行记录以及测试报告，可对任务进行重测、删除的操作。

批量暂停：进行中的任务批量暂停执行。批量恢复：已暂停的任务可批量操作恢复执行。批量立即执行：所有任务可批量操作立即执行。批量删除：可将选中任务批量操作删除。
