# 核心链路-定时任务模板执行

> 机制是**每个定时模板一个独立 Quartz Job**，不是周期性扫表。`TaskTemplateExecuteJob` 只在 Cron 到点时执行一次（读取 JobDataMap 里的 `taskTemplateId` 再触发执行），本身不做扫描。

## 触发链路

1. 定时模板（`template_type=2`）创建/保存时，`TaskTemplateQuartzServiceImpl.addTaskTemplateQuartz` 用 `CronUtil.checkCronExpression` 校验 cron 后，通过 `QuartzService.addScheduledJob` 注册 `TaskTemplateExecuteJob`（Job 名 `taskTemplateJob{id}`，组 `taskTemplateJobGroup{taskType}`），JobDataMap 携带 `taskTemplateId`；
2. Cron 到点，`TaskTemplateExecuteJob.executeInternal`：
   - 读 `taskTemplateId` → `taskTemplateService.selectById`，模板已删除（`status` 删除）则跳过；
   - 组装 `TaskExecuteRecordRequestDTO`（`taskSource = TIMER_TASK(2)`，`level` 默认），调 `taskExecuteRecordService.executeTask(request)`；
3. 后续与手动提测完全一致：`executeTask` 建快照 → LPUSH `task_execute_record_init_queue` → 标准执行管道。

## 模板状态对调度的控制

- `task_template_status = EXECUTING(2)`：正常参与调度；
- `task_template_status = PAUSE(1)`：`TaskTemplateQuartzServiceImpl.pauseTaskTemplate` 调 `pauseScheduledJob` 暂停该模板的 Job；恢复走 `resumeTaskTemplate`（Job 不存在则重建）。

## Quartz 配置

`TaskTemplateSchedulerConfig`：Scheduler 实例名 `real_task_scheduled`，线程池 `org.quartz.threadPool.threadCount` 默认 20（`REAL_TASK_QUARTZ_THREAD_POOL_COUNT`）。监听器 `TaskTemplateJobListener` / `TaskTemplateSchedulerListener` / `TaskTemplateTriggerListener` 记录 Job 执行与调度事件日志。

## 补偿机制（启动时重建，非周期检查）

`TaskTemplateExecuteRestartJob`（`InitializingBean.afterPropertiesSet`）：因 Quartz 非分布式、容器无法横向扩容，启动时在独立线程里抢 Redis 锁 `TASK_TEMPLATE_EXECUTE_RESTART_JOB`，分页扫描 `template_type=2 && task_template_status=EXECUTING` 的模板，逐个 `addTaskTemplateQuartz` 重新注册 Quartz Job，保证「到点必跑」的 Job 不因重启丢失。拿锁后线程进入 `LOCK.wait()` 常驻。

## 涉及表 / 组件

| 表/组件 | 操作 |
|---------|------|
| `task_template` | 读（触发时取模板基本信息） |
| `task_template_detail/script/device/case` | 读（`executeTask` 内加载配置快照） |
| Quartz Scheduler | 注册/暂停/恢复/删除 `TaskTemplateExecuteJob` |
| `task_execute_record` 族 | 写（执行记录快照） |
