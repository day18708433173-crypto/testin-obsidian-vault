# 任务管理服务 部署文档

> 工程：`D:\programfile\major\java\testin\workspace\real-task`（Java / Spring Boot，Maven 单模块，artifactId=real-task）。本文基于 Dockerfile 的构建/启动命令整理；镜像由 CI 产出供 k3s 使用。本地启动 pom.xml 修改见文末内部 wiki 链接。

## Docker 镜像构建（两阶段）

| 阶段 | 基础镜像 | 作用 |
|---|---|---|
| BUILD | `registry-jxq.testin.cn/ng/mevan-build:autopoc-3-9-1` | 带 JDK + Maven，编译打包（与其他服务不同，构建镜像独立） |
| RUN | `hub-mirror.testin.cn/library/busybox:stable` | 只承载 jar/config，启动时解包到挂载卷 |

### 打包命令（BUILD 阶段）

```bash
mvn clean install -P test -Dmaven.test.skip=true
```

- `WORKDIR /data/webhome`；直接用 `mvn`（非 `/var/maven/bin/mvn`），激活 `test` profile，跳过测试。

### 启动命令（startup.sh）

```bash
java --add-opens java.base/java.lang=ALL-UNNAMED -Xms1024m -Xmx2048m -XX:MaxRAMPercentage=75 -XX:+UseContainerSupport -jar real-task.jar
```

- `--add-opens java.base/java.lang=ALL-UNNAMED`：开放 java.lang 模块供反射；`-XX:MaxRAMPercentage=75` + `-XX:+UseContainerSupport`：容器感知，按容器内存上限取 75% 作堆。

### 运行阶段（busybox）

- 挂载卷：`VOLUME /data/webhome /home`
- CMD：`cp -R /data/target/* /data/webhome/` 解包 + 创建目录 `/home/syy/data/logs/real-task`

## 镜像构建与推送（.gitlab-ci.yml）

| 触发 | 命令 | 镜像 tag |
|---|---|---|
| 打 tag | `docker buildx build -f Dockerfile --platform linux/arm64,linux/amd64 -t $CI_REGISTRY_IMAGE:$CI_COMMIT_TAG . --push` | `$CI_REGISTRY_IMAGE:$CI_COMMIT_TAG` |
| `syy.release.*` 分支 | `docker build --pull` + 两次 `docker push` | `$CI_REGISTRY_IMAGE:$CI_COMMIT_REF_SLUG-<短SHA>` 与 `...:$CI_COMMIT_REF_SLUG` |

构建前 `docker login` 到 `$CI_REGISTRY`；DOCKER_HOST 指向 `tcp://registry.testin.cn-public-docker:2375`。

## 部署到 k3s

镜像推送后，k3s 工作负载引用镜像 tag；容器启动时 busybox CMD 先把 `/data/target` 解包到 `/data/webhome`，再由 startup.sh 的 java 命令拉起进程。

## 本地打包与启动

```bash
mvn clean install -P test -Dmaven.test.skip=true   # 打包
java --add-opens java.base/java.lang=ALL-UNNAMED -Xms1024m -Xmx2048m -XX:MaxRAMPercentage=75 -XX:+UseContainerSupport -jar real-task.jar
```

- 产物：`target/real-task/real-task.jar`。

## 本地启动 pom.xml 修改

本地启动（IDE 或直接 `java -jar`）时需两处改动：

1. **放开**被注释的 `src/main/resources` includes 块（`**/*.properties`、`**/*.yml`、`**/*.yaml`、`**/*.xml`）；
2. **注释掉** `src/main/resources → target/real-task/config` 外置块（`<targetPath>${project.build.directory}/${project.artifactId}/config</targetPath>`）。

改完后配置回到默认 classpath（打进 jar），本地才能启动。

> **注意：此修改仅用于本地启动；Docker 部署不需要** —— 镜像构建保持配置外置，由 startup.sh 从 `config/` 目录加载。
