# 开发指南

> 工程：`real-task`（任务管理服务，Java 17 / Spring Boot 3.2.12）。先读 [00-首页](../00-首页.md) 建立整体认识，执行链路细节见 [任务执行管道实现](../03-实现逻辑/任务执行管道实现.md)。

## 工程结构

```
real-task/
├── pom.xml                     Spring Boot 3.2.12 parent，finalName=real-task
├── Dockerfile                  两阶段构建：maven 构建 → busybox 拷贝产物
└── src/main/
    ├── java/cn/testin/
    │   ├── start/              RealTaskApplication（@SpringBootApplication + @MapperScan("cn.testin.mapper")）+ SpringBootContext
    │   ├── controller/         REST 入口（task/ 下 7 个 Controller，统一 /real_task 前缀）+ exception/ 全局异常
    │   ├── service/            业务层接口（task/ plan/ device/ script/ ...）
    │   │   └── impl/           实现（impl/task/ 下 TaskHandlerServiceImpl 3853 行、TaskExecuteRecordServiceImpl 3131 行是两个巨类）
    │   ├── mapper/             MyBatis-Plus Mapper 接口
    │   ├── entity/task/        29 个 MyBatis-Plus 实体
    │   ├── dto/                100+ DTO，按 domain 分包
    │   ├── dao/                （历史遗留，主要走 mapper）
    │   ├── schedule/task/      20 个后台线程/Quartz Job（消费线程 + 扫描线程 + Restart 补偿）
    │   ├── api/                远程服务封装（device/ script/ plan/ user/ data/ file/ system/ realcfg/ ...）
    │   ├── strategy/           plan/ 回调策略（7 种 CallbackType + 注册器）、action/ 扩展处理
    │   ├── config/             AsyncConfig（11 线程池）、RedissonConfig、WebClientConfig、Quartz 配置等
    │   ├── common/             常量（RedisQueueConstants/CommonConstants）、30+ 枚举、异常
    │   ├── interceptor/ + annotation/   @UnderlineToCamel 参数转换
    │   ├── listener/quartz/    Quartz 监听器
    │   └── util/               JsonUtil、ServiceRemoteApiUtil（统一远程调用）等
    └── resources/
        ├── application.yaml    唯一配置文件（无 profile 分文件，全走环境变量默认值）
        ├── log4j2.xml          日志
        ├── mapper/**/*.xml     MyBatis XML（classpath*:mapper/**/*.xml）
        └── bin/startup.sh      启动脚本
```

## 分层约定

- **Controller**：`@RestController + @RequestMapping("/real_task")`，context-path `/v3`，完整路径 `/v3/real_task/*`；入参 `@Valid`（Jakarta validation），返回统一 `ResponseResult<T>`；GET 列表用 `@UnderlineToCamel` 自动转下划线参数。
- **Service**：接口在 `service/<domain>/`，实现在 `service/impl/<domain>/`；写库以 MyBatis-Plus 为主，复杂条件查询走自定义 XML（`ConditionDTO` 命名规律：`XxxConditionDTO`）。
- **远程调用一律走 `api/` 包**：`XxxServiceApi extends BaseServiceApi`，经 `ServiceRemoteApiUtil.syncPostV3/syncGetV3/syncPostV1`；V3 是各服务 REST，V1 是设备控制中心的 RPC 风格（`op`/`action`/`data`）。**禁止在 service 里直接 new WebClient**。
- **状态变更用条件更新**：`updateSelectiveByCondition` 带原状态过滤做乐观并发控制，影响行数 0 视为冲突（见 [任务状态与异常处理实现](../03-实现逻辑/任务状态与异常处理实现.md)）。
- **队列常量集中在 `RedisQueueConstants`**，新增队列要同时加 bak 队列名与消费线程装配（`TaskExecuteRecordConsumerRestartInit`）。

## 新增一个功能的标准流程

1. 实体/DTO：`entity/task/` 放 MyBatis-Plus 实体，`dto/` 按域分包。
2. Mapper：接口放 `mapper/`，复杂 SQL 写 `resources/mapper/**/*.xml`。
3. Service 接口 + 实现；枚举进 `common/enums/`，常量进 `common/constant/`。
4. Controller：挂到对应域 Controller，注意 `BaseController.checkProjectId` 项目校验。
5. 涉及异步处理：优先复用现有队列管道；新管道 = 队列常量 + `XxxThread implements Runnable` + `TaskExecuteRecordConsumerRestartInit` 装配 + 分片数配置项。
6. 涉及定时：Quartz Job（集群 JDBC JobStore，参考 `TaskTemplateExecuteJob`），简单轮询用 `@Scheduled`（参考 `TaskStartExecuteThread`）。
7. 回调计划：新回调类型 = `CallbackTypeStrategyEnum` 加枚举 + `strategy/plan/` 加策略 + `InitCallBackStrategy` 注册。

## 本地构建运行

```bash
# 构建（跳过测试）
mvn clean install -P test -Dmaven.test.skip=true
# 产物：target/real-task.jar（finalName=real-task）

# 本地启动（需可达的 MySQL db_task 与 Redis）
java --add-opens java.base/java.lang=ALL-UNNAMED -jar target/real-task.jar
```

- 启动类 `cn.testin.start.RealTaskApplication`；`--add-opens` 参数来自 Dockerfile 的 startup.sh，JDK 17 下必须带。
- 依赖仓库是内网 Artifactory（`https://repository.testin.cn/repository/testin`），外网拉不到私有依赖。
- Dockerfile 是两阶段构建：maven 阶段 `mvn clean install -P test`，运行阶段 busybox 把 `target/real-task/` 拷进 `/data/webhome`，日志目录 `/home/syy/data/logs/real-task`。

## 配置要点

`application.yaml` 全部环境差异走 `${ENV:default}` 注入，无多 profile 文件。本地起服务最少要改/注入：

| 配置 | 环境变量 | 默认（指向生产，本地必改） |
|---|---|---|
| MySQL `db_task` | `TESTINPRO_MYSQL_HOST/PORT/USER` + `TESTINPRO_MYSQL_BAOMIDOU_SECRETPWD` | `mysql.pro.testin.cn:3306`（密码为 baomidou ENC 密文，需 jasypt 密钥） |
| Redis | `TESTINPRO_REDIS_HOST/PORT/PASSWORD` | `redis.pro.testin.cn:6379`，clientName=real-task |
| 队列分片数 | `TASK_INIT_CONSUMER_COUNT` / `TASK_RESULT_PARSE_COUNT` / `TASK_RESULT_ANALYSIS_COUNT` / `TASK_CANCEL_COUNT` / `TASK_SEND_PLAN_COUNT` / `TASK_EXECUTE_RECORD_COUNT` | 全部默认 20；分片数决定队列名后缀 `{id % count}`，**改了必须和历史队列里的存量消息对齐** |
| Quartz | `REAL_TASK_SCHEDULER_INSTANCE_NAME` / `REAL_TASK_QUARTZ_THREAD_POOL_COUNT` | `real_task_scheduled` / 20（JDBC JobStore，共用 db_task） |
| Druid 连接池 | 写死在 yaml | initial/min 10，max 40，慢 SQL 阈值 5s |
| 报告分享/导出 | `REPORT_SHARE_EXPIRE_DAYS` / `REPORT_EXPORT_*` | 分享 7 天，导出临时目录 `/tmp/report-export` |
| 下游服务地址 | `ApiUrlConfig`（`config/` 内） | 设备控制中心 / 脚本服务 / 平台基础功能服务等 URL 集中在此 |

## 约定清单

- **日志**：log4j2（`resources/log4j2.xml`），spring-boot-starter-logging 已在 pom 排除；业务代码 `LogManager.getLogger(Xxx.class)`。
- **序列化**：内部队列消息统一 `util/JsonUtil`（Jackson）；对设备控制中心 V1 报文结构是 `RemoteV1RequestDTO{op, action, data}`。
- **HTTP 客户端**：WebClient（`ServiceRemoteApiUtil` 封装）+ 少量 OkHttp；超时默认 100s（`ServiceRemoteApiUtil.java`）。
- **事务**：写多张表的入口方法标 `@Transactional(rollbackFor = Exception.class)`（executeTask / init / preComplete 都是），注意大事务问题。
- **线程池**：全部在 `AsyncConfig` 声明（11 个），新线程池进这里统一命名管理；消费线程优先复用现有池。
- **数据库**：单库 `db_task`，dynamic-datasource 只有一个数据源；MyBatis-Plus 分页插件在 `MyBatisPlusConfig`。

## 跨端修改红线

| 修改对象 | 影响 | 要求 |
|---|---|---|
| `TaskMatchResponseDTO` / `TaskPreCompleteRequestDTO` / `TaskResultReportRequestDTO` | 与设备控制中心/上位机的下发与回调协议 | 与设备控制中心同步评估；回调返回码 0/1 是对端重试协议，不能乱改 |
| `RedisQueueConstants` 队列名 / 分片数 | 队列寻址 | 灰度期新旧消息兼容；分片数变更要处理存量队列 |
| V1 RPC `op=Task.distributeTask` 报文 | 设备控制中心 TCP 下发 | 两端同改同发 |
| `task_send_plan_queue` 回调报文（`TaskExecuteCallbackRequestDTO`） | 平台基础功能服务计划汇总 | 与平台基础功能服务联调 |
| Controller 路径/出入参 | 前端与平台基础功能服务（RealTaskV3Api） | 保持 `/v3/real_task` 前缀与 `ResponseResult` 包装 |
