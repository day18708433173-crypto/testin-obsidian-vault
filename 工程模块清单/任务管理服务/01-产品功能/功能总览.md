# 功能总览

> 功能维度总索引：一句话定位 + 核心能力 + 深入阅读。代码级细节见 [03-任务执行管道实现](../03-实现逻辑/任务执行管道实现.md)、[03-任务状态与异常处理实现](../03-实现逻辑/任务状态与异常处理实现.md) 与 [04-专题索引](../04-复杂功能细节/专题-索引.md)。

## 功能地图

```
任务管理服务
├── 任务模板管理    → 模板 CRUD + 批量暂停/恢复/删除 + Cron 定时模板
├── 任务执行       → 手动提测 / 计划提测 / 定时触发 / 重测 + 取消/暂停/恢复
├── 任务报告       → 脚本级/步骤级报告 + 性能/日志/埋点摘要 + 导出分享
├── 用例报告       → 用例 × 数据行维度结果 + 步骤流转 + 缺陷/错误原因标记
└── 结果回收管道   → 预完成 → 结果上报 → 解析 → 分析 → 回调计划
```

## 任务模板管理

> 界面入口：[用例任务页](用例任务.md) `/platform/task-case-manage/list` 的任务模板。

任务模板是"可复用的任务配置包"：脚本/用例清单、设备清单（或设备条件）、执行标准（全局超时、加速、性能/日志采集开关等）、通知策略、执行时间段。

- **手动模板**（`template_type=1`）：点"执行"立即生成执行记录进入管道。
- **定时模板**（`template_type=2`）：挂 Quartz Cron，由 `TaskTemplateExecuteJob` 到点触发；模板暂停（`task_template_status=PAUSE(1)`）时调度跳过。
- 模板关联测试计划：计划侧可引用模板，模板用例状态变化经 `TaskTemplateCaseIdStatusThread` 同步回平台基础功能服务。
- 深入阅读：[核心链路-任务提测](../04-复杂功能细节/核心链路-任务提测.md)、[核心链路-定时任务模板执行](../04-复杂功能细节/核心链路-定时任务模板执行.md)、[端到端-定时任务](../../跨模块链路/端到端-定时任务.md)

## 任务执行（执行记录）

> 界面入口：[用例任务页](用例任务.md) `/platform/task-case-manage/list` 的执行记录列表。

执行记录是模板的运行实例，也是本服务的绝对核心。任务来源四种（`TaskSourceTypeEnum`）：手动(1) / 定时(2) / 测试计划(3) / 重测汇总(4)。其中重测子任务本身归为手动(1)，`重测汇总(4)` 仅用于聚合多次重测的汇总父记录。

- **提测**：`POST /v3/real_task/task_execute_records/execute`，支持按模板提测与无模板直接提测（临时选脚本+设备）。
- **重测**：基于旧记录重建任务，可按报告/用例/状态过滤仅重测失败项；可生成"汇总父记录"聚合多次重测（`parent_id` 父子链）。
- **取消 / 暂停 / 恢复**：`/cancel` `/pause` `/resume`；取消走 `task_cancel_queue_{n}` 异步处理，暂停的任务被 20s 扫描跳过。
- **设备分配**：执行时按需向设备控制中心锁设备，锁不到进入 `NO_DEVICE(10)` 状态等待重试。
- 深入阅读：[任务执行管道实现](../03-实现逻辑/任务执行管道实现.md)、[核心链路-任务执行](../04-复杂功能细节/核心链路-任务执行.md)、[核心链路-任务重测](../04-复杂功能细节/核心链路-任务重测.md)、[端到端-重测](../../跨模块链路/端到端-重测.md)

## 任务报告

> 界面入口：[用例任务页](用例任务.md)执行记录详情的报告，详见 [用例执行报告](用例执行报告.md)。

一次执行记录对应一份任务报告：

- 脚本任务：按"脚本 × 设备"生成报告行，步骤级明细、性能数据、日志、埋点摘要。
- 报告摘要（日志/性能/埋点）由 `TaskReportSummaryController` 提供；支持导出与免登分享（分享有效期、导出临时目录均可配置）。
- 结果异常时按"无结果文件"路径兜底归因（`dealReportResultWithErrorByNoSwjReport`）。

## 用例报告

> 界面入口：[用例任务页](用例任务.md)执行记录详情的用例报告。

用例任务按"用例 × 数据行"组织结果（`task_execute_record_report_case`），步骤间以 `preCaseStepIds / aftCaseStepIds` 形成 DAG 流转：上一步预完成后削减下一步的前置计数，前置清零即触发下发。支持错误原因类型匹配（OCR/日志规则）与用例状态回写。

- 深入阅读：[核心链路-结果回收](../04-复杂功能细节/核心链路-结果回收.md)、[核心链路-回调处理](../04-复杂功能细节/核心链路-回调处理.md)

## 数据模型要点

单库 `db_task`，全部数据按 `task_execute_record` 族组织。建任务（`TaskExecuteRecordServiceImpl.executeTask`，`src/main/java/cn/testin/service/impl/task/TaskExecuteRecordServiceImpl.java`）一个事务内写以下表（脚本任务 7 张，用例任务再多 4 张）：

| 分组 | 表 | 说明 |
|---|---|---|
| 主表 | `task_execute_record` | 状态机 + 统计字段（execute/success/fail/skip/timeout/cancel × script/case） |
| 配置快照 | `task_execute_record_detail` / `task_execute_record_standard_detail` | 提测参数与执行标准快照（改模板不影响已建任务） |
| 执行对象 | `task_execute_record_script` / `task_execute_record_case` | 脚本清单 / 用例清单 |
| 用例扩展 | `task_execute_record_case_step` / `task_execute_record_case_tag` / `task_execute_record_type` | 用例任务专有：步骤、标签、类型 |
| 资源 | `task_execute_record_device` / `task_execute_record_time_period` / `task_execute_record_notice` | 设备、执行时间段、通知 |

执行期另有三张关键运行表：`task_execute_record_executing_report`（待下发排队）、`task_execute_record_device_execute_record`（设备占用）、`task_execute_record_send_task_plan`（计划回调待办）。

> 字段级定义见 [db_task 表索引](../../数据库管理/db_task/00-表索引.md) 与 [表关系总览](../02-技术架构/表关系总览.md)；模板侧对应 `task_template` 族 8 表。
