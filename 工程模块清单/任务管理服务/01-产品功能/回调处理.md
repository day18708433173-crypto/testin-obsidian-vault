# 回调处理

> 本文是 [04-核心链路-回调处理](../04-复杂功能细节/核心链路-回调处理.md) 的自然语言版（不含代码细节）。
>
> 方向先分清：本服务的「回调」有两类、方向相反。
> 1. **入站回调**（设备控制中心 → 本服务）：`/pre_complete`、`/result_report`，驱动结果回收（见 [核心链路-结果回收](../04-复杂功能细节/核心链路-结果回收.md)）。
> 2. **出站回调**（本服务 → 平台基础功能服务）：把任务各阶段的执行进度与结果主动回传给计划侧。**本文讲的是这一类。**

## 功能是什么

任务从初始化到出结果的整个生命周期里，任务管理服务会按事件类型把执行进度、结果与状态变更主动回传给平台基础功能服务（计划侧），让计划/前端能实时看到任务的执行情况。平台按事件类型分别组装回调内容，同一条回调失败会自动重试，超过上限则丢弃。

## 支持的回调事件（7 类）

| 回调事件 | 触发时机 | 回调内容 |
|---|---|---|
| 任务初始化完成 | 任务初始化生成报告行后 | 回传本次任务的执行脚本总数 / 用例总数 |
| 脚本执行结果 | 单个脚本执行完成 | 脚本结果（成功/失败分类、各阶段耗时、脚本号、设备） |
| 任务完成 | 任务整体执行完成 | 任务最终状态（成功/失败/取消）+ 有效执行时长 + 错误信息 |
| 子任务下发 | 子任务下发/结束时 | 正在执行中的子任务数增减（ADD/REDUCE） |
| 脚本状态更新 | 手动更新脚本结果状态 | 脚本结果分类变更 |
| 错误原因更新 | 更新错误原因类型 | 脚本/用例的新错误原因类型与结果摘要 |
| 用例执行结果 | 单个用例执行完成 | 用例结果 + 其下脚本执行明细 |

## 对外约定

- 回调按类型独立处理，新的事件类型可独立扩展，不影响已有事件。
- 每条回调失败会自动重试（重试次数累加），超过上限（100 次）后静默丢弃并记错误日志，避免无限重试刷接口。
- 结果回收链路整体幂等，同一事件重复回调不会造成重复处理。
