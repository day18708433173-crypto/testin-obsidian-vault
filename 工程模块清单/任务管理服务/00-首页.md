# 任务管理服务 总览

> 任务模块：测试任务模板管理 + 任务执行调度 + 结果回收与报告生成。本页为分支无关的通用介绍，分支强相关内容见下方分支索引。

## 定位

任务管理服务 是测试平台的"任务工厂"，负责管理任务模板、调度任务执行、回收执行结果并生成报告：

| 职责 | 任务管理服务 | app处理服务 | 任务调度服务 | 平台基础功能服务 |
| ---- | --------- | --------- | --------------- | ----------- |
| 任务模板 CRUD / 定时 Cron | **核心** | — | — | — |
| 任务提测下发 / 执行调度 | **核心** | — | — | 计划触发 |
| 设备匹配 / 脚本分发 | 匹配请求 | **核心**（执行） | **核心**（分发） | — |
| 执行结果解析 / 报告生成 | **核心** | — | — | — |
| 用例执行记录 / 缺陷标记 | **核心** | — | — | — |
| 通知发送 | 请求 notice-manager | — | — | **核心** |

## 单入口架构

| 入口 | 路径前缀 | 技术 | 路由方式 |
|------|---------|------|----------|
| DispatcherServlet | `/v3/*` | Spring MVC | `@RestController` + `@RequestMapping` 注解路由 |

任务管理服务 **仅提供 Spring MVC 入口**，无 ApiServlet 反射入口。所有接口均以 `/v3/real_task` 为前缀（context-path `/v3` + 控制器 `@RequestMapping("/real_task")`）。

区别于 平台基础功能服务 的双入口架构，任务管理服务 的 API 路径为 `/v3/real_task/*`，通过 7 个 Controller 统一处理。

## 数据源

默认数据源 `db_task`（单库），Druid 连接池：初始 10，最小 10，最大 40。

| 数据源 | 数据库 | 业务域 |
|--------|--------|--------|
| `db_task`（默认/唯一） | `db_task` | 任务模板、执行记录、执行报告、用例结果、设备执行记录、标准详情、通知记录、定时调度 |

> 注：平台基础功能服务 管理 9 个 MySQL 库，而 任务管理服务 仅管理 `db_task` 一个库。任务执行过程中产生的数据和结果均在此库中。

## 核心业务域

### 1. 任务模板（task_template）

任务模板是"可复用的任务配置"，包含脚本、设备、数据源、用例、通知等配置。模板可以手动执行或通过 Cron 定时执行。

关联表：`task_template` → `task_template_detail` → `task_template_script` / `task_template_device` / `task_template_case`

关键流程：创建/编辑模板 → 手动执行或 Quartz Cron 触发 → 构建任务快照 (`task_execute_record`) → 进入执行调度管道。

详见：[核心链路-任务提测](04-复杂功能细节/核心链路-任务提测.md)、[核心链路-定时任务模板执行](04-复杂功能细节/核心链路-定时任务模板执行.md)

### 2. 任务执行记录（task_execute_record）

任务模板的"执行实例"，每次执行创建一个新记录。包含任务状态追踪、脚本/用例/设备统计。

任务来源（taskSource）：手动(1)、定时任务(2)、测试计划(3)、重测(4)。

状态机流转：`WAIT_APP_DEAL` → `WAIT_RUNNING` → `EXECUTING` → `SUCCESS` / `FAIL` / `CANCEL`

关联表：`task_execute_record` → `task_execute_record_detail` → `task_execute_record_script` / `task_execute_record_device` / `task_execute_record_case`

详见：[核心链路-任务执行](04-复杂功能细节/核心链路-任务执行.md)、[横切-任务状态机](04-复杂功能细节/横切-任务状态机.md)

### 3. 结果回收与报告

任务执行完成后，结果通过 Redis 队列异步回收。管道分为三个阶段：

1. **结果解析**（`TaskResultParseThread`）：原始执行数据 → 结构化结果
2. **结果分析**（`TaskReportResultAnalysisThread`）：结构化结果 → 统计聚合
3. **结果回传**（`TaskResultSendTaskPlanThread`）：结果通知计划服务

报告包含：用例步骤详情、性能数据、日志、埋点信息、脚本执行统计。

关联表：`task_execute_record_report` → `task_execute_record_report_case` → `task_execute_record_report_detail` / `task_execute_record_case_step`

详见：[核心链路-结果回收](04-复杂功能细节/核心链路-结果回收.md)

### 4. 任务取消与暂停

支持单任务取消、批量取消、暂停执行记录。

关联线程：`CancelTaskHandlerThread`（监听 Redis cancel 队列 → 调用 [app处理服务](../app处理服务（real-test）/07-开放接口文档/00-模块索引.md) 取消执行 → 更新本地状态）。

### 5. 任务重测

基于已有执行记录重新创建任务（复用原任务的脚本/设备/用例配置），更新 `parentId` 字段维护父子关系链。

详见：[核心链路-任务重测](04-复杂功能细节/核心链路-任务重测.md)

### 6. 回调策略

支持 7 种回调类型（`strategy/plan/`），通过 `CallbackTypeStrategyEnum` + `InitCallBackStrategy` 注册：
- `InitTaskCallbackStrategyService` — 任务初始化回调
- `ScriptCallbackStrategyService` — 脚本执行回调
- `TaskCallbackStrategyService` — 任务状态回调
- `SendSubTaskCallbackStrategyService` — 子任务下发回调
- `UpdateScriptStatusCallbackStrategy` — 脚本状态更新回调
- `UpdateErrorCauseTypeStrategyService` — 错误原因类型更新回调
- `CaseCallbackStrategyService` — 用例回调

## Redis 队列架构

任务管理服务 使用 Redis List 作为轻量级消息队列，通过 `brPopLPush`（阻塞式可靠消费）实现消息处理：

| Redis 队列 | 消费线程 | 用途 |
|-----------|---------|------|
| `task_execute_record_init_queue` | TaskInitThread | 新任务初始化入队 |
| `task_execute_record_exec_queue` | TaskExecuteStartThread | 任务开始执行 |
| `task_execute_record_execute_queue_` | TaskExecuteThread | 任务执行中 |
| `task_result_parse_queue_` | TaskResultParseThread | 结果解析 |
| `task_result_analysis_queue_` | TaskReportResultAnalysisThread | 结果分析 |
| `task_send_plan_queue_` | TaskResultSendTaskPlanThread | 结果回传计划 |
| `task_cancel_queue_` | CancelTaskHandlerThread | 任务取消 |

每条队列对应一个 bak 队列用于异常恢复，RestartThread 系列线程负责 bak 队列的重新投递。

## 后台线程全景

### Quartz Job（定时任务模板执行）
- `TaskTemplateExecuteJob` — 扫描 `task_template` 表中 `template_type=2`（定时类型）且到达执行时间的模板，创建执行记录并入队
- `TaskTemplateExecuteRestartJob` — 定时执行重启补偿
- `CancelTaskHandlerRestartJob` — 取消任务重启补偿

### Redis Consumer 线程（常驻阻塞消费）
- `TaskInitThread` / `TaskInitRestartThread` — 初始化队列消费
- `TaskExecuteStartThread` — 执行启动队列消费
- `TaskExecuteThread` / `TaskExecuteCheckThread` — 执行队列消费 / 检查
- `TaskResultParseThread` / `TaskResultParseRestartThread` — 结果解析
- `TaskReportResultAnalysisThread` / `TaskReportResultAnalysisRestartThread` — 结果分析
- `TaskResultSendTaskPlanThread` / `TaskResultSendTaskPlanRestartThread` — 结果回传
- `CancelTaskHandlerThread` — 取消队列消费

### Spring @Scheduled / 定时检查线程
- `TaskExecuteRecordConsumerRestartInit` — 执行记录消费者恢复初始化
- `TaskExecuteRecordReportCaseCheckThread` — 报告用例状态检查
- `TaskTemplateCaseIdStatusThread` — 模板用例 ID 状态同步

### AsyncConfig 线程池（11 个）
- `taskTemplateExecuteJobExecutor` — 定时任务执行
- `taskExecuteRecordJobExecutor` — 执行记录创建
- `cancelTaskExecutor` — 取消任务
- `reportResultHandlerExecutor` — 报告处理
- `reportResultParseExecutor` — 结果解析
- `reportResultAnalysisExecutor` — 结果分析
- `reportResultSendTaskPlanExecutor` — 结果回传
- `taskExecuteRecordExecuteExecutor` — 执行分发（corePoolSize=50）
- `taskExecuteRecordTriggerExecuteExecutor` — 触发执行
- `deviceDistributeExecutor` — 设备分发
- `taskTemplateCaseStatusCheckExecutor` — 模板用例状态检查
