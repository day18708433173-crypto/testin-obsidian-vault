# 四层鉴权模型

> 网关的鉴权不是简单的一个角色表，而是 McfgApp → McfgRole → McfgModule → McfgApi 四层逐级收敛。本文拆解每层的数据结构、缓存策略、RPC 来源和校验逻辑。

## 鉴权链路总览

```
apiKey (请求参数)
  │
  ▼
┌──────────────────────────────────────────────────────┐
│ 第一层：McfgApp                                       │
│ 缓存 key: IAppService.app.{apiKey}                    │
│ RPC 来源: AppCfgApi.get (op: AppCfg.get)              │
│ 校验: STATUS_ON / roles[] 非空 / bindEid 已设          │
│ 配置: AppConfig (checkIp/checkSig/checkTimestamp/     │
│       ignoreSid/onlineUserInfo)                       │
│ 产出: roleIds[], bindEid, appConfig                   │
└────────────────────┬─────────────────────────────────┘
                     │ roleIds[]
                     ▼
┌──────────────────────────────────────────────────────┐
│ 第二层：McfgRole（隐式）                               │
│ 缓存 key: 无独立缓存（通过 ApiServiceImpl 加载）       │
│ RPC 来源: ApiCfgApi.listByRole(roleId) 内部调用        │
│ 校验: 有 API 列表 = 角色有效                           │
│ 产出: 每 roleId → McfgApi[] 列表                       │
└────────────────────┬─────────────────────────────────┘
                     │ mkey (URL 路径)
                     ▼
┌──────────────────────────────────────────────────────┐
│ 第三层：McfgModule                                     │
│ 缓存 key: IModuleService.module.mkey.{mkey}           │
│ RPC 来源: ModuleCfgApi.get (op: ModuleCfg.get)        │
│ 校验: STATUS_ON                                       │
│ 配置: rpcPrefixName (RPC 寻址) / httpHosts (HTTP 地址) │
│ 产出: moduleId, rpcPrefixName, httpHosts               │
└────────────────────┬─────────────────────────────────┘
                     │ action+op (V1) / url+method (V3)
                     ▼
┌──────────────────────────────────────────────────────┐
│ 第四层：McfgApi                                        │
│ 缓存 key: IApiService.roleapi.{roleId} (V1)           │
│          IApiService.roleapi.v3.{roleId} (V3)         │
│ RPC 来源: ApiCfgApi.listByRole(roleId)                │
│          (op: ApiCfg.listByRole)                      │
│ 校验: STATUS_ON / 匹配 action+op 或 url+method         │
│ 配置: needLogin / protocolConfig (全部编排规则)        │
│       specialApiAction / specialApiOp / passThroughType│
│ 产出: needLogin, protocolConfig, passThroughType       │
└──────────────────────────────────────────────────────┘
```

## 第一层：McfgApp — 应用身份

`business/impl/AppServiceImpl.java`

**数据结构（api/bean/realcfg/McfgApp.java）**：
- `id` — 自增主键
- `apiKey` — 32 位应用唯一标识（请求必须携带）
- `secretKey` / `ivKey` — 加密密钥（签名/加解密用，当前签名校验未接线）
- `appName` / `appDesc` — 名称/描述
- `bindEid` — 绑定企业 ID（校验用户 eid 时比对）
- `ips` — IP 白名单（appConfig.checkIp=1 时生效）
- `roles` — `Integer[]` 角色 ID 列表
- `status` — STATUS_ON / STATUS_OFF
- `appConfig` — JSON：checkIp / checkSig / checkTimestamp / ignoreSid / onlineUserInfo
- `specialField` — 扩展字段

**校验逻辑（ApiUtil.commAuth）**：
1. `app == null` → `appInvalid`
2. `app.status == STATUS_OFF` → `appClosed`
3. `app.roles == null || app.roles.length == 0` → `popedomInvalid`
4. `StringUtils.isBlank(app.bindEid)` → `popedomInvalid`
5. `appConfig.checkIp==1 && !ips.contains(clientIp)` → `ipInvalid`
6. `appConfig.checkTimestamp==1 && |now - timestamp| > 12h` → `paraTimestampInvalid`（仅 V1）

**缓存策略**：
- Key: `IAppService.app.{apiKey}`
- 加载：`LockUtil.lock(key, () → AppCfgApi.get(apiKey))` 双重检查锁
- 刷新：Redis pub/sub `real.cfg` → target=`McfgApp` → `AppServiceImpl.refresh(apiKey)` → 清掉缓存 key

## 第二层：McfgRole — 角色（隐式）

角色表本身不单独缓存，而是通过 `ApiServiceImpl` 加载。`ApiCfgApi.listByRole(roleId)` 调用 `RoleCfgApi.get(roleId)` 内部校验角色 STATUS_ON，只有角色有效时才返回 API 列表。

角色通过 `McfgRoleApi` 中间表（roleId, apiId）关联接口权限，每个 role 可有独立的 `roleProtocolConfig`（覆盖接口级 protocolConfig）。

## 第三层：McfgModule — 目标模块

`business/impl/ModuleServiceImpl.java`

**数据结构（api/bean/realcfg/McfgModule.java）**：
- `id` — 模块 ID
- `mkey` — 模块唯一标识（URL 路径第一段）
- `rpcPrefixName` — RPC ICE 寻址前缀（如 `RealCfg`、`UserManager`）
- `httpHosts` — HTTP 目标地址列表（`;` 分隔，非空时走 HTTP 模式）
- `status` — STATUS_ON / STATUS_OFF

**httpHosts 多地址负载均衡（McfgModule.getHttpHost()）**：
```java
public String getHttpHost() {
    if (httpHosts != null && httpHosts.contains(";")) {
        String[] hosts = httpHosts.split(";");
        return hosts[new Random().nextInt(hosts.length)];
    }
    return httpHosts;
}
```

**缓存策略**：
- Key: `IModuleService.module.mkey.{mkey}` 和 `IModuleService.module.id.{id}`
- 加载：`LockUtil.lock(key, () → ModuleCfgApi.get(mkey))` 双重检查锁
- 刷新：Redis pub/sub `real.cfg` → target=`McfgModule` → `ModuleServiceImpl.refresh(mkey)`

## 第四层：McfgApi — 接口权限

`business/impl/ApiServiceImpl.java`

**数据结构（api/bean/realcfg/McfgApi.java）**：
- `id` — API ID
- `moduleId` — 所属模块
- `apiAction` / `apiOp` — V1/V2 匹配用
- `url` / `method` — V3 匹配用（含占位符如 `/users/{param0}`）
- `needLogin` — 是否需要登录态（>0 时 sid 校验）
- `needWrite` — 是否写操作（日志区分）
- `specialApiAction` / `specialApiOp` — V3→V1 转换时覆盖 action/op
- `protocolConfig` — 请求/响应编排规则 JSON
- `status` — STATUS_ON / STATUS_OFF

**V1/V2 匹配逻辑（ApiServiceImpl.get）**：
```
1. 遍历 app.roles[] 中的每个 roleId
2. 从缓存获取 IApiService.roleapi.{roleId} → Map<String, McfgApi>
3. mapKey = moduleId + "::" + apiAction + "::" + apiOp
4. 返回第一个 STATUS_ON 的匹配项
```

**V3 匹配逻辑（ApiServiceImpl.get）**：
```
1. 遍历 app.roles[] 中的每个 roleId
2. 从缓存获取 IApiService.roleapi.v3.{roleId} → Map<String, McfgApi>
3. mapKey = moduleId + "::" + placeholderUrl + "::" + httpMethod
4. 返回第一个 STATUS_ON 的匹配项
```

**缓存策略**：
- V1 key: `IApiService.roleapi.{roleId}` → `Map<moduleId::action::op, McfgApi>`
- V3 key: `IApiService.roleapi.v3.{roleId}` → `Map<moduleId::url::method, McfgApi>`
- 加载：`LockUtil.lock(key, () → ApiCfgApi.listByRole(roleId))` → 遍历结果构建 Map
- 刷新：Redis pub/sub `real.cfg` → target=`McfgRoleApi` 或 `McfgRole` → `ApiServiceImpl.refresh(roleId)` → 清掉该 role 的两个缓存 key

## 鉴权失败返回码速查

| 校验失败点 | 错误码 | 触发条件 |
|---|---|---|
| App 不存在 | `appInvalid` | apiKey 查不到 McfgApp |
| App 已停用 | `appClosed` | McfgApp.status = STATUS_OFF |
| App 无权限 | `popedomInvalid` | roles 为空 / bindEid 为空 |
| IP 不合法 | `ipInvalid` | checkIp=1 且来源 IP 不在白名单 |
| 时间戳不合法 | `paraTimestampInvalid` | checkTimestamp=1 且偏移 > 12h |
| 模块不存在 | `paraMkeyInvalid` | mkey 查不到 McfgModule 或 STATUS_OFF |
| 接口不存在 | `apiInvalid` | 无匹配 McfgApi |
| sid 不合法 | `paraSidInvalid` | sid 过期 / eid 为空 / eid 不匹配 bindEid |
| projectid 不合法 | `paraProjectidInvalid` | projectid 不在用户项目列表 |
| 配置不合法 | `configInvalid` | appConfig/protocolConfig 格式错误 |
