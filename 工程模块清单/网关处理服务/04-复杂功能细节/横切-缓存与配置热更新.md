# 缓存与配置热更新

> 网关不存数据库，所有配置（App/Module/Api/User）通过 RPC 查 real-cfg / testin-core 获取，缓存在本地 LocalCache 中。配置变更通过 Redis pub/sub 实时推送，秒级生效。

## 整体架构

```

│  │   10段×50000 容量      │    │   SubscribeFactory    │  │

│  │   5min 清理间隔        │    │          usermanager   │  │
```

## LocalCache 配置

`src/main/resources/cfg/spring/Spring-LocalCache.xml`

```xml
<bean id="localCache" class="cn.testin.common.util.LocalCache">
    <constructor-arg index="0" value="10"/>    <!-- 段数 -->
    <constructor-arg index="1" value="50000"/> <!-- 每段容量 -->
    <constructor-arg index="2" value="5"/>     <!-- 清理间隔（分钟） -->
    <constructor-arg index="3" value="60"/>    <!-- 过期时间（分钟） -->
</bean>
```

**容量计算**：10 段 × 50000 = 最大 500,000 条缓存项。

## LockUtil 双重检查锁防击穿

`AppServiceImpl.java`（典型模式）：

```java
public McfgApp getByApikey(String apiKey) {
    String key = "IAppService.app." + apiKey;
    McfgApp app = localCache.get(key);
    if (app != null) {
        return app;
    }
    // 缓存未命中，加锁加载
    return LockUtil.lock(key, () -> {
        // 双重检查
        McfgApp cached = localCache.get(key);
        if (cached != null) {
            return cached;
        }
        McfgApp loaded = appCfgApi.get(apiKey);
        localCache.put(key, loaded);
        return loaded;
    });
}
```

`LockUtil.lock` 基于 key 对象的 `synchronized` 块（来自 `real-common`），确保同一 key 只有一个线程去 RPC 加载，其他线程在锁释放后从缓存读取。

**注意**：`LockUtil` 仅用于 AppServiceImpl、ModuleServiceImpl、ApiServiceImpl。`UserServiceImpl` 部分缓存方法未加锁。

## Redis pub/sub 配置热更新

### 订阅启动

`cn/testin/startup/Boot.java`

```java
// 启动 MessageDispatchThread（从 BlockingPool 消费消息）
MessageDispatchThread.start();

// 订阅 Redis 频道
SubscribeFactory.subscribe("real.cfg");
SubscribeFactory.subscribe("usermanager");
```

### 消息格式

`NoticeMessage`（来自 `real-common`）：
- `target`：缓存目标类型（`McfgApp` / `McfgModule` / `McfgRoleApi` / `McfgRole` / `EnterpriseUserRelation` / `UserOnline` / `UserInfo` / `ProjectInfo` / `EnterpriseInfo`）
- `data`：变更数据（含具体 ID/key）

### 消息分发

`schedule/mq/MessageDispatchThread.java`

1. `SubscribeFactory.getMessageListener().getBlockingPool().take()` 拉取消息
2. 提交到线程池（核心 5 / 最大 50）→ `MessageHandlerThread.run()`
3. `MessageHandlerThread` 调用 `IMessageService.Handler(message)`

### 消息路由

`business/impl/MessageServiceImpl.java`

```java
public class Handler implements IMessageService.Handler {
    public void handle(NoticeMessage message) {
        switch (message.getTarget()) {
            case "McfgApp":
                appService.refresh(message.getData().getString("apiKey"));
                break;
            case "McfgModule":
                moduleService.refresh(message.getData().getString("mkey"));
                break;
            case "McfgRoleApi":
            case "McfgRole":
                apiService.refresh(message.getData().getInt("roleId"));
                break;
            case "EnterpriseUserRelation":
                userService.refreshMyProjects(
                    message.getData().getInt("userid"),
                    message.getData().getInt("eid"));
                break;
            case "UserOnline":
                userService.refreshOnlineUser(
                    message.getData().getString("sid"));
                break;
            case "UserInfo":
                if (message.getData().has("thirdPartyUserid")) {
                    // 第三方 ID 映射变更，evict 对应缓存
                    userService.evictThirdPartyUserId(...);
                }
                break;
            case "ProjectInfo":
                // 同 evict
                break;
            case "EnterpriseInfo":
                // 同 evict
                break;
        }
    }
}
```

### 刷新逻辑

各 Service 的 `refresh` 方法直接调用 `localCache.remove(key)` 清除对应缓存项。下次请求查不到缓存时，触发 LockUtil 双重检查锁重新从 RPC 加载。

### 手动刷新

`LocalCacheServlet` 暴露 `/localcache?key=...` 端点，运维可手动清除指定缓存 key。

## 注意事项

1. **缓存过期 vs pub/sub**：缓存 60 分钟被动过期是兜底机制，正常流程依赖 pub/sub 主动刷新。pub/sub 消息可能丢失（Redis 断连），此时最多等 60 分钟后缓存自动过期重新加载。
2. **App 级配置变更影响范围**：McfgApp 的修改只清除该 apiKey 的缓存（`McfgApp` 消息），但如果改了 `roles[]`，实际的角色-API 对应关系变化还需要 `McfgRoleApi` 消息触发刷新。
3. **UserOnline 缓存的特殊性**：`Online.getUserOnline` 接口调用后会主动刷新 UserOnline 缓存（更新过期时间），这是业务驱动的缓存更新，不走 pub/sub。
