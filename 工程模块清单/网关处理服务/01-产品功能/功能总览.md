# 功能总览

> 按功能域组织的清单：每个域一句话定位 + 核心能力 + 接口入口。接口级出入参见 [07-开放接口文档索引](../07-开放接口文档/00-模块索引.md)，路由转发模式判定见 [多版本入口](../04-复杂功能细节/横切-多版本入口（V1-V2-V3）.md)。

## 功能地图

```
网关处理服务（proxy-openapi）
├── 认证鉴权 ────────── apiKey + sid + timestamp + IP 白名单 + 恒生定制
├── 四层鉴权 ────────── McfgApp → McfgRole → McfgModule → McfgApi
├── 请求编排 ────────── check / field / ignore / additional / V3 fieldReplace
├── 代理转发 ────────── RPC (ICE) / HTTP 透传 / V3 passThroughType 直通
├── 响应处理 ────────── resultCheck / responseFieldReplace / ignoreJson / 登录态刷新
├── 缓存热更新 ──────── Redis pub/sub (real.cfg + usermanager) → LocalCache 秒级刷新
└── 用户活动追踪 ────── 异步记录日活用户到 Redis + V3 后端
```

## 认证与身份识别

外部调用方接入的第一步：验证"你是谁"。支持 apiKey（应用标识）+ sid（用户登录态）+ timestamp（防重放）+ IP 白名单四重校验。

**核心能力：**
- **apiKey 校验**：每个请求必带 `apikey`（V1）或 `apiKey`（V3），查 `McfgApp`（缓存 key `IAppService.app.{apiKey}`），校验 STATUS_ON、roles[] 非空、bindEid 已设
- **sid 多来源识别**：`sid` header → Cookie `authtoken_pro` → body `onlineUserInfo`（email+eid 查用户表构造虚拟会话）→ `onlineUserInfo.thirdPartyUserid`（第三方 ID 映射）
- **IP 白名单**：`appConfig.checkIp=1` 时校验来源 IP 在 `McfgApp.ips` 内（`ApiUtil.commAuth`）
- **时间戳**：`appConfig.checkTimestamp=1` 时校验请求时间戳与服务器时钟差 < 12 小时（仅 V1 生效，V2/V3 已注释）
- **恒生定制**：请求携带 `hundsunInfo` → `ProjectApi.hengsunCustomize()` 将恒生产品/项目 ID 映射为 Testin sid/projectid/userid（`ApiProxyServlet.conversionRequest()`）
- **签名校验**：`SigUtil.getSig` MD5 签名工具存在但服务端校验未接线

| 版本 | 入口 | 认证方法 |
|---|---|---|
| V1 | `/*` → ApiProxyServlet | `ApiUtil.commAuth` — apiKey + IP + timestamp + Hundsun |
| V2 | `/v2/*` → ApiV2ProxyServlet | `ApiV2Util.commAuth` — apiKey + mkey（timestamp 已注释） |
| V3 | `/v3/*` → ApiV3ProxyServlet | `ApiV3Util.commAuth` — apiKey + mkey + needLogin（timestamp 已注释） |

深入阅读：[请求代理主流程实现](../03-实现逻辑/请求代理主流程实现.md)、[核心链路-恒生定制](../04-复杂功能细节/核心链路-恒生定制.md)。

## 四层鉴权

认证之后决定"你能访问什么"：App → Role → Module → Api 逐层收敛，配置全部来自平台配置服务（real-cfg），本地缓存、实时生效。

**核心能力：**
- **App 层**：apiKey → McfgApp.roles[]，获得角色列表
- **Role 层**：每个 roleId → McfgRoleApi 中间表 → 关联一组 McfgApi
- **Module 层**：mkey → McfgModule（rpcPrefixName / httpHosts / 状态 STATUS_ON），决定目标路由
- **Api 层**：action+op（V1）或 url+method（V3）→ 匹配 McfgApi（needLogin / protocolConfig / passThroughType）

鉴权失败返回码：`appInvalid`（apiKey 不合法/已停用）、`popedomInvalid`（无角色/无 bindEid）、`apiInvalid`（无匹配 API）、`paraMkeyInvalid`（模块未找到/已停用）。

深入阅读：[四层鉴权模型](../04-复杂功能细节/横切-四层鉴权模型.md)、[缓存与配置热更新](../04-复杂功能细节/横切-缓存与配置热更新.md)。

## 请求编排

在转发前对请求 body JSON 做声明式转换：校验必填字段、过滤/裁剪/注入字段，由 McfgApi.protocolConfig 驱动，无需各内部服务重复实现。

**核心能力：**

| 编排项 | 阶段 | V1 | V2 | V3 | 说明 |
|---|---|---|---|---|---|
| `checkKeys` | 请求前 | ✅ | ✅ | ✅ | 校验必填字段存在且非空 |
| `fieldKeys` | 请求前 | ✅ | ✅ | — | 白名单过滤，只保留指定字段 |
| `ignoreKeys` | 请求前+响应后 | ✅ | ✅ | ✅ | 黑名单裁剪（V3 仅响应阶段生效） |
| `additionalKeys` | 请求前 | ✅ | ✅ | ✅ | 注入附加字段，支持 `${app.bindEid}` / `${app.appName}` 占位符 |
| `resultCheckKeys` | 响应后 | ✅ | — | — | V1 独有：校验响应 projectid 归属 |
| `ignoreSidKeys` | 请求前 | ✅ | ✅ | ✅ | 控制是否注入 sid 用户信息 |
| `queryParamKeys` | V3 请求前 | — | — | ✅ | URL query → body JSON 字段（含类型转换） |
| `pathPlaceholderParamKeys` | V3 请求前 | — | — | ✅ | `/user/{id}` 占位符 → body JSON |
| `responseFieldReplaceKeys` | 响应后 | — | — | ✅ | 响应字段递归重命名 |
| `bodyRequestFieldReplaceKeys` | 请求前 | — | — | ✅ | body 字段重命名 |

深入阅读：[请求响应转换引擎](../04-复杂功能细节/横切-请求响应转换引擎.md)。

## 代理转发

将处理后的请求发到后端内部服务，支持两种模式按模块配置自动切换。

**核心能力：**
- **RPC 模式（ICE）**：`McfgModule.httpHosts` 为空 → 走 `RpcServiceImpl.doPress`，通过 ICE Locator（`iceclient.properties`）路由到 `rpcPrefixName` 对应服务
- **HTTP 模式**：`McfgModule.httpHosts` 非空 → 走 `HttpServiceImpl.doPress`，`HttpURLConnection` POST 到随机选取的目标地址，支持 GZIP
- **V3 透传（passThroughType=1）**：保留原始 HTTP 方法/query/headers/body（含 multipart/form-data），直接转发到目标服务，响应流式回传（含 Set-Cookie、`application/octet-stream` 文件下载）
- **V3→V1 转换（passThroughType=0）**：将 V3 REST 请求转换为 V1 风格 body（`{data, action, op, mkey, sid}`），走标准 `executeRequest()`

| 转发模式 | 判定条件 | 代码入口 | 适用场景 |
|---|---|---|---|
| RPC（ICE） | httpHosts 为空 | `RpcServiceImpl.doPress` | RealCfg / UserManager 等 V1 服务 |
| HTTP POST | httpHosts 非空 | `HttpServiceImpl.doPress` | 内部 HTTP 微服务 |
| V3 透传 | passThroughType=1 | `HttpServiceImpl.doPressWithPassThrough` | V3 原生 REST 服务（real_task 全部 / script 部分） |
| V3→V1 转换 | passThroughType=0 + specialApi 非空 | `ApiV3ProxyServlet.executeRequest` | V3 URL 映射到 V1 action/op（realtest / script 部分） |

深入阅读：[双模代理](../04-复杂功能细节/横切-双模代理（RPC与HTTP）.md)、[V3透传](../04-复杂功能细节/核心链路-V3透传.md)、[V3→V1转换](../04-复杂功能细节/核心链路-V3转V1.md)。

## 响应处理

代理响应返回后，对响应 JSON 做与请求对称的声明式处理。

**核心能力：**
- **resultCheckJson**（V1 独有）：校验响应的 projectid 在用户项目列表中（`handleCheckResult`）
- **responseFieldReplaceKeys**（V3）：递归重命名响应字段
- **ignoreJson**：从响应中删除指定字段（V1/V2/V3 均支持）
- **登录态刷新**：对 `Online.getUserOnline` 接口的响应，更新 `UserOnline` 缓存过期时间
- **用户活动记录**：成功响应后异步调用 `UserActivityServiceImpl` 记录日活

## 缓存热更新

配置变更无需重启，Redis pub/sub 实时推送 → 本地缓存秒级刷新。

**核心能力：**
- **订阅频道**：`real.cfg`（McfgApp/McfgModule/McfgApi/McfgRole 变更）+ `usermanager`（UserOnline/User/Project/Enterprise 变更）
- **消息分发**：`SubscribeFactory` 接收 → `BlockingPool` → `MessageDispatchThread`（5 核心/50 最大线程池）→ `MessageHandlerThread` → `MessageServiceImpl.Handler`
- **支持刷新的缓存 key**：McfgApp（按 apiKey）、McfgModule（按 mkey）、McfgRoleApi/McfgRole（按 roleId）、EnterpriseUserRelation（按 userid+eid）、UserOnline（按 sid）、UserInfo.thirdPartyUserid / ProjectInfo.thirdPartyProjectid / EnterpriseInfo.thirdPartyEid
- **手动刷新**：`/localcache?key=...`（`LocalCacheServlet`）

深入阅读：[缓存与配置热更新](../04-复杂功能细节/横切-缓存与配置热更新.md)。

## 恒生（Hundsun）定制

恒生客户使用自己的产品/项目账户体系，请求携带 `hundsunInfo` 而非 sid。网关在 `conversionRequest` 阶段做账户映射。

**核心能力：**
- `hundsunInfo.productNo` + `projectId` → `ProjectApi.hengsunCustomize()` → 返回 `HundsunInfo`（含 sid/projectid/userid/eid/email）
- 后续鉴权流程复用标准 sid 校验逻辑（`dealOnlineUser` 用映射后的 sid 查 UserOnline）
- 仅 V1 `ApiProxyServlet` 支持（`conversionRequest()` 在 `preCheckDealRequest` 中调用）

深入阅读：[核心链路-恒生定制](../04-复杂功能细节/核心链路-恒生定制.md)。

## 使用方速查

| 使用方 | 用什么能力 | 入口 |
|---|---|---|
| OpenAPI 客户端 | V1 JSON-RPC 全能力 | `/*` → ApiProxyServlet |
| 第三方系统（恒生） | V1 + Hundsun 定制 | `/*` → ApiProxyServlet（含 `hundsunInfo`） |
| V3 管理台前端 | V3 REST 全能力 + 透传 | `/v3/*` → ApiV3ProxyServlet |
| 旧版管理台 | V2 REST | `/v2/*` → ApiV2ProxyServlet |
| 运维 | 缓存手动刷新 | `/localcache?key=...` |
