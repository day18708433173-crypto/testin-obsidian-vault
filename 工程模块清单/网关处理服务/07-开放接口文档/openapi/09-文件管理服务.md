# 文件管理服务 OpenAPI 接口文档

> 代码仓库：`fileupload`（分支 `syy.release.z7.8.1.0`）。V1 原生服务类在 `cn.testin.service.fs` / `cn.testin.service.script`；V3 透传 Controller 在 `cn.testin.filecloud.web.controller` / `cn.testin.filecloud.web.controller.v3`。
> 网关路由：模块 `fs`（V1 原生）/ `file_system`（V3 透传）→ `http://testin-aio-fileupload:8080/openapi`。

## 路由说明（重要：fs 与 file_system 是两个 mkey）

db_mcfg 中文件管理服务对应**两个模块**，均指向 `http://testin-aio-fileupload:8080/openapi`：

| 模块 id | mkey | 转发模式 | 内容 |
|---|---|---|---|
| 304 | `fs` | 🟢 V1 原生（pass_through_type=0） | 7 条：`File.upload` / `File.internalUpload` / `File.multipartUpload` / `File.merge` / `App.parse` / `Script.checkScript` / `TestResult.parse` |
| 305 | `file_system` | 🔵 V3 透传（pass_through_type=1） | 2 条：`POST /app/upload`、`POST /files/upload` |

- V3 的网关公开 URL 前缀是 **`/openapi/v3/file_system/`**（mkey=`file_system`），不是 `/openapi/v3/fs/`。经网关 `ApiV3ProxyServlet` + `ApiV3Util.commAuth` 核实：URL 第二段为 mkey，须精确匹配 `mcfg_module.mkey`，无别名。[01-API路由映射表](../01-API路由映射表.md) 第 9 节目前写的是 `/openapi/v3/fs/*`，**应为 `/openapi/v3/file_system/*`**。
- `fs.File.internalUpload` 在 db_mcfg 中配置 `special_api_op=File.upload`（V1 内部重定向，非 V3→V1 转换）：客户端调 `op=File.internalUpload` 时网关改写 op 为 `File.upload` 转发，代码中无独立 `internalUpload` 方法，且 `needLogin=0`（与 `File.upload` 的 `needLogin=1` 不同）。
- 路由表第 9 节列出的 `app/*`、`file/*`、`script/*`、`url/*`、`package/*`、`query/*`、`heartbeat` 等 V3 端点，**db_mcfg 仅注册了 `/app/upload`、`/files/upload` 两条**，其余为代码内 Spring MVC 端点（未在网关注册），本文一并列出并标注。

## 通用返回结构

**V1 原生（action/op 模式）**：返回由 `cn.testin.common.service.util.ApiUtil.getJSONobj` 构造，JSON 结构为：

| 字段 | 类型 | 说明 |
|---|---|---|
| action | String | 回显请求 action（如 `fs`） |
| op | String | 回显请求 op（如 `File.upload`） |
| code | Integer | 状态码，0 为成功（`CommonCode.success`） |
| msg | String | 提示信息 |
| data | JSONObject | 业务数据，字段见各接口 |

`data` 内通用字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| result | Integer / String / List | 处理结果（上传接口为 URL 字符串或 URL 列表） |
| objInfo | JSONObject | 业务对象（`ApiResponse.RES_OBJECT = "objInfo"`） |

> 说明：V1 返回的提示字段键为 `msg`（`ApiResponse.RES_MSG`），不是 `message`；00-OpenAPI索引.md 中的「message」为口径化描述，实际代码为 `msg`。

**V3 透传（Spring MVC）**：两个包装类：

| 包装类 | JSON 结构 | 成功码 |
|---|---|---|
| `FResult<T>`（`cn.testin.filecloud.common.http.FResult`） | `{code, msg, data}` | code=0（msg="成功"） |
| `RespMsg<T>`（`cn.testin.filecloud.common.http.RespMsg`） | `{code, msg, data}` | code=200（HttpStatus.OK） |

## 通用约定

- 「必填」依据：V1 看方法内 `reqjson.optString/optInt` 判空并 `return ApiUtil.getResult(paraInvalid)` 的分支；V3 看 Controller 内 `StringUtils.isBlank` / `@RequestParam(required=true)` 校验。
- 路径变量以代码实际 `@RequestMapping` 为准；V1 路径形如 `action=fs&op=File.upload`。
- `needLogin` 以 db_mcfg `view_role_api.need_login` 为准；未在网关注册的 V3 端点标注「代码未确认」。
