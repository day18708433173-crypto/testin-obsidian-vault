# 任务调度服务 OpenAPI 接口文档

> 代码仓库：`real-scheduling`（分支 `syy.release.z7.8.1.0`）。V1 原生服务类在 `cn.testin.service.scheduling` / `cn.testin.service.cross`；V3 透传 Controller 在 `cn.testin.mvc` / `cn.testin.controller`。
> 网关路由：模块 `RealScheduling` → `http://testin-aio-real-scheduling:8080`。

## 通用返回结构

**V1 原生（action/op 模式）**：返回由 `ApiUtil.getJSONobj` 构造，JSON 结构为：

| 字段 | 类型 | 说明 |
|---|---|---|
| action | String | 回显请求 action（如 `scheduling`） |
| op | String | 回显请求 op（如 `Task.init`） |
| code | Integer | 状态码，0 为成功（`CommonCode.success`） |
| msg | String | 提示信息 |
| data | JSONObject | 业务数据，字段见各接口 |

`data` 内通用字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| result | Integer / Long | 处理结果，通常 1=成功 / 0=失败（`reportResult` 为 Long） |
| objInfo | JSONObject | 匹配到的任务对象（`match`/`webMatch`/`clientMatch`/`matchTask`） |
| list | JSONArray | 列表数据（`list`/`levelTaskList`/`queueDetails`） |
| page | Integer | 当前页 |
| pageSize | Integer | 每页大小 |
| totalRow | Integer | 总行数 |
| totalPage | Integer | 总页数 |

**V3 透传（Spring MVC）**：统一返回 `ResponseResult<T>`（对应路由表口径中的「BaseResponseDTO」），JSON 结构为：

| 字段 | 类型 | 说明 |
|---|---|---|
| code | Integer | 状态码，0 成功 / -1 失败（`CommonConstant.SUCCESS_CODE` / `ERROR_CODE`） |
| msg | String | 提示信息（成功为「成功」） |
| data | T | 业务数据，类型随接口而定 |

## 通用约定

- V1 接口网关侧 `needLogin=0`；V3 接口 `pauseTask`/`resumeTask` 为 `needLogin=1`，`heartbeat/check` 为 `needLogin=0`（`ucomInterruptTask`、`get_device_task_info` 未收录于路由表，鉴权以 db_mcfg 实际为准，标注「代码未确认」）。
- 「必填」依据：V1 看方法内 `reqjson.isNull/getXxx` 判空并 return 错误的分支；V3 看 Controller 内 `@RequestBody` 判空 / `StringUtils.isBlank` 校验。
- 路径变量以代码实际值标注；V1 路径形如 `action=scheduling&op=Task.execute`。
