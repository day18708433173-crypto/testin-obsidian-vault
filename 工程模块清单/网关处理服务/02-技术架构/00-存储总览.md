# 存储总览

> 网关处理服务无 MySQL 数据库，全部配置数据通过 RPC 从上游服务（real-cfg、testin-core）实时查询，缓存在 LocalCache + Redis 中。

## 存储架构

```
┌─────────────────────────────────────┐
│         网关处理服务                  │
│                                     │
│  ┌─────────────────────────────┐    │
│  │  LocalCache（内存）          │    │
│  │  10 段 × 50000 容量          │    │
│  │  5min 清理 / 60min 过期      │    │
│  │                             │    │
│  │  缓存内容：                  │    │
│  │  - McfgApp (by apiKey)      │    │
│  │  - McfgModule (by mkey/id)  │    │
│  │  - McfgApi (by roleId)      │    │
│  │  - UserOnline (by sid)      │    │
│  │  - UserInfo (by email+eid)  │    │
│  │  - UserProjectList          │    │
│  │  - ThirdParty 映射          │    │
│  └─────────────────────────────┘    │
│              ↕                      │
│  ┌─────────────────────────────┐    │
│  │  Redis（远程）               │    │
│  │  redis.pro.testin.cn:6379   │    │
│  │                             │    │
│  │  - pub/sub 频道订阅          │    │
│  │    real.cfg / usermanager   │    │
│  │  - BlockingPool(500) 消息队列│    │
│  └─────────────────────────────┘    │
└─────────────────────────────────────┘
         │ RPC (ICE)
         ▼
┌──────────────────┐  ┌──────────────────┐
│  real-cfg        │  │  testin-core     │
│  (平台配置)       │  │  (用户管理)       │
│                  │  │                  │
│  mcfg_api        │  │  db_user.*       │
│  mcfg_app        │  │  db_admin.*      │
│  mcfg_module     │  │                  │
│  mcfg_role       │  │                  │
└──────────────────┘  └──────────────────┘
```

## LocalCache 缓存 Key 一览

### 配置域（来自 real-cfg）

| 缓存 Key 模式 | 数据类型 | 来源 | 用途 |
|---|---|---|---|
| `IAppService.getByApikey.{apiKey}` | McfgApp | AppCfgApi RPC | 应用身份校验 |
| `IModuleService.get.{mkey}` | McfgModule | ModuleCfgApi RPC | 目标模块路由 |
| `IModuleService.get.{id}` | McfgModule | ModuleCfgApi RPC | 按 ID 查模块 |
| `IApiService.roleapi.{roleId}` | Map<String,McfgApi> | ApiCfgApi RPC | V1 API 权限（key=moduleId+action+op） |
| `IApiService.roleapi.v3.{roleId}` | Map<String,McfgApi> | ApiCfgApi RPC | V3 API 权限（key=moduleId+url+method） |

### 用户域（来自 testin-core）

| 缓存 Key 模式 | 数据类型 | TTL | 来源 | 用途 |
|---|---|---|---|---|
| `IUserService.getOnlineUser.{sid}` | UserOnline | 10min | OnlineApi RPC | 登录态校验 |
| `IUserService.getUser.{email}{eid}` | UserInfo | 永久（直到变更通知） | UserApi RPC | 用户信息查询 |
| `IUserService.getUserProjectList.{userid}{eid}` | Integer[] | 1min | ProjectApi RPC | 项目成员校验 |
| `IUserService.getByThirdPartyUserid.{id}` | UserInfo | 永久 | UserApi RPC | 恒生用户映射 |
| `IUserService.getByThirdPartyProjectid.{id}` | ProjectInfo | 1min | ProjectApi RPC | 恒生项目映射 |
| `IUserService.getByThirdPartyEid.{id}` | EnterpriseInfo | 1min | EnterpriseApi RPC | 恒生企业映射 |

### 缓存策略

- **写策略**：Cache-Aside，RPC 查回后写入 LocalCache
- **防击穿**：`LockUtil.getLock(new KEY(cacheKey, param))` + `synchronized` 双重检查
- **null 值处理**：存空对象（如 `new McfgApp()` / `new McfgModule()` / `new UserOnline()`），通过判断关键字段（id/apiKey/mkey/sid）是否为 null 区分"查无此记录"和"缓存未命中"
- **失效刷新**：Redis pub/sub 收到配置变更消息后，`MessageServiceImpl.Handler` 分发到对应 Service.refresh 方法

## 上游 real-cfg 数据源：db_mcfg 库完整映射

> `10.33.84.100:3306` / `db_mcfg`，网关运行时缓存的所有配置均来源于此。real-cfg 服务端通过 JDBC DAO 直连该库读写。

### 表结构 → POJO → 网关 Bean 三层对照

| MySQL 表 | real-cfg 服务端 POJO | proxy-openapi 网关 Bean | 用途 |
|---|---|---|---|
| `mcfg_app` | `cn.testin.pojo.mcfg.McfgApp` | `cn.testin.api.bean.realcfg.McfgApp` | 应用身份：apiKey、secretKey、IP白名单、roles、bindEid、AppConfig（checkIp/checkSig/checkTimestamp/ignoreSid） |
| `mcfg_module` | `cn.testin.pojo.mcfg.McfgModule` | `cn.testin.api.bean.realcfg.McfgModule` | 目标模块：mkey、rpcPrefixName（RPC前缀）、httpHosts（HTTP地址列表，`;`分隔多地址随机负载均衡） |
| `mcfg_api` | `cn.testin.pojo.mcfg.McfgApi` | `cn.testin.api.bean.realcfg.McfgApi` | API定义：moduleId、apiAction（V1包名/V3 URL）、apiOp（V1方法名/V3 HTTP method）、needLogin、protocolConfig、passThroughType |
| `mcfg_role` | `cn.testin.pojo.mcfg.McfgRole` | `cn.testin.api.bean.realcfg.McfgRole` | 角色：name、status |
| `mcfg_role_api` | `cn.testin.pojo.mcfg.McfgRoleApi` | —（无独立Bean，融合到 McfgApi.roleProtocolConfig） | 角色-API关联：roleId、apiId、protocolConfig（可覆盖API级配置，如按角色定制fieldKeys/ignoreKeys） |
| `view_role_api` | `cn.testin.pojo.mcfg.ViewRoleApi` | —（查询结果拆解为 McfgApi 各字段） | **网关实际查询的视图**：JOIN mcfg_api + mcfg_role_api，合并两表的 protocolConfig 为 roleProtocolConfig |
| `customer` | —（无对应 POJO） | — | 客户名单：name、contact_person、contact_phone |
| `api_func_relation` | —（无对应 POJO） | — | API功能关系：func_id ↔ api_id |

### 关键字段详解

**mcfg_app（应用表）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `api_key` | varchar(32) UNIQUE | 网关第一道认证凭据 |
| `app_config` | text (JSON) | `{"checkIp"/1, "checkSig"/1, "checkTimestamp"/1, "ignoreSid"/1, "onlineUserInfo"/1}` |
| `secret_key` | varchar(32) | sig 签名密钥（SigUtil.getSig 末尾拼接） |
| `iv_key` | varchar(64) | 加密向量（预留，当前网关未使用） |
| `ips` | text | IP 白名单（支持网段格式） |
| `bind_eid` | int | 绑定企业ID，>0 时用户 eid 必须匹配 |
| `roles` | text (JSON Array) | 拥有的角色 ID 列表，如 `[1, 2, 5]` |

**mcfg_api（接口表）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `module_id` | int | 所属模块，FK → mcfg_module.id |
| `api_action` | varchar(128) | V1=服务包名（如 `task`）/ V3=URL路径（如 `/v3/task/tasks`） |
| `api_op` | varchar(128) | V1=类.方法名（如 `Task.add`）/ V3=HTTP method |
| `special_api_action` | varchar(255) | V3 转 V1：实际调用的 V1 action |
| `special_api_op` | varchar(255) | V3 转 V1：实际调用的 V1 op |
| `need_login` | tinyint | 是否需要登录态（sid） |
| `protocol_config` | text (JSON) | **核心配置**：checkKeys/fieldKeys/ignoreKeys/additionalKeys/resultCheckKeys/ignoreSidKeys/queryParamKeys/pathPlaceholderParamKeys/responseFieldReplaceKeys/bodyRequestFieldReplaceKeys |
| `pass_through_type` | int | 0=按协议配置组装请求 / 1=直接透传 |

**mcfg_role_api（角色接口关联表）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `role_id` | int | FK → mcfg_role.id |
| `api_id` | int | FK → mcfg_api.id |
| `protocol_config` | text (JSON) | **角色级覆盖**：与 mcfg_api.protocolConfig 同结构，最终合并时 role 级优先 |

**view_role_api（核心查询视图）**

```sql
-- 实际执行逻辑
SELECT
  mcfg_role_api.role_id,
  mcfg_role_api.api_id,
  mcfg_api.module_id, mcfg_api.api_action, mcfg_api.api_op,
  mcfg_api.need_login, mcfg_api.need_activation, mcfg_api.need_write,
  mcfg_api.protocol_config,   -- API级配置
  mcfg_api.rule_config,
  mcfg_role_api.protocol_config AS role_protocol_config,  -- 角色级覆盖
  mcfg_api.special_api_action, mcfg_api.special_api_op,
  mcfg_api.pass_through_type,
  mcfg_api.descr, mcfg_api.status, mcfg_api.createtime, mcfg_api.updatetime
FROM mcfg_api
JOIN mcfg_role_api ON mcfg_api.id = mcfg_role_api.api_id
```

网关 Bean（proxy-openapi 侧）在 `McfgApi.toBean()` 中处理合并：API 级 `protocolConfig` 和角色级 `roleProtocolConfig` 合并为一个 JSON，**角色级优先**。

### RPC 接口对应关系（proxy-openapi → real-cfg）

| proxy-openapi 调用链 | real-cfg 服务端 | 操作的表/视图 | 缓存 Key（proxy-openapi 侧） |
|---|---|---|---|
| `AppCfgApi.get(apikey)` → RPC `action=mcfg, op=AppCfg.get` | `AppCfg.get` → `AppServiceImpl.get(apikey)` → DAO 查 `mcfg_app` | `mcfg_app` | `IAppService.getByApikey.{apiKey}` |
| `ModuleCfgApi.get(mkey)` → RPC `action=mcfg, op=ModuleCfg.get` | `ModuleCfg.get` → `ModuleServiceImpl.get(mkey)` → DAO 查 `mcfg_module` | `mcfg_module` | `IModuleService.get.{mkey}` / `.{id}` |
| `ApiCfgApi.list(roleId)` → RPC `action=mcfg, op=ApiCfg.listByRole` | `ApiCfg.listByRole` → `ApiServiceImpl.listByRole(roleId)` → DAO 查 `view_role_api` | `view_role_api` | `IApiService.roleapi.{roleId}` / `.roleapi.v3.{roleId}` |
| `RoleCfgApi.get(roleId)` → RPC `action=mcfg, op=RoleCfg.get` | `RoleCfg.get` → `RoleServiceImpl.get(roleId)` → DAO 查 `mcfg_role` | `mcfg_role` | 缓存于 ApiServiceImpl.refresh 时查询 |

### 配置变更通知链路（Redis pub/sub）

```
real-cfg 侧数据变更
  │
  ├── McfgAppDAOImpl 写操作
  │     └── NoticeUtil.sendNotice("update", "McfgApp", 旧apiKey, 新apiKey)
  │
  ├── McfgRoleDAOImpl 写操作
  │     └── NoticeUtil.sendNotice("update", "McfgRole", roleId)
  │
  └── RoleServiceImpl.addApiList / removeApiList
        └── NoticeUtil.sendNotice("update", "McfgRole", roleId)

                   ↓ PublishFactory.publish()
                   ↓ Redis 频道: real.cfg
                   ↓
proxy-openapi SubscribeFactory（订阅 real.cfg 频道）
  │
  ├── BlockingPool<NoticeMessage>(500) 入队
  ├── MessageDispatchThread(5~50线程池) → MessageHandlerThread
  └── MessageServiceImpl.Handler(message)
        ├── target="McfgApp"        → IAppService.refresh(apiKey)
        ├── target="McfgModule"     → IModuleService.refresh(mkey)
        ├── target="McfgRoleApi"
        │    或 "McfgRole"          → IApiService.refresh(roleId)
        └── ...

失败兜底: publish 失败 → MqInfoNotice 写 MySQL → 后台重试
```

**通知可靠性**：`NoticeUtil.sendNotice` 先尝试 Redis publish；失败则落盘到 MySQL `mq_info_notice` 表，由 `INoticeService` 后台重试。确保网关侧最终一致性。其他 DAO（PcCfg/PcAccount/RaspiCfg/ProjectGroup/Model/DeviceModel/DeviceSource/DeviceCfg/Brand 等 14 类）也通过同一 NoticeUtil 发 `real.cfg` 频道通知。
