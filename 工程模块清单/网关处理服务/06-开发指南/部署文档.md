# 网关处理服务 部署文档

> 工程：`D:\programfile\major\java\testin\workspace\proxy-openapi`（JDK 1.8 / Spring Boot 1.5.4，Maven 单模块，artifactId=proxy-openapi，version 3.1）。本文基于 Dockerfile 的构建/启动命令整理；镜像由 CI 产出供 k3s 使用。本地启动 pom.xml 修改见文末内部 wiki 链接。

## Docker 镜像构建（两阶段）

| 阶段 | 基础镜像 | 作用 |
|---|---|---|
| BUILD | `reg-noc.testin.cn/pub/mevan:8u341` | 带 JDK8 + Maven，编译打包 |
| RUN | `hub-mirror.testin.cn/library/busybox:stable` | 只承载 jar/config，启动时解包到挂载卷 |

### 打包命令（BUILD 阶段）

```bash
/var/maven/bin/mvn clean install -P test -Dmaven.test.skip=true
```

- 激活 `test` profile，跳过单元测试。

### 启动命令（startup.sh）

```bash
/var/java/bin/java -Xms1024m -Xmx1024m -XX:PermSize=128M -XX:MaxNewSize=256m -XX:MaxPermSize=256m -jar proxy-openapi-3.1.jar
```

- 初始/最大堆均 1024m；jar 名带版本号 `proxy-openapi-3.1.jar`（Dockerfile 中引用，pom `finalName=${project.artifactId}` 时以实际 target 产物为准）。

### 运行阶段（busybox）

- 环境变量：`ENV PORT 8080`
- 暴露端口：`EXPOSE 8080`
- 挂载卷：`VOLUME /data/webhome /home`
- CMD：`cp -R /data/target/* /data/webhome/` 解包 + 创建目录 `/home/syy/data/logs/proxy-openapi`

## 镜像构建与推送（.gitlab-ci.yml）

| 触发 | 命令 | 镜像 tag |
|---|---|---|
| 打 tag | `docker buildx build -f Dockerfile --platform linux/arm64,linux/amd64 -t $CI_REGISTRY_IMAGE:$CI_COMMIT_TAG . --push` | `$CI_REGISTRY_IMAGE:$CI_COMMIT_TAG` |
| `syy.release.*` 分支 | `docker build --pull` + 两次 `docker push` | `$CI_REGISTRY_IMAGE:$CI_COMMIT_REF_SLUG-<短SHA>` 与 `...:$CI_COMMIT_REF_SLUG` |

构建前 `docker login` 到 `$CI_REGISTRY`；DOCKER_HOST 指向 `tcp://registry.testin.cn-public-docker:2375`。

## 部署到 k3s

镜像推送后，k3s 工作负载引用镜像 tag；容器启动时 busybox CMD 先把 `/data/target` 解包到 `/data/webhome`，再由 startup.sh 的 java 命令拉起进程（`/var/java/bin/java` 为节点/镜像层固定路径）。服务端口 8080（`cn.testin.startup.Boot`）。

## 本地打包与启动

```bash
/var/maven/bin/mvn clean install -P test -Dmaven.test.skip=true   # 打包
/var/java/bin/java -Xms1024m -Xmx1024m -XX:PermSize=128M -XX:MaxNewSize=256m -XX:MaxPermSize=256m -jar proxy-openapi-3.1.jar
```

- 产物：`target/proxy-openapi/proxy-openapi-3.1.jar`（pom `finalName=${project.artifactId}` 时可能为 `proxy-openapi.jar`，以实际 target 为准）。

## 本地启动 pom.xml 修改

本地启动（IDE 或直接 `java -jar`）时，pom 顶层 `<resources>` 用 `<excludes>` 把 properties/xml/json 排除在 jar 外、再由 `maven-resources-plugin` 拷到 `./config`，本地跑配置不在 classpath。需**放开这些 excludes**（让配置打进 jar）。

> **注意：此修改仅用于本地启动；Docker 部署不需要** —— 镜像构建保持配置外置到 `./config`，由 startup.sh 加载。
