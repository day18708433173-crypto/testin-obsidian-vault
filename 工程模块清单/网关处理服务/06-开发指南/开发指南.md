## 分层约定

### Servlet 层（web/servlet）

三个版本的 Servlet 各自独立实现，**不共享基类**。同样的编排逻辑（check/field/ignore/additional）在三个 Servlet 中重复实现。

- V1：JSON-RPC 风格，最低优先级（`@Order(2)`），匹配所有未被 V2/V3 截获的请求
- V2：REST 风格，路径三段式 `/v2/{mkey}/{action}/{op}`
- V3：RESTful 风格，高优先级（`@Order(1)`），支持所有 HTTP 方法

### Business 层（business/impl）

- 每个 ServiceImpl 继承 `AbstractGenericServiceImpl`（注入 8 个 API + LocalCache）
- `AppServiceImpl`、`ModuleServiceImpl` 使用 `LockUtil` 双重检查锁防缓存击穿
- `ApiServiceImpl` 使用 `LockUtil` 双重检查锁，V1/V3 两套缓存 key 独立管理

### API 层（api）

- 所有对 real-cfg 和 testin-core 的 RPC 调用封装在 `api/realcfg/mcfg/` 和 `api/user/user/` 下
- `AbstractApi` 提供 `realcfgPrefixName`（`RealCfg`）和 `userPrefixName`（`UserManager`）两个 RPC 前缀
- API 类通过 `ApiUtil.doPress(prefixName, action, op, params)` 发起 ICE RPC 调用

### 配置读取

- `application.properties` → `Config.java` 读取（`httpservice.proxy.headers`）
- `cfg/db/config.json` → `DbConfigUtil.loadConfig()` 在 `Boot.main()` 中首先加载
- `service.api.properties` → `ApiUtil.getServiceApiUrl(prefix)` 读取

## 新增 API 路由的标准流程

API 路由定义**不在此工程**，在平台配置服务 real-cfg 的 `mcfg_*` 表中。网关只负责按配置执行。新增流程：

1. **在 real-cfg 中新增 McfgModule**：定义 mkey、rpcPrefixName 或 httpHosts，状态置为 ON
2. **在 real-cfg 中新增 McfgApi**：关联模块 + 定义 action/op（V1）或 url+method（V3）+ needLogin + protocolConfig
3. **在 real-cfg 中关联角色**：McfgRoleApi 表中绑定 roleId ↔ apiId
4. **发布配置变更**：real-cfg 通过 Redis pub/sub `real.cfg` 频道推送 `NoticeMessage`，网关自动刷新缓存

无需重启网关即可生效。

## 本地构建运行

### 构建

```bash
cd proxy-openapi
mvn clean install -P test
```

构建产物在 `target/proxy-openapi/`：
- `proxy-openapi-3.1.jar`（Class-Path: config）
- `config/` — 配置文件和依赖 jar
- `lib/` — 依赖 jar 包

### 运行

```bash
cd target/proxy-openapi
java -jar proxy-openapi-3.1.jar
```

### Docker 构建

```bash
docker build -t proxy-openapi .
```

Dockerfile 两阶段构建：Maven 编译 + busybox 运行时，端口 8080。

| 配置 | 环境变量 | 默认值（指向生产，本地必改） |
|---|---|---|
| 服务端口 | — | 8080 |
| HTTP 代理超时（连接） | `OPENAPI_CONNECT_TIMEOUT` | 1,200,000ms（20 分钟） |
| HTTP 代理超时（读取） | `OPENAPI_READ_TIMEOUT` | 1,200,000ms（20 分钟） |

> 本地开发时必须修改 Redis、ICE Locator、RPC 目标地址指向开发环境。

## 约定清单

### 日志
- 使用 Log4j2 异步日志（`AsyncLoggerContextSelector`，在 `Boot.main()` 中设置）
- 日志路径：`/home/syy/data/logs/proxy-openapi/`
- 关键 logger：`api.proxy`（请求/响应追踪）、`sys.error`（错误）、`sys.debug`（调试）、`mq.notice`（Redis 消息）

### JSON 序列化
- 使用 Jackson（`JsonUtil`）和 Gson（`Config.GSON`）两套，Gson 用于与 V1 服务兼容（`ApiUtil.response`）
- 请求 body 最大 10MB（`protocolSizeInvalid`）

### HTTP 客户端
- HTTP 代理：`HttpURLConnection`（`HttpServiceImpl`）
- V3 远程调用：OkHttp3 `RestTemplate`（`RestTemplateConfig`）

### 线程池
- Redis 消息分发：核心 5 / 最大 50（`MessageDispatchThread`）
- 用户活动异步写入：单例 `ThreadPoolUtil`（`newFixedThreadPool(5)`）

### 缓存
- LocalCache：10 段 × 50000 容量，60 分钟过期，5 分钟清理（`Spring-LocalCache.xml`）
- 缓存加载使用 `LockUtil` 双重检查锁，严禁不加锁直接查 RPC

### 事务
- 网关无数据库，无事务

## 跨端修改红线

| 修改对象 | 影响 | 要求 |
|---|---|---|
| `McfgApp.appConfig` 结构 | 所有接入应用的认证行为 | 需兼容旧字段，`ApiUtil.commAuth` 中 `AppConfig` 解析逻辑同步更新 |
| `protocolConfig` 结构 | 所有接口的编排行为 | 新增编排项需在三个 Servlet 版本中都实现（或在非适用版本中明确跳过） |
| `service.api.properties` | RPC→HTTP 路由 | 与 real-cfg 的 `McfgModule.rpcPrefixName` / `httpHosts` 保持一致 |
| Redis pub/sub `NoticeMessage` 格式 | 配置热更新 | 需与 real-cfg / testin-core 的消息格式同步 |
| ICE Locator 地址 | 所有 RPC 调用 | 修改后所有 RPC 模式模块全部受影响 |
